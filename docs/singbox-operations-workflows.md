# sing-box 运维与代理用户流程

本文说明服务器运行时、节点与链路运维及代理用户操作流程的现行契约与边界。早期平台扩展里程碑的测试汇总见 [当轮历史验收记录](acceptance/operations-platform-expansion.md)；源码测试通过不代表当前组合已完成真实公网设备、外部 CA 签发或新版一体化 Agent 正式 Release 实机签收。

控制台入口：单台服务器的运行时状态、按需环境检查、偏差核对、重新部署、节点迁移与链路切换位于服务器详情「网络服务」分页（`/#/servers/{id}/services`）；跨服务器汇总位于「网络服务 › 节点」（`/#/nodes`）的「运行时」视图（`/#/nodes?view=runtimes`），批量失败部署恢复位于「服务器 › 自动化与维护」（`/#/operations`，实验）；用户诊断、限速与连接限制、连接凭据轮换、客户端模板及流量/有效期调整位于「网络服务 › 用户」（`/#/users`、`/#/users/{id}`），批量策略组分配在「策略与套餐」（`/#/groups`）及用户列表上方；代理用户自助门户使用独立入口（`/#/account/{account}`、`/#/member`、`/#/join`）。

## 14. 运行时、节点和链路

| 项目 | 源码覆盖 | 真实环境及能力边界 |
| --- | --- | --- |
| 内置运行时与失败部署恢复 | 按 [ADR 0141](adr/0141-self-contained-agent-and-desired-service-config.md)，`sing-box`（当前固定 `1.14.4-apsp.2`）随一体化 `apsp-agent` 内置交付，运行时升级随签名 Agent 整包升级与试用回退完成，无独立运行时库存或组件灰度。「服务器 › 自动化与维护」（`/#/operations`，`JobsTab`）保留 `singbox_retry_deployment`（重新应用已有失败的签名部署），经 `governance` 核实并冻结在线已验签一体化 Agent 与内置 `sing-box`（`1.14.4-apsp.2`）身份后重新应用既有失败修订，不生成新业务配置，也无独立组件选版 | 仅针对当前期望版本已记录失败的受管部署；结果未知的操作不自动重放。新版一体化 Agent 正式签名 Release 与实机升级验收待单独执行 |
| 按需部署环境检查 | `crates/traffic/src/runtime_workflows/preflight.rs` 与 `preflight_network.rs`（`POST /api/traffic/servers/{id}/operations-view/preflight`）对当前节点/有效授权、平台与策略执行按需只读采集：面板 DNS 返回的全部 A/AAAA 按地址族核对服务器地址，检查手工证书域名/期限/密钥匹配；自动签发核对真实编译后的 ACME 提供方、域名与节点引用，并检查 DNS、Agent 实测挑战端口、运行时及持久证书目录与系统服务权限。普通节点保存后直接自动发布，不再设首次空运行时安装或人工确认阻塞门禁 | Agent 专用能力 `fleet:runtime-preflight:v1` 与面板/本机双侧 `runtime_inspection` 授权默认关闭，需在「服务器详情 › 运维」（`/#/servers/{id}/fleet`）与本机 Agent 配置显式开启；系统后端真实只读连接且特权 UID 0 才可判定可管理；已有监听只有实际 unit MainPID 与近期 checkpoint 匹配才视为受管。首次签发无需预先已有证书，外部 CA 挑战可达仍须公网实测；部署后运行时仍须通过本机 TCP TLS / QUIC 握手与统计接口健康检查 |
| 应用前配置比较 | 已应用快照对业务目标逐节点显示新增、移除、参数/凭据变化与相关用户；敏感值隐藏 | 普通节点差异与链路版本分别展示；待发布不等于已应用 |
| 节点模板与克隆 | 复用已有 `catalog/clone.rs` 创建路径，密码、psk、Reality 身份与其他独立标识重新生成，不复制授权；迁移助手使用独立候选 | 需要按各协议验证克隆后配置检查及独立身份 |
| 链路替换流程 | 有序链路的冻结候选、依赖预检、候选探测、切换探测、恢复屏障、确认及旧路径清理，服务器详情「网络服务」分页（`/#/servers/{id}/services`）的运行时运维显示版本和阶段 | 网络探测和恢复屏障的真实设备签收仍独立，未绕过原条件 |
| 链路瓶颈诊断 | 并列展示受管跳的资源观测、设备连接、目标/应用、健康、失败和链路候选状态，跳转具体服务器网络检查 | 外部跳资源与实际网络性能保持未知；不据配置或一次资源值宣布瓶颈 |
| 上游来源更新比较 | 复用外部来源已有版本预览、增加/移除/参数变化和 `pinned`/`follow_node` 策略；用户诊断展示外部授权来源与最近来源错误 | 来源访问失败保留上一成功批次，不自动替代节点，也不自动授权新导入节点 |
| 受控故障切换 | 预览只接受明确原链路、已验证备选及固定策略组，确认后迁移这些策略组的链路授权，审计原因对象、保留旧链路 | 人工确认切换；没有显式配置的备选不允许选择，不提供自动出口池或绕链直连 |
| 运行时偏差检测 | 主动请求通用 `runtime-control` checkpoint，由 Agent 实际核对文件字节、清单、符号链接、受管进程和内置运行时身份；`verified`、确定偏差、未知失败、待回执和过期分别显示 | 只把当前绑定且五分钟内 `verified` 的回执记为核对时一致，未直接提供原始文件摘要时明确 `live_config_hash_available=false`；目标包摘要不冒充实际文件摘要 |
| 节点迁移助手 | 核对不同服务器、同协议、候选启用、候选设备当前部署、生命周期、入口/SNI、受影响用户/策略；迁移授权并重发两端，原节点与原账本保留 | 候选入口与证书握手、公网可达需明确来源实测；链路成员拒绝普通迁移，Agent 身份不复制 |

## 15. 代理用户、授权、套餐与客户端

| 项目 | 源码覆盖 | 真实环境及能力边界 |
| --- | --- | --- |
| 用户诊断入口 | 一次查看独立自助账号、Passkey 数量及有效会话数、套餐、策略组权限、来源、目标/应用、订阅生成、外部源错误、凭据轮换、批次、补偿及历史 | 离线设备未确认变化时继续待应用，生成订阅不等于真实客户端连接成功 |
| 有效权限解释 | 逐资源显示所属策略组、链路来源，以及套餐资格、启用与部署状态（用户只经策略组获得资源，ADR 0112） | 多个策略组重叠包含同一节点时保留原凭据；全部策略组移除后才撤销 |
| 批量分配预览 | 固定用户集合、固定变更后策略组集合，逐用户展示新增和撤销资源；事务指纹变化拒绝确认、相同预览幂等 | 不因列表实时变化扩大用户目标 |
| 套餐变更预览 | 说明确认时生效、额度、时区、当前新账期用量、有效天数、现有账本处理；保存不可变分配快照 | 新重置规则会重新归集原用量，不称为清空流量或续加期限 |
| 重置流量与调整有效期 | 重置流量为本期补偿实际已用量；有效期可按月或天延长、指定到期时间或改为不限期，预览显示原到期与新到期，确认后写入新的套餐快照；更换套餐独立操作 | 只改到期不重置流量，重置流量不改到期；不能设为早于现在或套餐开始的时间。迁移用户经兼容桥同步到原系统 |
| 流量账本核对 | 显示设备计数器代次（epoch）、序号、计量窗口、套餐周期、原始字节、首次接收、重放次数、最近重放与补偿 | 旧批次接收时间未知；接收延迟受设备时钟影响。相同身份不同 payload 继续拒绝，迟到批次计入原账期 |
| 用户限速与连接限制 | `crates/access/src/user_limits.rs` 与 `crates/compiler/src/limits.rs` 按用户设置每台服务器的上下行速率与并发连接上限（`0` 表示不限），编译进目标配置的用户限制路由表；诊断页一并显示生效状态 | 需要目标服务器运行时具备 `user-limits` 能力（`1.14.4-apsp.1` 及以上，当前固定 `1.14.4-apsp.2`，[ADR 0124](adr/0124-stable-runtime-and-user-limits.md)）；旧运行时不支持时明确拒绝，不静默忽略 |
| 订阅兼容检查 | `POST /api/access/users/{id}/compatibility` 对指定客户端、版本、格式检查完整生成与模板引用；返回协议列表、无丢字段情况和未实际客户端校验状态 | 当前校验 `sing-box` `1.14.4` 完整 JSON（`format="singbox"`）；其他版本/客户端明确返回不支持，不把配置生成当作原生客户端实测通过 |
| 客户端配置模板 | 管理选择组、DNS、路由、并发版本与有界草稿；未知字段、未授权节点引用、组名冲突拒绝；保存只核对授权引用，完整订阅按当前套餐及部署再次检查模板 | 保留原始受管/外部出站字段和凭据；分享链接格式无法表达模板时拒绝，其他字段模型不静默转换 |
| 凭据轮换流程 | 订阅地址重置与所选受管节点凭据轮换分别执行；在线、最近设备观测、无待发布变更、实际已应用快照与新摘要匹配，并在设备支持 checkpoint 时要求当前绑定五分钟内的真实核对后确认；过期和后续替代状态单列 | 外部凭据由提供方撤销；无法据配置应用保证现存长连接已强制断开，无数据不报告撤销成功 |
| 用户自助入口补全 | 独立 Passkey 或邮箱登录、自己的累计用量、本期用量/额度、到期、下次重置、可下载订阅及具体失败原因 | 不引入平台全局用户或公开注册；不能访问其他用户或管理诊断 |
| 访问与审计记录 | 管理预览确认、模板变更、订阅生成或阻止、令牌重置、完整凭据读取、独立门户登录/失败、退出、邀请和密钥增删分别记录；保留策略分管理员/订阅/安全事件，后台每三十秒清理并取平台 `audit`/`proxy-access` 与服务权益保留策略较短值 | 默认不收集原始客户端 IP，不保存连接密钥、订阅令牌；读取审计只含管理员、对象编号、入口、数量及格式。保留策略为 0 时停记订阅访问；计量账本不随审计清理删除 |

## 主要 API

- `POST /api/access/operations/preview` 与 `POST /api/access/operations/{id}/apply`：七类用户与策略操作的固定对象预览及再次验证确认（状态变化则拒绝）。
- `GET /api/access/users/{id}/diagnosis`：授权来源、套餐、部署、批次、限速状态、轮换、审计与能力限制。
- `GET/PUT /api/access/users/{id}/limits`：读取或更新逐用户每服务器限速与并发连接上限。
- `GET/PUT /api/access/users/{id}/client-template` 与 `POST /api/access/users/{id}/compatibility`：有版本的完整客户端模板及 `sing-box 1.14.4` JSON 兼容检查。
- `GET /api/traffic/servers/{id}/operations-view`：当前服务器的部署条件、配置差异、偏差、链路状态与历史。
- `POST /api/traffic/servers/{id}/operations-view/checkpoint`：请求目标 Agent 主动核对实际配置与受管进程，回执到达前保持待确认。
- `POST /api/traffic/servers/{id}/operations-view/preflight`：按需只读环境检查（DNS、证书、端口与运行时目录权限证据）；按 [ADR 0141](adr/0141-self-contained-agent-and-desired-service-config.md)，普通节点保存后直接自动发布，不再附带人工确认阻塞流或独立运行时库存接口。
- `POST /api/traffic/servers/{id}/deployments/redeploy`：在近期再次验证后将当前有效服务配置作为新修订重新下发。
- `GET/PUT /api/access/operations/privacy`：分别设置审计保留天数；订阅保留为 0 天表示停止记录。

预览只保存敏感状态摘要，不保存原始凭据。应用记录在同一业务事务内写入；高风险写操作要求平台最近五分钟内的再次验证证明，并逐台核对目标服务器权限。每台服务器实际执行状态保持排队、等待设备或已确认，不用 HTTP 保存成功替代设备回执。

用户列表、详情与访问授权在只读权限、API 令牌或证明过期时隐藏订阅地址/令牌与连接 UUID；管理员完整订阅与客户端模板明文读取（`?reveal=true`）要求 `proxy:write` 与近期再次验证，每次披露写入元数据审计。发布循环按每轮套餐资格、链路生命周期、外部来源更新、链路发布与配置发布结果更新 `sing-box` 心跳。

## 验收代码与验证进度

`crates/access/src/operations_workflows/tests.rs` 与 `crates/traffic/src/runtime_workflows/tests.rs` 覆盖脱敏配置差异、客户端原出站保留、模板自定义 DNS 头隐藏与失效引用拒绝、固定目标编号校验、配置偏差脱敏分类，以及 PostgreSQL 上的额度补偿与迟到批次计费、延期新快照保留原账期用量、预览指纹失效、离线或缺少 checkpoint 时凭据轮换保持待确认。当轮集中测试结果见 [当轮历史验收记录](acceptance/operations-platform-expansion.md)；真实设备部署、链路入口握手、外部 CA 签发与新版一体化 Agent 升级恢复在隔离测试机单独验收，不对生产自动执行。

## 按需部署环境检查细节

预检表按数据库单调序列保存元数据快照、业务摘要、Agent 请求编号、面板 DNS/证书证据与五分钟有效期，不保存节点密钥、订阅令牌或证书私钥。读取每一项返回 `state`、`blocking`、`observed_at`、`source`、`evidence` 与处理提示；Agent 回执到达前显示排队/已分发，超时保持未知，不以 HTTP 入队成功替代设备证据。历史记录按平台 `audit` 与管理员保留策略的较短值清理。

触发只读采集需要目标服务器的 `proxy:write`、`operations:read`、`monitoring:read`、`diagnostics:write` 管理员会话（API 令牌不可调用）。Agent 专用能力 `fleet:runtime-preflight:v1` 与面板「服务器详情 › 运维」、本机 Agent 配置中的 `runtime_inspection` 默认均关闭，不随节点创建自动开启；检查过程不创建业务文件、不修改系统服务、不读取私钥正文。

- **DNS 与地址核对**：面板解析器最多读取 33 条记录以识别超过 32 条的截断；返回的全部 A/AAAA 逐条核对服务器观测或登记地址，同地址族任一不匹配即判失败，返回未登记地址族记为未知；ACME 域名另要求返回公网地址。
- **自动证书签发条件**：编译器（`1.14.4-apsp.2`）生成 Let's Encrypt ACME 提供方、SNI 域名、联系邮箱、HTTP-01/TLS-ALPN-01 挑战（TCP 80/443）与节点引用后，一并核对 DNS、Agent 实测挑战端口、运行时目录与服务权限。首次部署前当前入口证书观测与已部署 TLS 握手保持非阻塞未知，不伪造已签发；实际应用后适配器等待最多 240 秒完成本机 TCP TLS / QUIC 握手与统计接口健康检查，失败则自动回滚至上一已验证修订。
- **运行时目录与权限**：通用 `RuntimePermissions` 以文件描述符和 `no-follow` 检查 `runtime_root/{module}@main`、`data` 与 `data/certificates`，读取已加载 `apsp-singbox@main.service` 的真实运行账号、UID/GID 与补充组降权核验读写遍历权限；服务尚未首次创建或账号未知时如实报告未知，不以 root 权限冒充运行时账号权限，也不阻塞普通节点的首次自动下发。
