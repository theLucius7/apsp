# ADR 0019：删除服务器前完成在线退役

状态：采纳。

## 行为与确认

删除决定使用面板实际持有的 WebSocket 连接，列表的最近消息时间仅用于显示在线状态。设备在线且声明 `server:retire-v1` 时，面板先持久保存随机退役请求 ID，再发送 `retirement.request`。没有能力的在线旧 Agent 返回升级提示，不把旧协议忽略消息视为退役成功。没有连接时沿用原先软删除行为，撤销面板会话、接入令牌和未完成诊断；界面明确此分支不能停止离线设备。

在线请求持久化后，Agent 阻止新的对账和诊断，等待已经进行的受管操作完成，采集能观测的最后用量，停止运行时及所有未结束诊断服务。已持久用量必须全部收到面板确认才允许完成清理；未采样到的字节不能宣称恢复。失败保留退役意图、账本与尚需发送的凭证，不回到正常运行模式；重启继续同一退役请求。

服务已停止后，Agent 清除设备身份与注册凭证、内存会话、管理目录中的运行配置和 SQLite 应用/恢复配置快照，包括其中的 Reality 密钥与用户凭据。历史计量、用量时钟、退役记录及公开制品留作审计。删除操作通过既有特权接口，只作用于已验证的管理路径，不跟随目录符号链接；逻辑删除不承诺物理介质安全擦除。停止确认读取 systemd 的 LoadState、ActiveState、MainPID 和 ControlPID；查询失败、缺字段或未知状态均阻止清理，过渡态或残留主/控制进程必须继续停止。不能把 systemctl 的非零退出码直接当作已停止。运行时 current 链接被移除，已完成退役的 Agent 以专用退出状态停止，systemd 不反复重启它。

## 清凭证之后仍能恢复确认

单纯先 ACK 再清凭证会留下崩溃窗口，先清凭证再 ACK 则可能因响应丢失无法重新认证。为此，在停服务之后、删除私钥之前生成一个仅证明此退役请求的公开 Ed25519 回执，并与退役意图一同持久化。签名消息是固定域 `apsp-retirement-v1\0`、8 字节大端有符号服务器 ID 和 16 字节请求 UUID；签名采用 URL-safe base64，无填充。它不能用于设备连接的随机 challenge，不能为另一个请求或服务器完成退役。

完成凭证清理与持久化之后才发送成功回执。已有 WebSocket 可以传 `retirement.result`；清凭证后的重启只允许恢复退役流程，并向原先绑定面板的 `POST /api/agent/v1/retirement/receipt` 重发回执，不启动代理。面板按持久请求 ID、服务器 ID 与原注册公钥验签，在同一事务内确认退役、软删除服务器并撤销全部设备会话与接入令牌。原公钥和请求作为 tombstone 保留，重复回执返回 204，解决响应丢失。

回执由本机受保护状态保存；只有实际完成清理后才允许发送。面板信任已部署 Agent 对本机结果的报告，签名不是硬件远程证明。拥有设备 root 权限的人仍能修改程序或提前提交其持有的回执。

在线删除等待有限时间。超时、停服务失败或清理失败返回可重试错误，保留面板记录，不在这次请求中自动转成离线成功。之后操作者重新请求删除时，若设备确实无连接，可以执行离线删除；此前的请求记为 `offline_unconfirmed`，不伪造成功记录。迟到的有效回执仍能把它更新为已确认。

如果离线删除发生在 Agent 尚未完成待确认用量、也未生成完成回执时，面板撤销认证会使它停留在安全停止状态，不能自动完成清凭证；需要操作者在设备上处理。只有已经完成清理并保存回执的设备，才能在清除私钥后匿名补交成功证明。

## 并发与验证

面板用一个短期设备生命周期锁串行连接注册、在线状态判定、删除和回执提交，并在其内部使用服务器行锁。锁顺序固定为生命周期、数据库行、连接映射；网络发送和等待回执不占用生命周期锁。认证挑战通过后，在注册事务中重新检查服务器仍有效且公钥未变，避免删除等待数据库时新连接插入、或已删除设备重新取得会话。重试使用原请求 ID。Agent 以持久退役标记和共享操作锁阻止停机后又启动新的运行时或诊断。面板继续接收与确认待提交用量，直到成功回执；已确认历史账本不随删除丢失。

验收覆盖在线先退役后删除、离线软删除、旧 Agent 能力缺失、停服务或清理失败、未知或错误签名回执、重复回执、请求/响应丢失后的恢复、清凭证前后崩溃恢复，以及历史账本与待确认批次不被删除。协议主版本维持 1，新增能力用于区分支持程度。
