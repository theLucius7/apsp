# ADR 0061：sing-box 两端插件与服务器安装流程

状态：已接受。

> 主线整合编号 0061；作者原独立分支编号 0044。旧主线同号决策及链接保留，历史验收仅认证原冻结输入。

## 决策

面板端业务插件在 `plugins/singbox/panel/`，负责代理节点、用户、授权、订阅、策略、套餐和两跳链路，生成完整原生配置。设备端 `adapter-singbox` 负责版本、配置、健康检查和计量翻译；通用 Agent 管理签名下载、服务、对账、回滚和确认。两端通过现有协议配合，不让适配器连接面板或自行持久化，不增加第二个控制面或修改上游运行时。

这补充 ADR 0030 的启用判定：设备声明 `singbox` 只表示支持，不作为新服务器启用业务的选择。管理员明确启用，或已有代理节点/部署，才构成启用证据。旧节点、部署、凭据、订阅和流量保持；0012 的旧 `agent_capability` 记录不删除，但单独的能力标记不再启用纯监控服务器。

“启用并安装”在同一事务记录管理员选择，并给尚无部署的服务器安排首次配置发布。重复请求保留原待办时间，不推迟五秒合并发布，也不反复发布已存在的部署。首次配置可以没有代理节点，不开放用户代理监听；依然通过现有签名制品和设备对账安装固定 sing-box 1.14.2。设备离线或能力不足可保存选择，随后等待支持该插件的 Agent 接入；这不表示运行时安装成功。

元数据增加 `installation`，区分未启用、已安排、等待设备、离线、等待应用、已确认运行、失败。运行成功来自已应用版本及健康确认。设备在线、能力声明、管理员选择、面板发布分别不能单独证明运行成功。清单准备失败（包括缺少签名制品或不受支持的平台）记录明确原因，既有 Agent 应用结果和仍运行的旧配置不被伪造或覆盖。

最新整合保留主线 `0019_latency_tasks.sql`、`0020_notification_rules.sql`、`0021_node_settings.sql` 与 `0022_statistics_indexes.sql`，安装准备表使用主线 `0023_singbox_installation.sql`，SQL 内容不变。该表曾在独立分支使用0019、统一准备分支使用0021，旧冻结收据保留原编号。完整组合须另做迁移验收，不改写历史证据。正式面板只读盘点显示已应用1–13，可正常按新序列升级；其他未知数据库先检查 `_sqlx_migrations`，如已将安装表应用到旧0019/0021，则保留SQLx的版本/校验拒绝，不自动删除、重编号或改写迁移记录。

## 页面与业务顺序

插件概览连接服务器接入、插件安装、代理节点、代理用户及策略与套餐。代理节点页按节点监听与两跳链路分类，标出专用入口和链路出口；链路管理归代理节点，策略页面只引用已有资源。每条现有两跳链路仍使用独立入口和另一台服务器的 Reality 出口；创建本身不授予用户权限。未授权节点不监听用户端口，授权后等待对应设备应用，订阅沿用原有已应用检查。

用户可以单独授权普通节点，或分配包含普通节点/链路的策略组。套餐是独立额度与期限限制，不授予节点；管理员属于系统，代理用户属于插件。流量周期不改变计量 epoch。策略选择草稿不被后台轮询覆盖，保存后显式读回服务端状态。

本次使用已有节点和链路 API，不将链路创建扩成任意拓扑或自动授权。批量原子创建、统一资源投影及跨端凭据轮换继续按其独立设计验收。

## 验证边界

验证能力声明不自动启用、首次安装待办和重复启用、空配置发布、缺制品原因、设备确认及失败、旧节点与订阅兼容，以及桌面/手机真实构建的操作流程和策略草稿。专用节点上的真实安装另记，不用模拟确认代替实机运行。生产服务器和数据库保持原有部署边界；不恢复暂停的 CI。
