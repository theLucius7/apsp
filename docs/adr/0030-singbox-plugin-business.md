# ADR 0030：sing-box 业务搬迁与服务器启用证据

状态：已接受。

## 决策

落实 ADR 0023：面板的代理节点、代理用户、授权、订阅、用户流量、配置发布和设备运行时清单实现移入 `plugins/singbox/panel/`。面板通过薄的 Rust path 桥嵌入根插件目录，根模块保留 Rust 导出作为兼容桥；后台诊断过期维护由独立 maintenance 服务处理，不由代理发布循环负责。

管理接口统一为 `/api/plugins/sing-box/nodes`、`users`、`usage`、`servers/{id}/deployments` 及其子资源。前后端同一版本切换，旧管理 API 不保留别名。已导入订阅的 `/sub/{token}` 永久保留，路由和解析归插件。表名、主键、订阅令牌、设备公钥、Reality 密钥、授权 UUID、发布快照和流量账本均不重写。

系统管理员仍是已有单管理员认证模型，导航归“系统 / 系统管理员”。业务用户的 Rust/TypeScript 模型命名为 ProxyUser，导航归“sing-box 插件 / 代理用户”。本次不新增多管理员或配额执行。

## 启用判定

本节记录原搬迁行为；设备能力与管理员选择的后续分离、实际安装待办及状态确认按 [ADR 0044](0061-singbox-plugin-lifecycle.md) 执行。单独的能力声明不再启用新服务器业务，已有节点/部署兼容保留。

服务器当前明确声明 `singbox` 能力，管理员明确启用，或已有代理节点/代理部署，是启用证据。迁移 0012 新增 `server_plugins` 表，只保存启用来源，不改旧表名。既有节点（包括已删除的历史记录）及 singbox 部署回填兼容启用；无上述证据的纯监控服务器关闭插件，不因为未知能力而默认启用。

当前设备声明优先显示为只读来源；已有节点或发布配置同样显示兼容来源只读。管理员从“系统 / 插件设置”明确启用后才允许在新服务器创建代理节点；重复启用幂等。已保存的旧设备声明若当前不再存在，并且没有管理员选择或既有配置，不单独作为启用证据。设备未声明能力时可先明确启用并配置，页面说明能力尚未上报。

服务器详情先读取插件元数据。未启用时不显示配置部署、代理节点、业务运行时信息，不请求节点和部署业务 API。插件发布循环忽略没有启用证据的服务器；设备清单仅由插件已有部署产生。网卡累计流量仍由 core 遥测显示。计量协议的 epoch 保持计数器重置标识，没有套餐周期含义。

## 验证

独立验收见 [sing-box 业务搬迁](../acceptance/singbox-plugin-business.md)。迁移测试先应用 0012 之前的真实迁移并导入订阅、密钥、授权、历史流量，再启动新面板验证旧订阅路径和两种输出完全相同。新版本管理接口、服务器关闭/启用判定、只读来源和前端实际 dist 分别验证；既有端到端对账和退役测试改用插件接口。
