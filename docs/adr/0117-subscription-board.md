# ADR 0117：订阅看板

## 背景

2026-11-06 用户要求“给 apsp 再制作订阅看板，把所有的订阅做成看板，放在服务器看板旁边”，随后补充“这个看板应该还包括 wallos 的订阅”。

此前三类“订阅”分散在三处，都没有一眼看全的视图：

- 代理用户的订阅：只能在「代理用户」里逐个打开，看套餐、本期用量、到期与重置；用户列表只有一行摘要。
- Wallos 式的续费项目（域名、AI 与其他周期付费的服务）：在「费用与续费」的表格里。
- 订阅来源（读取节点的机场订阅）：在「代理节点 › 订阅来源」，提供方上报的用量与到期混在来源设置里。

订阅被客户端拉取时，面板自己生成的订阅会记一条 `subscription_fetch`，但迁移用户经专属地址转发到原系统渲染器的拉取没有记录，所以“这个人最近有没有在用”无从判断。

## 决定

### 位置与地址

- 「总览 › 概览」的第四个分页「订阅看板」，紧挨服务器看板，地址 `/#/subscriptions`。看板同时汇总 sing-box 插件和费用与续费插件，所以与统计报表一样不放在某个插件的路径下，前端目录为 `web/src/subscriptions/`。
- 只给管理员看，不随「公开看板」公开：卡片上有用户名、套餐、费用与付款方式。
- 有代理或费用读权限、且能看全部服务器的管理员在侧栏看到它；看板只请求和显示管理员能读的部分。只能读费用的管理员只看到续费项目，不会请求代理数据。

### 三类订阅，一套看法

| 类型 | 每张卡片 | 点开 |
| --- | --- | --- |
| 代理用户 | 状态；本期用量圆环与“已用 / 额度”，环上小圆点标出周期进度（弧线越过圆点即用得比时间快）；套餐；重置、到期、最近拉取；策略组与“原系统”标记 | 该代理用户（`/#/plugins/sing-box/users/{id}`，新地址） |
| 续费项目 | 状态；圆环为本期已过的时间，中间是距下次续费的天数；价格与周期、折合每月（账本本位币）、分类；下次续费、续费方式、付款方式；备注 | 费用与续费 |
| 订阅来源 | 状态；提供方用量条；可用节点数、到期、最近成功更新；失败原因 | 代理节点 › 订阅来源 |

- 续费项目只列「费用与续费」里手动记的项目。服务器的费用与到期在服务器看板，不再重复；机场来源上报的到期就是订阅来源本身。已归档的订阅来源不显示；来源迁移前，数字编号来源仍在为节点库供节点，一并显示。
- 顶部一条统计：可用订阅、本期用量、每月费用、需关注、24 小时拉取（各自只在能读时出现）。工具栏是搜索、类型切换（全部 / 代理用户 / 续费项目 / 订阅来源，只有一类时不显示），「筛选与视图」里是状态（全部 / 可用 / 需关注 / 已停用）、排序与卡片 / 表格；排序和视图记在浏览器里。筛选时没有匹配的类型整段收起。
- 需关注的规则，停用的不算：
  - 代理用户：本期流量已用 90% 以上；按本期至今的速度会在重置或到期前用完（周期过了 10% 才估算）；7 天内到期；最近一次拉取失败。
  - 续费项目：7 天内续费；续费日已过（手动续费等确认，自动续费等后台顺延）。已安排在下次续费前取消的不算。
  - 订阅来源：更新失败；提供方流量已用 90% 以上；7 天内到期。
- 默认排序：需关注的在前，可用的其次，停用的最后；同一档里先到期、先续费的在前。

### 数据从哪里来

- 代理用户部分是新的只读接口 `GET /api/plugins/sing-box/subscription-board`（代理读权限）：一次只读快照、一条查询，返回套餐与状态、本期已用与额度、周期起止、到期、策略组名称、是否仍由原系统生成，以及最近一次拉取（时间、格式、结果）与 24 小时内次数，另附拉取记录是否开启及保存天数。不含订阅地址、令牌或任何凭据。
- 续费项目直接读费用与续费已有的 `/subscriptions`、`/labels` 与 `/summary`（费用读权限）。`/summary` 给出账本自己的日期（账本时区）、本位币与汇率：距下次续费的天数按账本日期计算，与「费用与续费」一致；折合每月按周期平摊（日、周按 365.25 天折算），用账本汇率换成本位币，缺少汇率的项目不计入合计并标出；设了月预算时，超出会在统计里提示。
- 订阅来源读现有的来源接口。插件之间不互相依赖，组合只在前端完成。

### 拉取记录统一

专属地址把迁移用户的拉取转发给原系统渲染器时，现在也记一条 `subscription_fetch`：格式记为 `renderer`，结果为 `relayed` 或 `unavailable`，节点数未知记为空。和面板自己生成订阅时走同一个记录函数，遵守同一组隐私设置与保存期限；记录失败只写日志，客户端照常拿到订阅。看板的“最近拉取”因此覆盖经 apsp 的全部请求；仍直接使用原系统地址的客户端看不到，卡片的提示里写明。

### 共用件

- 服务器看板顶部的统计条和卡片的悬停样式提到 `display/ui.tsx`（`StatStrip`、`Stat`、`cardLink`），两块看板共用。
- 费用与续费的“距下次续费天数”和“折合每月”提到 `plugins/expenses/types.ts`，费用与续费页面与看板用同一份计算。
- 手机宽度下分页标签收窄内边距，概览的四个分页在 320 宽度也能完整显示。

## 后果

- 不新增迁移，不改表；新增一个只读接口，拉取记录多覆盖了转发路径。
- 迁移用户若仍用原系统地址拉取订阅，看板显示“无记录”，这是记录范围的限制，不代表没有使用。迁移用户的本期用量来自兼容桥接上报，更新频率取决于桥接。
- 续费项目的“每月费用”是按周期平摊的估算，与「费用与续费 › 统计」按续费日推算未来 365 天（含服务器）的口径不同。
