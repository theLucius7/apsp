# ADR 0117：订阅看板

状态：部分被取代：订阅看板的位置由 [ADR 0126](0126-workspaces-language-and-addresses.md) 改为费用与续费中的「付费服务」（界面按重新设计步骤 4 调整）。

## 背景

2026-11-06 用户要求“给 apsp 再制作订阅看板，把所有的订阅做成看板，放在服务器看板旁边”，随后补充“这个看板应该还包括 wallos 的订阅”。

第一版（#228）把三类“订阅”放在一起：代理用户的订阅、Wallos 式的续费项目、订阅来源。用户看到后纠正：“订阅看板包含其他用户的订阅啊，只包含自己的 wallos 订阅”。代理用户的订阅是别人的，管理员在「代理用户」里管理即可；看板要回答的是“我自己付费的订阅”。

## 决定

### 只放管理员自己的付费订阅

- 看板只列「费用与续费」里手动记的项目，也就是 Wallos 式的订阅：域名、AI 与其他按周期付费的服务。
- 不列代理用户的订阅（其他人的，在「代理用户」），不列订阅来源（在「代理节点 › 订阅来源」，到期也出现在「费用与续费 › 即将续费」），不列服务器（在服务器看板）。
- 「总览 › 概览」的第四个分页「订阅看板」，紧挨服务器看板，地址 `/#/subscriptions`，前端目录 `web/src/subscriptions/`。只给管理员看，不随「公开看板」公开（卡片上有费用与付款方式）。有费用读权限、能看全部服务器的管理员在侧栏看到它。

### 每张卡片

- 状态；圆环是本期已过的时间，中间是距下次续费的天数（已过续费日时显示“逾期”）；价格与周期；不是按月付费或不是统计币种时给出“约 … / 月”；分类；需关注的原因；下次续费、续费方式、付款方式；备注。
- 点开即该项在「费用与续费」中的详情（`/#/plugins/expenses/items/{id}`，[ADR 0118](0118-costs-and-renewals-page.md)）。
- 顶部统计：使用中、每月费用（按周期平摊并折算到统计币种，设了月预算时超出会提示）、30 天内续费、需关注。工具栏是搜索与状态筛选（全部 / 使用中 / 需关注 / 已停用），「筛选与视图」里是分类、排序（先续费的在前 / 每月费用高的在前 / 按名称）与卡片 / 表格；排序和视图记在浏览器里。
- 需关注：已过续费日（手动续费等确认，自动续费等后台顺延），或 7 天内续费；停用的、已安排在下次续费前取消的不算。

### 数据

- 读「费用与续费」已有的 `/subscriptions`、`/labels` 与 `/summary`（费用读权限），不读任何代理用户数据。`/summary` 给出账本自己的日期（账本时区）、统计币种与汇率；状态文字、每月费用与排序用 `plugins/expenses/model.ts` 的同一套计算，和「费用与续费」页面一致。
- 第一版为代理用户部分新增的只读接口 `GET /api/plugins/sing-box/subscription-board` 已删除。

### 拉取记录统一（保留）

专属地址把迁移用户的拉取转发给原系统渲染器时，也记一条 `subscription_fetch`（格式 `renderer`，结果 `relayed` 或 `unavailable`，节点数未知记为空），和面板自己生成订阅时走同一个记录函数、遵守同一组隐私设置与保存期限，记录失败只写日志。它不再服务于看板，保留是为了让每个用户在「诊断与安全」里的拉取记录完整，不因所走的地址不同而缺一部分。

### 共用件

- 服务器看板顶部的统计条和卡片的悬停样式在 `display/ui.tsx`（`StatStrip`、`Stat`、`cardLink`），两块看板共用；圆环是共用的 `ProgressRing`。
- 手机宽度下分页标签收窄内边距，概览的四个分页在 320 宽度也能完整显示。

## 后果

- 不新增迁移，不改表；看板没有自己的后端接口。
- 代理用户页的 `/#/plugins/sing-box/users/{id}`（直接打开某个用户）在第一版中加入，保留。
- “每月费用”是按周期平摊的估算，与「费用与续费」页首的每月费用口径相同。
