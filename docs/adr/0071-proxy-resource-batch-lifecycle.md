# ADR 0071：统一代理资源与原子链路创建

> 主线整合编号 0071；作者原独立分支编号 0054。旧主线同号决策及链接保留，历史验收仅认证原冻结输入。

日期：2026-10-02。状态：实现与本地集中验收完成；实际双机传输与生产部署待验，结果见 [验收记录](../acceptance/proxy-resources.md)。

## 问题

代理节点页按物理监听和两跳关系分别读取，链路入口在普通节点列表中重复出现；创建一条链路要先保存入口，再单独保存关系。批量创建缺少事务和提交收据，失败或网络重试可能留下入口。旧节点删除没有链路及策略引用保护，问题已记录为 [Issue #147](https://github.com/theLucius7/apsp/issues/147)。

本步落实 [代理节点设计](../node-chain-design.md) 的资源管理与原子创建阶段，仍承接既有受管 Reality 两跳编译和发布。订阅来源、有序混合路径及候选路径验证继续按 ADR 0040 后续实施，不把旧两跳包装成已实现的混合路径。

## 统一资源

新增插件内 `proxy-resources` 公开投影，用 `kind` 和 ID 一起标识资源；直连 ID 是旧节点 ID，链路 ID 是旧链路 ID，允许数值相同。链路专用入口不再作为直连资源列出；共享出口保留直连投影并说明引用。链路名称和旧订阅入口名称分别保留，不隐式改写客户端名称。

列表与详情从同一只读数据库快照读取端点、引用和人数。公开字段不含用户身份、机场内容、私钥、内部 relay UUID 或完整配置。实际协议配置须能解析且与协议标记一致；损坏的协议或公开端口设置只使对应资源不可用，不中断整个列表读取。结构可用、服务器在线和已应用 revision 分别展示；结构完整或 revision 相同不能推导端到端网络健康。损坏或退役端点的链路保留在投影中，允许明确清理。

## 原子批量创建

`POST /chains/batch` 一次提交至多 32 行；每行创建一个专用 Reality 入口，或明确使用一个尚未授权且不被引用的旧入口，并选择另一服务器上的受管 Reality 出口。本步 `hops` 必须只有一个 `managed` 项；订阅项或多段明确拒绝，不截断路径或静默直连。

事务按既有拓扑 advisory lock 和服务器 ID 顺序取得锁。逐行复用节点的协议、地址、SNI、端口及配置校验，插件须已启用且服务器未退役；同一事务内先前创建的端口同样算占用。整批任一项失败，入口、关系、dirty 标记和请求收据全部回滚。创建本身不授予权限，也不把配置保存显示为设备已应用。

幂等键绑定规范化的完整请求，行顺序保留。相同键和相同内容返回原创建收据；不同内容返回 409。创建收据仅保存请求摘要和结果 ID，不保存新生成密钥；删除资源不会删除收据，旧请求重放返回原 ID，不复活资源。前端一次 POST，网络结果不确定时保留键与原请求；用户修改草稿后生成新键，不自动重试另一批。

## 删除与兼容

新资源删除链路时，删除关系并软删专用入口，移除入口授权并安排受影响服务器发布；共享出口、用户与历史计量保持。存在策略组引用时返回 409 和公开引用清单，管理员先明确解除引用。旧 `/chains/{id}` 删除继续表示解除关系，保留原入口；界面使用完整资源删除，不混淆两种操作。

旧、新普通节点删除共同检查策略和链路引用，不能通过旧 API 绕过保护。被引用的出口不能直接删除；停用或服务器退役仍按已有资格与发布逻辑撤销入口，不能回退直连。退役或软删端点的链路资源可清理，不能因服务器不再活跃而永久堵住清理。

不改名数据库旧表，不修改用户 ID、订阅令牌、旧 URL、凭据、授权并集、流量账本或 epoch；增加独立创建收据表。前后端与迁移同版切换，不混用发布进程。core、公共 Agent 协议及诊断制品本步不变。

## 验收边界

先完成后端、页面、回归代码和文档，再冻结一次集中验收。真实隔离 PostgreSQL 验证并发端口、事务回滚、幂等、删除后重放、引用保护、损坏资源清理、公开投影与旧订阅关系；实际 dist 浏览器验证分类、批量预览、一次提交、失败保留草稿、旧书签和读取失败保护。

这些证据不替代真实受管双机传输、混合路径、不旁路探测或持续代理与诊断联合负载。本步不部署生产迁移，不恢复暂停 CI，不签署或发布新诊断能力；整体目标的真实 builder、完整验机许可和专用节点故障矩阵保持待完成。
