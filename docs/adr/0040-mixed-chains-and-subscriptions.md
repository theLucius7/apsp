# ADR 0040：有序混合链路与机场订阅来源

状态：源码实现，本地隔离验证；真实设备签收和生产迁移未完成。日期：2026-10-01。

用户已进一步明确授权实现机场订阅与混合链路，参考成熟项目，和运行时运维、命令生命周期一起推进。新增 YAML 解析依赖固定为 `saphyr-parser = 0.1.0`，禁用默认特性，仅由面板插件导入边界使用；必要性与替代方案见下文。源码完成、隔离验证、实机签收及正式发布仍分别记录。

## 授权和范围

用户已确认代理节点页统一创建、管理直连与链路，进一步明确链路中间段可以来自机场等订阅配置。本决策覆盖 ADR 0035 仅两台受管服务器及历史 MVP 外部出口/链式代理的对应排除项，将路径扩展为“受管公开入口 + 有序代理跳”，每个内部或最终跳可为受管节点或订阅具体节点。保留单运行时实例、独立入口、固定顺序、授权并集和入口单次计量，不增加自动出口池或有环拓扑。

产品结构与协议组合见 混合链路设计，来源获取、解析和更新见 订阅来源设计。外部节点是插件业务资源，不是 core 管理的服务器；无需给机场安装 Agent，不改变 core 的服务器管理边界。

## 模型和迁移

保留 `singbox_chains.id`、独立 `entry_node_id` 和策略 `chain_ids`。增加以下插件模型，来源与路径迁移分别为 0025、0026，通用运行时验证为 0027：

| 表/模型 | 必须保存的内容 |
| --- | --- |
| 订阅来源及修订 | 受保护源设置、设置 revision/身份 epoch、不可变成功批次、解析版本、公开状态 |
| 外部节点及版本 | 来源内稳定身份、不可变规范化连接参数及能力 |
| 受管端点版本 | 不可变服务器/节点身份、host、port、SNI、公钥/short ID、协议/传输及运行时能力 |
| `singbox_chain_versions` | 链路 ID、代数、完整语义摘要、候选/已应用/恢复状态 |
| `singbox_chain_hops` | 链路代数、位置、受管端点版本或外部节点版本引用；受管段自己的 relay 身份 |
| 部署路径依赖 | 受管服务器的已签名配置 revision 包含哪些链路代数及内部身份 |
| 创建请求收据 | 规范化批量请求摘要及创建 ID，删除资源不级联清除 |

跳位置唯一且有界；受管端点版本引用与外部版本引用互斥，旧代恢复不能重读可变 node 参数。路径头部软删除保留历史版本，内部凭据与公开投影分开。旧 `exit_node_id`/`relay_uuid` 仅用于旧两跳兼容投影；迁移将原 NOT NULL 放宽并增加路径类型检查，legacy 必须有合法旧出口/relay，新有序路径使用跳记录，不伪造出口服务器 ID。旧链路迁为单个受管 hop，首次接管版本标为 legacy，保持原 ID/UUID/tag、订阅和编译字节；之后新代才使用新 tag/relay 规则，历史部署 source 和用户账本不改写。

策略、资格视图、节点删除保护、publisher 和订阅同时改为识别完整路径。旧两跳 API 可以兼容旧请求，不能默默把新路径降格为一段；新版资源 API 才覆盖所有路径。升级必须使用单个认识版本化路径的 publisher，禁止新旧进程混跑。

## 编译、依赖与版本应用

入口编译全部嵌套出站，后一个出站的 detour 指向前一个，入口路由指向最终出站；受管内部段接收逐链路、逐位置、逐代的内部身份且不计终端用户流量。原始来源的 tag、detour、路由、DNS 和控制接口不能进入编译输入。

编译器拥有路径与 DNS 依赖图、下层传输兼容性以及确定性内部 tag。原生 `check` 是其中一步，不保证图、缺失依赖或端到端承载；固定 1.14.2 的源码和九项配置观察已确认这个范围，不能声称真实混合路径验收通过。

每次发布绑定不可变路径版本、受管端点版本及来源节点版本，不能只记录“最新订阅”。完整版本向量在候选创建时冻结，允许不同来源批次及显式固定版本，发布各阶段不重读 latest。每链路最多一个正在应用的候选；受管依赖先接受候选身份并保留恢复身份，确认就绪后从入口的受认证回环路径探测候选，成功才切用户路由，并再次探测切换后的路径。初建同样先探测再开放；原 ADR 0020 的临时数据入口方案由 [ADR 0045](0045-mixed-path-execution.md) 的本机管理接口探测替代，不增加可转发数据的临时入口；请求期限、指定目标、实际配置绑定与持久恢复确认保持。这些是新路径的实施必需能力，缺少能力的 Agent 拒绝启用或切代，保留已有配置；旧两跳初次接管保留原资格规则，不能补造成功记录。

入口须持久确认最低可恢复代数，当前已应用配置和未完成 intent 均不再使用旧代，才撤旧身份；不能仅按时间窗或 revision 大小清理，超时不撤旧。迟到刷新及 ApplyResult 不推进新代。订阅从已经应用且当前仍有资格的入口投影生成，依赖及探测证明匹配实际已应用配置包含的代数、revision/hash 与请求 ID，不能只检查两个服务器。成功探测只证明指定时刻和目标，不保证第三方持续健康。

共享受管端点编辑生成新端点版本及所有依赖链路候选；旧/新端点须兼容或并存，按内部依赖就绪、入口切换和恢复屏障清理。如果无法同时支持可恢复旧参数，拒绝在线编辑并采用替代节点/链路，不能先改变可变 node 后期望旧代回滚。

同节点的有效新版本可按 `follow_node` 进入候选，`pinned` 保持快照。更新失败、来源缺失或身份歧义不构成管理员撤销，也不触发换节点/直连；保留已应用版本并显示事实。明确撤销授权、删除链路或受管资源退役则同时撤销资格和运行配置。尚未固定恢复边界时，候选失败可保留/恢复原已应用代数；固定边界后保持边界以上版本并报告故障，不自动回到已撤旧代。恢复不能原地改写原部署和计量证据。

来源 URL/获取认证更换建立新身份 epoch，任务及条件请求缓存绑定设置 revision/epoch；不能让新来源复用的 ID 自动覆盖旧链路。归档通过 PATCH 保留已有版本和引用，DELETE 受完整路径依赖保护，历史证据不级联删除。具体身份与更新动作见订阅来源设计。

## 解析依赖的必要性和替代方案

现有 `serde_json`、`base64`、`reqwest` 和 SHA-256 足以支持 JSON、链接和受限下载。Clash/Mihomo YAML 是本次机场订阅格式范围，仓库此前没有 YAML 解析依赖，因此仅在插件导入边界增加事件式 `saphyr-parser`，不把它放进 Agent/core/compiler。该解析器提供低层事件 API，来源见现维护的 [官方 monorepo](https://github.com/saphyr-rs/saphyr/tree/master/parser) 与 [解析器文档](https://docs.rs/saphyr-parser/latest/saphyr_parser/)。版本与传递依赖已核对并固定在 Cargo.lock，保留上游许可证，关闭调试输出。

自写 YAML 子集无法可靠覆盖机场常见引号、映射和别名；仅支持 JSON/URI 会遗漏用户要求的常见订阅配置；外部转换服务会传出订阅秘密；执行系统 Python、yq 或 shell 引入宿主工具及不必要执行边界。因此选择本地 Rust 事件解析，在建对象前控制深度、别名展开、节点数量与总字节。`yaml-rust2` 也可提供纯 Rust 解析，但上游说明仅基础维护，故优先现维护的 parser；若选用版本无法在恶意输入预算内工作，应补充此 ADR 并重新选择，不能放宽预算后宣布通过。[yaml-rust2 官方说明](https://github.com/Ethiraric/yaml-rust2)

本轮已固定新增上述 YAML 解析依赖，没有增加加密库。源 URL、节点秘密和签名运行配置按既有数据库/备份/目录保护存储，不能虚称已有应用层加密；如之后增加加密，需另行定义密钥保存、轮换、恢复和历史快照处理。

## 验收和交付状态

实现的必须项包括：订阅节点真正位于中间、多条独立监听、线性顺序和承载校验、来源格式与下载限制、稳定节点身份、两种更新方式、路径代数的应用/恢复、全路径引用保护、秘密不外泄、原数据及账本兼容。专用代理夹具还须证明指定最终出口、实际经过每跳、外部中间段停止后不旁路，以及 TCP/UDP 和入口单次计量。

当前源码与本地隔离验证已完成，实施范围与操作见 [Agent 运维与混合链路](../agent-runtime-and-chains.md)，实际路径和原生探测证据见[混合链路本地夹具记录](../acceptance/mixed-path-local-fixtures.md)。三/四段回环夹具不等同于真实机场、签名 Agent 分布发布或生产流量计量验收；对应证据分别记录。CI 按用户安排继续暂停；正式签署、发布、生产迁移和部署仍按现有独立流程执行。
