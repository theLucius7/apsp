# ADR 0140：领域整合与当前资料收口

状态：已接受（2026-11-17）。延续 ADR 0128、0131、0133 至 0139。

用户要求：“不要分批，一次性完成，加快完成速度，完成 apsp 的目标，不再 plugin 整合好，删掉历史冗余的东西”。本次作为一个整合变更交付，集中完成后统一验证。

## 决策

1. 面板是按领域维护的一个系统。资源、网络、流量服务、服务权益、名称、成本、治理、观测、作业各自拥有模型和规则；不恢复插件注册层或业务插件开关。Agent 的适配器是固定的运行时与诊断实现。
2. 代码里的组件描述使用 `artifact_name`，诊断实现使用 `tool`；控制台的诊断清单为 `tools`（独立制品页 `/settings/artifacts` 与手工启用状态随后由 [ADR 0141](0141-self-contained-agent-and-desired-service-config.md) 收敛为一体化自带能力 Agent 与服务配置驱动状态 `configured`/`status`）。改名同时更新调用、测试与接口说明，不保留旧 Rust 名称的包装接口。控制台旧插件地址的过渡期结束后删除，当前使用 `/nodes?view=runtimes` 与 `/servers/{id}/services`；代理用户的订阅、门户与邀请地址不随此清理失效。
3. 已签名制品、已发布 Agent 的 wire 字段、已持久化检查点和现有设备路径继续按原契约读取。必要的旧字段只在序列化边界通过精确 `serde(rename)` 出现，不成为内部对象模型；Shadowsocks SIP003 的 `plugin` 是外部协议字段。改写签名内容或直接改设备目录不能作为去除插件架构的办法。
4. 运行时附件能力按当前选中的已验签制品判断，不因同一 Release 中其他平台的附件拒绝该设备。现有服务健康、配置准备失败和运行时升级状态分别表达。
5. Nexus 的成员转入原生订阅时必须保留原 UUID、已发地址和当前周期用量，采用操作先预览再原子提交。桥是否仍服务某位成员由采用状态决定；历史身份本身不再等同于当前控制权。生产入口与成员切换有独立的读回证据，不能以源码合入代替切换完成。
6. 当前导航只保留现行架构、功能、操作说明和仍有效的验收条件。已完成的任务书、逐小时日志与被取代的执行计划从工作树删除，引用转到删除前的 Git 提交；`PROGRESS.md` 只记录近期结果和当前阻塞，`open-questions.md` 只保留仍需决定的事项。Git 历史及决策依据保留，不重写仓库历史。

## 验证与交付

所有实现完成后统一运行 Rust 格式、clippy、测试、领域边界与路由权限检查，以及前端构建和受影响的浏览器夹具。基线变更附接入脚本并走同一个 PR；只在隔离副本演练，不把未执行的生产迁移、实机验收或暂停中的 CI 记为完成。

清理只删除已经被替代的源码或资料。生产账本、凭据、仍提供旧地址服务的兼容入口和签名制品不会因名称包含历史词语就被删除；它们在替代生效并核对后退出。
