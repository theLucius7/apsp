# ADR 0115：原权限组并入策略组

## 背景

[ADR 0112](0112-group-only-access.md) 之后，自建节点只通过策略组授权，迁移用户却仍走另一套：用户的套餐通过 `singbox_nexus_plan_mappings` 对应一个原权限组，已接管的迁移线路按 `singbox_nexus_runtime_nodes.legacy_group_ids` 判断谁能用（[ADR 0095](0095-nexus-runtime-takeover.md)）。生产上 0086 没有任何单独授权可转，「策略组」页是空的，而 43 位迁移用户的线路全部来自三个原权限组（00、11、hk5）。

用户要求：把已有数据的套餐组对应的权限，在策略组里做好。这就是路线图 1.3 与决策 D14。

难点是订阅不能变：策略组会给成员在每个节点上生成新的 UUID 和密钥（写入 `accesses`），而迁移线路必须继续接受用户原来的 UUID；迁移用户的订阅仍由原面板生成，它按 `v2_user.group_id` 这一个原权限组列线路。

## 决策

- **每个原权限组一个策略组。** `singbox_policy_groups` 增加 `legacy_group_id`（唯一），函数 `singbox_legacy_policy_group(原组号)` 取得或新建对应策略组，名称取原面板上的组名：「原权限组 · 00」，没有名称时为「原权限组 #3」。迁移 0088 为套餐映射和迁移线路用到的每个原组建组。
- **迁移线路放进策略组，但不生成新身份。** 每条已接管线路加入它原来所属各组对应的策略组。`singbox_desired_accesses` 排除迁移线路，所以策略组不会为它们写 `accesses`；运行时发布、成员摘要和设备数预算改为“用户在某个包含该线路的策略组里且权益可用”，下发的仍是 `singbox_nexus_identities.legacy_uuid`。任何策略组都可以放迁移线路，只对有原身份的迁移用户生效。
- **成员按迁移时的套餐映射分组。** 0088 把每位迁移用户放进其当前套餐所映射原组的策略组（套餐到期的用户也放进去，续期后线路照旧）。之后线路只看策略组：修改套餐只改流量与期限，不再改线路。
- **原面板只认一个组。** 兼容桥写给原面板的 `group_id` 改由 `singbox_member_legacy_group(用户)` 给出：用户所在、对应原组的策略组里，优先其套餐映射的那个组，否则取组号最小的，都不在则为空。套餐和计划号仍由映射给出，兼容桥检查不变。
- **编辑入口只有策略组。** 管理员在「策略与套餐 › 策略组」里增删迁移线路和成员。`PATCH /nexus-nodes/{id}/groups` 仍用于记录原面板改动的组，它同时把已接管线路移入或移出对应的原组策略组（只动 `legacy_group_id` 非空的组），不再要求原组先有套餐映射。接管新主机时线路自动加入其原组的策略组；放弃准备与线路下线时同步移出。
- **邀请默认组。** 邀请设置的默认套餐若映射了原组，对应策略组加入邀请默认策略组，受邀账号仍得到原来的线路。生产上默认套餐为空，此步不产生变化。
- **诊断与门户。** 用户诊断与成员门户的“可用”改由策略组判断：原面板列出的线路看用户的原组，已接管线路还要有策略组授权；诊断对“原面板会列出但 apsp 已不授权”的线路标出「策略组未授权」。订阅仍由原系统生成，所以诊断保留“订阅由原系统提供”这一说明，只是依据换成策略组。

## 生产数据核对

用 2026-11-05 16:51 UTC 的生产备份恢复到本地临时库，在迁移前后分别按旧代码与新代码的查询计算，以下结果逐字节相同：已接管线路的发布成员（597 条“线路、用户、UUID”）、17 台接管主机的成员摘要（部署后不会触发重新发布）、设备数预算成员（597 条）、成员门户 308 条线路可用性（259 条可用）、44 位迁移用户的诊断原组与线路数、兼容桥 44 条成员记录（计划、组、额度、封禁、状态、UUID、到期），以及 `accesses` 与 `singbox_desired_accesses`（均为空）。

## 取舍

- **把迁移线路当普通节点放进策略组：** 会生成新 UUID，订阅全部失效。未采用。
- **策略组成员由套餐动态推导：** 不改变现有行为，但策略组成了只读视图，权限仍是两套。未采用；以迁移时的映射一次性落成成员。
- **原面板也按多个组渲染：** 原面板每个用户只有一个组号，做不到；等路线图 1.4 由 apsp 生成订阅后，用户才能完整使用多个组。在此之前，把迁移线路放进非原组的策略组，apsp 会接受连接，但原面板生成的订阅不会列出它。
- **为未接管主机上的线路建虚拟节点：** 这些线路没有 `nodes` 记录，伪造会污染节点表。只在策略组上显示“另有 N 条线路由原面板按此组提供”。
