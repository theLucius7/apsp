# ADR 0128：按领域组织的一体化系统，不再有插件

状态：已接受（2026-11-08）。分阶段实施，阶段与完成标准见[功能划分与逻辑结构 §9](../architecture.md#9-迁移阶段)。

2026-11-08 用户要求：APSP 重新设计成一个统一维护、按领域组织的一体化系统，功能分类从“管理什么对象、维护什么规则、对什么结果负责”出发；“不再用 plugin 的方式维护，全部自己维护，按照技术本质原理，重构代码，重写逻辑”。

## 决策

1. **一级分类是九个领域。** 七个对象与规则领域：资源与设备 `resources`、基础网络 `networking`、流量服务 `traffic`、服务权益与交付 `access`、名称与证书 `naming`、成本与费用 `costs`、平台治理 `governance`；两个运行支撑领域：观测证据与事件 `observability`、变更与作业 `operations`。“支撑”只描述职责，不代表优先级低。
2. **分类依据是对象身份、状态变化与不变量。** 一个功能归属于维护它所改变的对象及其规则的领域；技术职责、运行位置、交互入口与维护状态是附加属性，不决定归属。关联对象多不等于应当合并，要看是否共享规则、生命周期与变更责任。
3. **不再有插件。** 所有能力都是 APSP 自己维护的领域能力。供应商与运行时的实现（阿里云、Cloudflare 等云接口，sing-box，IPQuality 与 NodeQuality 等诊断工具）是所属领域后面的内部实现，编译时显式组合；不再有业务插件 crate、插件登记钩子，也不再有“插件之间不能互相依赖”的规则。
4. **领域经公开接口协作，依赖无环。** 领域之间允许依赖对方公开的类型与函数；禁止直接写其他领域的表、引用其他领域的内部实现、绕过对方规则修改状态、形成循环依赖。读取其他领域的数据经对方的公开接口，或经明确登记为公开只读的表。跨领域流程放在应用层编排；需要异步、持久化或跨机器时才使用任务与事件，不设通用的注册表或事件总线。
5. **技术机制归平台。** 数据库连接与事务、持久化任务的执行基础设施、Agent 通道与消息、加密与受控凭据访问、制品存储、通知发送通道、HTTP 外壳与通用界面组件属于平台 `platform`，不含任何业务决定。
6. **一个事实只有一个权威所有者。** 汇总视图与缓存可以存在，但要记录来源，修改一律经所有者。观测领域拥有“证据”，作业领域拥有“执行记录”，二者不因观察或操作了某个对象就取得它的业务所有权。
7. **期望、执行、已应用与观测分别保存。** 每类受管对象明确这四种信息，状态用语沿用 [ADR 0126](0126-workspaces-language-and-addresses.md) 第 4 条与[状态设计](../redesign/06-states.md)。
8. **维护级别是元数据。** 取消 `lab` 模块；实验与冻结功能回到所属领域，成熟度单独标记。
9. **迁移顺序**：先统一概念与写入权，再统一状态与跨领域接口，随后迁移实现，最后整理目录与菜单。每一步行为不变、可以单独上线；改到数据库基线的步骤附带接入脚本并走 PR。

## 取代

- [ADR 0085](0085-rearchitecture-plugins-sources-chains.md) 的宿主、插件、组装三层：改为平台、领域、应用三层。宿主与 Agent core 不认识代理业务词汇的检查继续有效，适用于平台。
- [ADR 0125](0125-feature-modules.md) 的功能模块清单（`proxy`、`dns`、`cloud`、`costs`、`alerts`、`lines`、`overview`、`lab`）、“内核只保留三块机制并提供登记口”与“用一组小接口代替 `PanelPlugins`”的组合方式。继续有效：每张表一个所有者、边界检查只许变好、上游代码归所属领域的 `upstream/`、模块化单体。
- [ADR 0126](0126-workspaces-language-and-addresses.md) 第 6 条中的“ADR 0125 的功能模块”：改为“一个领域”。工作区（界面分组）与领域（代码与数据）分开组织的原则不变。

## 后果

- 协作规则中按插件写的分层条款改为领域规则；[功能划分与逻辑结构](../architecture.md)按九个领域重写，逐项功能的归属见[领域归属表](../domain-map.md)。
- 边界检查按九个领域重新登记每张表与每个代码路径的所有者，现有越界重新计入只许减少的清单。
- 设备上的路径（如 `/opt/apsp/plugins/sing-box`）、接口前缀 `/api/plugins/...` 与数据库表名是外部契约或基线的一部分，不因本决策改名；改它们分别按地址与接口契约、数据库基线变更单独处理。
- 功能分级中的“可选插件”改称“可选”，含义不变（[ADR 0087](0087-narrow-positioning-proxy-network.md) 第 2 条）。
- 第一阶段把 DDNS、费用与云接口三个插件 crate 改为领域 crate；sing-box 拆为流量服务与服务权益、阿里云按资源与费用等领域拆分、宿主中的领域代码迁出，按后续阶段进行。
