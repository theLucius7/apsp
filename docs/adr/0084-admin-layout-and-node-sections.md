# ADR 0084：管理界面重排、节点页分区与离线时间

- 状态：已实现；本地构建、单元测试与浏览器回归验证，未在真实设备或生产面板上验收。导航分组已由 [ADR 0086](0086-product-map-and-navigation.md) 取代。
- 日期：2026-10-03。

2026-10-04 主线整合时，本决策由分支原 ADR 0078 顺延为 ADR 0084，联络时间迁移由原 `0050` 顺延为 `0060`。主线运维、网络和管理入口共同保留；原分支的构建及浏览器数字对应其历史输入，整合后结果见[本次整合记录](../acceptance/branch-main-integration-20261004.md)。

## 背景

用户要求重新排版界面，并在重排时处理全仓缺陷扫描中的 D12–D17（[记录](../acceptance/defect-scan-20261003.md)）。现状如下：

- 15 个管理入口按插件名称分组；手机宽度下，导航在每页顶部铺开四到五行，内容要往下滚动才能看到。
- 代理节点页把节点库、有序链路、两套订阅来源和导入预览纵向堆叠，桌面高度约 4500 像素。各区块分别轮询，删除链路后会短暂出现新旧数据并存（D13）。
- 后台刷新期间，按钮在 250 毫秒的防闪动延迟内看起来仍可用，但点击被直接丢弃（D12）。表单在刷新期间整体禁用，连续操作会丢失点击或输入。
- 管理页面全部打包进主文件，主包约 730 KB（D15）。
- 设备正常断开时 `last_seen` 被提前 61 秒，离线告警因此比阈值早约 61 秒触发（D14）。

## 决定

1. **导航按任务分组。** 分为五组：概览（统计仪表盘、服务器看板）、服务器（服务器、延迟检测）、代理服务（代理服务、代理节点、代理用户、策略与套餐）、扩展插件（动态域名解析、阿里云 CDT、服务器插件、插件目录）、系统（看板与通知、告警通知、系统管理员）。入口名称、路径和“主导航”地标保持不变。
   - 顶栏面包屑显示“分组 / 页面”。
   - 宽度不超过 800 像素时，导航收进“菜单”按钮：点击链接、按 Esc 或点击外部区域后关闭；退出登录按钮始终可见。
   - 外框样式从压缩的 `styles.css` 拆到可读的 `app/shell.css`。
2. **对话框挂到文档根节点。** `Modal` 通过 portal 渲染到 `document.body`，标题使用唯一 ID。这样，未激活的分区或其他隐藏区域不会把它打开的对话框一起隐藏。原外框上防闪动的过渡规则同时作用于对话框。
3. **代理节点页分区。** 同一页面分为“节点库”“链路”“订阅来源”三个分区，由路由参数 `view=catalog|chains|sources` 选择。
   - 不带 `view` 时，旧的 `kind=chains` 及 `/plugins/sing-box/chains` 打开链路分区，其他地址打开节点库，原有链接全部可用。
   - 分区链接保留当前服务器筛选。未激活的分区保持挂载，链路草稿和待确认操作在切换分区后仍保留。
   - 节点库继续并列显示直连节点和链路，符合“统一代理节点页面”的既定要求。链路分区承担链路专属操作：两跳和有序链路创建、路径与引用、版本、替代链路。原来重复的“全部 / 直连节点 / 链路”切换链接删除，类型筛选由节点库负责。
   - 两套订阅来源（外部节点来源、有序链路来源）放在同一分区，各自的数据模型和接口不变。
4. **节点页数据同轮发布（D13）。** 新增 `useResourceGroup`：节点、资源、有序资源、服务器、用量和节点库六个读取，每轮一起请求；有变化的数据等整轮返回后一起发布。节点库改为使用页面的这份快照。写保护的语义与 `useResource` 相同：
   - 每轮读取（包括后台轮询）开始时，全部成员立即失效。
   - 某个成员的响应与界面上已显示的数据相同时，它立即恢复为当前，不必等待其他成员。因此一个读取挂起时，只依赖其他资源的操作照常可用。
   - 单个成员失败只影响它自己。
5. **刷新期间的点击（D12）。** 按 [ADR 0075](0075-node-options-and-background-refresh.md)，提交和打开写入对话框只使用已确认的快照，现有验收也要求读取未完成时不打开对话框、事后也不自动打开，因此不排队延后执行。在按钮还没显示为禁用的短暂窗口内点击时，显示约 3 秒的“操作未执行，请稍候再试”状态提示，不再静默忽略。表单遇到暂时刷新时只拦住提交，草稿仍可编辑；遇到持续失败时仍整体锁定。
6. **按页面拆分代码（D15）。** 各管理页面改为按需加载。加载完成后通过普通状态更新渲染页面，不经过 `Suspense`。这样页面显示不依赖计时器，在测试使用暂停的假时钟时也能正常显示；已加载过的页面再次进入时直接渲染。页面样式仍按原层叠顺序静态引入主样式文件，避免拆分 JavaScript 后改变样式覆盖结果。
7. **离线告警使用真实联络时间（D14）。** 主线迁移 `0060` 为 `servers` 增加 `last_contact_at`（原分支编号 `0050`）。
   - 设备建立会话和收到消息时，`last_seen` 与 `last_contact_at` 同时更新；正常断开时 `last_seen` 仍提前 61 秒，让设备立即显示离线，`last_contact_at` 记录真实断开时间。
   - 离线告警的阈值和告警事件中的“最后在线”改用 `last_contact_at`；该列为空时回退到 `last_seen`。在线判断和其他依赖 `last_seen` 的查询不变，接口输出不新增字段。
8. **代理用户页。** 超长的单行 JSX 拆成结构化片段，行为不变。通行密钥和外部节点授权两个区块仍放在列表布局之外：用户列表清空或读取失败时，它们必须保持挂载，草稿才能保留。

## 暂不处理

- **D16：** 只拆了本轮改动文件中的超长行，没有统一格式化全部前端和 SQL。引入格式化工具属于新增依赖，并会与其他进行中的分支大面积冲突，待用户决定后另行处理。
- **D17：** 订阅来源两套实现、链路三种模型、插件以 `#[path]` 编入面板，涉及数据模型和接口的合并，留到下一步“重新架构”单独设计。本轮只在界面上把它们归到同一分区。
- 服务器详情中显示的最后在线时间仍来自 `last_seen`，正常断开后显示的时间早约 61 秒，没有改动。

## 替代方案

- **节点页只加锚点导航：** 改动最小，但页面仍过长，各区块也仍然各自刷新。
- **刷新期间点击排队、完成后自动执行：** 违反现有写保护验收，也会让对话框在用户没有预期时自行弹出。
- **关闭后台刷新期间的写保护：** 违反 ADR 0075。
- **不改 `last_seen`，改为单独记录断开时间：** 在线判断需要同时比较两列，涉及的查询更多。
