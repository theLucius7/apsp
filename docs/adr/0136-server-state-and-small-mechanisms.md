# ADR 0136：每种底层机制只有一套实现（第四部分：服务器状态与几类小机制）

状态：已接受（2026-11-13）。延续 [ADR 0133](0133-one-implementation-per-mechanism.md)、[ADR 0134](0134-outbound-network-and-delivery.md)、[ADR 0135](0135-health-retention-vendor-clients.md)；处理 [architecture.md §12](../architecture.md#12-扫描结论与余下工作2026-11-13) 中“服务器此刻是否可用”与几类小机制。

2026-11-13 用户：“目前是底层原理深度统一”，之后说“continue”。

## 背景

1. **服务器状态。** 服务器的生命周期、退役与资产属于资源领域，维护窗口属于作业，其他领域却各自用 SQL 推断：“服务器此刻能不能接新任务”有十几份写法，“是否正在退役”另有 11 处，服务器行锁有 41 条各写各的语句（外加 3 个辅助函数），资产设置的 JSON 键在 10 处直接读取。
2. **小机制。** 审计记录的写入语句 16 处、口令散列 3 份、短文本检查 57 处、金额与币种检查 9 处、日期计算 3 份、随机值 11 处、Cookie 的读写 3 份、面板设置的直接读取 9 处、保留策略的直接读取 3 处、外部来源的到期引用 2 份。

## 决策

1. **服务器状态由所有者各答一次。** 资源给出“正在退役”“生命周期挡住新任务”“处于服务器自己的维护期”的 SQL 判断、服务器行锁（`lock`、`lock_row`、`lock_all`，四种锁强度，多台时按编号升序加锁）与资产设置的读取（逐键给出类型化的默认值）；作业拥有维护窗口，在资源的判断之上组合出“关闭”与“拒绝新任务”（`DeviceWork` 的回答）。行锁的顺序不变；`SKIP LOCKED` 的认领与几个派生集合的加锁作为有理由的例外列明。守卫：服务器行锁、生命周期判断、资产设置的键与维护窗口的匹配只能出现在各自的所有者里。
2. **小机制各合为一处。** 审计写入由治理的 `control_center::audit` 负责；口令散列（Argon2id，参数不变，已保存的散列照常校验）、短文本、金额与币种、日期、随机值、Cookie、面板设置的读取与锁定都在平台（`passwords`、`text`、`money`、`time`、`tokens`、`cookies`、`settings`）；服务权益与观测改经治理的保留期接口读写策略；外部来源的到期引用只留流量服务那一份，成本直接使用。各处的上限、提示文字、字母表与长度都不变。守卫：审计插入、Argon2、Cookie、日期、随机值、设置读取与控制字符检查只出现在各自的那一处。
3. **没有合并的。** 五张单行设置表的版本更新写法各不相同（版本列名、语句形式、冲突提示），合成一个需要拼接 SQL，暂不做；IP 质量的两份字段规范化接受的输入不同；成本的金额解析（符号、千分位、12 位）与账本单位是另一种格式。服务器状态里有三处语义差别要先由产品定下一种含义（见 architecture.md §12.2）。

## 后果

- 越界清单 360 → 332；新增的守卫与前三部分一样随 `cargo test` 运行。
- 修正了一处并发缺陷：创建链路时原来在加锁的同一条语句里检查退役，等锁期间提交的退役会被漏掉；现在先加锁再读退役状态，与其他各处一致。
- 只在异常数据或日志里可见的差别：成本账本的“自动续费”改为按文本比较（对资源写入的 JSON 布尔值结果相同）；随机值改用操作系统的随机源；管理员会话的 Cookie 属性顺序与其他 Cookie 一致；控制台读取会话时检查全部 Cookie 头并拒绝重复（登录与退出本来如此）；设置读取失败的日志由“数据库错误”改为“内部错误”（返回的状态与文字不变）；云资源通知在缺少设置行时报错（基线总会插入这一行）。
