# ADR 0070：IPQuality 最小闭包证明贯穿工厂与制品

> 主线整合编号 0070；作者原独立分支编号 0053。旧主线同号决策及链接保留，历史验收仅认证原冻结输入。

日期：2026-10-02。状态：整步实现与集中验收完成，230 项有效合同通过，实际离线派生成功；实际工厂、builder 和发布验收仍待执行。详情见 [验收记录](../acceptance/ipquality-minimal-profile.md)。

## 问题

派生入口已经从认证 Debian 缓存选择独立 IPQuality 闭包，但原工厂只检查十一种直接包是否存在。完整 NodeQuality 的 237 包库存也可能通过这一条件；后续 prepare、build、export 和制品校验没有同一份最小闭包证明，不能声称成品独立且最小。问题已记录为 [Issue #146](https://github.com/theLucius7/apsp/issues/146)。

上一整步的实际派生在磁盘管理预留处拒绝，旧材料和失败证据保持。本步增加独立输出盘后取得一次真实离线派生成功；builder 审核与完整制品仍未完成，源码准备不能被当作已发布能力。

## 选择

IPQuality prepare 必须使用真实派生及候选绑定，重新验证父收据、缓存正文和固定 profile，再实际运行隔离的离线求解。所选二进制包和对应源必须精确等于材料库存；只包含必需包、通过工具集合检查或保存一个 `minimal=true` 字段均不足以证明。缺少证明或多出完整 NodeQuality 包时拒绝，不静默回退。

准备目录私有保存重新验证所需的父路径和文件身份。公开证明只绑定规范化 profile、实现、材料、求解选择和精确包／源库存摘要，不暴露本地父路径、UID、设备号、inode 或原始私有身份清单。公开摘要由实际记录计算，不能接受调用方声明代替。

prepare 收据、build 输入和输出、export 收据与元数据以及最终制品都绑定同一份证明。每个重放入口重新核对对应记录和实际库存，跨准备目录、跨 profile、过期身份和缺失记录均拒绝。原生 builder、签名、许可、实际 rootfs 构建及完整对应源审批仍各自独立。

共用 NodeQuality 工厂增加默认关闭的扩展点，只有 IPQuality 工厂安装最小 profile 逻辑。原 NodeQuality 路径、既有收据语义和完整验机门禁保持。扩展点仍使用现有资源守卫、绝对截止时间、普通单链接文件约束与自有输出清理；独立 profile 不应成为绕过工厂保护的入口。

## 独立输出空间

正向原生派生使用专用 Debian 12 虚拟机的独立输出盘，原根盘、完整包缓存及证据不删除或搬迁。盘创建前核算宿主最坏分配、至少 512 MiB 宿主管理空间及 256 MiB 根盘／日志余量。稀疏文件的逻辑大小不能当作已取得的物理容量，动作期间继续观察宿主与 guest 剩余空间。

仅本次独占创建、原先不存在的空盘可以在首启格式化。实际确认挂载设备、label 和 UUID 后关闭自动格式化并正常重启，重新核对同一 UUID；禁止对既有盘重格式化、强制停止虚拟机或删除旧材料。存储变更不改变父缓存的只读身份规则。新的输出空间只用于本步派生，不表示后续 rootfs 构建预算充足。

## 验收与剩余事项

本步所有实现、回归代码、操作控制器和文档先完成，冻结后再集中执行受影响合同、旧 NodeQuality 默认路径兼容以及专用节点的实际离线派生。修改期间不穿插测试、构建、导入检查或目标节点操作；最终失败只补验修复影响的范围并保留原日志。

最终八组合同有效去重 230 项通过。首轮一个新增夹具的模块替换范围错误修复后，仅补验受影响的 15 项，产品与其余受验输入保持。两个原容量算法的 600 MiB loop 原生场景提前具名排除，不计入本步通过。新输出盘正常重启两次且关闭自动格式化后 UUID 保持；实际离线派生选出 130 包／91 对应源版本，旧缓存只读且不变、无新增下载、OOM 为 0，所属进程／挂载／cgroup 清理确认。小内存单元的回收压力如实记录，不能推导 Agent／sing-box 联合运行已经验收。

实际派生记录最小库存、认证摘要、资源和清理情况。过程期间旧缓存不能被写入；OOM、管理空间跌破预留、未知观察或截止时间均停止。不以 hash 相等宣布 builder 获准，不假造缺少的 mmdebstrap／hook 证据，不使用无许可商业硬件工具，不签署、发布或部署新制品。本 ADR 不替代完整 NodeQuality 与持续代理流量的联合故障矩阵，也不宣布整体整改完成。
