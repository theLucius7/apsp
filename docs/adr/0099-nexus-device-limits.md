# ADR 0099：接管后的 Nexus 节点继续执行设备数限制

## 背景

Nexus（Xboard）给大多数成员设定设备数限制：当前 37 名主组成员中 34 名、第二组 4 名中 2 名的套餐限制为 3 台设备。旧节点把 sing-box 嵌入自身进程，在连接建立时按客户端 IP 判定：同一成员已在用的 IP（本机或其他节点）直接放行；未达上限的新 IP 放行；已满时把全部在用 IP 与新 IP 按字符串排序，排在前 N 个的放行，其余拒绝；已建立的连接不会被断开。各节点把在用 IP 报告给旧面板，旧面板以 300 秒有效期汇总并下发给所有节点，状态超过 60 秒未更新时只看本机。

apsp 以独立系统服务运行固定、已签名的上游 sing-box，不修改上游源码，原本没有对应能力。用户确认接管前先补齐设备数限制，不改变成员体验，并选择“仅内存的日志驱动”方案和“新旧节点共享同一份设备计数”。

## 决定

**判定规则与旧节点一致。** Agent core 的通用会话准入模块按面板下发的“预算组”（同一成员在该主机所有已接管节点上的统计名）执行上述规则，排序方式与旧节点相同；首次观察（Agent 启动或配置变更后）已存在的会话一律放行，不断开已建立连接。日志证据尚未到达的会话等待 5 秒后放行；证据随后到达时仍计入对应预算，但不追溯断开已建立连接。

**归属来自运行时日志，只保留地址和统计名。** 上游 sing-box 的控制接口不提供连接所属用户。启用会话控制的配置把日志级别设为 info，每个连接各有两行日志，共享同一日志编号：

- 一行记录客户端地址：`inbound connection from <地址>`；
- 一行记录统计名：`[<统计名>] inbound connection to <目标>`。

适配器只把日志行翻译为（日志编号、地址、统计名），目标地址不进入 Agent 状态、报告或面板。运行时服务单元使用 journald 命名空间 `apsp-runtime`，安装器写入 `/etc/systemd/journald@apsp-runtime.conf`：仅内存存储、最多 64 MB、保留 1 小时、不限速、不转发。Agent 用 `journalctl --namespace=apsp-runtime` 跟随读取；管理员读取运行时日志时同样读取该命名空间，但只显示警告及以上级别，不显示逐连接行。

**关闭超额会话。** 编译器为接管主机的配置开启仅监听回环 `127.0.0.1:18086` 的控制接口，并使用每台主机固定的 64 位十六进制密钥；Agent 列出会话、匹配客户端地址与端口，并关闭被拒绝的会话。与旧节点在建连时拒绝不同，这里在约 1 秒内关闭：被拒绝的设备可能短暂建立连接，但无法持续使用。

**设备计数跨新旧节点共享。** 设备计数在面板、兼容桥与旧面板之间这样流转：

- **Agent → 面板：** 每 10 秒（变化时最快 2 秒）报告已放行会话的地址。面板以接收时间记录，保留 300 秒，判定新鲜度按 60 秒。
- **面板 → Agent：** 每 10 秒向开启会话控制的在线主机下发策略，内容包括：
  - 每名有限制成员的统计名；
  - 限额；
  - 该成员在其他 apsp 主机与旧节点上的新鲜地址。

策略为完整替换；取消最后一个设备限制时仍下发空策略，清除 Agent 的旧限制。面板每轮维护都清理超过 300 秒的设备地址和旧面板地址证据，即使所有 Agent 已离线、没有后续上报也会清理；配置的设备数限制继续保留。
- **兼容桥 ↔ 旧面板：** 兼容桥每轮把旧面板 `v2_user.device_limit` 与旧节点上报的在用地址交给 `singbox_nexus_device_exchange`，并取回 apsp 已放行的地址。这些地址以被接管节点原有的旧节点编号写入旧面板的设备状态，旧节点像对待其他节点上报的设备一样计数。被接管节点的旧条目不会回读到 apsp，避免重复计数。旧节点软件停止后，旧面板不再收到该节点的心跳，成员页会显示离线，旧面板还会在 30 分钟后发出掉线通知。因此在 apsp 确认该主机在线、已应用版本健康时，兼容桥同时刷新该节点的最后检查与推送时间及在线人数；apsp 运行时不健康时停止刷新，离线状态和掉线通知照常出现。

**接管门禁。** 启动接管要求兼容桥在 120 秒内同步过设备数限制；主机有任何设定限制的成员时，还要求 Agent 声明 `runtime:session-admission-v1` 能力。该能力只在运行时服务单元确实写入 `apsp-runtime` 命名空间时声明（需要 systemd 245 及以上），OpenRC 等其他服务管理器不提供。主机 Agent 具备该能力时，编译器总是开启会话控制，候选摘要因此稳定。

## 取舍

后续支持边界：Agent 0.3.3 的 OpenRC 内存日志方案见 [ADR 0100](0100-openrc-volatile-session-logs.md)。只有安装完整新服务合同的 OpenRC 主机才声明同一能力；0.3.2 与旧模板仍遵循上述限制。生产接管需另有正式签名发布和真实客户端验收记录。

- 日志驱动依赖上游日志文本格式。固定的 sing-box 1.14.2 有单元测试覆盖解析，真实运行时测试核对实际输出；升级运行时版本必须重新验证。
- 超额连接在被关闭前可能存在约 1 秒。速度限制仍不执行；当前成员均未设定速度限制，接管前的 `compare-users` 继续报告。
- 逐连接日志虽然只在内存中保留，持有 root 权限的主机操作者仍能读取；这与旧节点在内存中处理相同信息的风险相当，并在部署文档中说明。
- 在用地址属于个人数据：面板只保存当前放行会话的地址并在 300 秒后清除，不记录历史、目标或连接时长。
