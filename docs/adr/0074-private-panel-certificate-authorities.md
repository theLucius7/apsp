# ADR 0074：Agent 的可选私有面板 CA

> 主线整合编号 0074；作者原独立分支编号 0057。旧主线同号决策及链接保留，历史验收仅认证原冻结输入。

状态：已采纳。

## 背景

专用 Linux 验收节点需要连接使用自有 CA 的 HTTPS 面板。现有 Agent 的 reqwest 和 WebSocket 客户端使用公有 webpki 根；仅设置 `SSL_CERT_FILE` 不会把该 CA 加入它们的信任集。关闭证书或主机名校验无法验证真实的面板身份。

## 决策

- Agent 本机配置增加 `panel_ca_file: Option<PathBuf>`，默认没有附加 CA。旧配置和 `PanelClient::new` 保持原有行为。
- 文件必须是绝对路径的普通 PEM 文件，最多 256 KiB、32 张证书。读取上限在实际读取时生效；拒绝文件及上级目录的符号链接、父目录跳转、非证书块、私钥、空文件、非法 PEM 或 DER。错误不回显文件内容；不自建证书认证器。
- 同一加载器为注册请求、面板配置与制品下载、认证 WSS 和退役回执添加这些证书。公有 webpki 根继续生效，TLS 协议、有效期和主机名验证继续由正常 rustls 验证器完成。
- 配置来自节点操作者，面板协议不能设置此字段。独立 GitHub 下载、公网地址探测和其他外部请求不加载这份私有 CA。面板下载继续要求同一面板 origin，并拒绝跳转。
- 不增加原生系统根加载依赖。使用已锁定的 rustls 0.23.45、rustls-pki-types 1.15.1 和 webpki-roots 1.0.9；真实 TLS 回归服务使用已锁定的 tokio-rustls 0.26.6。
- Unix 打开文件同时指定 `O_NOFOLLOW` 和 `O_NONBLOCK`，防止普通文件预检之后被替换为链接或 FIFO 而阻塞，再核对实际描述符与预检身份。仅引用已锁定 libc 0.2.189 的平台常量；无需 unsafe 系统调用，不复制各平台数字，也不升级锁文件版本。块外只允许空白或 `#` 注释。
- 面板连接建立时重新读取该文件。CA 更新在后续连接或 Agent 重启后生效；已经建立的 TLS 连接保持其原有信任上下文。操作者应原子更新受保护的 CA 文件。

## 配置与运行时边界

`panel_ca_file` 与发布制品的 minisign 公钥是两套独立信任。它不会授权未签名制品，也不会改变设备签名身份。建议将 CA 放在 `/etc/apsp/trust/panel-ca.pem`，避免放入退役时会清理的设备身份、插件或安装目录。

原生路径验证由独立运行时通过自己的 HTTPS 客户端发出。Agent 只访问已应用配置中的回环控制接口；该运行时的 CA 应通过其正常的系统或进程证书配置提供。Agent 的 `panel_ca_file` 不会改写运行时配置或宿主证书库。

## 验证

回归使用隔离的 TEST_ONLY CA 和真实 HTTPS/WSS 服务，验证添加正确 CA 后注册、下载、认证和退役成功，未添加 CA、错误主机名或过期服务证书时拒绝连接。配置与读取回归覆盖旧配置、文件类型、字节与证书数量预算，以及私钥/其他 PEM 块和损坏 DER 的拒绝。测试素材不用于正式发布。
