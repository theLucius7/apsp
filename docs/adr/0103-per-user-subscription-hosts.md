# ADR 0103：用户专属地址与 Cloudflare 账号保存

- 状态：已实现；本地集成测试与浏览器回归验证，生产入口与真实客户端见下方“上线步骤”。
- 日期：2026-11-01。

## 背景

用户要求：

- 订阅地址不再用面板域名，改成 `apsp-<用户随机串>.example.com/<随机串>`，可重置，以降低被扫到的可能。
- 登录地址同样走专属地址，重置后旧地址释放。
- 能添加并保存 Cloudflare 令牌。

之前添加 DNS 账号要先到凭据中心建凭据、手工复制 UUID、再手工填 Zone ID，每条 DDNS 规则还要再粘贴一次账号 UUID。

## 决定

### 地址形式

每个用户有一对随机值：`slug`（16 位小写 base32，80 比特）和 `path_token`（256 比特）。

| 用途 | 地址 |
| --- | --- |
| 订阅 | `https://{前缀}{slug}.{域名}/{path_token}` |
| 登录 | `https://{前缀}{slug}.{域名}/{path_token}/login#/plugins/sing-box/account/{账号}` |

**专属主机只回答自己的内容。** 裸域名、其他路径、其他用户的路径、管理接口都返回同样的空 404，所以猜到一个主机名也看不出这里是什么。门户接口只放行这个用户自己的账号；静态资源可读，内容本来就是公开的。

**重置即释放。** 重置同时更换 `slug`、`path_token` 和原有的 `subscription_token`，事务提交后旧地址立刻 404，旧解析记录由后台删除。

**迁移用户同样有专属地址。** 仍由原系统出节点的迁移用户（Nexus 桥接），面板自己的 `/sub/{token}` 没有节点，会返回 409，所以：

- 面板给出的链接改为真正能用的地址：有专属地址用专属地址，没有就用原系统地址 `{subscription_base}{token}`，不再给 `/sub/`。
- 专属主机把请求转发给原系统，并带上客户端的 User-Agent，格式仍由原系统决定。响应头（用量、文件名）原样带回。
- 重置只换专属地址，令牌留在原系统。原系统的旧链接继续有效，不能由「旧地址继续可用」关闭：这条路径在节点接管完成前必须保留。

这意味着迁移用户的新地址依赖面板在线，原地址不依赖。

**旧地址由管理员决定何时关闭。** 启用后 `/sub/{token}` 和面板域名上的门户继续可用，「旧地址继续可用」关闭后才返回 404，已有客户端不会被突然切断（AGENTS 要求保留旧订阅路径）。

### 解析与入口

每个用户一条 Cloudflare 代理的 CNAME 记录，指向一条专用的 Cloudflare Tunnel，由后台任务按需创建和删除。Tunnel 把这些主机名转发给面板；面板按主机名分流，非 `apsp-` 开头或未签发的主机名都没有内容。

**不能给每个主机名单独签证书。** 证书透明日志是公开的，逐个签发等于把所有随机主机名公布出去。边缘由 Cloudflare 通用证书（`*.example.com`）覆盖，名字不进日志。

**不把通配符证书放进共用的 Caddy。** 曾尝试过 Origin CA 通配符证书加 `*.example.com` 站点，实测有副作用：Caddy 一旦加载能覆盖某子域名的通配符证书，就不再为这个域名下其他站点管理各自的证书，全部改用这张证书。Origin CA 只受 Cloudflare 信任，不走代理的站点立刻证书报错。`auto_https ignore_loaded_certs` 也解决不了：Caddy 仍把精确主机名并入通配符，还会尝试申请 `*.example.com`。已回滚并吊销该证书。Tunnel 不需要源站证书，也不影响其他站点。

**未选泛解析。** 域名上已有一条不走代理的 `*.example.com`，指向别处；改它会影响所有未单独配置的子域名。逐条记录影响范围最小。

### Passkey

Passkey 绑定依赖方 ID（RP ID）。面板域名是 `panel.example.com`，专属主机不是它的子域名，所以专属主机上的门户改用根域名（`example.com`）作为 RP ID，源站校验仍然精确到这个主机。这样重置地址后 Passkey 继续有效，只需要把新地址发给对方。

代价：之前在面板域名上绑定的 Passkey 不能用于专属主机，这些用户需要重新生成一次开通链接；旧地址开启期间，他们仍可用原地址登录。

### Cloudflare 账号

新增 `POST /api/plugins/ddns/accounts/cloudflare`：粘贴一个令牌，面板校验它、列出它能管理的域名、加密保存、创建账号。之后动态解析规则和专属地址都从下拉框选择账号和域名，不再出现 UUID 和 Zone ID。令牌按原有凭据中心方案加密（AES-256-GCM），不回显；保存与选择凭据要求所有者身份和五分钟内的再次验证，每次使用留审计。

Cloudflare 账户令牌显示的 Access Key ID 和 Secret Access Key 由令牌本身派生（令牌 ID 与令牌值的 SHA-256），用于 R2。本功能只需要令牌，不单独保存它们。

## 影响

- 新增迁移 `0078_subscription_hosts.sql`，只加表；未启用时行为不变。
- 面板在所有路由之前增加一层按主机名的分流；面板自身的域名和其他主机名原样通过。
- 新增只读接口 `GET /api/plugins/sing-box/subscription-domain` 与所有者写接口 `PUT`。

## 上线步骤

代码部署后功能默认关闭。启用需要：

1. 入口：创建一条 Cloudflare Tunnel，把 `*.example.com` 转发到面板的本地监听端口，常驻运行 `cloudflared`。
2. 「域名解析 → 添加 Cloudflare 账号」粘贴令牌。
3. 「代理用户 → 专属地址」选择账号和域名，解析目标填 `隧道 ID.cfargotunnel.com`，启用。
4. 把新地址发给用户；都切换后关闭「旧地址继续可用」。

## 未选

- **泛解析 + 面板按主机名拒绝：** 不用逐条写 DNS，但会改变整个域名未配置子域名的解析结果。
- **逐主机 ACME 证书：** 主机名进入证书透明日志，抵消防扫描的目的。
- **源站通配符证书放进 Caddy：** 影响同域名的其他站点，见上。
- **以专属主机本身作为 RP ID：** 隔离更强，但每次重置都要重新绑定 Passkey。
- **把 Access Key 和 Secret 也存起来：** 可由令牌推导，多存只增加风险。
