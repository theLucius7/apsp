# ADR 0035：sing-box 策略组、套餐快照与受控两跳链路

状态：采用。日期：2026-10-01。按人单独授权已由 [ADR 0112](0112-group-only-access.md) 删除；“只支持两台服务器”的链路限制已由 [ADR 0040](0040-mixed-chains-and-subscriptions.md) 取代。

## 背景与本次授权范围

用户明确要求在 sing-box 插件中增加包含节点、链路的策略组，并将每月流量、月度重置时刻、可使用期限定义成可分配的套餐组。本决策覆盖历史 MVP 对这三项功能的排除，不扩展为平台全局用户、营销计费或任意链式拓扑。主线已授权的多协议与证书能力按 [ADR 0034](0034-modern-protocols-and-certificates.md) 保留，不退回仅支持 Reality 的旧编译器。

上游核对以仓库固定的 SagerNet/sing-box `v1.14.2` 为准，不修改上游源码或引入动态用户管理分叉。参考上游 [VLESS inbound](https://sing-box.sagernet.org/configuration/inbound/vless/)、[V2Ray API](https://sing-box.sagernet.org/configuration/experimental/v2ray-api/)、[原生路由动作](https://sing-box.sagernet.org/configuration/route/rule_action/)，以及该 tag 的 `experimental/v2rayapi/server.go`、`experimental/v2rayapi/stats.go`。统计服务按显式用户名列表选择计数；它不负责套餐、日历或授权业务。

## 决策

策略组是一组授权资源，不是客户端自动选路策略。一个用户可分配多个组，组内可包含普通节点及已创建的两跳链路。最终权限取所有组与单独授权的并集。使用既有 `accesses` 持久化有效来源对应的 UUID，新增 `direct_grant` 区分旧单独授权；重叠来源保留凭据，最后一个来源消失才撤销凭据。策略组修改在同一事务内同步全部成员，不靠页面刷新或异步任务补授权。

普通节点支持主线所有协议。组授权按节点协议生成对应长度的 `credential`，发布和订阅同时校验 UUID 与该凭据，避免合并后组授权仍生成空密码或订阅失去凭据校验。两跳链路仍限定双方为 VLESS + Reality，后端与编译器拒绝将其他协议节点重新解释成 Reality；同一服务器可同时承载其他直接授权协议及原有托管证书。

套餐组是可复用模板，每位用户有且仅有一个当前套餐快照，不共享额度。快照包含流量额度、重置日、时分、IANA 时区、开始与到期时间。修改/归档模板不改变已分配快照。分配请求携带 UUID 幂等键；旧请求重放只返回原结果，不覆盖更新的当前套餐。首次分配前保持既有不限制流量和有效期的兼容行为，界面明确提示，不能把“没有套餐”解释成已经禁用。

月度流量从不可变 `usage_records` 按用户和时间范围汇总，包含上传与下载。套餐重分配不会删除或清空流水，第一次分配也包含当前日历周期已经发生的用量。重置时刻由 PostgreSQL 日历计算：29–31 日在短月取月末，下个月重新按原始日期计算；时间戳沿用协议的 Unix 秒，不与配置 debounce 的毫秒混用。有效天数按 24 小时计算，从分配时刻开始；月度重置不延长有效期。不提供额度结转、首月折算或自动续期。

每条已提交计量批次完整归入其排他结束时刻前一秒所在的周期。同一个批次跨过重置点时不按时长猜测拆分字节；这是采样粒度限制。重放依靠原有 `(server_id, epoch, seq)` 幂等账本，迟到旧周期的记录不会消耗新周期，`epoch` 只标识运行时计数器代际，不是套餐周期。

订阅与服务端快照共用 `singbox_eligible_accesses`。过期/耗尽不仅过滤订阅，还会通过现有发布任务移除运行时用户。发布任务定期记录资格变化，只有变化才标记服务器待发布，避免重复刷新造成 debounce 永远不结束。资格缓存刷新与配置生成使用一致数据库快照；同次配置编译共享同一时间，防止额度变化发生在用户选择和链路选择之间，导致入口缺失路由后意外直连。

## 两跳链路

本轮仅支持不同服务器上的独立入口节点 → 出口节点，仍使用 VLESS + Reality。入口不得已有单独授权、普通节点策略引用或其他链路身份；出口可供多个入口共用，也可单独授权给其他用户。不支持同机双节点、循环、嵌套、动态出口池或任意自定义 outbound。

客户端仅获得入口的用户 UUID。入口配置按 inbound 路由到出口，并使用独立内部 UUID；出口接收内部用户。内部用户不进入 `stats.users`，真实用户只在入口扣量；真实用户直接连接出口时，仍正常记录其自己的用量。内部凭据不出现在策略组、链路列表、代理用户接口或客户端订阅中。

修改关联节点/授权时标记链路两端待发布。链路只有在两端都健康、已应用目标版本且没有待发布变更时才进入订阅。任一端被删除后，入口资格失效，周期任务补充处理 core 退役造成的跨端撤销。多机发布不是原子事务；链路准备期间可能暂不可用，不以直接连接出口或绕过链路降级。

## 并发、兼容与代价

插件拓扑、用户权限和套餐写入先取得同一个事务级 advisory lock，再按确定顺序取得用户/服务器锁。资格刷新也走该锁；普通计量仍使用原账本事务，配置发布在可重复读快照中独立执行。面板和 Agent 的通用协议、签名链、运行时代际与重放逻辑不变，未新增生产依赖。

旧用户 ID、订阅 token、节点 UUID、历史部署与计量保持。套餐改变或流量恢复不会换发用户 UUID；权限的最终撤销后重新授权会换发。数据库增加插件命名的表、视图和函数，以及 `usage_records(user_id, period_end)` 索引。

这不是逐字节硬限速器。停用速度受上报、事务提交、周期检查、原有 5 秒发布 debounce 和设备应用影响；离线设备仍可能持有旧配置。原生整包应用也不是无损热更新。本轮不修改内核以获得立即断流能力，也不把本地编译或数据库通过等同于真实双机持续流量验收。

升级不得运行新旧面板混合发布：旧版 publisher 不认识套餐资格，可能重新放行用户。迁移后不允许只替换旧面板二进制作为安全回滚。停止旧发布进程、备份、单实例升级；需要回退时先撤回代理运行配置并恢复一致的面板/业务数据版本。PR 阶段不执行生产迁移或部署。
