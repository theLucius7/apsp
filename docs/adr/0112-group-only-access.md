# ADR 0112：代理用户只通过策略组获得节点

状态：已接受。

## 背景

[ADR 0035](0035-singbox-policy-package-groups.md) 让代理用户有两种拿到节点的方式：单独授权某个节点，或者分配策略组，最终权限取并集；[ADR 0076](0076-node-catalog-and-external-access.md) 又让外部节点只能按人单独分配。结果「代理用户」页同时有「单独节点授权」「外部节点」和「权限与套餐」三块，诊断页还要逐行说明“单独授权；来自某组”。

用户反馈：代理用户不需要单独授权，授权一个组就可以了。

## 决策

- 代理用户只通过策略组获得受管节点、链路和外部节点。删除 `POST /users/{id}/accesses`、`DELETE /users/{id}/accesses/{node}`、`GET/PUT /users/{id}/external-accesses`；`GET /users/{id}/accesses` 保留为只读的连接身份列表，不再有 `direct_grant` 字段。
- 策略组可以包含外部节点：新表 `singbox_policy_external_nodes` 记录节点、身份批次、版本和更新方式（跟随节点或固定版本），校验规则与原来按人分配相同：组里已有的绑定即使暂时不可用也保留，新加入的必须已采用、已启用且是当前版本。`GET /external-node-candidates` 列出可加入的外部节点，策略组的读写接口带 `external_nodes`。用户的外部节点是所在各组的并集，同一节点优先取身份仍匹配、跟随更新的绑定。
- 迁移 0086 把现有的单独授权原样转成策略组：每位用户直接授权的节点、两跳与混合链路入口（改为授权整条链路）和外部节点合成一组，授权完全相同的用户共用一组，组名为「原单独授权 · 用户名」。有序链路入口上的单独授权本来就不生效，不转换。之后删除 `accesses.direct_grant`、`singbox_external_accesses` 和 `singbox_external_access_state`。`accesses` 继续保存每位用户在每个节点上的连接身份。
- 节点迁移（`migrate_node`）只把源节点所在的策略组换成候选节点；链路转换与接管的阻断原因不再有 `entry_direct_grants`，策略组把入口当普通节点仍会阻断。
- 订阅来源删除、外部节点删除和来源迁移的检查改为看策略组是否引用；来源迁移回滚不需要改写组内引用，因为组按公开编号引用节点和版本。
- 迁移用户不受影响：他们的线路仍由套餐对应的原权限组决定（[ADR 0095](0095-nexus-runtime-takeover.md)）。用户诊断为迁移用户单独说明“套餐 → 原权限组 → 可用线路”，不再显示“授权 0 项”。

## 取舍

- **保留单独授权，只在界面上隐藏：** 数据和接口两套并存，诊断与计数仍要解释两种来源。未采用。
- **每个转换出的用户各建一组：** 最直观，但几十个用户会产生几十个只有一人的组。按授权集合合并，结果相同而组更少。
- **外部节点组内只支持跟随更新：** 更简单，但会改变已有固定版本授权的行为。保留两种方式。
