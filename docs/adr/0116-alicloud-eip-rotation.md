# ADR 0116：阿里云 ECS 更换公网 IP

日期：2026-10-30 起草，2026-11-06 并入主线。用户要求把“换 IP 直到国内可用”的运维脚本做成 APSP 功能，并释放不用的旧 IP；起草版本没有合并，2026-11-06 用户说“继续”后移植到当前主线完成。此决策覆盖 [ADR 0057](0057-alicloud-cdt-management.md) 中“不申请/释放 IP、不改绑定”的范围限制，仅限本流程。

## 背景

阿里云 ECS 绑定的 EIP 被封锁后，整台机器从国内不可用，但换一个 EIP 就能恢复。手工脚本的做法是：申请新 EIP，加入原共享带宽，换绑，从国内探测，不通就换下一个，通了就释放旧 EIP。这一过程涉及付费资源和不可逆的释放，而且可能被面板重启打断，不能只是把脚本搬进请求处理函数。

## 决定

- 在阿里云插件内实现。入口是「阿里云 CDT」页资源的「资源操作 › 更换公网 IP」，只对运行中、绑定 EIP 的 ECS 可用。进度和结果是「操作记录」里的一条，结束通知并入这一条，不单独成表。
- 预览只读，不需要再次验证。确认、取消和结束人工核对属于阿里云插件的高风险写入，由请求守卫统一要求五分钟内的证明（[ADR 0108](0108-unified-reauthentication.md)）；确认还要求原发起管理员的会话和预览摘要，并重新读取云端，状态变化就要求重新预览。API 令牌不能确认。
- 确认后写入持久记录，由后台任务逐步执行，不依赖请求或管理员在线。每一步先读云端状态，再决定动作，因此面板重启后从保存的阶段继续，不会重复提交。
- 申请地址使用保存在数据库中的 `ClientToken`：令牌先保存、再发请求，响应丢失时重试同一令牌，得到同一地址，不会多买一个。
- 新地址沿用旧地址的线路、资源组和共享带宽。只支持按量付费、NAT 模式的 EIP；包年包月、删除保护、安全防护、地址池、连续 EIP 和已单独登记的 EIP 在预览时拒绝，因为新地址无法保持相同配置，或释放后会留下失效记录。
- 同一时刻只有一个 EIP 绑定实例。候选地址不通时，先换绑下一个候选，再释放上一个，减少实例没有公网地址的时间。
- 只有新地址通过复测后才释放旧地址。所有候选都不通、服务连不上或探测服务不可用时，绑回旧地址并释放全部候选，结果记为“未更换，已恢复原地址”。
- 只能释放两类地址：本次记录中申请的候选，以及预览时冻结的旧地址。释放前核对 IP 一致且未绑定。
- 实例上出现不属于本次流程的 EIP 时，立即停止所有自动操作，转为“需要人工核对”，不绑定也不释放。人工结束只记录结论，不改动云资源。
- 换绑超时不会让实例一直没有地址：先尝试绑回旧地址。旧地址释放失败时仍算更换成功，但提示手动释放。

## 执行与账户锁（2026-11-06）

[ADR 0057](0057-alicloud-cdt-management.md) 的账户锁串行化同一账号的写入。第三轮性能整理（#224）已让账户刷新不再持锁调用云端，本流程沿用同一规则：

- 每一步在没有事务的情况下调用阿里云和 Globalping，只在保存结果时短暂持有账户锁。云端调用可能长达数十秒，持锁会让 CDT 守护、启停任务和同账号其他资源的编辑一起等待。
- 运行中的记录只由后台任务推进。每一步只在记录的 `version` 仍是读取时的值时保存，否则丢弃这一步，下一轮重新读取。没有保存的一步（崩溃、冲突）会重做：每一步都按云端当时的状态决定动作，申请沿用已保存的令牌。
- 结束时（已更换、已恢复原地址）在同一事务里写入资源快照的公网 IP 与绑定 EIP，`checked_at` 取保存时刻。账户刷新跳过 `checked_at` 不早于本轮开始的资源，所以早先开始的刷新不会用旧读数覆盖它。
- 进行中时，账户刷新不保存这台实例的快照，避免把即将释放的候选地址显示为当前地址；转为“需要人工核对”后恢复刷新，以便核对。

## 互斥

- 进行中或待人工核对的更换占用资源：带宽变配、各类启停任务（手动、每日计划、保活与 CDT 守护）、安全组调整和移除登记都先检查资源空闲，因此会等待或跳过；CDT 守护与每日计划按现有规则在下一轮重试。
- 预览、确认同样检查资源空闲，所以已有待执行或待核对的操作时不能开始更换。
- 进行中的更换涉及的 EIP（原地址、当前绑定、候选和待释放地址）不能单独登记为云资源，避免释放后留下失效记录。
- 编辑或移除资源、编辑账号会取消未确认的更换预览；预览冻结了账号和资源版本，本来也无法再确认。

## 共享带宽

生产实例的 EIP 都在共享带宽中，ECS 接口对它们报告共享带宽的计费方式（`PayByDominantTraffic`，按主流量计费），EIP 本身的计费方式在加入共享带宽期间不起作用，而这种方式不能用来申请 EIP。因此：

- 旧地址在共享带宽中时，不检查它报告的计费方式；新地址按流量计费、峰值 200 Mbps 申请，随即加入同一共享带宽，与 2026-10-30 在真实账号上成功执行的脚本一致。
- 不在共享带宽中的旧地址必须是按流量或按带宽计费，新地址沿用它的计费方式和带宽。

## 判断“国内可用”

使用公共探测网络 Globalping 从中国的探针做 TCP 握手。先用 8 个探针初筛，再用 14 个探针复测。排除阿里云内网探针（网络名含 Alibaba），因为它们不经过边境过滤，总能连通。初筛至少 3 个有效探针、85% 连通；复测至少 6 个有效探针、90% 连通。2026-10-30 的真实执行中，8 个探针里有 5 个有效，14 个里有 11 个有效。

探测端口由管理员填写。预览时面板先连接当前地址的这个端口，填错端口会被拒绝，否则每个候选都会被误判为不通。绑定新地址后也要先从面板连通，再发起国内探测。

这只证明 TCP 可达，不证明代理协议未被识别，也不保证新地址不会再被封锁。Globalping 会收到候选 IP 和端口，预览界面明确说明。匿名使用有每小时额度，额度用完时探测失败，流程恢复原地址；没有内置备用探测，不在缺少证据时释放旧地址。

## IP 变化之后

插件之间不互相依赖，阿里云插件不写代理节点、域名解析或其他插件的数据。

- 自动跟随：Agent 上报的公网地址、使用 Agent 上报地址的域名解析、阿里云页面的资源快照。
- 需要管理员处理：公开地址直接写成旧 IP 的代理节点和已经下发的客户端配置。「操作记录」里已更换的一条直接链接到这台实例关联服务器的节点列表；通知和预览也明确提示。
- 兼容期仍由原面板生成订阅的迁移线路，在原面板或通过迁移线路的公开入口接口更新（入口和公开端口一起更新，见 #214）。

## 权限

现有 CDT 最小权限不含 VPC 操作。使用本流程需要另外授予 `vpc:DescribeEipAddresses`、`AllocateEipAddress`、`AssociateEipAddress`、`UnassociateEipAddress`、`ReleaseEipAddress`、`AddCommonBandwidthPackageIp`、`RemoveCommonBandwidthPackageIp`，见 [RAM 最小权限](../alicloud-ram.md)。缺少读取权限时预览直接说明缺少 VPC 权限；应一次授予全部权限，只缺换绑或释放权限时，流程会绑回原地址或停在“需要人工核对”，可能留下需要手动释放的地址。

## 费用

阿里云按量 EIP 直接绑定 VPC ECS 时不收配置费，未绑定等其他情况收取，按小时计费；加入共享带宽后，公网网络费归入共享带宽账单。因此换 IP 不会对同一份流量重复计费，地址计入同一个 CDT 额度池。可能的额外费用只有候选和旧地址在换绑过程中短暂未绑定的配置费，流程会尽快释放，具体以账单为准。

依据：[EIP 计费常见问题](https://help.aliyun.com/zh/eip/support/billing-faq)、[EIP 与共享带宽](https://help.aliyun.com/zh/internet-shared-bandwidth/user-guide/create-an-internet-shared-bandwidth-instance)、[Globalping](https://globalping.io)。

## 验证范围

开发测试使用内存云替身、回环云接口替身和隔离 PostgreSQL，覆盖成功、候选被封、全部被封、服务不可达、重复地址、响应丢失、请求被拒、换绑失败、外来地址、旧地址释放失败、面板重启和凭据失效，逐项断言发给云接口的参数；并验证云端调用期间账户锁空闲、并发改动时不保存旧结果、进行中时其他操作等待且相关地址不能登记、账户刷新不覆盖进行中或刚结束的结果。面板流程未在真实云账号上运行；同样的云接口序列曾由运维脚本在真实账号上成功执行一次。首次真实使用前须授予上述权限，并核对账单。
