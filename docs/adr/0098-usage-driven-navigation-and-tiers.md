# ADR 0098：按使用逻辑重组界面：功能分级呈现、运维工具并入服务器详情与概览首页

- 状态：已实现。集中验证结果见 [PROGRESS](../../PROGRESS.md) 本轮记录；未在真实设备或生产面板上验收。
- 日期：2026-10-25（审查与调研于 2026-10-24 完成）。
- 取代：[ADR 0086](0086-product-map-and-navigation.md) 决定 2 的分组组成（七组，含 2026-10-24 把代理服务移到第一组的调整）与服务器详情的七个分页。ADR 0086 的其余决定继续有效：已发布的 Hash 路径不变、服务器详情只放这台服务器的事、告警设置与面板设置分开。
- 落实：[ADR 0087](0087-narrow-positioning-proxy-network.md) 决定 3（各级别的界面处理）、[路线图](../roadmap.md) M0 工作包 0.2 与决定 D6。
- 关联：[功能地图](../product-map.md)、[ADR 0085](0085-rearchitecture-plugins-sources-chains.md)、[ADR 0089](0089-nexus-member-commerce.md)、[ADR 0096](0096-costs-and-renewals-ledger.md)、[ADR 0097](0097-ledger-server-records-and-source-references.md)。

## 背景

用户要求逐项扫描功能与交互体验、并行验证每项是否必要及逻辑是否恰当，再按约束与项目走向重构：该分类的分类，该重新布局的重新布局，按使用逻辑来；研究论坛用户需求；插件该合并的合并、该拆分的拆分；方向统一，无需审核，按最佳决定执行。

本轮先由四个审查分别核对代理网络与部署、代理用户与门户、服务器与运维、监控/网络/系统，再从中文论坛与竞品 issue 整理需求；运行面板逐页截图，以界面实际表现核对结论。与界面结构有关的结论如下：

1. **主线被埋。** 审查开始时「代理服务」排在侧栏第五组（随后的界面调整移到了第一组，但“服务概览”仍只是静态清单）；登录后落在外框之外的服务器看板；全站没有“实验”“冻结”标记，降级和冻结功能与主线并列。服务器看板把服务器称作“节点”。
2. **运维工具其实是“一台服务器的事”。** 页面先选服务器，再在七个分页之间切换，却占一个跨服务器工作区。其中「面板健康」是系统自检的子集；更严重的是，核心部署预检要求的“只读运行时预检”授权只能在这里开启，核心旅程依赖了降级页面。
3. **支撑与降级混放。** 面板备份与恢复（支撑）、批量运维（降级）、云资源与费用（冻结）同在「自动化与恢复」。
4. **诊断分散。** 服务器详情的 IP 信息、节点验机、TCP 诊断都是线路质量，却占三个分页。
5. **同一设置多处编辑。** 监控历史保存期限在面板设置与系统自检两处可改，保护强度不同，只单向同步；面板设置与告警设置两页必须整包提交设置，后保存的一页会覆盖另一页。
6. **用户需求。** 多台服务器统一管理正是现有工具的空缺；用户反感菜单膨胀和默认开启的远程执行；首页应先显示待办与异常；订阅响应头 `Subscription-Userinfo` 是投入最小、收益最高的缺口。

## 决定

1. **侧栏按使用顺序分为六组，共 22 个入口：** 先看全局，再运营代理服务，然后管理服务器、监控告警与线路，最后是面板本身。

   | 分组 | 入口 |
   | --- | --- |
   | 总览 | 概览（原「服务概览」，登录后的首页）、服务器看板、统计报表、费用与续费 |
   | 代理服务 | 代理节点、代理用户、策略与套餐、成员运营 |
   | 服务器 | 服务器列表、插件中心（原“扩展”）、动态域名解析（原“网络”）、阿里云 CDT（原“扩展”） |
   | 监控告警 | 告警事件、告警设置、延迟检测、网络检测（原“网络”） |
   | 系统 | 面板设置、备份与恢复（新入口）、管理与安全、账号安全 |
   | 实验功能 | 自动化与维护（原「自动化与恢复」）、网络配置 |

   “网络”“扩展”两组撤销。DDNS 与阿里云 CDT 都作用于具体服务器，与插件中心同在“服务器”组；插件中心的第二视图本来就是服务器启用表。

2. **登录后的首页改为「概览」（决定 D6）。** 没有指定地址时，进入 `/#/plugins/sing-box`。页面依次显示：
   - 需要处理的事项：离线服务器、sing-box 安装或运行失败、未恢复的告警、30 天内续费的项目。
   - 关键数字。
   - 开始使用步骤，只在尚未全部完成时显示。
   - 各服务器的 sing-box 状态。

   没有代理服务读取权限的管理员进入服务器列表或管理与安全。匿名访问 `/` 在开启公开看板时仍显示服务器看板。

3. **功能分级在界面上呈现。**
   - **降级（实验）。** 侧栏放在“实验功能”组，页面顶部说明级别，分页和链接标“实验”。功能保持可用。
   - **冻结。** 默认隐藏：
     - 网络配置：系统网络参数、反向隧道、私有组网、受管防火墙。
     - 自动化与维护：云资源与费用。
     - 网络检测新增步骤：硬件测试、持续稳定性、Geekbench 导入、Speedtest、NodeQuality 完整验机，以及依赖它们的模板。

     开启「面板设置 › 功能显示 › 显示冻结功能」后，冻结功能在原位置显示并标“冻结”。已保存的方案、数据和接口不受影响。开关保存在面板设置的 `show_frozen_features` 字段，默认关闭，不新增数据库迁移。
   - **远程命令。** 服务器本机未开启时，只显示“本机未开启”和开启方法，不再展示禁用的表单。

4. **运维工具并入服务器详情。**
   - 新增分页「运维（实验）」，地址沿用已发布的 `/#/servers/{id}/fleet`。
   - 模板批量接入移到服务器列表的「批量接入」，新地址 `/#/servers/batch`。
   - 「面板健康」分页撤销，面板自身状态统一在「管理与安全 › 系统自检」查看，`/api/fleet/health` 保留。
   - 旧地址 `/#/fleet` 继续可用：显示服务器选择和迁移说明，侧栏高亮「服务器列表」。

5. **服务器详情分页由七个减为六个：** 概况、资产与流量、Agent 与任务、插件、线路诊断、运维（实验）。线路诊断下分 IP 信息、TCP 诊断、节点验机（实验）三个子视图，各自沿用原地址。“带此服务器打开”只保留网络检测、网络配置（实验）、自动化与维护（实验）。

6. **核心旅程不依赖降级页面。** 部署预检在“受限本机预检授权”不满足时，就地提供「在面板策略中允许」。这仍写入同一份面板策略，同样需要近期验证；页面同时说明服务器本机 `fleet-policy.json` 中的同名授权。有新增监听等待预检时，预检区域自动展开。

7. **备份与恢复归入“系统”：** `/#/system/backup`。

8. **同一设置只有一个编辑位置。**
   - **监控历史保存期限只在「面板设置」修改。** 保存时同步写入记录保留策略；缩短期限会提前删除历史，需要近期验证。系统自检中只读显示，`PUT /api/control-center/retention/monitoring` 返回冲突并指向面板设置。
   - **`PATCH /api/settings` 改为部分更新。** 未提交的字段保持原值，面板设置与告警设置两页不再互相覆盖。

9. **插件的合并与拆分。**
   - **合并。** IP 质量、TCP 连接诊断与 NodeQuality 在插件中心和服务器详情中都合为“线路诊断”。三个 Agent 适配器、签名制品和完整验机门禁不变。
   - **不拆。** sing-box 插件保持单一 crate：用户业务、门户、订阅来源与链路共用同一事务和锁，插件之间也不得互相依赖。费用与续费不是按服务器启用的插件，不进插件中心。
   - **后置。** 诊断插件从 `#[path]` 编入宿主改为独立 crate，需要先把诊断任务类型提升为宿主接口，仍按 ADR 0085 的阶段说明。

10. **代理服务内统一入口。**
    - 链路只保留一个「创建链路」，打开有序链路表单，提供“两跳”“入口 → 中转 → 落地”“含订阅来源节点”三个模板。
    - 订阅来源显示数字编号来源的迁移状态与迁移命令。
    - 节点库默认只显示搜索、类型、服务器、状态四个筛选。
    - 禁用按钮说明原因，创建后的提示指向授权，而不是无条件提示预检。

## 不改变的内容

- 已发布的 Hash 路径全部有效，包括 `/fleet`、`/servers/{id}/fleet`、`/servers/{id}/{ip-info,node-quality,tcp-quality}`、`/operations`、`/plugins/catalog`、`/system/plugins`、`/artifacts`、`/plugins/sing-box/chains`。改的只是显示名称、所在分组或所在页面。
- 不删除任何接口、数据库表、迁移或数据。降级和冻结功能的接口与记录照旧保留，隐藏只影响界面。
- 宿主、插件与组装的分层（ADR 0085），代理业务与服务器的边界（ADR 0023），Agent 默认关闭远程执行与本机运维策略，诊断安全门禁与签名制品规则。

## 替代方案

- **保留七组，只加“实验”标记：** 主线位置靠后、运维工具占跨服务器入口、核心预检依赖降级页面这三个问题仍在。
- **插件中心放入“系统”：** 插件按服务器启用，和服务器放在一起更直接；“系统”组已有四个入口。
- **网络检测与延迟检测立即合并为“线路质量”：** 需要先统一两套授权目标与任务模型，按路线图 3.3 进行。
- **故障事件并入告警事件：** 需要合并两套事件模型，留到路线图 M3/M4 评估；本轮故障事件随“自动化与维护”标为实验。
- **策略与套餐并入代理用户的页签，或改称“权限组”：** 会改动产品术语和文档用语，收益不足以抵消迁移成本。保持「策略与套餐」独立入口，术语不变。

## 后果

- 侧栏 22 个入口、六组，每组 2–4 个；服务器详情 6 个分页；运维与诊断都回到“这台服务器”。
- 依赖旧标签的浏览器夹具同步更新。
- 订阅来源的生产迁移、旧两跳链路接管和 sing-box“停用”语义仍需单独执行或决定，见[待决问题](../open-questions.md)。
