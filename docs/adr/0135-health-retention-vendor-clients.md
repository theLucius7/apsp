# ADR 0135：每种底层机制只有一套实现（第三部分：健康视图、保留期与供应商客户端）

状态：已接受（2026-11-13）。延续 [ADR 0133](0133-one-implementation-per-mechanism.md) 与 [ADR 0134](0134-outbound-network-and-delivery.md)；处理 [architecture.md §12](../architecture.md#12-扫描结论与余下工作2026-11-13) 中“系统健康视图用 SQL 拼其他领域的积压”“保留期清理替别的领域删行”“Globalping 客户端两个”“Cloudflare 接口三处”四项。

2026-11-13 用户：“目前是底层原理深度统一”，之后说“continue”。

## 背景

1. **系统健康视图。** 治理的 `control_center/system.rs` 直接读作业（备份计划与记录、恢复演练、作业、设备操作、远程命令）与观测（诊断任务、IP 质量数据集）的表，拼出健康页的积压。治理排在依赖顺序的最前面，不该读后面领域的私有表；平台的 `Outbox` 接口为此还多了一个“积压数”方法。
2. **保留期。** 治理的 `system::maintain` 在一个事务里替观测与作业删行：治理既定策略，又执行别人的删除。
3. **供应商客户端。** Cloudflare 有三份（名称的 DNS 记录、名称的区域列表、服务权益专属地址的 `DnsApi`，后者有自己的客户端、分页、81044 处理与中文提示），Globalping 有两份（`cloud-api` 给更换 EIP 用的一份、观测给中国可达性用的一份）。

## 决策

1. **健康视图是应用层的组合视图**，与全局搜索、云页面总览同一做法：应用的 `system_health.rs` 把治理的面板状态（版本、运行时间、数据库、磁盘、后台任务心跳、独立观察者、更新信息）与作业的 `backlog()`、`backups::summary()`、观测的 `backlog()` 拼在一起。地址、权限、审计与返回的 JSON 都不变（22 条 SQL 原样迁到各自的所有者，测试逐键核对）。治理的“期待的后台任务名”全局变量去掉，改由应用传入 `HEARTBEATS`；平台 `Outbox` 的积压方法去掉。
2. **保留期：治理定策略，所有者删自己的行。** 治理的 `control_center::retention` 给出每类记录的截止时间与清理节奏（每小时一次，失败的下一分钟重试）；治理清理审计记录、观察者报告与过期的 API 令牌（`control-center` 任务），观测清理 IP 质量数据与服务器事件（`telemetry-history` 任务，循环从应用移入 `observability::telemetry::run`），作业清理终端输入输出与已关闭的会话、配置历史内容、已完成作业的内容与命令输出（新任务 `operations-retention`，健康页显示“运维记录清理”）。保留时长、节奏与删除的内容都不变；一个所有者一个事务，不再一轮一个事务。
3. **每个供应商接口一个客户端，在 `cloud-api`。** Cloudflare 客户端提供两种判断方式（先看状态码再要求成功的 `call`，以及无论状态码都读信封的 `result`），名称的 DNS 记录、区域列表与专属地址都用它；DNS 记录是名称领域的对象，专属地址经名称新公开的 `zone_records` 写记录。Globalping 客户端以观测那份为基础（令牌、限额、轮询、可注入的传输），更换 EIP 的检查经参数保留原来的地点、匿名访问、包数、限额与超时。各调用方的超时、分页、上限与用户看到的文字逐字保留。守卫：两个供应商的接口地址只出现在各自的客户端里。

## 后果

- 治理不再读任何后面领域的表；越界清单 377 → 360。`cloud-api` 的词汇例外减为零。
- 健康页多出 `operations-retention` 一行（首次心跳之前显示为未知）；观测的清理失败时 `telemetry-history` 的心跳也会显示失败。
- 只在边缘情况可见的差别：81044 按第一条错误的代码判断，不再按格式化后的文字找子串；Globalping 的回答先看状态码（观测：读不出正文的拒绝记为限流或 HTTP 状态，不再记为网络错误；更换 EIP：形状不对的行使整次读数记为无效，不再计入）；区域列表在 `result` 为空值时得到空列表；区域列表与专属地址读取 Cloudflare 响应新增了 1 MiB 与 4 MiB 的上限；更换 EIP 遇到 429 时记录默认的 300 秒等待（引擎把等待限制在 30 秒以内，实际相同）。
- 余下：服务器状态（可用判断、服务器行锁、资产设置）与几类小机制在下一部分处理。
