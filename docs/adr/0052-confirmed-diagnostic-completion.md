# ADR 0052：诊断终态以停止和清理证明为准

状态：源码及工作区回归完成，专用 Linux/systemd 与完整工具链联合验收待完成。

对应 [Issue #143](https://github.com/theLucius7/apsp/issues/143)。诊断程序自然退出、状态丢失或取消请求都不能直接释放任务。原观察结果必须先持久化，随后确认原任务进程和挂载已清理；失败时保留任务占用及历史结果。

## 决策

Agent 将最初观察到的成功、失败、缺失或保护终态及报告冻结在原 Started 检查点中，以 `cleaning` 上报。停止和清理使用检查点中的精确任务 UUID、安装目录、程序及服务身份，未经校验的检查点拒绝特权操作。即使后端证明能力丢失，已有任务仍尝试停止；不能取得证明时保留占用，并显示有界清理错误。

SQLite 在同一锁内检查当前 owner、终态收据和取消意图，再决定更新检查点或删除 ACTIVE、提交结果。已经取消的旧观察不得重新写回检查点；监控循环在取消改变 owner 后丢弃原悬挂 future。历史任务的取消查询不得阻塞当前任务的内存和截止保护。冻结的空报告也属于结果，不重新采集覆盖它。

Panel 使用服务器锁和任务锁串行处理终态、取消及创建。`cleaning` 仍占用唯一活动任务位置，不按普通运行截止直接过期；恢复和晚到的旧 Running 状态不覆盖清理中的报告。迁移 0034 追加此状态，原 0001–0033 的字节、任务 UUID、配置及历史保持。

新任务要求 `diagnostic:confirmed-completion`，队列读取也检查该能力。旧设备失去能力后不领取新任务，原队列和历史仍保存；已有任务的停止与取消不以新任务门禁为理由跳过。

## 验证范围

回归覆盖自然终态、停止或清理失败、能力丢失、损坏检查点、内存与截止保护、历史取消、在途取消及旧状态恢复竞争，以及真实 PostgreSQL 的迁移、互斥和历史保留。前端展示清理状态并禁止占用期间创建新任务。
