# ADR 0130：线路质量合为一个入口，三网延迟与中国可达性同表

状态：已接受（2026-11-09）。

2026-11-09 用户在延迟检测页面要求：“这几个页面整理重做，相同的目标应该合并，你来规划重写这个页面”，确认方案后说“开始”。

## 背景

侧栏「线路检测」下有网络检测与延迟检测两个分页，延迟检测里又分三网延迟与中国可达性两个视图：

- 三网延迟把同一批服务器在电信、联通、移动三张表里各列一遍（生产 18 台服务器、3 个广东三网 ICMP 任务，共 54 行），只有最新一次采样，下方是任务列表。
- 中国可达性是单独的页面，只有所有者可见，含检测设置、端点表和封锁记录，页头样式与延迟页不同。
- 网络检测是测试方案工作台（测试方案、授权目标、工具与许可、IP 资料来源、任务与报告），生产中没有用过。

三网延迟（服务器到国内三网的延迟与丢包）与中国可达性（国内探测点到节点端口的 TCP 连接）回答同一个问题：从国内看，每台服务器的线路好不好。任务与可达性设置回答另一个问题：测什么、怎么测。网络检测是临时诊断，目标不同。

## 决策

1. **入口改名「线路质量」**（功能地图的目标名称），分三个分页：质量概况 `/#/latency`、检测设置 `/#/latency/settings`、网络检测 `/#/network-workbench`。侧栏入口打开质量概况。旧地址 `/#/latency/reachability` 打开质量概况（ADR 0126 第 5 条：旧地址至少保留一个发布版本）。
2. **质量概况每台服务器一行。** 三网各一列，显示最近一次的延迟与丢包，并用看板同一套条形（`QualityBars`）画出最近 20 个采样时段；所有者另有「中国可达性」一列，显示该服务器各端点中最严重的状态。顶部一条统计：需要关注的服务器数、三网延迟中位数与丢包偏高的台数、可达端点数。可按「全部 / 需要关注」筛选，按异常、名称、延迟、丢包排序，按名称、分组、地区搜索。
3. **「需要关注」只看可用性、丢包与可达性，不看绝对延迟。** 条件是：服务器离线；检测不可用、采样过期或授权失效；最近平均丢包不低于 5%；所有者可见时中国可达性为封锁、未定或部分可达。延迟高低取决于服务器所在地，只用颜色分级，不单独算作异常。等待首次采样、已暂停的任务与读取失败不算线路问题。
4. **展开一行看原因：** 每个检测目标的方式、地址族、最近采样与错误；这台服务器的延迟与丢包曲线（服务器监控中的同一个 `ProbeCharts`）；各端点从国内与海外的连接结果、待确认状态与风险提示；以及服务器详情、线路诊断的链接。封锁与恢复记录在概况底部。
5. **检测设置放测什么、怎么测：** 延迟任务的列表与编辑框（行为不变），以及中国可达性的开关、间隔、令牌与立即检测（仅所有者）。单台服务器自己的拨测仍在服务器详情 › Agent。
6. **网络检测保持原样，作为第三个分页。** 它做临时诊断，与持续检测目标不同；把其中的基础探测并入线路质量（路线图 4.1）留给后续。
7. **不改后端接口与数据库。** 质量概况只组合现有的 `/api/servers`、`/api/probes/overview` 与 `/api/plugins/sing-box/reachability`；后端只改两处提示文字与全局搜索中延迟任务的跳转地址。
8. **质量分级的「较差」改为警告与危险之间的颜色。** 原来借用图表的青绿色，看起来比「一般」的蓝色还好；看板与线路质量共用这套分级，一起改正。

## 后果

- 原 `LatencyTasks`、`ChinaReachability` 与 `LatencyTabs` 删除，分别由 `LineQuality`（概况）、`LineQualitySettings`（设置）与共用的 `ReachabilityEndpoints` 取代；聚合与判断在 `monitoring/line-quality.ts`，有单元测试。
- 全局搜索中的延迟任务改称「延迟任务」并打开检测设置；服务器详情「持续网络拨测」的跳转按钮改为「管理延迟任务」。
- 未做：网络检测的整理、回程路由、IP 质量与解锁历史、按入口/中转/落地分组（路线图 4.1 其余部分）；两套目标授权（延迟任务的执行授权与网络检测的授权目标）仍分开保存。
