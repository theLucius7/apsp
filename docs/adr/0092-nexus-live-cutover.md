# ADR 0092：Nexus 实际迁移与旧订阅兼容

用户在 2026-10-24 进一步授权实际迁移：旧 Nexus 网页地址跳转到 apsp，现有订阅链接暂时保持不变。这覆盖 ADR 0089 中只做迁移准备、不激活成员的阶段边界。

迁移前核对当前生产数据库、未决订单、充值、邀请、节点协议和入口路由。先完成全部实现与隔离验证，再做一致性备份和最终数据核对。旧网页跳转与订阅/节点协议路径使用不同路由，不能将订阅响应改成 HTML 或 302。

现有节点仍使用 Nexus 协议。过渡期保留原订阅和节点兼容后端，停止旧成员业务写入口；apsp 是成员、钱包、套餐、订单与邀请的唯一业务写入方。一个显式启用的本机兼容同步器将 apsp 的成员资格复制给兼容后端，将其流量观测回传 apsp。同步只修改明确列出的成员资格字段，不改原节点 UUID、订阅令牌、监听配置、机器凭据或流量计数。支持新成员与套餐续费；套餐映射缺失时拒绝生效，不猜测权限组。同步器停止时不改变已下发节点配置，apsp 暂停新的资金购买并显示同步状态。

迁移保留旧成员 bcrypt 密码哈希，使成员沿用原邮箱密码登录；不读取或保存明文密码，也不迁移旧会话。新增 `bcrypt = 0.19.3`，依据 [官方 API](https://docs.rs/bcrypt/0.19.3/bcrypt/) 验证 PHP `$2y$`，成功登录后升级为 Argon2。替代方案是强制所有成员重置密码，但当前部署并未配置可用 SMTP，会导致成员无法登录，因此不采用。导出哈希需要明确 `--include-password-hashes` 参数，文件权限为 0600，摘要或密码哈希不得进入 Git、日志或报告。

兼容同步器只在宿主本机运行，通过已有 Docker PostgreSQL CLI 交互，使用固定结构参数和标准输入，不把数据库凭据放在命令行。配置文件和生产快照属于私密部署材料。每轮使用原 SQLite 读事务、apsp PostgreSQL 事务与原 SQLite 写事务；保留最后成功时间与确认版本，失败重试幂等，不重置流量或重复充值。

原订阅域名和路径长期保持到用户另行决定。停止兼容后端、迁移节点 Agent、替换 UUID 或统一旧客户端格式不作为本次网页跳转的隐式副作用。兼容阶段的组成与后续节点接管要求在最终部署报告明确记录。

旧后端的财务触发器和钱包账本保持原样；兼容器不回写余额，新建的旧协议身份余额为零。实际余额、充值、购买与退款只由 apsp 账本处理。旧协议仅使用套餐、期限、配额及禁用状态；停用、待资助和原生归档在兼容身份上表现为停用，不伪造旧归档审计记录。原本已归档的旧身份保持归档，不在兼容阶段重新启用。
