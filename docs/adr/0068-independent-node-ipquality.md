# ADR 0068：独立节点出口 IPQuality

> 主线整合编号 0068；作者原独立分支编号 0051。旧主线同号决策及链接保留，历史验收仅认证原冻结输入。

日期：2026-10-02。状态：源码实现与本地统一验收完成；专用 Linux 实机签收、实际制品与发布另行待验。

## 问题与执行范围

面板查询一个入口不能代表节点出口，NAT 地址也不一定出现在服务器网卡列表。流媒体地区与可达性必须从节点自身出口观察。原 IPQuality 固定脚本仍包含统计访问、在线广告、双栈预先发现、宿主依赖安装、邮件端口与批量 DNSBL 请求；这些行为不能随质量查询默认执行。完整 NodeQuality 的商业跑分工具许可没有得到解决，独立 IP 查询不得依赖它们或宣布完整验机已就绪。

独立 `ipquality` 插件固定 `xykt/IPQuality` 提交 `87397e2c3196ec796f5477c83343c2354df601ea`，版本 `87397e2c3196ec796f5477c83343c2354df601ea-node-r1`。原脚本、AGPL 许可证、地区参考和 DNSBL 清单共四个输入按大小与 SHA256 固定；DNSBL 清单只保留来源，不发起该类请求。复用已审查的确定性源码策略，再加节点执行策略；修改后的源码、策略、包装器及许可证进入对应源代码包。使用真正上游 JSON 字段和查询方法，不以少量 IP 回显替代 IPQuality。

每次只允许 IPv4 或 IPv6，最多 300 秒、128 MiB、64 个任务、CPUWeight/IOWeight 10、OOMScoreAdjust 500。所有同机诊断继续使用共用互斥、启动预检、运行保护、取消、持久回报及清理确认；保留统一额外 256 MiB 可用内存和 2 GiB 磁盘预检。SMTP、DNSBL、缺少凭据的来源与不能可靠确认的解锁类型保持未知。公开页面结果描述测试时间和出口下的可达性，不保证订阅服务的持续可用性。

## 制品与执行

独立最小 Debian 12 工具配置复用现有工厂的签名索引认证、完整二进制与对应源闭包、原生 builder 审核、容量准入、动态保护和失败取证。只请求 Bash、Python、curl、jq 及其必要开源基础工具；不增加 Geekbench、Ookla 或硬件、测速工具。配置选择不授予任何许可证，也不批准 builder。

签名清单覆盖 `ipquality` 和六个附属文件：rootfs、rootfs 清单、build-info、LICENSE、source.tar.gz、THIRD_PARTY_NOTICES。打包必须先验证真实 prepare/export 和独立许可审查记录，审查逐个绑定原库存、包、对应源和许可证文本。审查文件中的 reviewer/evidence 是声明，非空字段不是自动审批证明；真实审阅和实机签收必须另有证据。发行校验重新比对固定源码派生、完整清单与参考资料。source 包携带九个原策略的精确副本，脱离完整 NodeQuality 也能复导出。制品 intake 不执行诊断，不下载运行时依赖。

同架构另附 `ipquality-<固定版本>-linux-<架构>-sources.tar.gz`，其中包含完整 Apsp/上游对应源包及每个 Debian 对应源的真实文件；只列 URLs、库存或哈希不能通过。机器可读 THIRD_PARTY_NOTICES 记录其固定名称、大小与 SHA256，外层附属文件签名覆盖这份声明，不修改既有协议 ReleaseArtifact。assemble、完整 bundle 校验和 draft 发布都必须取得对应文件并流式检查完整成员和源闭包；正式源下载地址由同一已签 release 的仓库、tag 和固定 asset 派生。缺少配套源包不能正式发布。

设备经 core 验证外层签名与每个文件后，适配器从已核对的 release.json 获取当前归档哈希，并固定任务执行上下文。包装器再次验证 rootfs 清单及全流，在独立挂载命名空间内解包和只读挂载；工作目录单独可写，只提供必要只读设备、只读 proc 和本机 DNS 配置副本，不挂宿主 sys，也不安装宿主软件。整个进程组和挂载都须清理确认。设备重启后读取原结果并清理，绝不因为缺少结果重新运行旧工作目录。

网络包装层只允许固定 HTTPS 公开 GET、所选 IP 版本与确定的入口路径。保留原生 curl 身份，不修改 UA、不使用不安全 TLS、不暴力重试、不向排名、报告、访问统计或广告入口请求。响应、耗时、请求总数和重定向均有界，重定向不能逃逸允许的服务或携带凭据。每次请求保存来源、响应视图、目标 IP、时间、耗时、状态和错误；403、429、超时等失败不能变成“干净”或零分。

## 协议、缓存与界面

不增加专用 Agent 上传接口，JSON envelope 作为登记章节 `ipquality_result` 的文本，通过既有受设备身份认证的章节接口提交。envelope 固定任务 UUID、工具/原源码版本与哈希、归档哈希、IP 版本、执行窗口、出口、原上游 JSON 和至多 64 条逐源记录。章节完整度与执行终态分别保存，部分章节可以先投影已经完成且证据一致的查询源。

共用章节扩展钩子默认为无副作用。接收按 server→job 锁序核对归属、登记章节、版本与幂等，插件解析和缓存投影使用同一事务，避免 ACK 后缓存丢失。数据库增加单调任务 generation；按 generation 和同任务章节 revision 排序，旧任务迟到不能覆盖新出口或新尝试。一次失败只更新最近尝试与错误，已有成功 payload、时间和有效期保留。

`ipquality-node/<实际入口>` 与面板来源缓存隔离，同一个聚合入口的七个响应视图仍表示一个来源。独立记录节点观察的出口及历史出口，网卡地址保持原定义。页面分别显示面板查询、节点自查、等待清理/取消、各个失败原因和历史结果；设备能力与匹配签名制品缺失时不能创建，读取失败或切换服务器后旧回调也不能提交。后台同机互斥始终为最终约束。

## 验收边界

修改期间不执行测试、构建、格式检查或实机探测，整步输入冻结后统一验收。源码 fixture、模拟 HTTP、PostgreSQL 和浏览器结果不等于真实节点出口、Linux mount/systemd 或持续代理负载验收。没有已审核 builder、完整最小对应源制品和专用节点证据时，这些能力保持待验；不部署到生产来补证据，不解锁完整 NodeQuality，也不恢复暂时停用的 CI。
