# ADR 0089：Nexus 成员业务原生接入

用户要求整理当前部署的 Nexus，将功能添加到 apsp，为后续迁移准备，并明确统一到 apsp 的界面和架构。

## 决策

成员资料、钱包、销售目录、订单、付费邀请、首次代购、充值、公告指南和迁移工作台放在 `plugins/singbox/panel/commerce/`，继续使用现有代理用户、套餐快照、策略组、用量账本和独立 Passkey 会话。服务器、节点、监控、终端、通知、备份和管理员安全复用 apsp，不再引入 PHP、第二个控制面或 Nexus 浏览器会话。

默认关闭成员商业入口。管理员可在成员运营中启用；启用不导入数据、不切换域名、不启动旧发布器。成员准入通过单次邀请和 Passkey 开通，旧浏览器会话不转换成新会话。成员邮箱密码与验证邮件按 ADR 0091 扩展；实际迁移沿用原密码哈希的决定见 ADR 0092。

金额使用整数分及固定 CNY；钱包扣款、流水、订单、套餐快照和邀请交付在同一 PostgreSQL 事务中完成。幂等键绑定请求内容；先锁套餐拓扑再按用户 ID 加锁。普通邀请仅提供准入，首单由邀请人支付；预付邀请购买时扣款和保留名额，兑换交付不可变套餐快照，未兑换预付邀请撤销全额退款（含准入费）；普通邀请的准入费不退，沿用当前 Nexus 规则。钱包只保留余额，不重新引入返佣和提现。

EPay 充值使用渠道配置、金额、商户、业务单号和支付回执共同校验。前端返回不是付款证明，重复回调不能重复入账；取消后或金额上限导致的未入账付款保留异常供管理员核对。计划购买从钱包扣款，余额不足先充值，避免两套资金状态机。依赖新增 `md-5 = 0.10.6`，复用锁文件已有的 RustCrypto 实现，仅用于既有 EPay 协议签名，不用于密码、令牌或文件完整性；替代方案是手写摘要或移除现有支付兼容，均不采用。密钥引用宿主加密凭据库，API 不回显密钥。

停用和待开通状态参与现有套餐资格计算，因此订阅和运行时使用同一条件。流量重置使用额度抵扣记录，保留历史账本和设备 epoch。续费延长同套餐有效期，换套餐显式按新快照交付，不静默继承旧套餐价格或授权。

## 迁移边界

只读 SQLite 导出使用字段白名单和一致性快照，不读取支付密钥、管理员密码、SSH 凭据或登录会话。原成员 ID、令牌、状态、余额、套餐、历史流水及邀请关系分别校验，先预览后事务导入；冲突不覆盖。导入身份保持待迁移，节点接管和激活通过显式迁移流程安排，实际迁移已由用户授权，见 ADR 0092。历史财务记录保留来源和原始 ID，不再次计入钱包；初始余额用一笔有来源的期初流水导入。不同系统的计费周期、节点 UUID、旧客户端格式、支付未决单和邀请旧链接须在切换前逐项核对，不能用导入成功代替实机签收。

实际部署与仓库存在差异，以只读盘点的领域行为为依据。不得提交成员数据、真实域名、IP、密钥和生产证据原文。实现完成后统一执行本地验证；GitHub Actions 仍暂停。
