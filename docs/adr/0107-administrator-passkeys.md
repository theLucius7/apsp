# ADR 0107：每位管理员各自的 Passkey

## 背景

[ADR 0082](0082-control-center.md) 引入多管理员时，只保留了初始所有者（编号 1）的 Passkey，具名管理员只能用密码和 TOTP。所有管理员 Passkey 都挂在 0039 迁移创建的同一个认证账户上，绑定接口拒绝初始所有者以外的管理员，Passkey 登录总是签发编号 1 的会话。用户在后台给其他人开了管理员账号后，这些人无法使用 Passkey。

## 决策

- 每位管理员有自己的 Passkey 认证账户，由新表 `administrator_passkey_accounts` 记录对应关系。初始所有者继续使用 0039 的账户，已绑定的密钥不变；其他管理员在第一次绑定时创建账户，创建在该管理员行锁内完成，同一人并发绑定不会产生两个账户。
- 绑定、列表、删除和再次验证都作用于当前会话所属的管理员。这些接口归入“本人账号”：任何角色都可管理自己的密钥，只能用交互式会话，API 令牌不能调用。绑定与删除需要本人的再次验证（2026-11-04 起统一为五分钟证明，Passkey 或密码均可，见 [ADR 0108](0108-unified-reauthentication.md)）；删除只退出本人的其他会话并作废本人未完成的挑战。
- 登录沿用 ADR 0059 的指定账户流程：请求带登录名，只提供该启用管理员的密钥，不依赖浏览器的无用户名发现。不带登录名等同 `admin`，与密码登录的默认一致。未知登录名、已停用的管理员和没有密钥的管理员得到同样的回答。完成登录时由挑战记录的账户反查管理员；代理用户门户的账户不在对应表中，不能换成后台会话。
- 认证器里显示的用户名和显示名取自管理员的登录名和显示名，同一设备上保存多位管理员的密钥时可以区分；代理用户门户保持原来的写法。
- 停用管理员后，其 Passkey 登录立即失效；管理员不会被删除，重新启用后原密钥恢复可用。

## 取舍

- **无用户名登录（可发现凭据）：** 省去输入登录名，但 ADR 0059 已决定不依赖这一能力，且会让一台设备上的多把管理员密钥都出现在选择框里。未采用。
- **继续只给初始所有者：** 不改代码，但用户明确需要其他管理员使用 Passkey。

## 验证

`crates/panel/tests/passkeys.rs` 覆盖具名管理员的密钥列表、本人密码验证、认证器显示名、独立账户、API 令牌拒绝，以及未知名称、无密钥名称和默认所有者的相同回答。浏览器虚拟认证器测试（`web/tests/passkey-administrators.mjs`）覆盖只读角色管理员绑定、Passkey 再次验证、从登录页按登录名登录、一位管理员的密钥不能登录另一位、停用后无法登录。
