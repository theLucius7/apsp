# ADR 0122：未发布阶段统一当前结构

日期：2026-11-07。用户要求整体清理旧版本兼容和历史数据库迁移，并确认采用「统一当前基线，旧开发库手动重建」。

## 决策

- 面板 PostgreSQL 和 Agent SQLite 都只支持当前结构，空库一次初始化；重复启动只核对当前基线。发现旧历史、版本不一致、初始化不完整或未知数据库时，明确拒绝启动并提示手动重建，不自动清空、不伪造迁移记录。
- 91 个面板增量迁移收敛为当前结构的单份初始化 SQL。使用隔离空库展开现有 DDL 只是生成实现输入，删除数据回填、改名和兼容修补步骤；随后集中验证新基线。组装 crate 仍拥有唯一 SQL 序列，宿主只使用通用初始化入口，不引入具体业务依赖。
- Agent 的附加建表和为旧版本回退保留的版本号收敛为单份当前结构，版本及结构标识一并校验。失败拒绝不改动原有账本。
- 清理内部旧页面地址重写、监控上传的旧面板回退和根据旧节点推断插件启用的逻辑；旧开发数据库与改名前页面地址明确拒绝。业务必需的云提供方响应格式、订阅标准和跨操作系统支持不是旧 APSP 兼容，不按名称机械删除。外部系统导入与服务器间业务迁移按现有功能处理，不自动运行。
- 历史升级测试改为当前基线、重启、约束、事务回滚及旧库拒绝测试。保留当前业务和账本测试，不把删除升级测试当作验证通过。更新安装、开发、恢复和备份文档，明确旧开发数据不再自动升级。
- 本轮在 main 完成一个整体提交；全部实现、界面、测试源码与文档完成后再集中验证。真实服务、数据、凭据和已发布制品不作修改，CI 暂停安排保持。

本决策覆盖此前 ADR 与协作规则中为旧 APSP 开发版本保留数据库升级、旧地址、旧消息或自动迁移的规定。历史文档仅记录当时决策；当前支持边界以本 ADR 为准。
