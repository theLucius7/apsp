# ADR 0103：中国可达性监控

- 状态：已接受。源码与本地测试完成；真实 Globalping 调用和生产运行未在开发中执行。
- 日期：2026-11-01。
- 关联：[功能地图](../product-map.md)、[ADR 0087](0087-narrow-positioning-proxy-network.md)、[ADR 0023](0023-proxy-business-boundary.md)、[ADR 0085](0085-rearchitecture-plugins-sources-chains.md)、[监控文档](../monitoring.md#中国可达性)。

## 背景

面板的健康检查都从中国大陆以外发起，节点被封锁时仍然显示“健康”。2026-10-31 的一次手工检查中，17 个公开节点里有 8 个从中国无法连接，而 26 个节点里有 25 个从德国用真实客户端可以正常使用。监控需要自动区分“被封锁”和“服务故障”。

## 决定

**数据来源是 Globalping REST。** 使用 `POST /v1/measurements` 的 TCP ping、`GET /v1/measurements/{id}` 轮询和 `GET /v1/limits`。这是已有 HTTP 客户端可以完成的调用，不新增依赖。

**默认关闭，由所有者明确开启。** 开启后节点的 IP 和端口会发给第三方，设置说明写明这一点。域名先在面板解析，只提交结果。客户端接口的目标类型是 IP，主机名无法被提交。私有和保留地址不外发。隔离恢复的副本会关闭本功能并取消待发告警。

**实现位于 sing-box 插件的 `reachability` 模块。** 它判断的是节点，依赖节点与 Nexus 清单，所以不放进宿主；宿主代码未改动。

**每个端点的检测步骤：**

1. 从中国测节点端口：电信 2 个、联通 1 个、移动 1 个探测点。
2. 从海外测节点端口：欧洲 2 个探测点。
3. 只有中国全部失败且海外至少一个成功时，才依次查找 22、443、80 中海外开放的端口，然后从中国测同一端口。节点端口本身不作为对照，否则端口封锁都会被读成 IP 封锁。

**分类：**

| 状态 | 含义 |
| --- | --- |
| `reachable` | 超过一半的中国探测点连接成功，且没有运营商整体失败 |
| `partial` | 部分运营商或探测点连接成功 |
| `service_down` | 中国和海外都失败 |
| `port_blocked` | 海外通，中国节点端口失败，中国对照端口通 |
| `ip_blocked` | 海外通，中国节点端口和对照端口都失败 |
| `unconfirmed` | 海外通，中国节点端口失败，没有可用对照端口 |
| `unknown` | 探测点太少或测量失败 |
| `not_applicable` | 该端点的节点全部是 UDP 协议，TCP 检测不能说明问题 |

**防抖。** 连续两轮失败才进入封锁状态，失败类型可以不同，以最新一次为准。一轮正常结果即解除。`unknown` 不计入失败，也不解除封锁，避免测量故障被读成恢复。

**额度。** 每个探测点算一次测试。开始前读取 `/v1/limits`，已用量（含同一 IP 上的其他用途）与本轮用量合计不超过上限的 80%。名单按最久未检查排序，只放行前面放得下的目标；上轮失败的目标同时预留对照所需的额度。其余目标顺延到额度窗口重置后，不算失败。读不到额度时不发送任何测量。运行中收到 429 时停止后续发送。同时最多测量 4 个目标。

**存储。** 迁移 `0079_china_reachability` 保存设置、每个端点的当前状态、历史（30 天）、事件（90 天）和投递记录。节点与端点在读取时按主机和端口匹配。API 令牌保存在凭据中心，用途为 `external-api`，只写不回显。

**告警。** 使用费用提醒已采用的插件通知路径：插件表保存事件和逐渠道投递，通过宿主渠道渲染和发送，并遵守维护窗口。未配置渠道时事件仍会记录。消息不含 IP。

**接口只开放给所有者会话。** 页面显示节点地址和已导入的 Nexus 清单，还能决定是否外发地址，因此沿用 Nexus 清单的边界。修改设置是高风险操作，需要再次验证。会员、门户和订阅响应不包含本功能的任何内容。

**对外函数。** `reachability::latest_node_state` 按原生节点或 Nexus 节点返回最新状态，供接管流程以后作为门禁使用。调用方需要自行判断 `checked_at` 是否过旧。

**REALITY 风险提示。** 公开端口不是 443，或目标、SNI 以 `.ru`、`.ir`、`.cn` 结尾或包含 `apple`、`icloud`、`microsoft` 时显示警告，对应 Xray-core v26.10.31 的 REALITY 配置警告。只提醒，不阻止。Nexus 节点只读取明文展示摘要，不解密归档，摘要里没有 SNI 时不显示该项。

## 替代方案

- **把探针放在中国大陆的自有机器上：** 结果更可控，但需要用户拥有并维护三网机器。
- **把事件写入 `server_alert_events`：** 能显示在「告警事件」页，但需要修改宿主的分类约束和评估逻辑，而且该评估会关闭未登记的事件。费用提醒已有不改宿主的路径。
- **用真实客户端握手检测：** 能发现协议层封锁，但 Globalping 不提供这种能力。

## 后果与限制

- TCP 连接成功不代表协议可用，基于流量特征的封锁可能仍显示 `reachable`。
- UDP 节点（Hysteria2、TUIC 等）不被检测，页面显示“不适用”。
- 主机名解析到多个地址时只测一个，优先 IPv4。中国探测点很少有 IPv6，IPv6 目标更容易得到 `unknown`。
- 对照端口可能被单独封锁，`ip_blocked` 是基于一个端口的推断，不是证明。
- 匿名额度下每小时最多 200 次测试，节点较多时实际间隔会长于设置值。
- 探测点数量和网络名称由第三方决定。非中国大陆的探测点不计入结果。
