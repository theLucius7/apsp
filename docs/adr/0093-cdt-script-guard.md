# ADR 0093：原 CDT 脚本行为的原生守护模式

日期：2026-10-24。用户明确要求先按合适架构补齐原有两个 CDT 脚本的行为，再迁移线上任务。

## 决策

在阿里云插件 `power` 中增加可选的 `cdt_guard` 策略和资源月度状态，复用现有启停队列、账号串行锁、云端状态核对及管理员权限。保持宿主和 Agent 边界，不引入 Python 运行时依赖或新的 Rust 依赖。

ADR 0057–0058 的账单策略和兼容读数展示保持不变。新模式由用户明确选择，允许使用原脚本的完整 BGP 额度池读数，配合月度最高值、观察月度重置、最大突增缓冲和两分钟新鲜度检查，驱动 ECS 启停。这是迁移原脚本的受限扩展，不把没有账期的兼容读数宣称为可信实时账单，也不将它接入自动变更带宽或计费方式。

一个资源只启用一种自动启停模式。未确认的启停任务阻止新任务。停止策略、手动暂停、修订号变化及失效读数在云请求发送前再次检查；月度状态先于云写入持久化。启停结果不明时沿用既有只读回机制。

迁移通过管理 API 完成，云密钥存入现有加密凭据中心。导入仅允许暂停策略且没有未结束的云操作；原有账号、地域、资源身份、账期和时间须匹配。同月历史取最大值，导入历史不能充当最新观测。上线先验证读数，之后取得旧脚本锁、停止两个旧 cron、导入最终状态再启用 APSP。

保留原脚本、配置和回滚材料；回滚必须将较新的保护状态带回旧脚本。功能验证不以真实开停机作为测试，生产切换属于本轮用户授权的实际迁移。CI 仍暂停。

详细行为与操作步骤见 [CDT 脚本迁移](../cdt-script-migration.md)。

## 2026-10-28：最小权限调整

根据用户要求，守护改用单实例启停 API，账号的余额与账单查询分别显式启用。零用量不再调用额外的开通产品接口；持久化可信非零 API 观测证据后，允许同一凭据与实例的完整零读数继续参与月度重置。首次零、空响应和仅导入的历史均不授权开机。此变更替代上文批量 API 和零用量产品查询决策；持久化任务、未知结果只读核对及保守月界保护保持，配置与升级步骤见 [RAM 最小权限](../alicloud-ram.md)。
