# ADR 0100：成员门户的线路目录与探针

## 背景

Nexus 成员登录后，「节点」页展示线路图谱，内容包括：

- 每条线路的入口与落地地区；
- 线路类型（直连、转发、智能分流、住宅宽带、动态家宽）；
- 在线状态与倍率；
- 广东三网延迟；
- 直连入口的 ASN 与运营商。

用户要求迁移到 apsp 后，代理用户登录门户也能查看线路及其展示，并提供探针面板，显示 IP 质量、家宽、ASN 等属性。此前 apsp 门户只有订阅、用量、成员服务和 Passkey。产品地图把公开探针和地图展示列为非目标。

## 决定

**门户新增「线路与探针」面板。** 面板位于订阅之后、成员服务之前，读取 `GET /api/plugins/sing-box/portal/{account}/lines`。接口只接受该账户自己的成员会话，与门户其他接口使用同一套账户锁和会话校验。

**线路来自已导入的 Nexus 节点目录，只列出可见节点。** 拓扑规则移植自 Nexus 的 `NexusNodeTopology`，按以下标签与名称推断入口、落地和线路类型：

- `geo:`、`provider:`；
- `residential`、`dynamic-residential`；
- `relay`、`via-node:`；
- `ai-split`、`taiwan-ai-egress`、`apple-news-us-egress`；
- 旗帜和关键词。

共享入口推断只采信有状态来源的直连节点。推断得出的入口与目录明确标注的入口分别标识，位置只精确到国家或地区。每条线路显示以下信息：

- 协议名称、传输和安全类型，不含 SNI、密钥和 short id；
- 倍率与分时标记；
- 所属套餐，以及当前套餐是否可用；
- 状态及其来源；
- 三网延迟。

**状态来源按线路是否已接管区分。**

- **已由 apsp 接管的线路：** 以 Agent 心跳（60 秒内）和运行时健康判定。
- **仍由旧节点服务的线路：** 以旧面板状态判定。兼容桥每 30 秒导出一次，由迁移 0077 的 `singbox_nexus_node_status_exchange` 校验字段白名单、新鲜度和数量，只保存在线、检查时间、负载百分比和三网延迟。超过 300 秒未更新的状态视为未知。

兼容桥读取状态失败时不阻塞设备数限制交换，失败时也不会写入空目录。转发与分流线路在入口在线时显示「入口在线」，落地是否可用不单独确认。

**探针面板按主机汇总。** 主机以 `h1`、`h2` 这类不透明编号出现，不暴露服务器编号、名称和地址。各项数据来源如下：

- **在线状态与负载：** 优先取 apsp Agent；尚未接入 Agent 的主机取旧面板状态。
- **三网延迟：** 优先取主机自身最近 1 小时的 apsp 网络探测，按探测的 `monitor.network` 归类到电信、联通、移动；没有时取旧面板的广东三网监控。
- **网络属性：** 取面板已缓存的 IP 质量结果，不触发新的外部查询。只返回公网地址的属性，按 IPv4/IPv6 汇总，包括：
  - ASN；
  - 网络组织与 ISP；
  - 国家；
  - 用途、连接与 ASN 类型；
  - 风险布尔值与评分。

城市、时区、经纬度和地址本身均不返回。尚未接入 Agent 的主机显示「尚未测量」。

**家宽来自运营方声明。** 家宽属性来自目录标签或线路名称，界面标注“运营方声明，非测量结果”；测得的用途类型和风险标记单独显示。转发线路的落地网络未经面板测量，探针中的数据只代表其前置入口。

**不做地图，也不做公开探针页。** Nexus 的世界地图图谱改为跳点链：你的设备 → 前置入口 → 落地出口，符合产品地图的非目标。面板只对已登录成员开放。

## 取舍

- 旧面板状态经兼容桥中转，最多滞后约 30 秒再加一个桥周期。
- 接管前的主机没有 Agent，提供不了 IP 质量，随接管进度逐台补齐。
- apsp 原生节点与链路（非 Nexus 导入）本轮不进入成员目录，见 [待决问题](../open-questions.md)。
- 门户每 60 秒刷新一次。接口先在一个事务内读取目录、状态和探测，提交后再读取 IP 质量缓存，不访问外部服务。
