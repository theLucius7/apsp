# ADR 0043：运行时状态、脱敏日志与明确运维操作

状态：源码实现；本地验证见独立验收记录；未授权生产迁移、发布或部署。

## 问题

节点配置部署已有自动对账与失败回滚，但管理员缺少明确的状态、日志、重启和失败部署重试入口。不能为此要求启用任意远程命令，也不能绕过原有验签、健康检查、计量采样、事务恢复和服务器退役。

## 决策

1. `protocol/runtime_operations.rs` 定义通用 `inspect`、`restart`、`retry_deployment` 及 `runtime:operations:v1` 能力。旧 Agent 不声明能力时禁用入口，消息版本保持兼容。模块名称只能选择已注册适配器；请求不包含命令、文件路径、服务名或日志过滤表达式。
2. sing-box 管理接口位于 `plugins/singbox/panel/runtime_operations.rs`；通用设备队列及结果接口位于面板公共服务。管理员请求通过服务器行锁、插件启用、在线状态、退役状态、当前目标版本和唯一活动操作校验。修改性操作在发布待合并时拒绝；失败重试只针对最近失败的当前目标。
3. 请求保存至 PostgreSQL，Agent 每五秒领取。读取与修改均在原对账 worker 串行执行，持退役读锁与模块操作锁。修改前重新读取当前 manifest；版本改变拒绝，重启还验证 manifest 制品身份与已应用配置摘要、内核版本完全一致。
4. 明确重启复用配置应用事务：验证本地签名制品、重新执行适配器 prepare、采集末次计数器、持久化 intent、切换/启动、开启计数器 epoch、健康检查；失败使用原回滚与恢复逻辑。epoch 仅表示运行时计数器重置。失败部署重试重新进入原 reconcile，不指定任意旧版或跳过验证。
5. Agent 在 SQLite 保存操作身份和执行前记录；完成结果先落盘，再上传。结果上传失败可重发，即使面板已接收结果并从待办移除，也先重放本地未确认结果；重启后仅有执行前记录的请求报告“中断”，不再次执行操作。采集及完成时间采用面板校正时钟，并保留请求、采集事件的时间下界，避免秒级舍入使有效结果永久无法确认；配置版本与摘要校验不变。原部署 intent 仍先执行恢复。面板终态不可改写，活动操作不会因网页超时被当作已结束。
6. 服务日志经 `ServiceManager` 和 `Privileged` 固定命令读取。systemd 使用单位限定的最近一小时 journal、逆序最新 100 条；OpenRC 使用既有 `/var/log/apsp/runtime.log`；launchd 使用既有固定服务日志；FreeBSD 读取有界 syslog 末尾后按确切服务 tag 筛选；Windows 读取最近一小时对应计划任务事件，并明确标记为任务事件，不能冒充运行时标准输出。后端不支持、日志不可用或命令失败时展示读取不可用。
7. 单次日志读取限制为 10 秒、64 KiB、100 条；传输仅允许时间、枚举级别与枚举事件类别，任何原始正文、控制字符、地址、令牌、配置片段和未知字段均不上传。未知日志保留“正文已隐藏”的计数位置。此选择牺牲远程排错细节，避免仅替换已知秘密却遗漏新协议凭据；完整日志由管理员在本机查阅。操作记录与服务日志分别展示。
8. 请求十分钟内可开始；同服务器十秒内不能连续创建新请求。面板保存最近 100 条完成记录、界面展示最近 20 条；Agent 最多缓存 64 条未过期/未确认记录。尚未得到设备结果的请求保持互斥，离线和中断不会伪造成功。

## 未采用的方案

- 通过远程 shell 执行 `systemctl`、`journalctl`：权限过宽且依赖本机任意命令开关。
- 直接调用 restart 而不保存部署 intent：无法保持计量末次采样、失败恢复与进程中断后的可信状态。
- 仅显示固定操作日志：无法满足读取实际服务日志的需求。
- 直接回传完整日志并按关键词打码：无法证明未知配置字段或下一种协议的秘密不会泄漏。
