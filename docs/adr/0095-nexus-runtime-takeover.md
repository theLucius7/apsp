# ADR 0095：保留客户端身份的 Nexus 运行接管

用户要求将实际节点服务迁到 apsp Agent，包括重写 Shadowsocks 配置，并继续使用原订阅和客户端。库存导入不能视为完成接管。

## 配置与发布

以物理主机为最小切换单元，必须包含该主机所有原节点。sing-box 插件把经过核对的单节点原生配置保存到现有加密凭据库；宿主及 Agent core 不增加代理业务。准备阶段创建受保护的节点映射，保持插件停用。普通节点修改路径不能覆盖这些节点，避免生成新密钥或遗漏本机其他实例。

编译器保留监听、端口、Reality 密钥、短 ID、SS 服务端密钥、TLS 和出站配置，仅将用户统计名称改为 apsp 账本身份。SS 2022 用户密钥按旧 UUID 文本前 16/32 字节进行 Base64 编码，Hysteria2 沿用 UUID 密码。主机合并时为出站标签及 detour 加节点前缀，为每条路由保留原条件并加入口约束；旧 block 出口转为 reject 动作。无法无歧义合并的 DNS、全局路由或外部文件依赖直接拒绝，不省略配置或回落直连。当前支持 VLESS Reality、SS 2022 AES 和 Hysteria2；分时倍率需单独迁移后才能接管。

准备、导出候选、启动接管、暂停和撤销准备分别为操作。撤销只适用于从未启动、也从未生成部署的准备：删除受保护节点映射并停用加密快照，使修正后的快照可以重新准备；启动过的主机保留发布历史、流量和密钥，只能暂停。启动要求在线的 0.3.1 或更新 Agent、独立验签能力、已验签运行时、健康兼容桥，以及与当前授权完全一致的候选摘要；主机有设定设备数限制的成员时，另需会话控制能力与兼容桥同步的限制（见 ADR 0098）。操作者先在节点核验正式制品和候选，备份并停用旧发布器，提交两分钟内的停用记录。该记录是操作者的切换证据，不冒充面板独立探测；面板只在设备应用健康回执后显示“已接管”。安装仍从 GitHub 下载并独立验签，不改旧 Release 的签名或身份。

## 授权与计量

迁移期权限根据 apsp 套餐到原权限组的映射动态计算，用户使用原 UUID。迁移节点不能加入策略组或直接授权：这两条路径会为用户生成新 UUID 与新密钥，接口直接拒绝并提示修改套餐与原权限组映射。授权摘要变化触发重新发布，包括资格仍有效但权限组发生变化的情况。移除最后一个 SS 用户时移除监听，避免空多用户列表被解释为单用户服务。

Agent 原始流量进入原不可变账本，同一事务生成带原倍率的持久投递记录。兼容桥在 SQLite 写事务内更新当前账期流量和唯一回执，提交后再确认 PostgreSQL 投递。确认丢失可以重试，重复记录不会再次扣量；跨重置边界的区间按当前账期重叠比例计入，完整原始记录仍保留在 apsp。旧节点仍走旧计量，已接管节点只走 Agent，不能让两个发布器同时管理同一监听。

原订阅后端继续提供既有路径、令牌及格式，权限和当前用量继续通过兼容桥更新。因此切换节点运行所有权不要求客户重新订阅。最后一个节点切换后，订阅后端和账期调度仍是需要单独替换的兼容组件，不能提前关闭。

## 回退与限制

失败先停用 apsp 运行时和 Agent，投递已确认的终末流量，再暂停接管，恢复备份的旧配置和旧服务。暂停不会删除发布历史、流量、密钥或原始资料。不得在 apsp 仍运行时启动旧服务。

当前源码提供接管控制和配置重写，不等于生产节点已经切换。新正式签名 Agent、逐主机可达性、TLS 续期、端口跳跃、出口依赖及原客户端实测均须有对应证据。GitHub Actions 暂停期间不触发发布流程，也不能用测试签名绕过生产信任根。
