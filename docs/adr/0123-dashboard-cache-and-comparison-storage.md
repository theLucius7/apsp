# ADR 0123：看板缓存一致性与分钟对比存储

日期：2026-11-07。用户要求参考本地 NodeFlare 最近修复及数据库测试看板，随后授权优化。

## 决策

- 看板轮询在请求完成时合并一次快照；页面与内存缓存保存相同的数据及更新时间。合并和缓存写入均不放入 React 状态 updater，避免严格模式重复调用副作用。读取被拒绝时清除对应缓存，退出登录继续清除整个会话缓存。
- 数据库优化保留两种当前业务语义：`telemetry_history` 用于均值、范围和缺测聚合，`metrics_minutely` 用于每分钟最后一次实际观测的对比。直接把后者改读均值会改变结果，不能把它当作等价优化。
- 分钟对比只保存接口支持的七项非负数值：CPU、内存、磁盘、负载、交换区和 TCP/UDP 连接数。字段允许清单由读取验证与写入投影共享，缺项仍为未知，整数保持原始精度；进程、网卡、清单等完整 JSON 不再重复写入这个投影。
- 实时最新值、原始样本、去重摘要、历史聚合与网络账本保持原有存储和事务语义。已有分钟记录随当前保留期限正常过期，不执行一次性清空或历史重写。
- 本次不修改 PostgreSQL 或 SQLite 基线，不新增迁移、依赖、共享跨权限缓存或实时推送协议。额外刷新优化需先有真实规模的性能证据。

## 验证要求

浏览器覆盖乱序响应后离开并返回页面、新请求尚未完成时仍保留新指标；同时复验隐藏节点、公开范围变化、拒绝访问、金额和窄屏布局。数据库测试覆盖完整原始值保留、分钟投影大小、最后样本与均值区别、乱序及重放、未知与真零值和大整数精度。生产部署与远端 CI 不属于本次本地验证。
