# ADR 0087：收窄定位为代理网络控制平面：功能分级、用户门户与费用续费账本

- 状态：已接受（定位、分级规则与文档）。界面调整、默认关闭和账本实现按[路线图](../roadmap.md)分阶段实施，本 ADR 落地时尚未实施。
- 日期：2026-10-24。
- 关联：[功能地图](../product-map.md)、[ADR 0086](0086-product-map-and-navigation.md)、[原始 MVP 任务](../requirements.md)、[ADR 0023](0023-proxy-business-boundary.md)、[ADR 0077](0077-fleet-operations.md)–[ADR 0082](0082-control-center.md)。

## 背景

项目在 2026-09-30 以“自托管的服务器与代理网络控制平面”起步。原始任务只有一条验收链路：接入服务器、创建节点、授权用户、得到订阅、看到逐用户流量，并且重启后流量不重复、不丢失。核心设计是声明式全量快照、Agent 对账、独立运行的 sing-box 和只计一次的流量账本；链路、转发、DDNS、WebSSH、防火墙等都在“不做”清单中。

随后三天（10-01 至 10-03）提交了 819 次，“不做”清单几乎全部被后续授权推翻：先后对齐 NodeFlare 的监控、对照 X-UI / S-UI 的节点功能、参考 CDT-Monitor 与妙妙屋，并在平台扩展中一次加入 21 类运维能力。ADR 增至 87 篇，大部分能力停留在“源码已实现”，实机签收很少，只发布过 Agent 0.3.0。用户反馈使用逻辑混乱。

市场调研（见[路线图](../roadmap.md)出处）表明：通用探针已经商品化，Komari、哪吒和免费的 Cloudflare 方案占据这一市场；通用运维正在转向 SSH 工具与 AI Agent；而“多服务器 sing-box + 入口 / 中转 / 落地链路 + 逐用户精确记账 + 服务器感知”的组合没有开源项目提供。论坛中 VPS 的头号用途正是代理、中转与落地。

用户同意收窄定位，要求加入 Wallos 式的订阅费用记录与续费提醒，并希望 apsp 完全取代自己现有的 Xboard 类系统，但只作为自用的多人订阅管理，让用户自己登录查看。

## 决定

1. **定位。** apsp 是自托管的代理网络控制平面：把分散在各家的 VPS 编成一张可靠的代理网络，入口、中转、落地一处配置，节点和订阅自动下发，流量按用户精确记账，面板离线不断网。服务器监控、费用与续费、线路质量是为这张网络服务的支撑能力。
2. **功能分级。** 每项现有功能归入核心、支撑、可选插件、降级或冻结，清单见[功能地图](../product-map.md#功能分级)：
   - 核心：服务器接入与 Agent、节点与证书、链路、代理用户与自助门户、策略组与套餐、订阅与流量账本、sing-box 部署与运行时运维，以及从 Xboard 类系统迁移。
   - 支撑：看板、统计、资产与流量、告警、三网延迟、IP 质量与解锁、TCP 诊断、基础网络探测与路由追踪、系统设置与安全、面板备份恢复，以及新的费用与续费账本。
   - 可选插件：DDNS、阿里云 CDT。
   - 降级：远程命令、终端、日志与文件、运维资源视图、批量任务与自动处置、故障事件、吞吐测试与测试方案、域名 / 证书 / 端点台账、端口转发、采集迁移、NodeQuality 日常检查。
   - 冻结：系统网络参数、反向隧道、私有组网、受管防火墙、云资源与费用对照、硬件测试与 Speedtest、NodeQuality 完整验机。
3. **各级别的处理规则。** 降级功能只修缺陷和安全问题，界面标“实验”，高风险操作默认关闭并按服务器显式开启；冻结功能只修安全问题，默认关闭或隐藏。移除任何已有功能或数据需要用户单独授权；本 ADR 不删除功能、接口、数据或迁移。
4. **费用与续费账本（支撑）。** 在“总览”新增「费用与续费」入口，以 Wallos 的使用方式统一记录周期费用：
   - 项目来源：服务器（沿用资产设置的价格、周期与到期）、机场订阅来源（引用 `Subscription-Userinfo` 中的到期与流量，仅作参考）、域名，以及管理员手动添加的任意服务（如 AI 订阅）。
   - 记录：沿用运维资产档案已有的购买、续费、退款、调价与退订记录，按原币保存、按显示币种汇总；带有效期的续费更新到期日。
   - 提醒：沿用现有到期提醒与退订提醒，经 Telegram、Webhook 投递；每个项目可设提前天数。
   - 视图：月度与年度支出、即将到期列表、续费日历。
   - 运维资产档案中的“续费与年度成本”“退订提醒”并入此账本；不接入支付，不自动续费或退订。
   - 为避免与代理“订阅”混淆，界面称为“费用与续费”，其中一项称为“续费项目”。
5. **代理用户自助门户与 Xboard 迁移（核心）。** 用户希望 apsp 完全取代自己现有的 Xboard 类系统，但只保留自用的多人订阅管理。代理用户门户升为核心能力，以“熟人自用”为边界：
   - 保留并补齐：用户自行登录（现有 Passkey），查看订阅、累计与本期用量、套餐额度、到期与重置日、可用节点状态，重置自己的订阅链接，查看客户端使用说明；到期与流量将尽时提醒用户本人；管理员可发布简单公告。
   - 对应 Xboard 的概念：用户 → 代理用户，套餐 → 套餐，权限组 → 策略组，节点 → 节点与链路，流量重置 → 套餐重置周期。
   - 不做：公开注册、订单与支付、优惠券、邀请佣金、工单、知识库运营、多租户。
   - 迁移：提供从 Xboard 类数据库导入用户、套餐、到期与已用流量的工具，保留用户的代理凭据，使客户端在重新获取订阅后无需改动；是否兼容旧订阅地址待确认原系统后决定。
   - 多客户端订阅输出是完全替代的前提，见路线图待决定事项。
6. **新功能的准入。** 新功能必须直接服务节点、链路、用户与订阅，或是运营这张网络所需的服务器、线路与费用感知；否则进入路线图候选池。此规则写入 AGENTS.md。
7. **对外措辞。** 公开文案使用“代理网络”“网络连接管理”等中性措辞，与上游 sing-box 一致。

## 不改变的内容

- 已有接口、数据库迁移、权限检查与数据全部保留；降级和冻结只影响投入方式与界面默认状态。
- 宿主、插件与组装的分层（ADR 0085），代理业务与服务器的边界（ADR 0023），Agent 下载与验签规则，诊断安全门禁和 CI 暂停安排。
- 七个功能区的导航结构（ADR 0086）。侧栏顺序与“实验”标记的调整属于路线图阶段 1。

## 替代方案

- **保持全能多机控制台：** 每个方向都与最好的单项工具正面竞争，开发和验收资源分散，也与“安全、最小权限”的卖点冲突。
- **转为纯探针与资产面板：** 放弃项目最难复制的部分，在一个已经商品化、有免费方案的市场里竞争。
- **拆成两个产品（探针与代理网络）：** 维护两套发布与文档，用户仍需拼装；服务器感知对代理网络本身就是必需的。
- **把订阅费用记录交给 Wallos：** 用户仍需在两个系统里维护同一批服务器，且无法复用 apsp 已有的到期提醒、汇率与资产数据。

## 后果

- 平台扩展中授权的部分方向不再获得新投入；文档按新分级描述，原授权和实现记录保留。
- 路线图改为围绕代理网络：核心旅程签收、多客户端订阅、代理用户门户与 Xboard 迁移、中转规则、线路质量中心、费用与续费账本、AI 可调用接口。
