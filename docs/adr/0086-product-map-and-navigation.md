# ADR 0086：产品定位、功能分区与管理界面导航

- 状态：已实现；本地构建、单元测试和受影响的浏览器回归见 [PROGRESS](../../PROGRESS.md) 本轮记录，未在真实设备或生产面板上验收。
- 日期：2026-10-24。
- 取代：[ADR 0084](0084-admin-layout-and-node-sections.md) 决定 1 中的五组导航；该 ADR 的其余决定（窄屏菜单、对话框挂载、节点页分区、同轮发布、按页拆分代码、离线时间）继续有效。
- 后续：产品定位由 [ADR 0087](0087-narrow-positioning-proxy-network.md) 收窄为代理网络控制平面；本 ADR 的七个功能区与导航结构继续有效。
- 关联：[功能地图](../product-map.md)、[ADR 0023](0023-proxy-business-boundary.md)、[ADR 0077](0077-fleet-operations.md)–[ADR 0082](0082-control-center.md)。

## 背景

用户反馈项目“使用起来逻辑混乱，拆分不好”，要求规范项目、拆分并分类功能、划分边界、明确定位并重写文案。

ADR 0084 把导航分为五组。2026-10-03 平台扩展新增的五个工作区直接塞进原有分组，核实后的问题如下：

- “服务器”组有六个入口，其中「接入与日常运维」「网络与验机」「网络与证书」「批量运维与恢复」名称相近、彼此重叠；网络功能与服务器管理混在一起。
- “系统”组的「看板与通知」同时管理公开看板、显示币种、历史保存、通知开关、阈值、Telegram、Webhook 和资源规则；「告警通知」只是事件列表。要配置告警的人很难想到去“看板”设置里找。
- 入口与分组同名（“服务器 / 服务器”“代理服务 / 代理服务”），面包屑没有信息量；“统计仪表盘”和“服务器看板”都叫 dashboard。
- 「服务器插件」和「插件目录」是两个侧栏入口，其实是同一件事的两个视角。DDNS 按实现方式放在“扩展插件”，而用户是为了 DNS 才使用它。
- 服务器详情的分页把四个跨服务器工作区排在本机内容前面；概况页从指标一路堆到资产、Agent 设置、拨测、远程命令和 sing-box 运维，需要长距离滚动。
- `web/src/pages/` 混放 41 个服务器、监控、诊断、系统和插件页面，与其他按功能建目录的代码不一致。
- 根 README 按功能罗列，没有说明产品是什么、给谁用、不做什么。

## 决定

1. **写下定位与边界。** 新增[功能地图](../product-map.md)，说明一句话定位、适用对象、不做什么、五个核心概念、七个功能区、归类规则和界面用语，作为界面、文档和后续新增功能的归属依据。
2. **导航按任务分为七组，共 20 个入口。**
   - 总览：服务器看板、统计报表。
   - 服务器：服务器列表、运维工具、自动化与恢复。
   - 监控告警：告警事件、延迟检测、告警设置。
   - 网络：网络检测、网络配置、动态域名解析。
   - 代理服务：服务概览、代理节点、代理用户、策略与套餐。
   - 扩展：插件中心、阿里云 CDT。
   - 系统：面板设置、管理与安全、账号安全。

   入口名不与分组同名；页面标题与入口名一致，眉题使用分组名。侧栏补充图标，便于扫视。

   2026-10-24 修订（界面第五轮，路线图工作包 0.2 的侧栏部分）：代理服务移到第一组，组内按任务先后排列为服务概览、代理节点、代理用户、策略与套餐，其后是后来加入的成员运营；服务器、总览、监控告警、网络、扩展与系统依次作为支撑入口。地址不变，登录后的默认首页仍待决定 D6。
3. **旧地址全部保留。** 已发布的 Hash 路径和含义不变：后端全局搜索、书签和文档都依赖它们。只新增 `/#/monitoring/settings`（告警设置）和服务器分页 `/assets`、`/agent`。`/#/system/plugins` 在侧栏中归入「插件中心」，与 `/#/plugins/catalog` 共用一组页内分页。
4. **拆分设置。** 原「看板与通知」拆为「面板设置」（公开看板、币种与汇率、监控历史保存）和「告警设置」（通知开关、各类阈值、资源规则、Telegram、Webhook、渠道状态）。两页共用 `/api/settings`；接口要求提交完整开关集合，所以每页保存前重新读取最新记录，只改本页显示的字段。后端接口不变。
5. **服务器详情按本机内容分页。** 概况、资产与流量、Agent 与任务、插件、IP 信息、节点验机、TCP 诊断。跨服务器工作区移到分页下方的“带此服务器打开”，仍高亮各自的侧栏入口。sing-box 的配置部署、运行时运维和部署历史移到「插件」分页，与启用状态放在一起；同一分页不重复显示安装状态和启用来源。切换分页不重新挂载服务器读取。
6. **前端目录对应功能区。** `pages/` 拆入 `servers/`、`server-diagnostics/`、`monitoring/`、`system/`、`statistics/` 和 `plugins/`，用脚本改写相对导入；样式仍按原层叠顺序由 `app/page-styles.ts` 静态引入。
7. **统一文案。** 每页说明先讲“在这里做什么”，再补最重要的限制；更新英文词典、权限功能名称（如“检测验机”改为“网络检测”）、跨页提示中对旧页面名的引用，以及首次接入后的下一步提示。修正运维工具中指向不存在路由 `/#/control-center` 的链接。
8. **文档按同样的分区组织。** 根 README 改为定位、适用对象、功能区和边界；文档导航按七个功能区排列；现行使用文档改用新入口名称。验收记录、旧 ADR 和 PROGRESS 历史条目保留当时的名称，不追溯修改。

## 不改变的内容

- 后端接口、权限检查、数据库迁移和插件分层。侧栏可见性仍按原规则：未声明功能权限的入口只对所有者显示，跨服务器聚合入口需要全服务器授权。
- 代理业务与服务器的边界（ADR 0023）、Agent 下载与验签规则、诊断安全门禁和 CI 暂停安排。
- 公开看板的访问边界：只有明确的看板路由可以匿名访问。

## 替代方案

- **只改名，不调整分组和页面：** 改动最小，但“服务器”组仍过长，告警配置仍藏在看板设置里，用户问题没有解决。
- **把 DDNS 和阿里云都留在“扩展插件”：** 与实现方式一致，但管理员要先知道“DDNS 是插件”才能找到 DNS 功能。按任务归组更符合使用习惯；阿里云 CDT 暂无更合适的任务分组，所以留在“扩展”。
- **合并「告警事件」与「故障事件」：** 二者的数据来源、保留期和处置流程不同，合并需要改后端模型，本轮只在用语上区分。
- **改用新的 URL 体系（如 `/#/monitoring/alerts`）：** 地址更整齐，但会让后端搜索结果、书签和历史文档失效，或需要维护双份路由。

## 验证

`web/tests/app-routes.test.ts` 检查七个分组、20 个入口、入口不与分组同名、服务器分页与插件中心的归属，以及旧路径和非法路径。受影响的浏览器回归同步改为新入口与分页，具体运行结果记录在 PROGRESS 本轮条目中。
