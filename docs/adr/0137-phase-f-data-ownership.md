# ADR 0137：阶段 F 的数据收尾——哪些合并、哪些保留，第一步

状态：已接受（2026-11-14）。延续 [ADR 0131](0131-one-model-per-object.md)（一类对象一套模型）与 [ADR 0133](0133-one-implementation-per-mechanism.md)–[ADR 0136](0136-server-state-and-small-mechanisms.md)；处理 [architecture.md §12](../architecture.md#12-扫描结论与余下工作2026-11-13) 中标为“阶段 F”的各项。

2026-11-14 用户：“continue，依次”（按“阶段 F 的数据收尾 → 流量服务的作业胶水 → 前端重复”的顺序继续）。

## 背景

§12 里标为阶段 F 的事项都要改数据库基线：名称的文档存放在基础网络的表里、管理员与设备会话共用一张表、`servers` 与云资源行上有其他领域写的列、六张投递表、价格与到期存了四处、六套预览存储、五份事件日志、表名与数据里的“插件”字样。逐项核对读写方与生产数据后（阶段 F 涉及的表合计不到 10 MB，五张投递表从未写入）有两点要先说清：

1. **不是每一项“合成一张”都对。** 一类对象一套模型，前提是它们确实是同一类对象。
2. **结构指纹把列的物理序号算了进去。** 删除不是最后一列的列会留下空号，生产从此对不上空库初始化的指纹；部署器用 `pg_dump` 做的结构副本还会把列号重新排满，之后每次预检都会失败。`servers` 有 69 个外键指向它，不能靠重建整表绕开。

## 决策

1. **结构指纹按未删除列中的序号计算（F0）。** 列名、类型、默认值与相对顺序照样严格核对，只是不再看物理空号；`SELECT *`、`COPY` 与 `pg_dump` 本来就只依赖相对顺序。改 `crates/panel/schema_fingerprint.sql` 与基线末尾的内嵌副本，历史接入脚本不动。
2. **设备会话单独成表（F1，资源）。** 设备会话（握手签发、1 小时、绑定服务器、退役时删除）与管理员会话（登录签发、24 小时、可撤销、再次验证引用）是两类对象；共用一张表时，每条查询都得记着按哪一列过滤，漏写一处就会把设备令牌当成管理员令牌。新表 `device_sessions(token_hash, server_id, expires_at)` 归资源，过期的设备会话由资源在自己的 30 秒维护里清理；`sessions` 只留管理员会话。表暂不改名为 `administrator_sessions`：接入与换镜像之间的几秒里旧面板仍在用旧表名，运维文档里也有按表名写的命令，改名单独做。
3. **服务权益的两份审计流水合一（F3）。** `singbox_commerce_events`（成员账号与管理员内容操作，代码只写不读、从不清理）与 `singbox_operation_events` 是同一对象，合为后者；同一事件不再有两个名字（口令登录记为带 `authentication: password` 的 `security_portal_login`）。202 行在接入脚本里逐行转换，管理员编号取自 `admin:N`、`administrator:N`，其余操作者与对象编号写进 `detail`；转换前已导出受保护的存档。这些事件从此出现在用户诊断的“操作记录”里，并受隐私保留期约束。
4. **保留，不合并。** 六套预览存储（共性只有“过期加一次确认”）、`fleet_events`、`operations_history` 与 `expense_events`（所有者、键、读者与保留期都不同）、六张投递表（每行挂在各自所有者的事件上；合成一张要么违反“每表一个所有者”，要么把认领条件改成回调并放弃外键级联，而生产一行都没有——可选做法是统一状态列与标准列）。
5. **余下的顺序。** 观测写在 `servers` 上的列迁到观测（F4）→ 流量服务写在 `servers` 上的列迁到流量服务、`server_plugins` 改名为 `runtime_enablements`（F5，发布锁不再压在服务器行上）→ 云账号与云资源上的成本列（F6）→ 作业列（F7，CDT 关机守护，避开月初翻月与接近阈值的时候）。每步一个 PR、一个接入脚本，前一步部署完成后下一步再变基。名称的文档暂缓搬表（实验功能、0 行），先改为经基础网络的函数写入；`diagnostic_jobs.job` 里的 `plugin` 键随 Agent 协议改名；资产重复（`fleet_profiles.asset`、云链接的采购字段）合并前要先由用户决定未关联服务器的云资源是否保留采购金额与到期。
6. **接入脚本的写法。** 部署器在旧面板仍运行时执行接入脚本，之后不回滚。所以每个迁移脚本先显式加锁，在同一个事务里复制并删除旧结构，不分“先扩后缩”两步（旧面板会继续写旧列）；`lock_timeout` 设为 5 秒，拿不到锁时这次部署失败，下一分钟重试。
