# ADR 0037：可复制接入入口与按服务器架构导入

- 状态：已采纳，2026-10-01。
- 用户要求：安装命令包含可直接下载执行的链接，复制到新服务器即可接入；ARM 服务器不下载 AMD 制品，修复已有制品不可用的问题。

## 接入入口

面板原来只输出 `sudo apsp-bootstrap`，但新服务器没有验证器和预置公钥；`/install.sh` 又拒绝请求。改为输出一条从固定官方 GitHub 仓库下载独立、自包含入口的命令。入口按 Git blob 身份定位，执行前核对完整 SHA-256，失败即停止。

`deploy/bootstrap.sh` 由现有发布验证工具和已批准的公开根生成。首次信任建立于官方 GitHub 的 HTTPS 来源和该入口中的固定公钥；不是从面板响应接受新的发布根。入口通过系统软件源准备 Python、minisign 和安装工具，独立验证官方 Release 的完整签名、清单及静态安装器，从 GitHub 或独立 HTTPS 镜像下载本机架构 Agent，并核对精确长度与摘要。跨平台入口与旧已签安装器兼容的受信执行器见 ADR 0041。Agent 编译根、身份、状态、缓存预检与升级回滚继续遵守 ADR 0017。

这覆盖 ADR 0017 中普通官方安装必须先手动预置 bootstrap 的流程。源码审查、自建信任域及离线部署仍可采用原来的独立预置方式。复制命令的首次信任不能抵御已控制操作者所信任的官方源码渠道的攻击；命令内的摘要也不是独立于命令来源的认证。面板仍不能提供直接执行的动态 shell，旧 `/install.sh` 返回安装描述 JSON。

生成器提供同步检查，源工具、模板或公钥改变后必须重新生成入口；不维护第二份手写验签实现。本阶段的 Linux systemd/OpenRC 验证保留；后续跨平台单行入口与 GitHub 直接 Agent 下载见 ADR 0041，不借入口实现宣称其他平台已完成安装验收。

## 按需导入与已有目录

管理员可指定平台架构；默认取已接入服务器上报的 Agent/运行时 ABI，没有可用上报时取面板宿主平台。完整发布 proof 继续验签，但只下载所选平台的兼容制品，保留旧 `amd64`/`arm64` 身份与精确 ABI 的兼容规则。

局部导入通过本地清单记录已下载的 canonical 路径。清单只选择完整签名 metadata 的合法子集，不能增加身份或绕过内容验证；本地制品列表和运行时下载只使用已公布路径；Agent 版本目录与 GitHub 更新候选使用完整签名 proof 的兼容目标，允许未缓存架构。旧完整目录无需迁移即可读取。同一发布追加架构或重试下载时先在私有 staging 验证全部待发布内容，成功后公布文件和清单；下载或签名失败保留已有集合，缺失或损坏的普通文件可通过重导入修复，软链与相同身份不同签名内容继续拒绝。

正式 Release 仍要求完整候选和全部发布校验。本地只下载所需架构不改变正式发布要求，也不允许覆写已有发布资产。

## GitHub-only 整合兼容门禁

按 ADR 0038 保留面板 Agent 下载禁用。此前仅执行已签 Release 安装器的入口要求唯一 `preloaded-github-v1` 契约，旧公开 `agent-v0.3.0` 因依赖面板而不能直接执行。ADR 0041 的独立入口仍验证旧安装器摘要，实际执行固定官方 blob 中内嵌的可信 Linux 安装器，允许安装同一完整签名 proof 中的 Agent，不修改正式发布资产。新的原生制品及旧 Agent 自动升级能力仍需独立签名发布与可信手工迁移；源码整合不等于正式签署、发布、部署或跨版本验收。

自动升级客户端必须显式请求 `download_source=github`；旧/未知/重复查询返回空候选，认证仍优先。不能只凭 Agent 版本号推定下载能力。
