# ADR 0059：管理员与代理用户 Passkey

## 背景与范围

用户授权管理员和用户使用 Passkey，并确认用户功能只适配现有代理用户。管理员继续是单一系统管理员；代理用户入口、开通和自身订阅/用量查询归属 sing-box 插件，不建立平台全局用户、公开注册或新的用户名/密码体系。

## 决策

- 使用 `webauthn-rs` 0.5.5 的高层 Passkey 注册与认证流程，要求认证器进行用户验证。协议验证不自行实现；前端使用浏览器原生 WebAuthn API，不引入前端认证 SDK。
- 必须新增该 Rust 依赖，因为现有依赖没有完整的 WebAuthn 注册、认证器数据和签名验证实现。手写协议需要承担 CBOR/COSE、来源校验及认证器兼容责任；外部身份服务会改变自托管部署和账户边界，均不采用。库依赖系统 OpenSSL，面板容器声明其构建和运行库；不影响 Agent 依赖和制品。
- 开启库的服务端状态序列化特性，仅将仪式状态存入 PostgreSQL。浏览器只持有随机挑战标识和 HttpOnly 绑定 Cookie，不接收完整验证状态。挑战五分钟到期，绑定用途、主体和浏览器，验证请求一次性消费；失败不得重放。
- RP ID 和精确 Origin 从现有 `APSP_PUBLIC_URL` 派生，不信任 Host 或转发头来扩大来源。生产使用 HTTPS 域名，本地支持 `http://localhost`；不适用的配置禁用 Passkey 并给出原因，不影响现有密码入口。
- 通用验证、凭据和挑战放在面板共用模块；管理员适配在 `auth`，代理用户业务在 `plugins/singbox/panel/`。每个主体最多十把密钥，公开列表仅含管理 ID、名称和时间，私钥永不上传。

## 管理员与用户开通

- 管理员可用已绑定 Passkey 登录，原密码/TOTP 登录保留。绑定和删除密钥要求有效管理员会话及重新验证密码、已启用的 TOTP；绑定挑战同时关联发起会话。删除密钥撤销其他管理员会话和未完成仪式。
- 代理用户由管理员生成短期、一次性开通链接。链接中的秘密只出现在 URL fragment 和提交请求中，数据库仅保存摘要；旧订阅令牌不能用于开通或恢复账户。已开通用户的重置必须明确确认，撤销原密钥、会话和开通链接。
- 用户入口使用插件内的独立账户 UUID 链接，作为可收藏的非秘密登录标识；认证只允许该账户已登记的凭据。采用标准指定账户流程，不依赖实验性无用户名发现能力。
- 代理用户会话使用独立 Cookie 与数据库表，仅允许访问自己的订阅、用量和 Passkey。增加/删除密钥要求近期 Passkey 验证；不能删除最后一把密钥而使账户无法登录。丢失全部密钥时由管理员明确重置后重新开通。
- 代理用户删除后，入口与会话立即失效。凭据更新、邀请消费、会话签发与撤销按事务串行处理；认证用途、账户或浏览器不匹配不能产生会话。

## 验证与发布

使用本地数据库和浏览器虚拟认证器验证正常注册/登录、签名与 Origin 拒绝、挑战过期及重放、会话绑定、跨账户/角色隔离、密钥撤销和邀请竞争。保留旧密码/TOTP 回归；不把虚拟认证器测试声称为真实 Touch ID、Windows Hello 或手机跨设备验收。CI 继续暂停，不进行生产迁移或部署。
