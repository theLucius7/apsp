# 执行中的问题与选择

## 2026-10-30：Clash 转换与有序来源标准化字段的兼容

- 问题：#194 的 HTTP 测试使用稀疏 JSON，但有序来源实际经过 `NormalizedOutbound` 与 `ExternalOutbound::from_normalized`，普通 HTTP 代理会带上 `path:""`、`headers:{}`；Clash 白名单不接受 `path`，导致这些节点全部被跳过，只有此类节点时订阅返回 409。HTTP/2 传输同样总是带上 `method` 与 `headers`，即使能等价表达也被直接拒绝。
- 选择：只修 Clash 转换边界。HTTP 代理允许缺省或空路径，保留原有凭据及请求头转换；自定义路径继续跳过。HTTP/2 仅接受缺省、空或 `PUT` 方法及缺省或空请求头，其他方法、自定义请求头、无 TLS 和 Trojan HTTP/2 仍跳过并说明。不开新功能、不改变来源解析、节点身份、存储格式或 sing-box 配置。
- 依据：[mihomo v1.19.29 HTTP 代理](https://github.com/MetaCubeX/mihomo/blob/v1.19.29/adapter/outbound/http.go) 使用普通 CONNECT；[H2 传输](https://github.com/MetaCubeX/mihomo/blob/v1.19.29/transport/vmess/h2.go) 固定使用 PUT，且没有自定义请求头字段；[sing-box v1.14.0 HTTP 传输](https://github.com/SagerNet/sing-box/blob/v1.14.0/transport/v2rayhttp/client.go) 在方法为空时使用 PUT。有序来源解析器填充的 GET 不能当作 PUT 静默丢弃。
- 回归通过真实 `NormalizedOutbound → ExternalOutbound → compile_clash` 路径覆盖默认字段及不能等价表达的边界。复用 #194；#190 仍为草稿，不纳入。已有验收源码摘要核对一致，修复后只补验编译器受影响范围，结果见本轮验收记录。

## 2026-10-28：Clash 订阅合并前的格式与传输边界修复

- 问题：#194 已包含当前 main，但审查发现合法外部节点的数组请求头、内置策略同名可能使整份 YAML 导入失败；Trojan HTTP/2 及无 TLS HTTP 不能沿用原有的统一 H2 映射；跳过节点名称中的 Unicode 换行会突破 YAML 注释。
- 选择：沿用同一授权快照和外部节点渲染入口，只修转换边界。请求头字符串和单元素数组转为单字符串，多值/空数组与不能等价表达的传输跳过并说明；完整避让内置策略名；注释替换控制字符及 U+2028、U+2029、U+FEFF。保留 sing-box 格式与可转换节点，不引入第三方转换服务或新依赖。
- 依据：mihomo v1.19.29 的 [WSOptions](https://github.com/MetaCubeX/mihomo/blob/v1.19.29/adapter/outbound/vmess.go)、[Trojan 传输](https://github.com/MetaCubeX/mihomo/blob/v1.19.29/adapter/outbound/trojan.go)、[内置策略](https://github.com/MetaCubeX/mihomo/blob/v1.19.29/config/config.go)，以及 [YAML 换行识别](https://github.com/yaml/go-yaml/blob/v3/yamlprivateh.go)；HTTP 的 TLS 分界与仓库现有导入器和回归保持一致。
- 回归通过 `compile_clash`、`ExternalOutbound` 和 typed normalized 输入覆盖这些边界，并扩充既有离线样例。复用 #194 集中交付，#190 保持草稿；完整验证结果见本轮验收记录。

## 2026-10-24：主线缺陷修复第 3 步的取舍

- **跨断点保留页面（E13）：** 桌面使用可调宽度的分栏组件，手机使用纵向布局，两者的 DOM 结构不同。没有把两种布局合并为同一组件树（需要在手机上隐藏分栏并改动持久化的侧栏宽度），而是让页面渲染进一个独立的宿主节点，由当前布局挂载；切换断点只移动该节点，React 不卸载页面，打开的对话框与草稿保留。
- **语言偏好（E30）：** 页头切换语言视为本次会话的选择，不写回外观偏好；已保存的语言只在读取或修改偏好时应用。需要长期改变语言时在外观设置中保存。
- **批量操作（E32、E52）：** 选择不随筛选自动扩大或缩小，但操作只作用于当前可见的已选项，并明确提示被隐藏的已选项不会被操作，避免误操作看不见的对象。

## 2026-10-24：主线缺陷修复第 2 步的取舍

- **兼容通道成员的计量（E11）：** ADR 0092 允许新成员进入兼容通道，因此不把原生会员排除出交换。改为已用流量取旧计量与原生节点在同一旧周期内用量之和：两者统计的是不同节点，相加不会重复；节点日后接管时也不丢量。倍率与单机交接检查点仍按 `docs/nexus-agent-migration.md` 另行实现。
- **已发布迁移 0065（E9）：** 迁移文件的校验和已被记录，不能修改。选择由拥有迁移序列的组装 crate 在迁移前做同样的改名（临时停用归档触发器），而不是新增插件钩子：来源迁移与接管命令在登记插件前就会打开数据库，钩子覆盖不到。
- **通知投递（E41）：** 外部发送无法与数据库事务原子提交。选择先提交租约再发送：提交失败不会重发，进程在发送后崩溃时会在租约到期后重试一次（至少一次）。不选择“先标记已发送”，因为那会在崩溃时丢失通知。
- **发布后的服务事件（E18）：** 没有记录目标修订开始等待应用的时间，使用部署记录的创建时间并给 5 分钟宽限；服务本身不健康时不等待。
- **邀请等待（E27）：** 不在邀请人被停用时自动解除，避免绕过付费邀请规则；改为管理员显式解除，并阻止只改状态造成的半启用。

## 2026-10-24：主线缺陷修复第 1 步的取舍

- **凭据引用：** 受限管理员原本可以把任意凭据编号填入 DNS 账号、ACME 计划、会员邮件、DDNS 规则或证书部署。选择只能由所有者会话完成，受限管理员保留不改引用的编辑和经已授权 DNS 账号的委托路径。没有按凭据逐项授权，因为现有凭据中心没有可委托的范围模型，新增会扩大本次修复。
- **无服务器对象：** 没有关联服务器的网络文档、只含面板来源的工作台方案、工具与目标视为全局共享：读取保持对有读取权限者可见（与全局搜索的既有用例一致），修改须全局授权。费用记录涉及全面板成本，读写都须全局授权。
- **会员找回：** 用邮箱找回已有密码会同时移除已登记的 Passkey，管理员重置 Passkey 会清除会员密码；首次设置密码不影响 Passkey。这样任一找回都会让可能泄露的另一种凭据失效，代价是成员需要重新添加 Passkey 或经邮箱验证重设密码。
- **导入成员的登录邮箱：** ADR 0092 允许导入成员沿用原邮箱密码登录，而 ADR 0091 要求密码登录使用已验证邮箱。采用迁移 0075 记录原登录邮箱，邮箱未变时视同原系统身份，改动后须验证；本次修复前已被管理员改过邮箱的导入成员无法区分，记为已知限制。

## 2026-10-01：多条链路在代理节点内创建

用户要求重新规划链路创建归属，并明确选择“统一代理节点页面，直连节点和链路并列管理”。采用代理节点页统一管理直连与链路，策略组只引用已创建资源。将“多条”解释为同一页面能创建多条独立链路，同一入口服务器上的每条链路拥有独立入口监听；不将一个入口节点绑定多个出口，以免失去确定路由和独立授权。完整页面、原子创建、幂等、生命周期与验收见 [设计方案](node-chain-design.md)。

用户进一步明确中间段可来自机场等订阅配置，采用“受管公开入口 + 有序混合代理跳”，中间/出口均可选受管或导入的具体节点，不要求机场安装 Agent，不把订阅 URL 当一跳。导入支持链接、Base64、sing-box JSON 和 Clash/Mihomo 节点 YAML；原规则、DNS、脚本及控制接口不执行。决策见 [ADR 0040](adr/0040-mixed-chains-and-subscriptions.md) 和 [来源设计](chain-subscription-sources.md)。

默认跟随同一明确节点的有效版本，另可固定快照；下载/解析失败、节点缺失或身份歧义保留已应用旧版并显示事实，不自动换节点或绕链直连。来源 URL/获取认证更换产生新身份 epoch，防止另一机场复用 ID 接替旧绑定；归档只停止刷新及新引用，明确授权撤销、链路删除及受管退役执行本地撤销。

最初交付为规划；用户本轮授权后已实现页面、接口和迁移，操作与验证边界见 [Agent 运维与混合链路](agent-runtime-and-chains.md)。旧接管版本保留原 ID、tag、凭据、授权、订阅、原生字节和历史计量；新建入口与链路事务内一起保存。一个链路的入口不会重复显示为直连，删除整个链路资源也不能自动将入口转为直连。完整路径版本冻结外部及受管端点，所有依赖按精确代数发布、探测及恢复屏障切换；资源完整、受管配置应用与实际路径验证分开，不能将 check 或配置健康当作跨机链路已连通。

## G4：接入、制品和历史记录

- 安装尚未产生设备 session，增加 `/api/bootstrap/{version}/{arch}?token=...`，只允许有效未消费注册 token 下载 Agent，下载不消费 token。运行时制品与配置包仍要求设备 Bearer 会话。
- 制品保存为 `artifacts/{agent|sing-box}/{version}/{amd64|arm64}`，每个版本目录使用 SHA256SUMS 列出架构文件哈希。面板校验文件与清单匹配才提供下载。
- 同设备升级可用新 token 再次注册同一公钥；已有服务器不允许替换成另一公钥。安装脚本先用暂存二进制完成注册，再激活版本。
- 服务器、节点和用户采用软删除，保留流量与部署历史。增加 usage_batches 表保证同一批次编号不能以不同记录集合重复入账；usage_records 仍保留规定唯一约束。
- 管理员会话 24 小时、设备会话 1 小时。管理员密码只在首次创建时生效，密码校验并发限制为 4，避免匿名请求同时分配无上限 Argon2 资源。

macOS 27 的动态库加载器暴露了 Rust/LLVM 删除调试信息后的 LINKEDIT 对齐问题。dev/test 显式设置 strip="none" 后编译通过，保留 debug=0 控制磁盘使用。参考上游问题：https://github.com/rust-lang/rust/issues/157750 。Linux 部署不依赖此工作机环境。

## G5：通用契约与运行恢复

- `Privileged`、`ServiceManager` 的 trait 定义放在 adapter-sdk，core 的 system 模块重导出并实现，避免具体适配器反向依赖 core。
- 注册身份额外持久化面板 origin，重试沿用同一设备密钥；密钥和目录在网络请求前落盘，禁止把既有身份意外注册到另一面板。
- 本地 status 返回 JSON，包含连接、模块版本、健康和待确认批次数；先占用私有 socket，再恢复状态，防止重复启动同时恢复同一意图。
- 计量序号与累计计数在 SQLite 中保存为十进制文本，支持协议的完整 u64 范围；每次采样的基准与 outbox 在同一事务提交。未知 ack 不改变账本。
- 断线只替换认证会话，对账与计量 worker 持续运行。相同已应用版本仍重新发送健康结果，修复回报丢失造成的面板状态落后。
- 制品同版本不可覆盖；缓存同时核对归档与已安装二进制的哈希。若首次安装在写入缓存元数据前中断，安全拒绝复用，需删除尚未激活的不完整版本后重试。
- 失败恢复优先重启旧版本以兼容跨内核回滚。未能读到重载前终值时取消应用；外部重载或异常终止仍可能产生无法观测的短缺失窗口，日志明确记录，已落盘批次不会丢失。

## G6：原生统计与重载边界

- 原样保留上游 proto 的 package；上游运行时实际注册服务名与 proto 不同，因此显式调用 `/v2ray.core.app.stats.command.StatsService/QueryStats`，使用 `patterns` 和 `reset=false`。
- `systemctl reload` 只保证发出 HUP。适配器在重载前建立已完成 HTTP/2 握手的统计连接，并等待该旧连接关闭，确认旧运行代已终止后才让 core 开启新计量周期；健康检查再等待新的端口和统计 API。
- 适配器支持稳定版 1.14.x，要求实际二进制版本与清单完全一致且包含统计标签。当前面板固定发布 1.14.2；没有扩展运行时版本选择界面。
- 首次成功应用或版本变化后补发静态信息，使面板及时看到运行时版本，无需等待下一次连接。

## G7：发布、已应用订阅和历史计量

- `dirty_at` 使用 PostgreSQL 时钟的 Unix 毫秒，精确等待至少五秒；模型修改与标脏在同一事务中，发布时锁定服务器，避免漏掉并发变更。启动后的发布器继续处理数据库中遗留的脏标记。
- 节点不支持迁移服务器或手动改端口；端口在锁定服务器后从默认范围取最小空位。节点私钥只保留于数据库、部署快照和设备配置包，不出现在管理列表或发布历史响应中。
- 配置包哈希相同时不创建 revision，仅刷新该版本的订阅元数据。订阅使用已应用且健康的快照，并与当前未删除授权的 UUID 取交集；撤销立即从订阅移除，重新授权要等新凭证成功应用。
- 认证心跳可修复丢失的成功回报，但只接受本服务器已发布且更高的 revision；不倒退已应用版本，不抹去最新失败目标的错误。
- 流量允许已经撤销或删除用户的历史统计名重发，前提是该身份曾为此服务器发布；整批事务提交后才确认。同一批次编号更改内容会被拒绝，记录顺序变化不影响去重。
- PostgreSQL 计量字段改用 NUMERIC(20,0) 保存协议完整 u64；汇总可超过 u64，API 使用十进制字符串传递，避免浏览器数字精度损失。

## G8：前端构建与路径权限

## Agent 能力对齐：用户确认全部补齐

- 用户确认将基础监控细节、离线遥测补报、持续拨测、通用命令、升级恢复和非 Linux 常驻部署全部纳入，覆盖原来的仅编译产物限制与自更新排除项；按 ADR 0022 分阶段实现。
- sing-box 上游支持 musl。原脚本只调用 glibc 工具链，属于本仓库缺口；新增官方 musl 工具链与标签，不删除默认功能或修改上游源码。
- 辅助 outbox 和命令表采用幂等建表，不提高账本 `user_version`，避免旧版本回退时拒绝打开数据库。压缩上传复用已有 `flate2` 依赖。
- 管理员可以拨测内网、回环和公网的单播目标；命令使用设备服务账号执行。命令执行状态在启动进程之前落盘，重启后的未完成命令统一标记中断，不重放无法确认副作用的操作。失联超过一天暂停使用缓存拨测配置。
- OpenRC 一次性诊断由同一 Agent 二进制的内部任务入口运行，在独立服务中监督；它不是对外开放的特权 helper。挂载命名空间使用系统 `unshare`，保留 Linux 专属 NodeQuality 范围。

- 原生服务采用系统内置 launchd、rc.d/daemon 和 Windows 计划任务，Agent 与运行时分开注册；Windows 不增加需要 unsafe 的服务控制器库。运行时 DLL 通过通用文件白名单描述，core 保持运行时无关。
- 自动更新只使用面板导入的稳定版，初始关闭；本地 PID/版本检查允许离线启动。Supervisor 与 Agent 同属系统服务，代理进程归另一服务；更新前的持久试运行状态用于恢复中断升级。Windows 文件内容刷盘后原子替换引用，目录元数据断电语义仍是已知验证边界。
- FreeBSD 保留代理普通账户，因此默认使用非特权节点端口；需要 443 等低端口时由管理员配置宿主端口授权。安装器不自动修改全局 sysctl 或加载端口策略模块，避免覆盖现有主机策略；详见 README 和 FreeBSD `mac_portacl(4)`。
- FreeBSD 的 sysinfo 0.33 磁盘枚举调用 `getmntinfo`，其[官方实现](https://github.com/freebsd/freebsd-src/blob/releng/15.0/lib/libc/gen/getmntinfo.c)会修改并重新分配进程全局缓冲区。连接上报和采样可能并发构造 Collector，因此以进程级互斥锁保护完整磁盘枚举及 libgeom 快照；不新增 unsafe 或修改上游依赖。CI 增加重复启动采样和可用时的原生崩溃回溯。
- Windows 新建运行时账户明确加入普通 Users 组，使用固定 SID 和本地账户对象，避免本地化名称与域同名账户歧义，依据 [Add-LocalGroupMember 文档](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.localaccounts/add-localgroupmember?view=powershell-5.1)。运行时保持非管理员；原生 CI 校验账户分组及真实任务执行。Windows ARM64 实测启动权限检查可能超过 60 秒，更新试运行给出 120 秒有界健康检查，其余平台仍为 60 秒。
- Windows runner 的任务继承 DACL 给 SYSTEM/Administrators 的掩码为 `0x1f019f`，不含文件执行位，因此 Agent 可以读写任务但无法启动运行时。注册后按 [SetSecurityDescriptor](https://learn.microsoft.com/en-us/windows/win32/taskschd/registeredtask-setsecuritydescriptor) 明确将本项目任务的控制权限限定为 SYSTEM 和 Administrators，禁止继承及自动添加运行账户控制 ACE；任务仍以原普通账户执行，不改变运行时文件权限。
- Windows ARM64 的测试日志显示升级已激活但状态保存超过夹具等待，安装也在大量权限操作期间超时。权限读写改用内置 .NET Framework 的 [File.SetAccessControl](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.setaccesscontrol?view=netframework-4.8.1) 及目录对应接口，合并同次目录创建和制品文件权限，避免反复自动加载 PowerShell 文件系统/安全模块；新文件在写入内容前设置 ACL。服务启停使用同一任务计划程序的 COM 接口，避免每次导入 CIM 模块；重启先等待旧任务停止。仍保留 ACL 拒绝检查与普通账户隔离，不添加依赖或常驻 helper。
- Windows 任务 DACL 修复后的事件确认错误 `0x80070569`：普通运行账户缺少批处理登录权。安装通过系统 [secedit](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/secedit-configure) 读取并保留现有 `SeBatchLogonRight`，只追加该专用账户 SID；不更改拒绝策略及其他用户权利。新账户先禁用，设置随机密码后再启用。CI 比较安装前后及重复安装后的全部用户权利，验证只发生预期追加。
- Windows 用户权利模板允许以账户名或带星号的 SID 表示同一主体（[MS-GPSB 2.2.6](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-gpsb/3413b381-a445-4d17-b77e-5bbfadda253b)）。重复安装识别这两种表示；原生测试统一转换为 SID 后比较，保留全量权限差异断言与失败详情，避免仅按原始文本误报。

## 磁盘容量：容器挂载与文件系统去重

- 磁盘总量沿用已挂载文件系统的容量口径，不改为裸块设备标称容量；已用空间仍为 `total_space - available_space`，包含普通进程不可用的保留空间，与 `df` 的 Used 列可能不同。Unix 的静态总量、动态已用和逐盘列表共用一次筛选后的快照，读取失败、容量无效或溢出继续表示未知。
- [sysinfo 0.33.1 的 Linux 枚举](https://github.com/GuillaumeGomez/sysinfo/blob/v0.33.1/src/unix/linux/disk.rs)会返回 overlay 与单文件绑定挂载；原来仅按名称累加时，真实分区与名为 overlay 的视图各计一次。按[内核 overlayfs 语义](https://docs.kernel.org/filesystems/overlayfs.html)，Linux 排除非根 overlay/overlayfs/fuse.overlayfs 与单文件挂载；容器中的 `/` overlay 保留。
- Unix 使用挂载点的设备标识去重绑定挂载与设备别名，优先保留根及较浅挂载；元数据不可读时回退设备名，无名时回退挂载路径。Btrfs [子卷共享文件系统存储](https://btrfs.readthedocs.io/en/latest/Subvolumes.html)，继续按可解析的源设备名称去重，不因子卷设备标识不同重复累加；I/O 基线同时使用名称与挂载点。
- Windows 保留原 sysinfo 逐盘列表与按名称首条去重的总量规则。[固定 sysinfo 的 Windows 枚举](https://github.com/GuillaumeGomez/sysinfo/blob/v0.33.1/src/windows/disk.rs)会为同一卷的每个挂载路径生成一条记录，因此不能仅凭路径将它们计为独立容量。不同卷标签相同或为空仍有既有歧义，须在取得真实卷 ID 后另行实现和原生验收；本项不声称修复该歧义、不新增 unsafe、依赖或外部命令。容量无效、溢出和首条记录的未知语义保留。
- 不根据相等容量猜测两个文件系统是否同盘；容器内无法访问 overlay 后端时，也不推断它与额外目录卷的物理归属。此项修复不提供跨命名空间或所有存储池的物理容量映射。


## 交付加固：签名缓存的跨平台验证边界

- 生产信任根仅来自编译时 `APSP_RELEASE_PUBLIC_KEYS`；Rust 库显式 `with_trusted_keys` 接口用于受信 embedding 与测试，Agent 命令行没有运行时换根开关。测试公钥及确定性公开测试私钥均明确标记为 TEST_ONLY，正式发布工具按真实公钥字节拒绝这些根。

## 签名与多平台整合后的 CI 修复

- Windows 的文本模式写入会将 LF 转成 CRLF，使安装到磁盘的签名证明不再符合 canonical 格式。夹具、清单及固定安装器都按 UTF-8 原始字节写入；不让验证器替换换行或放宽签名检查。回归在 Linux 模拟 Windows 文本模式，并使用独立 minisign 验证正确证明及拒绝篡改。
- 当前 cryptography 50.0.2 的发布文件没有 Windows ARM64 wheel，直接 pip 安装会进入本机构建。原生 CI 改用 `apsp-protocol` 已有的 ed25519-dalek/blake2 测试签名实现，编译独立 example；仅内嵌公开 TEST_ONLY 密钥，只接受有界 stdin，不接受密钥参数。合并上游 `541f52d` 后统一使用其 `ci-fixture-sign` 和 `APSP_CI_FIXTURE_SIGNER`，同时覆盖 macOS 与 Windows；未增加生产依赖，也不向 CI 提供正式私钥。
- BusyBox `install -d` 会让隐式父目录受 `umask 027` 影响。安装器显式创建共享的 `/opt/apsp`、`/opt/apsp/plugins` 和 `/var/lib/apsp` 为 0755，保证独立普通运行账户可遍历；身份和 core 账本仍为 0700，运行时私有配置仍按专用组限制。隔离 Alpine 实际启动验证保留，不通过把运行时改为 root 绕过权限问题。
- 静态 musl Agent 可以运行在 glibc 主机上，编译 ABI 不能兼作外部运行时的 libc。保留 `libc` 的 Agent 更新语义，新增可选 `runtime_libc`；在 core 读取系统程序有界 ELF64 头中的 `PT_INTERP` 判断 GNU/musl，不执行额外工具、不依赖 init 类型、不新增依赖。面板与 core 的签名缓存选择使用宿主信息，旧协议字段缺失仍兼容。解析参考 [ELF Header](https://refspecs.linuxfoundation.org/elf/gabi4+/ch4.eheader.html) 与 [Program Header](https://refspecs.linuxfoundation.org/elf/gabi4+/ch5.pheader.html)；无法识别时保留编译 ABI 回退，不将未知 libc 任意映射到 GNU。
- 合入上游 `13f2975` 后统一使用其 `runtime_platform` 实现，移除重复解析与选择逻辑。GNU 宿主上的静态 Agent 保留已有 musl、旧目录、GNU 运行时的优先级，以避免同一已签证明包含多个平台时改变现有不可变缓存的选择；Agent 自更新仍按编译 ABI。
- 上游把扩展平台检查改为手动；按本次此前的多平台自动构建要求，`CI` 继续在 push/PR 构建全部平台，OpenRC 保留在 Linux musl 任务内。上游的独立手动平台工作流保留，便于按需复验。
- macOS 的软链接继承进程 umask，`readlink` 又检查链接自身的读取权限；launchd 的 `umask 027` 因此会阻止普通运行账户解析 root 创建的 `current`。依据 [Apple XNU 的 symlink/readlink 实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/vfs/vfs_syscalls.c)，在 `SystemOps::atomic_symlink` 发布前使用 `chmod -h 755` 设置临时链接自身权限；不改变目标文件、私有目录权限或整个进程的 umask。仍保留签名、路径边界、摘要与离线缓存复验，并在 macOS CI 用 `umask 077` 检查链接可读、目标权限不变及悬空链接替换。

## 2026-10-01：策略组与套餐组的分配语义

本轮按用户新增要求扩展 sing-box 插件，不恢复已删除的平台全局代理用户模型。策略组定义可使用的普通节点及两跳链路；多个组与旧单独授权取并集，避免取消一个来源误撤其他来源的权限。套餐组是独立模板，每个用户保留一个当前快照，模板编辑不追溯改变已分配用户。详见 [ADR 0035](adr/0035-singbox-policy-package-groups.md) 和 [操作/API 说明](singbox-groups.md)。

用户未指定首月折算、结转和续期累加，本轮选择完整月度额度、无结转、从分配时刻起计算有效天数。更换套餐不删除流水，按新模板的周期边界统计已有流量；界面明确提示期限是重新起算而非在旧到期日累加。没有套餐的旧用户和新用户保留不限制流量与有效期的兼容模式，必须明确分配套餐才能启用限制。

用户要求策略组包含链路，因此补齐可执行的原生两跳配置，而不是只保存没有运行时效果的链路编号。暂不支持任意多跳、同机链路或入口直接授权；链路内部凭据不进入订阅，用户流量只在入口计量。跨月采样批次完整归入排他结束时刻前一秒的月份，不按时间比例猜测字节分布。配额/到期通过订阅资格和运行时整包发布共同执行，离线与尚未上报的流量仍存在滞后，不能承诺立即断流。生产双机、长连接及离线恢复验收另行执行，本 PR 不部署。

## 2026-10-03：重新架构阶段二的范围调整

- 用户确认先做 ADR 0085 的阶段一、二。阶段二原计划同时合并订阅抓取和解析，并用逐字节对照保证已存外部节点不生成新版本。
- 实施前逐项核对两套解析器，发现差异不只在安全限制，还在解析语义：
  - YAML 标量：B 把 `0x`/`0o` 开头的值解析为数字，并接受 `!!int` 等显式标签；A 把它们当字符串，或直接拒绝标签。
  - YAML 合并键：多个合并来源有相同键时，B 报错，A 取第一个。
  - 格式识别：两边识别 Base64 和 YAML 的条件不同。
  - URI 参数：两边接受的查询参数和协议别名不同，例如 A 接受 `socks5h`。
  - 名称规则：长度和禁止字符不同；B 会隐藏与凭据相同的名称。
  - 输出：A 输出经过校验的原始 sing-box JSON，B 输出类型化模型并做规范化。
- 统一到任一侧都会改变部分现有订阅的解析结果：有的生成新版本，有的刷新直接失败。这违反 ADR 0085 “已存外部节点不会因为升级而生成新版本”的约束。若保留两种方言再包进一个模块，并没有真正减少维护面，阶段三删除一套来源时还要再拆。
- 选择：阶段二只合并抓取器，规则取两边并集。安全规则只在一处维护；两套来源各自保留错误码和调用方式。解析器合并并入阶段三：选定保留哪套来源时，另一套的解析器随其存储一起删除，迁移方案再说明受影响的订阅如何处理。

## 2026-10-24：界面第四轮的实施选择

- 有序链路表需要约 56rem 才能完整显示。手机、平板或展开较宽侧栏时，原表格要横向滚动，桌面上有序路径文字还会溢出到相邻列。选择按面板宽度（CSS 容器查询）切换：面板窄于 56rem 时，每行堆叠为卡片，状态与流量排在名称之后，每格用列名作标签。没有像服务器列表那样另渲染一套卡片：这张表在手机上要显示的内容与桌面相同，同一 DOM 可以避免重复渲染入口与出口详情，也让现有夹具中按 `data-resource-key`、行和单元格定位的写保护断言保持不变。堆叠时行和单元格改变了显示方式，因此显式标注表格角色，表头只在视觉上隐藏。
- 行操作只直接显示“详情”、编辑类操作和“删除”，其余收进“更多操作”菜单。“删除”保留在外：它始终先弹出确认框，写保护夹具还要直接调用它的点击回调，验证刷新尚未让按钮变为禁用时回调本身也会拒绝。有序链路的“详情”与“路径与引用”打开同一个弹窗，菜单中不再重复后者；受管两跳链路和直连节点的“详情”跳转资源页，菜单仍保留“路径与引用”。
- 节点库与链路在同一页面，采用同一规则：保留“详情”“编辑”“删除”，“部署”“整理”“复制”收进菜单；自定义排序的上移/下移仍是独立按钮（拖动排序的替代操作），改为 Lucide 箭头图标并保留原无障碍名称。
- 菜单选择非模态：打开菜单不隐藏页面其余部分，点击外部或按 Esc 关闭。菜单只有进入动画，关闭后立即移除。菜单项打开弹窗前，先把焦点交还“更多操作”按钮，弹窗关闭后焦点回到该按钮。
- 原先所有经 `Modal`、`Confirm` 打开的弹窗关闭后，焦点都落到页面开头，因为弹窗由状态打开、没有 Radix 触发器可还原。改为在弹窗打开时记住获得焦点的元素，关闭后还给它；元素已从页面移除时不处理。这影响全部弹窗，但只改变关闭后的焦点位置，不改变弹窗内容和写入逻辑。
- 验证阶段的截图发现顶栏与节点库在平板宽度下的两个第一轮遗留缺陷，现有夹具宽度覆盖不到。顶栏的根因是它作为固定高度滚动列中的弹性项被压缩，改为不压缩，并调整平板宽度下的内容让它保持一行。节点库改为与有序链路表相同的按面板宽度切换；视口在 1100 像素左右、侧栏展开时也显示卡片。服务器列表仍按视口宽度切换：它在平板宽度下表格可横向滚动、没有重叠或截断，本轮不改。

## 2026-10-24：Nexus 运行接管的快照来源、授权边界与限制差异

- 问题：Codex 中断前用脚本按旧节点逻辑手工推导了 7 台主机的候选，自定义出口、分流和本地 `custom_config` 的主机全部跳过；复核发现这些候选的 Reality 握手端口是字符串 `"443"`，面板会拒绝，绕过校验则新运行时无法启动。另外，准备后没有撤销途径；迁移节点仍可被加入策略组；旧节点按套餐执行的限速与设备数，apsp Agent 不执行。
- 选择：快照只由旧节点自身的 `buildConfig` 生成（`tools/nexus-legacy-export`），`tools/nexus_runtime_snapshot.py` 转换并严格校验类型，整台主机任一节点不能转换就不写快照；编译器接受各节点完全相同的主机级路由选项（出站网卡、默认解析器）。新增仅限从未启动、没有部署的“撤销准备”；迁移节点拒绝加入策略组。限速与设备数差异由 `compare-users` 统计并写入运行手册，不阻止切换。
- 理由：模拟旧逻辑无法覆盖弱类型转换和本地合并，复用原代码才能保证客户端看到的服务不变；不同主机级选项无法无歧义合并，仍然拒绝。撤销只删除从未发布的准备记录，启动过的主机保留发布和流量历史。策略组会生成新 UUID 与密钥，破坏原链接。去掉限速与设备数只会放宽而不会中断现有使用，按“不影响以前的使用”的要求可以接受；需要恢复这两项时属于新运行时能力，另行实现。

## 2026-10-24：界面第五轮第一步的实施选择

- 滚动归属有两种做法：主列在所有宽度负责滚动，或手机改用文档自然滚动。选择前者：外框结构在两种宽度一致，手机页头和菜单固定在上方不随页面滚走；页面内已有的吸顶顶栏、贴底批量栏按同一个滚动容器工作，不需要分两套写法。
- 跨断点保留状态有两种做法：只增删外围元素，或把内容渲染进稳定的承载元素再移动它。外框选择前者：分栏组始终存在，手机时只移除侧栏面板。`ListDetailLayout` 选择后者：手机上下堆叠无法用分栏组的内联尺寸表示，改为门户承载，布局切换只移动承载元素。
- 浏览器后退、前进发生时地址已经改变，无法事先阻止。选择在路由收到 hashchange 时询问，用户留下则用 `pushState` 写回原地址（不产生第二次 hashchange）。后退被拒绝时，原来的“前进”记录会被这条新记录替代；这是 hash 路由下不改动历史栈就能恢复地址的最小做法。
- 有未保存草稿时，同一页面内只改查询参数的地址变化也会询问，与原链接拦截“地址不同就询问”的规则一致；目前登记草稿的只有添加服务器、运维计划、设备群操作与网络检测方案，它们编辑期间不会自行改写地址。
- 命令面板在其他弹窗打开时不响应快捷键，而不是在弹窗上方打开后再询问：模态弹窗中的表单此时无法通过侧栏离开，阻止打开最直接，也避免面板与弹窗争夺焦点。
- 评审建议把动态状态改为显式 `t()`，并停止对 React 管理的节点二次改写。全量迁移涉及数千条中文，本轮修正翻译器的来源判断（覆盖全部现有节点），并先把服务器列表与详情的连接状态改为 `t()`；后续页面按同一规则逐步迁移。

## 2026-10-24：界面第五轮第二步的实施选择

- 页头的语言选择可以只作用于当前会话，也可以保存为管理员偏好。选择后者：设置页的同一选项本来就保存偏好，两个入口行为一致；只作用于会话时，下次登录或另一窗口仍会回到旧语言，与评审描述的“被改回”是同一种体验。保存失败不撤销选择，下次读取到的已保存值照常生效。
- 公开看板的浅/深色选择仍按浏览器保存，管理端主题仍按管理员保存；两者都在各自显示期间写入 `<html>`。没有把看板主题并入管理员偏好：公开看板也供未登录访客使用，没有管理员身份可保存。
- 服务器批量操作的确认框中，“进入维护”“停止接收新任务”使用警示样式，“恢复接收任务”使用普通样式；三者都先确认，因为它们都会立即改变这些服务器能否接收任务、终端和远程命令。
- 批量操作的目标取“当前可见 ∩ 已勾选”，被筛选或搜索隐藏的已选对象保持勾选但不修改，而不是在筛选变化时自动取消勾选：用户切换筛选查看时不会丢失已做的选择，隐藏数量在操作栏和确认框中写明。
- 弹窗打开者已不在页面上或无法获得焦点时，焦点交给页面主体 `main`（可聚焦但不进入 Tab 顺序）。没有改为聚焦页面标题：不是每个页面都有标题，`main` 在所有后台页面都存在，屏幕阅读器会播报所在区域。
- 多选控件保持原生 `select multiple`，只取消固定高度和下拉箭头，没有换成复选框列表：两处多选（链路出口扩展、网络检测服务器集合）的提交逻辑读取 `selectedOptions`，保持原生控件不改变表单与键盘行为。

## 2026-10-24：界面第五轮第三步的实施选择

- 导航顺序按评审和路线图工作包 0.2 调整：代理服务移到第一组，组内为服务概览、代理节点、代理用户、策略与套餐，后来加入的成员运营排在最后。评审写作“节点与链路”，入口名仍保留「代理节点」：链路已在该页的“链路”视图中，改名会牵动文档、测试和已有习惯，留待 0.2 统一处理“实验”标记时一并考虑。登录后的默认首页仍是服务器看板，等待决定 D6。
- 弹窗退出动画有两种做法：每个调用点改为常驻并传入 `open`，或用一层 `DialogPresence` 保留被移除的弹窗直到动画结束。选择后者：74 处调用的内容大多依赖“正在编辑的对象”非空，改为常驻需要逐处处理空值；包一层后弹窗内容保持移除前的样子，行为不变。调用点用 TypeScript 语法树批量改写，自带 `open` 的三个编辑器改为在组件内部包裹。
- 退出动画期间 Radix 保持页面其余部分对辅助技术隐藏，直到弹窗离开文档（约 0.18 秒），这与常见的带退出动画的模态弹窗一致。关闭中的弹窗只设为 `inert`，没有再加 `aria-hidden`：浏览器的辅助技术已跳过 inert 内容，测试中的“等待弹窗隐藏”因此会等到弹窗真正离开，不会在退出途中读取页面。为避免两个弹窗同时出现在页面上，新弹窗打开时立即结束其他弹窗的退出。
- Motion 的退出动画随动画帧推进，夹具安装页面时钟后（无论是否暂停）退出都不会完成，页面会一直对辅助技术隐藏。现实中只有后台标签页会暂停动画帧，回到前台后动画照常结束。选择让系统设置“减少动态效果”时弹窗立即关闭（这本身也是该设置的合理行为），控制页面时钟的夹具请求减少动态效果；没有在产品代码中加入不受页面时钟控制的计时。实际退出动画由 `visual-hierarchy.mjs` 在正常时钟下覆盖。
- 实现中发现：关闭一个有未保存输入的弹窗后，在退出动画结束前点击导航会误报“未保存”。离开保护改为只在弹窗仍在页面上时生效（`useLeaveGuard` 读取 Motion 的 presence 状态）。
- 紧凑密度保留全局缩小的间距单位，在按钮、输入框、选择框、复选框、开关、菜单项和侧栏链接上恢复舒适密度的单位。没有逐个改写内容区的间距类名：表格、面板和区块都使用同一套间距刻度，按控件恢复更不容易遗漏。
- 汇率缓存从 Zustand 移回看板的数据读取一侧：store 只保存访客选择的币种，汇率由读取它的组件经 context 提供，重新进入看板时的过渡值放在读取模块中。没有只把它登记为例外：移动后与“服务端数据不放进 store”的规则一致，改动只涉及一个文件。
- 服务器列表新增“地区”筛选，与“分组”一起放入更多筛选；手机卡片字段单独保存在视图中，默认只显示处理器和内存。已保存的旧视图没有这两个字段，应用时使用默认值。

## 2026-10-25：首次空运行时安装后预检无法通过

- 问题：恢复真实 CI 验收时发现，首次空运行时安装后流程会卡死。精确核对只在服务器没有待发布业务时（`dirty_at` 为空）认定目标为当前目标，而空安装特意保留待确认的业务节点，所以 Agent 的核对回执被判为 `superseded`。重新采集的完整预检又要求运行时统计监听 `127.0.0.1:18085` 空闲或归“已核对”的受管进程，空运行时自己占用该端口，于是端口检查永远失败，业务无法确认发布。生产面板尚无已安装 Agent，所以还没有人遇到。
- 选择：不放宽核对认定，部署状态在业务发布前仍显示已应用 0、未健康。端口归属改为也接受 Agent 五分钟内成功回答当前已发布目标绑定的核对，同时仍要求实际 unit MainPID 匹配；见 ADR 0080 补充。验收驱动在空安装后等待已应用，或等待 Agent 回答该版本的核对请求，再重新采集预检。
- 待定：已有部署的服务器新增监听时同样需要五分钟内的核对回执，但业务待发布期间界面禁用主动核对，Agent 也只在重连或应用后自动核对。是否在请求预检时一并请求核对（会把健康暂时置为否），或在界面放开待发布期间的核对，需要单独决定。空安装版本是否应显示为已应用也一并评估。

## 2026-10-25：全功能审查后按使用逻辑重组

用户要求扫描每项功能与交互体验、并行验证、研究论坛需求，并“无需审核，按最佳决定来”完成分类、重新布局、插件合并拆分与方向统一。决定见 [ADR 0098](adr/0098-usage-driven-navigation-and-tiers.md)，路线图第五节的 D1–D11 同时定案。主要取舍：

- **侧栏分组。** 六组：总览、代理服务、服务器、监控告警、系统、实验功能。插件中心放在“服务器”而不是“系统”：插件按服务器启用，“系统”组已有四个入口。DDNS 与阿里云 CDT 也作用于具体服务器，一并归入“服务器”。
- **运维工具。** 并入服务器详情的「运维（实验）」，地址沿用 `/#/servers/{id}/fleet`；批量接入移到 `/#/servers/batch`。`/#/fleet` 继续显示服务器选择，侧栏高亮「服务器列表」，没有改成跳转，以免打断已有书签上的操作。
- **冻结功能的显示开关。** 选择面板级设置（`panel_settings.settings.show_frozen_features`，默认关闭），而不是每位管理员各自的偏好：功能地图规定“在面板设置中可显示”。设置以 JSON 保存并带默认值，不需要迁移。外框从 `/api/control-center/me` 读取开关，不增加请求。隐藏只影响界面，不是权限控制，接口照常。
- **核心旅程不依赖降级页面。** 部署预检要求的“只读运行时预检”面板授权原本只能在运维工具里开，现在可在预检区域就地开启。写入的仍是同一份面板策略（同样需要 `servers:write`、`security:write` 与近期验证）；Agent 本机的同名授权仍需操作者在服务器上开启。
- **首页。** 登录后进入「概览」（原服务概览）。“需要处理”只列面板已有数据能判断的事项：离线服务器、sing-box 安装失败、未恢复告警、30 天内续费。代理用户的到期与额度需要新的聚合接口，留给路线图 2.7。每个数据源都可以缺席：管理员无权读取时，对应卡片不显示，不报错。
- **单一编辑位置。** 监控历史保存期限只在「面板设置」修改，保存时同步记录保留策略；缩短期限需要近期验证，因为会提前删除历史。系统自检中只读显示，`PUT /api/control-center/retention/monitoring` 返回 409。`PATCH /api/settings` 改为部分更新，取代 2026-10-24 条目中“每页保存前重新读取再整包提交”的做法：后者在两页同时编辑时仍会互相覆盖。
- **停止类操作免近期验证；批量登记补上。** 取消远程命令、关闭终端会话只是结束已获授权的工作，不再要求重新输入密码。`/api/fleet/batch-enrollment` 不含 `/enrollment` 子串，原规则漏掉了它，现在与单台登记一样需要近期验证。终端输入每五分钟重新验证一次的规则不变，这是有意的安全选择。
- **批量维护必须有结束时间。** 原来从服务器列表批量“进入维护”不设结束时间，会无限期暂停离线告警。现在在确认框里选择 1–72 小时；单台的维护时段仍在服务器详情的运维分页设置。
- **自助修改密码。** 新增 `POST /api/security/password`，需要当前密码，启用二步验证时还需验证码，并与登录共用限速。和关闭二步验证一样，修改后撤销其他会话以及所有者的管理员 Passkey，防止被植入的 Passkey 在改密后继续有效。审计按键名脱敏，`current_password`、`new_password`、`totp_code` 都不会写入。
- **链路创建入口。** 统一入口提前到来源迁移之前：始终打开有序链路表单，mixed 链路编辑器从界面移除，`/chains/batch` 接口保留。迁移前只有数字编号来源的管理员，需要先在有序来源中添加来源；订阅来源视图会说明这一点，并给出迁移命令。
- **代理用户操作与订阅。**
  - 预览指纹不再包含实时用量，在线用户的批量操作不会因为预览与应用之间新到的流量而被拒绝。
  - 延期从“现在”与原到期日中较晚者起算，结果仍已到期时直接拒绝。
  - 受限用户的两种订阅格式都返回带原因的 409，审计结果记为 `restricted`。
  - 成功的订阅响应带 `Subscription-Userinfo`、`Profile-Title`（base64 形式，可容纳中文名）、`Profile-Update-Interval: 24`。
- **Xboard 迁移的凭据模型（D4）。** 以已实施的 ADR 0092、0095 为准：成员与订阅令牌迁入，原订阅地址兼容，运行接管保留客户端身份；本轮审查推荐的“每节点独立凭据”只用于今后在 apsp 中新建的代理用户，不改变已迁入的身份。
- **本轮发现但未修复。** 下列问题记入路线图：
  - **费用与续费账本（`plugins/expenses`）。** 自动续费项目被后台顺延后再手动“续期”，会再推进一期，付款也记到已顺延后的账期。手动项目逾期后从“30 天内续费”、日历与提醒中消失。年度预计中服务器与手动项目的口径不一致。提醒去重键含版本号，编辑备注会重发提醒。这些都涉及生产中的真实账本数据，单独修复并补测试。
  - **其余工作包。** 代理用户暂停状态、部署控制台统一、节点证书状态、sing-box 停用语义、故障事件并入告警事件、告警设置分页。
