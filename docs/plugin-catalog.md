# 插件中心与服务器执行边界

## 页面职责

侧栏「服务器 → 插件中心」有两个分页：「插件目录」（`/#/plugins/catalog`）介绍每个插件，「服务器启用」（`/#/system/plugins`）按服务器汇总启用状态。原“制品”页面混合了插件介绍、Release 导入与逐架构下载包清单，现由插件目录取代；旧 `/#/artifacts` 书签继续可用，并使用新标题和导航高亮。目录没有 Release 标签输入、导入按钮或面板安装操作。

目录按插件展示用途、使用方式和执行位置。当前登记 sing-box、DDNS、阿里云 CDT，以及合为一组「线路诊断」的 IP 质量、TCP 连接诊断与 NodeQuality（日常检查标“实验”，完整验机仍受门禁限制），共六个插件；是否存在签名下载包不会影响介绍展示。服务器 Agent 属于基础组件，单独展示，不占用插件条目。未登记的分发组件按自己的名称归并，只展示版本资料，不套用代理运行时名称，也不提供执行入口。

同一插件的多个版本、AMD64/ARM64 或其他平台文件都属于同一个条目。展开条目后按版本列出真实存在的架构、大小和摘要，不把旧版支持的架构推断成新版也支持。版本排序仅用于阅读，不决定“最新兼容版本”，也不改变后端的签名、不可变版本或平台选择规则。

## 按插件选择管理范围

阿里云 CDT 条目通过“进入云服务管理”跳转到按云账号登记的资源页面，无需选择服务器或安装设备程序。DDNS 仍按服务器启用，执行在面板，使用 Agent 已上报的 IP。

其他条目中的“选择服务器”只读取服务器列表并跳转，不发起启用、下载、安装或诊断任务。没有默认目标，不存在“面板本机”选项；服务器列表读取失败、没有服务器或没有选择时，不能继续。目标必须是列表中的有效正整数服务器 ID。

sing-box 跳转到 `/#/servers/{id}/plugins`，只读取和展示这一台服务器的启用状态。明确点击启用后仍调用现有 `POST /api/plugins/sing-box/servers/{id}/enable`，不创建全局启用状态。`/#/system/plugins` 是插件中心的「服务器启用」汇总页；纯监控服务器的「插件」分页不显示代理业务，不增加默认安装或代理运行时读取。

线路诊断组跳转到所选服务器的「线路诊断」分页（`/#/servers/{id}/ip-info`），再在 IP 信息、TCP 诊断与节点验机之间切换。页面继续检查在线状态、设备能力、签名版本、资源预算和安全门禁，浏览目录不能绕过这些条件，也不自动创建任务。服务器详情的「插件」分页只负责管理该服务器：先显示启用状态，启用 sing-box 后再显示配置部署、运行时运维、部署历史和本机节点。

启用 sing-box 只是允许为此服务器配置代理业务，不代表安装已完成；创建节点并发布配置后才由该服务器的 Agent 获取、校验和运行代理内核。面板负责控制与展示，不运行这些服务器插件。面板所在主机若也承担服务器职责，需要独立接入 Agent，并通过对应服务器 ID 管理，不能把面板进程当作隐式安装目标。

## 状态和分发

“目录有介绍”“存在已验证下载包”“某台服务器已安装或可执行”是三件不同的事。目录只声明前两项；读取失败时显示版本状态未知，历史版本资料可以保留，但不沿用成功状态。

面板不增加任意第三方插件加载或插件市场交易功能。签名 Release 的准备仍属于[部署维护](deploy.md#导入签名-release)：保留已鉴权的运维导入 API、验签、内容校验和独立 bootstrap，删除的是网页导入表单，不是供给链校验。Agent 二进制继续按主线要求从 GitHub Release 下载，面板只提供更新元数据；运行时与配置仍经面板分发。目录不提供安装接口；DDNS 与云账号管理的独立迁移见各插件文档。

## 回归入口

`web/tests/catalog.test.ts` 检查按组件归并、版本与架构对应关系、空集合介绍、Agent/未知组件分类、有效服务器 ID 和旧地址兼容。

`web/tests/plugin-catalog.mjs` 使用已构建 `web/dist` 与回环 API 夹具，在桌面和移动端检查目录只读、展开版本、失败恢复、空集合、服务器选择、诊断门禁及仅针对所选服务器的启用请求。`web/tests/singbox-business.mjs` 继续检查纯监控页面隐藏代理业务、只读来源与系统管理员/代理用户边界。这些不是生产 Agent 安装或新增诊断能力的实机签收。
