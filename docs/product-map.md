# 产品定位与功能地图

本文定义 apsp 是什么、不是什么、每项功能处于哪个投入级别，以及新功能放在哪里。界面分组、页面命名、文档目录和新增功能都以本文为准；架构分层与授权范围仍以 [AGENTS.md](../AGENTS.md) 和[各项 ADR](adr/README.md) 为准。定位收窄的决定见 [ADR 0087](adr/0087-narrow-positioning-proxy-network.md)，界面分区见 [ADR 0086](adr/0086-product-map-and-navigation.md)。

## 一句话定位

**apsp 是自托管的代理网络控制平面。** 它把你分散在各家的 VPS 编成一张可靠的代理网络：入口、中转、落地一处配置，节点和订阅自动下发，流量按用户精确记账；面板离线时，已应用的节点照常工作。你分享给的每个人都可以自己登录，查看订阅、用量、套餐与到期。

服务器监控、费用与续费、线路质量是为这张网络服务的：只做运营代理网络需要的那部分，不与通用探针或运维面板比功能。

## 初衷与取舍

项目最初（2026-09-30）的目标就是代理网络控制平面：面板保存期望状态，编译成每台服务器的原生 sing-box 配置；Agent 主动连接、对账、应用并回报；sing-box 作为独立服务运行；流量只在一端计算一次，重启后不重复、不丢失。这些是 apsp 最难做对、也最难被复制的部分。

此后几天内，项目陆续吸收了探针、单机节点面板、订阅管理、云资源管理、验机和通用运维的功能，宽度远超验证能力，用户也觉得逻辑混乱。现在回到初衷：代理网络是主线，其余功能按下方“功能分级”保留、降级或冻结。

## 适合谁

- **线路玩家**：手上 5–50 台跨多家厂商的服务器，按入口机、中转机、落地机组织，关心回国线路、延迟丢包和 IP 能否解锁。
- **为自己和亲友自建节点的人**：需要多台服务器上的节点、链路、订阅、套餐和准确的流量统计，让每个人能自己登录查看，不想手工改配置文件，也不想为此运营一个售卖平台。原来用 Xboard 一类面板管理熟人订阅的，可以迁移过来，只保留自用需要的部分。
- **不想再忘记续费的人**：服务器、域名、机场订阅和各种服务分散在不同平台，希望在一处看清每月花多少、下一笔什么时候到期，并按时收到提醒。

## 不做什么

| 不是 | 说明 |
| --- | --- |
| 通用探针 | 监控只服务于代理网络的运营。主题、地图、公开展示这类探针竞赛不是投入方向；只想要探针的用户更适合 Komari、哪吒或 Cloudflare 上的探针。 |
| 通用运维面板 | 不再扩展终端、文件管理、防火墙、组网、批量脚本这类能力。通用运维交给 SSH 工具和用户自己的 AI Agent，apsp 通过接口提供数据与受控操作。 |
| 公开售卖的代理平台 | 不做 Xboard 一类面板的运营功能：公开注册、订单与支付、优惠券、邀请佣金、工单和多租户。代理用户由管理员创建，管理员和代理用户使用各自独立的登录和会话。 |
| 云厂商控制台 | 费用、到期和续费是记账与提醒。只有阿里云 CDT 插件在管理员明确配置后调整带宽或启停实例，其他云资源不开通、不续费、不删除。 |
| 多内核代理网关 | 每台服务器只运行一个上游 sing-box，不修改上游源码，不接入 xray 或自动出口池。 |

## 核心概念

| 概念 | 是什么 | 不要混淆 |
| --- | --- | --- |
| 面板 | 保存期望配置、权限和历史记录的 Web 服务。面板暂时离线时，服务器上已应用的配置继续运行。 | 面板进程本身不是一台“服务器”；面板主机要承载节点，也需要单独接入 Agent。 |
| Agent | 安装在每台服务器上的常驻程序。它主动连接面板，比对期望状态并应用配置，上报指标与流量。 | Agent 只从 GitHub Release 或配置的镜像下载并独立验签，面板不提供 Agent 二进制。 |
| 服务器 | 一台接入了 Agent 的机器，是节点、监控和费用的承载单位。 | 服务器 ≠ 节点。 |
| 节点 | 某台服务器上的一个代理入口，包含协议、端口、证书和公开端点。 | 一台服务器可以有多个节点。 |
| 链路 | 由入口、中转、落地等多段组成的线路；中间段或落地也可以是订阅来源中的节点。 | 链路只在入口计一次流量，内部凭据不进入用户订阅。 |
| 代理用户 | 使用订阅的人。策略组决定能用哪些节点和链路，套餐决定流量额度、有效期和重置周期。 | 代理用户 ≠ 面板管理员。 |
| 插件 | 按需启用的能力。sing-box 插件承载整个代理业务；DDNS、阿里云 CDT 和诊断工具是可选插件。 | “启用”是管理员的许可，“安装完成”要等 Agent 回报确认。 |

## 功能分级

每项现有功能处于下面五个级别之一。级别决定投入方式，也决定界面上的位置和默认状态。

| 级别 | 含义 |
| --- | --- |
| **核心** | 主线。持续投入，每个版本都必须在实机上签收。 |
| **支撑** | 运营代理网络需要的能力。保留并维护，只做代理网络需要的部分。 |
| **可选插件** | 按需启用。保持可用，不扩展新能力。 |
| **降级** | 保留现有功能，只修缺陷和安全问题，不新增能力。界面上标为“实验”并移出主线位置；高风险操作默认关闭，按服务器显式开启。 |
| **冻结** | 不再投入，只修安全问题，默认关闭或隐藏。评估后移除或拆为独立插件，移除需要用户单独授权。 |

已有安全门禁而“暂停”的能力（NodeQuality 完整验机）继续拒绝新任务，并按冻结处理。

| 功能 | 位置 |
| --- | --- |

### 冻结

| 功能 | 位置 | 原因 |
| --- | --- | --- |
| 系统网络参数调优、反向隧道、私有组网、受管防火墙 | 网络配置 | 通用网络运维，改动风险高，与代理网络主线无关 |
| 云资源与费用（费用对照、Hetzner 资源、安全组、供应商对比） | 自动化与恢复 › 云资源与费用 | 云厂商控制台方向 |
| 硬件测试（CPU、磁盘等）与 Speedtest | 网络检测 | 验机方向 |
| NodeQuality 完整验机（已暂停） | 服务器详情 › 节点验机 | 安全门禁未解除 |

| 分组 | 入口 | 地址 | 主要级别 |
| --- | --- | --- | --- |
| 代理服务 | 服务概览、代理节点、代理用户、策略与套餐 | `/#/plugins/sing-box`、`/#/plugins/sing-box/nodes`、`/#/plugins/sing-box/users`、`/#/plugins/sing-box/groups` | 核心 |
| 服务器 | 服务器列表 | `/#/servers` | 核心与支撑 |
| 服务器 | 运维工具 | `/#/fleet` | 降级 |

| 总览 | 服务器看板、统计报表；费用与续费（规划） | `/#/dashboard`、`/#/statistics`；新地址待实现时确定 | 支撑 |
| 监控告警 | 告警事件、延迟检测、告警设置 | `/#/system/notifications`、`/#/latency`、`/#/monitoring/settings` | 支撑 |
| 网络 | 网络检测 | `/#/network-workbench` | 基础探测与路由为支撑，其余降级或冻结 |
| 网络 | 网络配置 | `/#/network-configuration` | 降级与冻结 |
| 网络 | 动态域名解析 | `/#/plugins/ddns` | 可选插件 |
| 扩展 | 插件中心、阿里云 CDT | `/#/plugins/catalog`、`/#/system/plugins`、`/#/plugins/alicloud` | 支撑；可选插件 |

**服务器详情**按“这台服务器”分为七个分页：概况（`/#/servers/{id}`）、资产与流量（`/assets`）、Agent 与任务（`/agent`）、插件（`/plugins`）、IP 信息（`/ip-info`）、节点验机（`/node-quality`）、TCP 诊断（`/tcp-quality`）。分页下方的「带此服务器打开」进入运维工具、网络检测、网络配置和自动化与恢复，并预先选中这台服务器。

## 归类规则

新增或调整功能时按下面的顺序判断：

1. **先问是否服务代理网络。** 新功能必须直接服务节点、链路、用户与订阅，或者是运营这张网络所需的服务器与线路感知。都不是，就进入[路线图](roadmap.md)的候选池，不直接实现。
2. **降级和冻结的功能不加新能力。** 只修缺陷和安全问题；需要扩展时，先申请调整级别。
3. **按任务归组，不按实现方式。** 插件提供的页面放进它服务的任务分组：DDNS 属于“网络”，sing-box 属于“代理服务”。
4. **一台服务器的事放服务器详情，跨服务器的事放工作区。** 工作区页面支持从服务器详情“带此服务器打开”。
5. **同一设置只有一个编辑位置。** 例如告警阈值只在「告警设置」，公开看板只在「面板设置」。
6. **每组两到四个入口，入口名不与分组同名。** 页面标题与侧栏名称一致，眉题使用分组名；说明文字先讲“在这里做什么”，再补最重要的限制。
7. **旧地址永久可用。** 改名只改显示文字，不改已发布的 Hash 路径。

## 界面用语

| 用这个 | 指的是 | 区别于 |
| --- | --- | --- |
| 服务器 | 接入了 Agent 的机器 | 节点：服务器上的一个代理入口 |
| 链路 | 入口、中转、落地组成的多段线路 | 节点：单个代理入口 |
| 管理员 | 登录面板的人，分所有者、运维和只读 | 代理用户：使用订阅的人，只能进入自己的门户 |
| 策略组 | 用户能用哪些节点和链路 | 套餐：流量额度、有效期和重置周期 |
| 续费项目 | 「费用与续费」中需要按周期付款的一项：服务器、域名、机场订阅或其他服务 | 订阅：代理用户使用的订阅链接，或作为节点来源的订阅来源 |
| 服务器看板 | 实时状态，可公开 | 统计报表：历史趋势，仅管理员 |
| 告警事件 | 自动检测产生的单条告警及恢复 | 故障事件：聚合、指派与处置记录（降级） |
| 网络检测 | 只测量，不改动 | 网络配置：会改变服务器网络状态，需要确认 |
| 启用插件 | 管理员允许在这台服务器上使用插件 | 安装完成：Agent 下载、校验、应用并回报健康 |

对外文案使用“代理网络”“网络连接管理”等中性措辞，与上游 sing-box 保持一致。其余技术术语见[术语表](glossary.md)。
