# 产品定位与功能地图

本文定义 apsp 是什么、不是什么，以及每项功能放在哪里。界面分组、页面命名、文档目录和新增功能都以本文为准；架构分层与授权范围仍以 [AGENTS.md](../AGENTS.md) 和[各项 ADR](adr/README.md) 为准，本次整理的决策记录见 [ADR 0086](adr/0086-product-map-and-navigation.md)。

## 一句话定位

**apsp 是自托管的服务器与代理节点管理面板。** 它把分散在不同云厂商、不同地区的服务器接入同一个面板，集中查看状态、流量、到期与费用，完成日常运维和网络诊断；需要时再通过 sing-box 插件在这些服务器上提供代理节点，管理代理用户、套餐和订阅。

## 适合谁

- 手上有几台到几十台 VPS 的个人或小团队，服务器分布在多家云厂商和多个地区。
- 想在一个地方看清每台服务器是否在线、资源够不够、流量用了多少、什么时候到期、每月花多少钱。
- 自己维护代理服务，给自己或少量熟人使用，需要节点、订阅、套餐和流量统计，但不想手工改配置文件。

## 不做什么

| 不是 | 说明 |
| --- | --- |
| 云厂商控制台 | 费用、到期和续费是记账与提醒。只有阿里云 CDT 插件在管理员明确配置后调整带宽或启停实例，其他云资源不开通、不续费、不删除。 |
| 公开售卖的代理平台 | 没有公开注册、在线支付或多租户。代理用户由管理员创建，管理员和代理用户使用各自独立的登录和会话。 |
| 通用自动化或编排系统 | 远程命令受 Agent 本机授权限制；批量任务只使用固定步骤，不接受任意脚本模板。 |
| 自动处置的告警平台 | 通知只负责提醒，不付款、不停机，也不执行远程命令。 |
| 多运行时代理网关 | 每台服务器只运行一个上游 sing-box，不修改上游源码，不提供 xray、Clash 订阅或自动出口池。 |

## 五个核心概念

| 概念 | 是什么 | 不要混淆 |
| --- | --- | --- |
| 面板 | 保存期望配置、权限和历史记录的 Web 服务。面板暂时离线时，服务器上已应用的配置继续运行。 | 面板进程本身不是一台“服务器”；面板主机要被管理，也需要单独接入 Agent。 |
| Agent | 安装在每台服务器上的常驻程序。它主动连接面板，上报指标，对比期望状态并应用配置。 | Agent 只从 GitHub Release 或配置的镜像下载并独立验签，面板不提供 Agent 二进制。 |
| 服务器 | 一台接入了 Agent 的机器。监控、资产、费用和运维都以服务器为单位。 | 服务器 ≠ 节点。 |
| 插件 | 按需启用的业务能力：sing-box（代理服务）、DDNS、阿里云 CDT，以及 IP 查询、NodeQuality、TCP 诊断三个诊断插件。 | “启用”是管理员的许可，“安装完成”要等 Agent 回报确认。 |
| 代理业务 | 由 sing-box 插件拥有：节点、链路、订阅来源、代理用户、策略组、套餐和代理流量。 | 服务器网卡总流量属于服务器，代理用户流量属于代理业务，两本账不互相改写。 |

## 七个功能区

侧栏按管理员要完成的任务分为七组。每组的入口、负责范围和不负责的内容如下。

### 1. 总览：看清全局

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| 服务器看板 | `/#/dashboard` | 实时查看所有服务器的状态、历史曲线、延迟与丢包。可在「面板设置」开启只读公开访问。 |
| 统计报表 | `/#/statistics` | 回顾一段时间内的在线情况、网卡流量和代理流量的趋势与排行。仅管理员可见。 |

只展示，不修改。需要改配置时，从对应的服务器、监控或代理页面进入。

### 2. 服务器：管好每台机器

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| 服务器列表 | `/#/servers` | 添加并接入服务器，按状态、地区和分组筛选，批量进入维护。点开一台进入它的详情。 |
| 运维工具 | `/#/fleet` | 对选定服务器使用资源与能力、资产与生命周期、服务日志与文件、交互式终端、历史与比较；用模板批量登记新服务器；查看面板自身健康。 |
| 自动化与恢复 | `/#/operations` | 跨服务器的批量任务与定时计划、故障事件、面板备份与恢复，以及云资源与费用账本。 |

**服务器详情**按“这台服务器”组织为七个分页：

| 分页 | 地址 | 内容 |
| --- | --- | --- |
| 概况 | `/#/servers/{id}` | 资源指标、连接数、扩展系统指标、系统信息、网络接口。 |
| 资产与流量 | `/#/servers/{id}/assets` | 地区、标签、成本、到期、续费记录、网卡流量额度和流量矫正。 |
| Agent 与任务 | `/#/servers/{id}/agent` | Agent 采集与上报设置、这台服务器发起的周期拨测、远程命令。 |
| 插件 | `/#/servers/{id}/plugins` | 在这台服务器上启用插件；已启用 sing-box 时显示配置部署、运行时运维、部署历史和本机节点。 |
| IP 信息 | `/#/servers/{id}/ip-info` | 出口 IP 的查询结果、逐源状态和历史。 |
| 节点验机 | `/#/servers/{id}/node-quality` | NodeQuality 日常检查与历史报告；完整验机受安全门禁约束。 |
| TCP 诊断 | `/#/servers/{id}/tcp-quality` | 向已授权目标发起有限的 TCP 连接诊断。 |

分页下方的「带此服务器打开」链接进入运维工具、网络检测、网络配置和自动化与恢复，并预先选中这台服务器；这些工作区仍属于各自的侧栏入口。

边界：服务器网卡流量、成本与到期属于这里；代理用户的流量和套餐属于代理服务。服务器详情的「资产与流量」保存看板、到期提醒和流量提醒使用的设置；「运维工具 → 资产与生命周期」记录供应商与订单、采购配置、续费与年度成本账本和维护状态，带有效期的续费记录会更新前者的到期日期。

### 3. 监控告警：出问题时第一时间知道

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| 告警事件 | `/#/system/notifications` | 离线、资源、到期和流量告警的触发与恢复记录，以及每个渠道的投递结果。 |
| 延迟检测 | `/#/latency` | 让服务器周期性地用 TCP / ICMP 测量到已授权运营商目标的延迟与丢包。 |
| 告警设置 | `/#/monitoring/settings` | 通知总开关，离线、到期和流量阈值，资源告警规则，Telegram、Webhook 及渠道投递状态。 |

边界：告警阈值只在「告警设置」编辑，单台服务器的离线告警开关在服务器编辑中。「故障事件」是对告警和任务失败的聚合与处置记录，放在「自动化与恢复」。

### 4. 网络：先测，再改

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| 网络检测 | `/#/network-workbench` | 从面板或指定服务器测试连通性、路由、吞吐、硬件与 IP 质量；按方案冻结目标与参数，报告记录从哪里测到哪里。 |
| 网络配置 | `/#/network-configuration` | 维护域名、证书、端点、端口转发、系统网络参数、反向隧道、私有组网和受管防火墙。保存配置与执行变更分开确认。 |
| 动态域名解析 | `/#/plugins/ddns` | DDNS 插件：让域名跟随服务器公网 IP 更新，支持 Cloudflare、腾讯云、阿里云和华为云。 |

边界：“检测”只读取和测量，不改动服务器；“配置”中的变更须单独确认并保留回退记录。单台服务器的 IP 信息、节点验机和 TCP 诊断在服务器详情。

### 5. 代理服务：sing-box 插件

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| 服务概览 | `/#/plugins/sing-box` | 首次使用的四个步骤，以及各服务器的 sing-box 安装与运行状态。 |
| 代理节点 | `/#/plugins/sing-box/nodes` | 节点库、链路、订阅来源三个视图：受管节点、多段链路和外部节点集中管理。 |
| 代理用户 | `/#/plugins/sing-box/users` | 创建代理用户，分别分配策略组和套餐，管理订阅链接、Passkey 开通和实际代理流量。 |
| 策略与套餐 | `/#/plugins/sing-box/groups` | 策略组决定能用哪些节点与链路；套餐决定流量额度、有效期和重置周期。 |

边界：只有启用了 sing-box 的服务器才出现代理业务；纯监控服务器不显示代理入口。代理用户与面板管理员是两类账号。

### 6. 扩展：插件管理与独立插件

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| 插件中心 | `/#/plugins/catalog`、`/#/system/plugins` | 「插件目录」介绍每个插件的用途、执行位置和已验证版本；「服务器启用」按服务器汇总插件启用状态。 |
| 阿里云 CDT | `/#/plugins/alicloud` | 按云账号管理 CDT 用量与账单、公网带宽、ECS 启停计划与阈值策略，无需 Agent。 |

边界：插件中心只介绍和导航，不提供 Release 导入或任意第三方插件安装；签名制品的导入属于[部署维护](deploy.md#导入签名-release)。

### 7. 系统：面板本身

| 入口 | 地址 | 用来做什么 |
| --- | --- | --- |
| 面板设置 | `/#/system/settings` | 是否公开服务器看板、金额显示币种与每日汇率、监控历史保存天数。 |
| 管理与安全 | `/#/system/control-center` | 我的工作区、会话、管理员授权、凭据、API 令牌、审计、系统自检、工具与依赖。 |
| 账号安全 | `/#/system/administrator` | 当前管理员的 Passkey 与二步验证。 |

## 归类规则

新增或调整功能时按下面的顺序判断位置：

1. **按任务归组，不按实现方式。** 插件提供的页面放进它服务的任务分组：DDNS 属于“网络”，sing-box 属于“代理服务”。「扩展」只放插件管理本身，以及暂时没有更合适分组的独立插件。
2. **一台服务器的事放服务器详情，跨服务器的事放工作区。** 工作区页面要支持从服务器详情“带此服务器打开”，并保留自己的侧栏入口。
3. **同一设置只有一个编辑位置。** 例如告警阈值只在「告警设置」，公开看板只在「面板设置」。其他页面只放链接，不重复表单。
4. **每组两到四个入口。** 入口名称不与分组同名；页面标题与侧栏名称一致，眉题使用分组名。
5. **说明文字先讲“在这里做什么”，再补最重要的限制。** 避免只罗列内部机制。
6. **旧地址永久可用。** 改名只改显示文字，不改已发布的 Hash 路径；只有新页面才使用新路径。后端搜索结果、书签和文档链接都依赖旧路径。

## 界面用语

| 用这个 | 指的是 | 区别于 |
| --- | --- | --- |
| 服务器 | 接入了 Agent 的机器 | 节点：服务器上的一个代理入口 |
| 管理员 | 登录面板的人，分所有者、运维和只读 | 代理用户：使用订阅的人，只能进入自己的门户 |
| 服务器看板 | 实时状态，可公开 | 统计报表：历史趋势，仅管理员 |
| 告警事件 | 自动检测产生的单条告警及恢复 | 故障事件：聚合、指派与处置记录 |
| 网络检测 | 只测量，不改动 | 网络配置：会改变服务器网络状态，需要确认 |
| 启用插件 | 管理员允许在这台服务器上使用插件 | 安装完成：Agent 下载、校验、应用并回报健康 |
| 策略组 | 用户能用哪些节点和链路 | 套餐：流量额度、有效期和重置周期 |

其余技术术语见[术语表](glossary.md)。

## 代码对应

| 功能区 | 前端目录（`web/src/`） | 后端位置 |
| --- | --- | --- |
| 应用外框、路由、侧栏 | `app/` | `crates/panel-host/src/frontend.rs` |
| 总览 | `display/`（看板）、`statistics/` | `panel-host` 的 `dashboard`、`statistics` |
| 服务器 | `servers/`、`server-diagnostics/`、`fleet/`、`operations/` | `panel-host` 的 `servers`、`telemetry`、`fleet`、`operations`、`diagnostics`；Agent 在 `crates/agent-core/` |
| 监控告警 | `monitoring/` | `panel-host` 的 `notifications`、`probes`、`latency_tasks` |
| 网络 | `network-workbench/`、`network-configuration/`、`plugins/ddns/` | `panel-host` 的 `network_workbench`、`network_configuration`；`plugins/ddns/panel/` |
| 代理服务 | `plugins/singbox/` | `plugins/singbox/panel/`、`crates/compiler/`、`crates/adapter-singbox/` |
| 扩展 | `plugins/`（插件中心）、`plugins/alicloud/` | `panel-host` 的 `artifacts`；`plugins/alicloud/panel/` |
| 系统 | `system/`、`control-center/` | `panel-host` 的 `settings`、`control_center`、`auth`、`passkeys`、`exchange` |

后端的宿主、插件与组装分层不随界面分组改变，见[仓库目录与维护约定](repository.md)。
