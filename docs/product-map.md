# 产品定位与功能地图

本文定义 apsp 是什么、不是什么、每项功能处于哪个投入级别，以及新功能放在哪里。界面分组、页面命名、文档目录和新增功能都以本文为准；对象与界面用语以[对象词典](redesign/03-objects.md)为准，代码与数据的归属以[功能划分与逻辑结构](architecture.md)为准，架构分层与授权范围以 [AGENTS.md](../AGENTS.md) 和[各项 ADR](adr/README.md) 为准。定位收窄的决定见 [ADR 0087](adr/0087-narrow-positioning-proxy-network.md)，六个工作区、统一用语与地址策略见 [ADR 0126](adr/0126-workspaces-language-and-addresses.md)。

> **过渡说明（2026-11-08）**：下文按 ADR 0126 的目标结构描述位置。界面要到[重新设计执行计划](redesign/09-execution.md)步骤 4 才改；在那之前，各位置在现有界面中的入口见[“步骤 4 之前的界面”](#步骤-4-之前的界面)。新增页面按目标工作区归类，侧栏中先放进对应的现有分组。

## 一句话定位

**apsp 是自托管的服务器管理与配置面板。** 它把你分散在各家的 VPS 统一管理：入口、中转、落地一处配置，节点和订阅自动下发，流量按用户精确记账；面板离线时，已应用的配置照常运行。你分享给的每个人都可以自己登录，查看订阅、用量、套餐与到期。

服务器监控、费用与续费、线路质量是为这张网络服务的：只做运营这些服务需要的那部分，不与通用探针或运维面板比功能。

## 初衷与取舍

项目最初（2026-09-30）的目标就是服务配置的控制平面：面板保存期望状态，编译成每台服务器的原生 sing-box 配置；Agent 主动连接、对账、应用并回报；sing-box 作为独立服务运行；流量只在一端计算一次，重启后不重复、不丢失。这些是 apsp 最难做对、也最难被复制的部分。

此后几天内，项目陆续吸收了探针、单机节点面板、订阅管理、云资源管理、验机和通用运维的功能，宽度远超验证能力，用户也觉得逻辑混乱。现在回到初衷：服务配置是主线，其余功能按下方“功能分级”保留、降级或冻结。

## 适合谁

- **多台服务器的维护者**：手上 5–50 台跨多家厂商的服务器，按入口、中转、落地组织，关心延迟、丢包与 IP 质量。
- **为自己和身边的人维护服务的人**：需要多台服务器上的节点、链路、订阅、套餐和准确的流量统计，让每个人能自己登录查看，不想手工改配置文件，也不想为此运营一个售卖平台。原来用 Xboard 一类面板管理熟人订阅的，可以迁移过来，只保留自用需要的部分。
- **不想再忘记续费的人**：服务器、域名和各种订阅服务分散在不同平台，希望在一处看清每月花多少、下一笔什么时候到期，并按时收到提醒。

## 不做什么

| 不是 | 说明 |
| --- | --- |
| 通用探针 | 监控只服务于这些服务器与服务的运营。主题、地图、公开展示这类探针竞赛不是投入方向；只想要探针的用户更适合 Komari、哪吒或 Cloudflare 上的探针。 |
| 通用运维面板 | 不再扩展终端、文件管理、防火墙、组网、批量脚本这类能力。通用运维交给 SSH 工具和用户自己的 AI Agent，apsp 通过接口提供数据与受控操作。 |
| 公开售卖的代理平台 | 不做 Xboard 一类面板的运营功能：公开注册、订单与支付、优惠券、邀请佣金、工单和多租户。代理用户由管理员创建，或由已有用户用管理员发放的邀请名额邀请（不收费、无佣金）；管理员和代理用户使用各自独立的登录和会话。 |
| 云厂商控制台 | 费用、到期和续费是记账与提醒。只有阿里云 CDT 功能在管理员明确配置后调整带宽或启停实例，其他云资源不开通、不续费、不删除。 |
| 多内核代理网关 | 每台服务器只运行一个 sing-box（上游版本加 `tools/singbox-runtime/` 的补丁，见 ADR 0104、0124），不接入 xray，不做多个运行时实例或自动出口池，不实现 SSM API。 |
| 高可用平台 | 面板单实例部署，不做面板高可用；特权操作经 `Privileged` trait，不另设独立的特权 helper 进程。 |

## 核心对象

八个核心对象的定义、所有者、身份与历史模型见[对象词典](redesign/03-objects.md)，这里只列一句话：

| 对象 | 是什么 | 不要混淆 |
| --- | --- | --- |
| 服务器 | 一台接入了 Agent 的机器，是运行时、节点、监控、地址与费用的承载单位 | 服务器 ≠ 节点；面板主机要承载节点，也需要单独接入 Agent |
| 运行时 | 服务器上由 Agent 管理的 sing-box 服务实例，每台至多一个 | 运行时 ≠ 面板功能；签名的二进制叫“制品” |
| 节点 | 一个可分配给用户的代理入口：受管节点在 apsp 的服务器上，外部节点来自外部来源 | “节点验机”等测的是服务器，改称服务器验机 |
| 链路 | 一个公开入口加 1–8 个有序段；只在入口计一次流量，内部凭据不进入用户订阅 | “两跳”只是模板名 |
| 外部来源 | 机场订阅等外部节点来源，抓取后生成外部节点的不可变版本 | 外部来源 ≠ 客户端订阅 ≠ 付费服务 |
| 用户 | 使用网络服务的人（代理用户），持有客户端订阅、凭据与门户账号 | 用户 ≠ 管理员 |
| 策略组与套餐 | 策略组决定能用哪些资源；套餐决定流量额度、有效期与重置周期，分给用户时生成不可变快照 | 策略组不是路由策略，也不是管理员权限 |
| 用量规则 | 读取计量账本得出“还能不能用、还剩多少、何时重置”，规则不改账本 | 计数器代次（epoch）不是套餐周期 |

面板保存期望配置、权限和历史记录，暂时离线时服务器上已应用的配置继续运行；Agent 主动连接面板，比对期望状态并应用配置，上报指标与流量，只从 GitHub Release 或配置的镜像下载并独立验签。

## 功能分级

每项现有功能处于下面五个级别之一。级别决定投入方式与默认显示，不决定代码放在哪里（[ADR 0128](adr/0128-domain-architecture.md)、[ADR 0126](adr/0126-workspaces-language-and-addresses.md)）。

| 级别 | 含义 |
| --- | --- |
| **核心** | 主线。持续投入，每个版本都必须在实机上签收。 |
| **支撑** | 运营服务需要的能力。保留并维护，只做主线需要的部分。 |
| **可选** | 按需使用。保持可用，不扩展新能力（原称“可选插件”，ADR 0128 起不再有插件，含义不变）。 |
| **降级** | 保留现有功能，只修缺陷和安全问题，不新增能力。界面上标为“实验”，放在所属工作区内、默认隐藏；高风险操作默认关闭，按服务器显式开启。 |
| **冻结** | 不再投入，只修安全问题，默认关闭或隐藏。评估后移除，移除需要用户单独授权。 |

已有安全门禁而“暂停”的能力（NodeQuality 完整验机）继续拒绝新任务，并按冻结处理。

| --- | --- | --- |

| 资产与生命周期（采购配置、维护状态） | 服务器详情 › 运维 | 续费与年度成本、退订提醒已并入「费用与续费」（[ADR 0097](adr/0097-ledger-server-records-and-source-references.md)），这里只留链接；采购配置与「资产与流量」合并为一份资产记录待路线图 4.4 |
| 模板与批量接入 | 服务器 › 服务器列表 › 批量接入 `/#/servers/batch` | 保留可用 |
| 批量任务、定时计划、维护窗口、有界自动处置 | 服务器 › 自动化与维护 | 固定步骤的跨服务器运维，非主线 |
| 故障事件 | 监测与诊断 › 故障事件 | 告警事件已覆盖主要需要，计划与告警合并（路线图 4.3） |
| 吞吐测试（双端 iperf3）、测试方案与综合报告；工具与依赖 | 监测与诊断 › 线路质量；系统 › 管理员与权限 | 验机与运维方向，保留不扩展 |
| 域名台账、证书版本、端点台账、端口转发、采集配置迁移 | 服务器 › 网络配置 | 节点证书已在网络服务内；端口转发计划改造为中转规则（路线图 4.2） |
| NodeQuality 日常检查 | 服务器详情 › 诊断 › 服务器验机 | IP 与解锁由「IP 信息」覆盖 |

### 冻结

冻结功能默认隐藏；“显示实验与冻结功能”开启后在原位置显示并标“冻结”。数据与接口保留。

| 功能 | 位置 | 原因 |
| --- | --- | --- |
| 系统网络参数调优、反向隧道、私有组网、受管防火墙 | 服务器 › 网络配置 | 通用网络运维，改动风险高，与服务配置主线无关 |
| 云资源与费用（费用对照、Hetzner 资源、安全组、供应商对比） | 费用与续费 | 云厂商控制台方向 |
| 硬件测试（CPU、内存、磁盘、持续稳定性、Geekbench）与 Speedtest | 监测与诊断 › 线路质量（新增步骤时） | 验机方向 |
| NodeQuality 完整验机（已暂停） | 服务器详情 › 诊断 › 服务器验机；监测与诊断 › 线路质量 | 安全门禁未解除 |

## 工作区与入口

一级导航是六个工作区，每个回答一个问题，顺序与使用频率一致（[ADR 0126](adr/0126-workspaces-language-and-addresses.md)，设计依据见[六工作区方案](redesign/04-workspaces.md)）。

| 工作区 | 回答的问题 | 入口（分页） |
| --- | --- | --- |
| 概览 | 现在需要我处理什么？ | 概览（侧栏中是一个独立入口，不设分组标题） |
| 服务器 | 我有哪些机器，它们是否正常？ | 服务器列表（列表、看板两种视图；单台与批量接入）；地址与域名；云资源；自动化与维护（实验）；网络配置（实验，含冻结项） |
| 网络服务 | 我提供哪些服务，给谁用？ | 节点；链路；外部来源；用户；策略与套餐 |
| 监测与诊断 | 哪里出了问题，为什么？ | 告警（事件、规则、通知渠道）；线路质量（质量概况、检测设置、网络检测）；趋势与报表；故障事件（实验） |
| 费用与续费 | 花多少钱，什么时候续？ | 续费项目（项目、即将续费、支出三个视图）；付费服务 |
| 系统 | 面板怎样运行？ | 面板设置；管理员与权限；备份与恢复；制品与版本；迁移与兼容 |

账号安全、外观与语言在账号菜单。面向其他角色的入口保持独立：公开看板（访客）、用户门户、邮箱登录与接受邀请（代理用户）。

**服务器详情**按“这台服务器的什么”分为七个分页：概况（监控面板，与看板单机视图是同一个面板，[ADR 0111](adr/0111-server-monitor-and-ink-jade-visuals.md)）、网络服务（运行时、下发状态、本机节点与经过的链路段、部署历史）、地址与资源（公网地址、指向它的解析规则、云资源）、资产与流量、诊断（IP 信息、TCP 诊断、服务器验机）、Agent（版本与升级、采集与上报、周期拨测、远程命令）、运维（实验）。除概况外，每个分页都是按这台服务器筛选的视图或这台服务器自身的设置；关联对象的编辑在它自己的家。页面右上角的「带此服务器打开」进入线路质量（实验功能开启时还有网络配置和自动化与维护），并预先选中这台服务器。

## 归类规则

新增或调整功能时按下面的顺序判断：

1. **先问是否服务主线。** 新功能必须直接服务节点、链路、用户与订阅，或者是运营这张网络所需的服务器、线路与费用感知。都不是，就进入[路线图](roadmap.md)的候选池，不直接实现。
2. **降级和冻结的功能不加新能力。** 只修缺陷和安全问题；需要扩展时，先申请调整级别。它们放在所属工作区内、默认隐藏并标注级别，不再集中到一个分组；级别变化只改标记，不搬位置与代码。
3. **按任务归组，不按实现方式。** 各领域提供的页面放进它服务的任务所在的工作区：DDNS 与阿里云 CDT 作用于服务器，属于“服务器”；sing-box 属于“网络服务”。
4. **一台服务器的事放服务器详情，跨服务器的事放工作区。** 服务器详情里的关联对象是按这台服务器筛选的视图，编辑仍在对象自己的家；工作区页面支持从服务器详情“带此服务器打开”。
5. **同一设置只有一个编辑位置。** 影响整个面板的设置在「系统」，属于某个领域的设置在该工作区的设置分页；其他页面只读显示并链接到编辑位置。
6. **讲同一件事的页面合成一个入口下的分页，入口名用对象名，不与工作区同名。** 页面标题与侧栏名称一致，不加眉题或面包屑；外观（主题、密度、语言）只在账号菜单里设置；说明文字只用一句话讲“在这里做什么”。
7. **核心旅程不依赖降级页面。** 核心功能需要的授权或设置，在使用它的位置就地提供。
8. **地址按读者区分**（[ADR 0126](adr/0126-workspaces-language-and-addresses.md)）。已发给代理用户或客户端的地址（客户端订阅、门户、邮箱登录、邀请、开通链接、专属地址）永不失效，改名必须改写到新地址；控制台页面地址尽量稳定，对象换了家时才改，旧地址改写到新地址并至少保留一个发布版本；接口地址按接口契约管理。
9. **每个入口属于一个领域。** 新页面先确定所属的领域（[ADR 0128](adr/0128-domain-architecture.md)、[领域归属表](domain-map.md)），再确定工作区；工作区是领域前端清单里的分组属性，调整工作区不搬代码。组合几个领域的页面（概览、服务器详情）属于应用层，只组合各领域的入口，不另存数据。

## 界面用语

对象与界面用语的唯一出处是[对象词典](redesign/03-objects.md)，其中“多义词的处理”一节列出“订阅”“节点”“插件”“套餐”“额度”“到期”等词的分开用法。最常用的几组：

| 用这个 | 指的是 | 区别于 |
| --- | --- | --- |
| 客户端订阅 | 代理用户拿到的配置链接（sing-box、Clash Meta、分享链接） | 外部来源：作为节点来源的机场订阅；付费服务：管理员自己付费的服务 |
| 外部来源 | 作为节点来源的机场或外部订阅 | 客户端订阅 |
| 付费服务 | 「费用与续费」中管理员自己付费、按周期续费的服务 | 代理用户的客户端订阅 |
| 服务器 | 接入了 Agent 的机器 | 节点：服务器上的一个代理入口 |
| 链路 | 入口、中转、落地组成的多段线路 | 节点：单个代理入口 |
| 管理员 | 登录面板的人，分所有者、运维和只读 | 代理用户：使用订阅的人，只能进入自己的门户 |
| 策略组 | 用户能用哪些节点、链路与外部节点 | 套餐：流量额度、有效期和重置周期 |
| 运行时 | 服务器上的 sing-box 服务实例 | 制品：签名的二进制；面板中的业务代码称“功能” |
| 安装运行时 | 管理员要求这台服务器运行 sing-box，面板安排安装 | 安装完成：Agent 下载、校验、应用并回报健康 |
| 概览 | 登录后的首页：需要处理的事项与整体状态 | 服务器看板：服务器实时状态，可公开 |
| 告警事件 | 自动检测产生的单条告警及恢复 | 故障事件：聚合、指派与处置记录（实验） |
| 网络检测 | 只测量，不改动 | 网络配置：会改变服务器网络状态，需要确认（实验） |
| 实验 | 降级功能：保留可用，只修缺陷和安全问题 | 冻结：只修安全问题，默认隐藏 |

会下发到服务器的对象用同一套状态词：已保存、已下发、已应用、已验证，以及失败与未知（[状态设计](redesign/06-states.md)）。

对外文案（README、仓库简介、登录前的页面）不描述用途，只写“服务器管理与配置”；控制台内使用“网络服务”“节点”“订阅”等功能名称（2026-11-06 用户要求）。界面以中文为源语言，英文是翻译（[ADR 0127](adr/0127-chinese-source-language.md)）。其余技术术语见[术语表](glossary.md)。
