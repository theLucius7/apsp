# Agent 运维与混合链路

本轮源码按 ADR 0043、0044、0045 实现。CI 继续暂停；本地检查与真实常驻设备、正式发布和生产迁移分别记录，不能互相代替。

## sing-box 运维

在服务器的 sing-box 区域或节点部署弹窗中，可以检查运行状态、查看脱敏服务日志、重启当前运行时，以及重试当前失败的期望配置。需要 Agent 声明 `runtime:operations:v1`；旧设备显示升级提示。

重启和重试要确认当前配置版本。排队期间版本变化、服务器退役或已经存在冲突操作时，拒绝执行过时请求。重启沿用签名校验、末次计量、健康检查与回滚流程；同一请求不会因为断线或 Agent 重启而再执行一次。结果与未完成记录持久保存，面板确认丢失时重发原结果。

日志仅返回时间、等级和固定分类，正文隐藏，避免认证信息进入浏览器。Windows 提供计划任务事件，不能当作运行时标准输出；日志不可读时明确显示不可用。真实平台步骤见[运维验收](acceptance/runtime-operations.md)。

## 远程命令

服务器任务页分别显示排队、已领取、执行中、取消请求、已取消、成功、失败、过期和中断，以及开始和结束时间。运行中点击“取消执行”先进入等待确认，设备清理受管进程后才成为已取消。默认仍需在服务器本机启用 `allow_remote_commands`。

Unix 运行取消的范围为受管进程组，不保证控制自行建立新会话或脱离进程组的程序。Windows 当前支持生命周期和未领取时取消，不提供运行中确认取消。旧 Agent 的开始时间与取消能力据实显示，不把领取期限当作已经执行命令的终止时间。详见 [ADR 0044](adr/0044-command-lifecycle.md)。

## 创建链路和机场来源

进入 **sing-box 插件 → 代理节点**，可筛选直连、链路和节点角色。链路在这里创建、查看和删除；策略组页面只负责引用资源和分配授权。

1. 在“订阅来源”填写 HTTPS 地址及可选认证，或者粘贴、上传内容。支持 URI 列表、Base64 URI 列表、sing-box JSON 和 Mihomo YAML。所有格式均在本机解析，未支持的协议或参数给出原因，不调用第三方转换站。
2. 创建链路时选择受管入口服务器，新建独立 Reality 监听；也可使用尚未授权、未被路径引用的独立 Reality 节点。自动端口从 20000–29999 分配，手动端口需未占用。
3. 按顺序添加 1–8 个内部或最终节点。受管跳使用其他服务器的 Reality 节点；订阅跳选择来源中的具体节点，允许放在中间。公开入口与每个受管跳不重复服务器，资源和端点不能循环。
4. 一批可创建 1–32 条独立链路。同批出现非法配置或端口冲突会整体撤回；重复发送同一个创建请求不会生成重复入口。每个入口服务器最多 64 条混合链路，以保留双代验证预算。
5. 将链路加入策略组，再分配给代理用户。创建链路不会自动授权用户，策略组也不能把链路入口当普通节点授权。

用户订阅只包含公开入口。机场 URL、全局路由/DNS/脚本、上游密码和内部 relay 身份不会出现在用户订阅或普通管理响应中。入站协议范围与导入协议范围不同；具体无损导入支持见[订阅来源实施记录](subscription-source-implementation-notes.md)。

## 应用、更新和恢复

所有受管服务器需要声明 `runtime:dependency-validation:v1`。入口签名运行时需包含本次配置要求的构建特性；Agent 准备阶段会检查 `with_clash_api`、uTLS、QUIC 或 Naive 等实际要求，缺少时拒绝应用。

链路先准备内部身份，入口再验证候选路径、切换、复验，并持久确认最低恢复代数，最后清理旧身份。验证使用入口本机受认证管理接口，经过完整路径请求面板 HTTPS 地址的 `/healthz`。因此面板的公开 HTTPS 地址必须能从最终出口访问。它证明当时的 HTTPS 连接可达，不保证所有 UDP 服务或机场持续可用。

每个设备最多排队四项路径验证；请求有效期为五分钟。设备离线、能力不足或依赖尚未应用时显示等待，不伪造成功。恢复屏障建立前失败会保留或恢复原路径；部分设备已记录恢复下界后，不自动回到低于下界的配置，等待其余确认或管理员明确撤销。屏障、签名配置和执行身份持久化，不能用超时猜测旧代已安全清理。

来源刷新新增不可变节点版本。跟随模式只为同一稳定身份的参数变化创建候选；固定模式等待管理员在详情中应用指定新版本。正在应用的完整版本集合被冻结，后来的来源刷新不改变它。来源缺失、歧义、归档或刷新失败保留已应用快照并显示事实，不替换节点或绕路直连。候选失败可在详情中重试，或选择同一节点的新版本。

修改来源 URL、获取认证或明确更换来源会建立新的身份代数；新来源不能自动接替旧绑定。更换路径、端点或顺序通过创建替代链路完成。已被混合链路引用的受管节点只允许改名称和启用状态，不能先改监听参数再期待旧配置可以恢复。

链路管理名称与客户端订阅名称分开；只有明确选择同步时才改入口订阅名称。订阅投影与历史部署证据分别保存，重命名不改写旧 `source_json`、凭据或流量流水。

删除链路前需解除策略组引用；新资源删除同时撤销其专用入口和内部身份。共享节点及来源保留，全部历史版本和创建收据保留。来源可以归档；被未删除链路的任何保留代数引用时不能删除。服务器停用或退役会撤销关联资格并发布清理配置，不缩短原路径。恢复记录每台运行时最多 1024 个路径标识，达到限制时拒绝新增引用，不清除旧恢复下界来腾出位置。

## 接口索引

管理接口均位于 `/api/plugins/sing-box` 并要求管理员登录：

| 接口 | 用途 |
| --- | --- |
| `GET/POST /servers/{id}/runtime-operations` | 运维历史与固定操作 |
| `GET /proxy-resources` | 统一直连、链路列表 |
| `GET/PATCH/DELETE /proxy-resources/{kind}/{id}` | 资源详情、名称与删除；kind 为 direct 或 chain |
| `POST /chains/batch` | 带请求 UUID 的原子批量创建 |
| `POST /proxy-resources/chain/{id}/apply-node-versions` | 带期望代数的节点版本应用，失败候选可用空版本集合重试 |
| `GET/POST /subscription-sources` | 来源列表与新增 |
| `GET/PATCH/DELETE /subscription-sources/{id}` | 脱敏详情、修改、归档与删除 |
| `POST /subscription-sources/{id}/refresh` | 手动刷新 URL 来源 |
| `GET /subscription-sources/{id}/nodes` | 已解析节点与不可用原因 |
| `GET /subscription-source-jobs/{id}` | 刷新任务进度 |
| `POST /subscription-source-jobs/{id}/cancel` | 取消刷新，迟到结果不能覆盖设置 |

旧两跳 API 保留兼容，不能用它编辑或降格新的混合路径。旧 Agent 协议、用户 ID、订阅令牌、旧路径、节点凭据、授权及历史账本保持兼容；升级时只能运行一个认识新模型的 publisher。
