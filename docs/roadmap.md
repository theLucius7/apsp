# APSP 当前目标与完成条件

APSP 是自托管的服务器管理与配置面板。服务器、节点与链路、用户与订阅、精确计量是主线；名称、观测、作业和费用为主线服务。代码按领域统一维护，当前不存在独立业务插件，见[领域架构](architecture.md)与[功能地图](product-map.md)。

本次按用户 2026-11-17 的要求作为一个完整变更整合、集中验证和交付，不再把同一项收口拆成多轮待办。

## 当前交付目标

| 目标 | 完成条件 |
| --- | --- |
| 一体化的领域实现 | 面板无插件外壳；内置组件与诊断工具命名一致；接口、界面和测试使用同一模型 |
| 配置可持续下发 | 面板下发期望配置；设备验证已签 Agent 并应用内置运行时；仅监控、当前配置健康、同步受阻与需升级分别显示 |
| 一次命令完成升级计划 | 明确目标与候选，异常和超时失败，恢复自动更新开关；运行时与仅监控主机分别核对 |
| 迁移成员原生采用 | 原 UUID、已发地址、当期用量与额度保持；预览与提交一致，并发和重复提交安全；已采用成员退出桥同步 |
| 当前资料只有一套 | 已完成的计划、逐小时日志与重复执行记录退出；当前状态、操作、决策与验收条件各有唯一入口 |
| 集中验证与可评审交付 | Rust、前端、边界与路由检查有最终整合结果；基线变更有接入脚本和隔离演练；生产切换单独记证据 |

## 已完成的结构收口

- 平台与九个领域已经拆开，链路与外部来源各只留一套模型。
- 后台周期、咨询锁、受控出站、通知投递与供应商客户端已经统一。
- ADR 0137 的会话、观测、运行时发布、成本、作业与资产列迁移完成。
- 通用暂停、逐用户限速与连接数已经有实现，后续是端到端验收，不重复建设。
- Agent 0.3.9 与运行时 `1.14.4-apsp.2` 已签名发布。16 台在线运行时主机已采用该版本，逐台核对结果见[当前交接](handoff/2026-11-17-reality-hardening.md)。

## 上线与实机完成条件

所有在线运行时主机能取得期望服务配置并用相应的内置运行时完成应用，真实客户端与用量正常；仅监控设备单独验收。hk3 在恢复开机后补验。迁移成员的原生采用完成、旧入口持续可用、账本核对无重复或遗漏后，APSP 才是唯一控制面，兼容桥才能退出。

签名面板镜像、AMD64/ARM64 测试环境、升级失败恢复、面板断连恢复与发布验收共同决定可发布状态。全面恢复 CI 遵守现行协作规则，不以历史绿色构建认证当前代码。

## 后续投入

先补齐用户列表、订阅交付、暂停恢复与异常解释，再改善线路质量、费用和续费体验。AI 接口先只读，写操作建立在受控发布和审计之上。新需求按功能地图准入；不扩展通用运维、售卖、地图主题或多内核平台。
