# 后续路线图

- 状态：**执行中**。2026-10-24 起草并按 [ADR 0087](adr/0087-narrow-positioning-proxy-network.md) 收窄定位；**2026-11-05 按实际进度重排**：Nexus 迁移进入收尾，成员运营删除（[ADR 0113](adr/0113-invitation-quota-without-commerce.md)），授权只走策略组（[ADR 0112](adr/0112-group-only-access.md)）。排期是建议值。
- 依据：[功能地图](product-map.md)的定位与分级、2026-11-05 的 main 与生产状态，以及第八节的市场调研。

## 一、定位

**apsp 是自托管的服务器管理与配置面板**：把分散在各家的 VPS 统一管理，入口、中转、落地一处配置，节点和订阅自动下发，流量按用户精确记账，面板离线不影响已应用的配置；每个用户可以自己登录查看订阅、用量与到期，并用管理员发放的名额邀请他人。服务器监控、费用与续费、线路质量是支撑能力。

接下来的顺序：**先把 Nexus 迁移彻底收完，让 apsp 成为唯一的控制面；再把核心做成可发布、可签收的版本；然后改善用户与运营体验；最后让 AI Agent 能安全地调用它。**

## 二、现状（2026-11-05）

**已完成（10-24 以来）：**

- 界面：按使用逻辑重组与功能分级（ADR 0098）、控制台重新设计（ADR 0102）、域名解析页重做（进行中，ADR 0110）。
- 订阅：Clash Meta 订阅与按 User-Agent 识别（ADR 0101）、用户专属地址（ADR 0103，生产 44 人已启用）。
- 运行时：自维护 sing-box `1.14.0-apsp.1`，即旧服务同一份内核（ADR 0119，替代 ADR 0104 的补丁）；隧道后的 VLESS 源站（ADR 0109）。
- 监控：中国可达性监控（ADR 0105）、三网 ICMP 拨测、成员线路与探针（ADR 0106）。
- 安全：具名管理员各自的 Passkey（ADR 0107）、统一再次验证（ADR 0108）。
- 费用与续费账本首批（ADR 0096、0097）；性能检查两轮（PR #209）。
- 2026-11-05：删除成员运营（钱包、销售套餐、订单、充值），邀请改为名额与邀请码、余额换算为名额；代理用户只通过策略组获得节点；用户诊断能说明迁移用户的真实来源。

**Nexus 迁移进度：** 2026-11-06 起全部 17 台主机都在 apsp 运行时上，内核是旧服务同一份 `1.14.0-apsp.1`（ADR 0119），Agent 0.3.7。最后 7 台（oracle-sg2、azure-in1、oracle-sg3、wap-tw1、aws-jp1、netcup-de1、aws-sg1）按用户决定在换内核后同一天连续切完。各主机上的 xboard-node、旧配置和 komari 监控已删除，回滚材料留在运维机上，不入仓库。Alice 与 CF 线路已按 ADR 0109 迁入（6 条隧道线路）。44 位用户中 43 位是迁移用户，**订阅内容仍由原系统渲染**；原权限组已并入策略组（ADR 0115），线路权限只看策略组，兼容桥每 30 秒同步成员、原面板组号与用量，并替健康的主机向原面板续心跳。

**欠账：** CI 自 10-01 暂停至今（仅为发版临时开启）；M0 的过程文档瘦身与测试环境未做；面板仍在生产主机上从源码编译（7 GB 内存、磁盘紧张）；成员状态（暂停、归档）只对迁移用户有效，普通代理用户没有暂停。

## 七之一、明确不做与候选池

| 不做 | 原因 |
| --- | --- |
| 与探针比主题、地图和展示效果 | 已商品化且有免费方案 |
| 通用运维面板（终端、文件、防火墙、组网、脚本编排） | 交给 SSH 工具和用户自己的 AI Agent |
| 机场售卖：公开注册、订单、支付、钱包、优惠券、邀请佣金、工单 | 定位是自用和小圈子；邀请只按名额发放，不收费 |

| 自研 AI 聊天或托管模型 | apsp 提供数据与受控操作即可 |
| 多内核代理（Xray 等） | sing-box 已覆盖主流协议 |

候选池（未排期，进入前须确定所属功能区、级别和验收旅程）：更多 DNS 提供方、面板高可用、移动端小组件、单二进制加 SQLite 的轻量部署形态、邀请码有效期与一次性批量导出。

v1.0 标准：三条核心旅程与迁移收尾在 AMD64、ARM64 上签收（Linux systemd，其他平台标明支持级别）；从上一个次版本升级与回退经过实测；CI 连续四周全绿且无未处理的高危安全问题；冻结功能去留确定、功能地图与界面一致；管理员手册覆盖全部核心与支撑功能。

## 八、市场依据

### 谁在长期玩服务器

- **机器多、厂商杂。** 有人十几台服务器分布在腾讯云、阿里云、netcup、甲骨文等多家厂商和零售商家，“不可能每次都去商家后台一个一个看”，还会忘记续费。
- **用途集中在网络服务。** 小机器主要用来做入口、中转、落地；用户按线路机和性能机区分，线路机看延迟、丢包和用量。很多是几十到几百 MB 内存的 NAT / LXC 小鸡。
- **续费是独立的痛点。** 到期、价格、流量重置日分散在各家后台，论坛里有人专门搭配 Wallos、DueGuard 等工具来记录和提醒。
- **AI 成了新负载和新入口。** VPS 上大量出现 Hermes 等 AI Agent、AI 接口中转（CLIProxyAPI、sub2api）；运维越来越多地交给“AI + SSH”。

### 他们现在用什么

| 需求 | 主流选择 | 对 apsp 的启示 |
| --- | --- | --- |
| 探针与监控 | Komari、哪吒、Beszel，零成本的 CF-Server-Monitor | 已商品化，不正面竞争；只做主线需要的监控 |
| 节点面板 | 3x-ui、s-ui（单机），Marzban、Remnawave（多节点、偏运营） | 单机面板不管链路和多机记账；多节点面板基于 Xray、面向售卖 |
| 多人订阅管理 | Xboard、V2Board 一类机场面板，常被拿来给熟人自用 | 自用只需要用户、套餐、订阅、用量和自助查看；注册、支付、工单都是负担 |
| 订阅管理 | Sub-Store、妙妙屋 | 玩家要多客户端订阅，并混用机场节点 |
| 中转转发 | flvx、哆啦A梦（flux-panel）、nyanpass、realm | 入口 → 落地的转发与按规则计量是长期需求 |
| 续费与费用 | Wallos、DueGuard、探针自带的到期字段 | 需要一处记录所有周期费用并按时提醒 |
| 质量测试 | NodeQuality、融合怪、IPQuality、回程路由脚本 | 关注 IP 是否原生、流媒体与 AI 服务能否解锁、回程线路 |
| 运维操作 | Netcatty（自带 AI 运维 Agent）、Hermes、Muse | 通用运维交给它们；apsp 提供可调用、可审计的接口 |

### 2026-10-24 补充调研

本轮按论坛与竞品 issue 重新核对需求（论坛页面多数只能看到搜索摘要，日期按帖号推算，误差约一到两个月）：

- **空位仍在。** s-ui 维护者承认多服务器管理是该仓库最受期待的功能，但不打算做（[s-ui#729](https://github.com/alireza0/s-ui/issues/729)）。玩家仍在用单机面板、订阅工具、转发面板、探针和续费工具拼装。
- **订阅层的投入产出比最高。** 用户最常问的是客户端里看不到用量、到期和订阅名（[妙妙屋#13](https://github.com/iluobei/miaomiaowu/issues/13)，[NodeSeek：合租如何给人显示到期与剩余流量](https://www.nodeseek.com/post-601147-1)）；小白最常卡在客户端格式不兼容（[V2EX](https://www.v2ex.com/t/1227915)）。
- **信任成为选型理由。** 2026 年密集出现的安全事件包括：面板 Web 终端以 root 运行（[nezha#1202](https://github.com/nezhahq/nezha/issues/1202)）、订阅工具的未授权远程执行（[Sub-Store#634](https://github.com/sub-store-org/Sub-Store/issues/634)）、面板内的赞助横幅（[3x-ui#6844](https://github.com/MHSanaei/3x-ui/issues/6844)）。
- **用户抵触膨胀。** 有用户请求探针停止扩展路线（[Komari#613](https://github.com/komari-monitor/komari/issues/613)）。首页应先显示待办与异常，导航要精简。
- **计量方式。** 用倍率表达线路成本差在多节点与转发面板中很常见（[Remnawave#222](https://github.com/remnawave/panel/issues/222)）。apsp 在额度评估层折算倍率，原始账本保持精确。

### 结论

1. 没有开源项目同时提供“多服务器 sing-box + 入口 / 中转 / 落地链路 + 逐用户精确记账 + 服务器与费用感知”，这是 apsp 的空位，也是它最初的设计重心。
2. 玩家现在用节点面板、Xboard 类面板、订阅工具、转发面板和续费工具拼出这套能力。apsp 应把与主线相关的部分合成一套，而不是复制每个工具的全部功能。
3. 安全是选型理由：Agent 最小权限、默认不开放远程执行，应成为默认行为。
4. AI 是新入口：面板要成为 AI 可调用、可审计的数据与操作源，而不是自己做运维工具。
