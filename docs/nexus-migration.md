# Nexus 与 Wallos 迁移

成员运营位于「代理服务 → 成员运营」，成员入口为 `/#/plugins/sing-box/member`。订阅费用位于「总览 → 费用与续费」（地址仍为 `/#/plugins/expenses`），服务器按资产设置自动列入，续期会记录付款，见 [ADR 0096](adr/0096-costs-and-renewals-ledger.md)。两者使用 apsp 原有管理会话、权限和组件，成员采用独立会话。

## 功能与资料

成员运营包含成员资料与批量状态、钱包调整和不可覆盖流水、销售套餐、钱包购买、代受邀成员首次开通、普通/预付邀请、EPay 充值与回执异常、公告指南、邮箱密码/Passkey、邮箱验证/恢复、提醒偏好及站内通知。策略组、基础套餐、节点、流量重置、服务器监控、终端和备份继续使用已有功能。

导入历史保留来源编号，原订单、钱包、邀请、支付、流量和重置记录可在迁移工作台及成员详情查询。已删除成员的历史仍保留原编号，但不伪造当前成员关联。历史不重新执行付款或入账；余额只生成一笔期初流水。新的交易使用原生账本。原成员编号、订阅令牌、UUID、余额、有效期及已用量保持；原密码只导入哈希，成功登录后升级算法；原到期/流量提醒偏好保持。新成员默认使用邀请和 Passkey，配置可用邮件后也可设置密码。

订阅费用包含分类、付款方式、付款人、币种和预算、单项周期及频率、下次付款、取消日期、替代订阅、手动续期/复制、统计、日历/ICS、通知记录及导入导出。金额精确到万分之一货币单位，按自然日历推进周期；服务商自动续费设置只推进计划，不在 apsp 发起付款。提醒复用已有 Telegram/Webhook，全局默认关闭。统计保留原币金额，缺少汇率时不伪造汇总。

## 私密快照

在本机私密目录生成 SQLite 一致性只读快照。工具不覆盖已有文件，输出权限 0600，单份上限 8 MiB。生产快照、哈希、支付凭据、成员资料均不得提交。

```bash
python3 tools/export_nexus.py /private/nexus.sqlite /private/nexus.json --source-id migration-001 --include-password-hashes
python3 tools/export_wallos.py /private/wallos.db /private/wallos.json --source-id wallos-001 --user-id 1 --timezone Asia/Shanghai
```

在迁移工作台先预览再确认导入。编号、邮箱、订阅令牌或来源冲突拒绝覆盖，同一摘要重复导入不会重记余额。成员先为待迁移状态，销售套餐和指南先保存为草稿。Wallos 文件在订阅费用的导入导出页处理。导入提醒默认关闭，核对后再开启。

成员登录门户后，可在「线路与探针」查看原 Nexus「节点」页的内容，见 [ADR 0100](adr/0100-member-lines-and-probes.md)：

- **线路：** 入口与落地地区、直连/转发/分流/家宽类型、在线状态、倍率、套餐归属和三网延迟。
- **探针：** 每台主机的负载，以及测得的 ASN、网络组织、用途类型与风险标记。

线路来自已导入的节点目录。仍由旧节点服务的线路，其状态由兼容桥每 30 秒从旧面板导出；已接管线路的状态取 apsp Agent。尚未接入 Agent 的主机暂无 IP 质量，家宽标为运营方声明。成员视图不显示连接地址、SNI、密钥、城市与坐标。

## 实际切换

1. 核对源库成员、余额、套餐、未决支付/订单/邀请、当前节点协议和订阅路由。将旧成员业务入口设为维护/只读，保留订阅、节点接口和历史付款回调。重新获取最终一致性快照。
2. 备份 apsp PostgreSQL、面板数据/凭据密钥、旧 SQLite、反向代理配置和当前镜像。备份留在私密部署目录，校验可恢复。
3. 在隔离库演练导入与兼容交换，通过后使用最终快照导入实际 apsp。逐字段核对余额、身份、期限、用量和全部来源记录。旧付款必须已结算或有明确的回调归属安排。
4. 在迁移工作台激活兼容通道，填写**原 HTTPS 订阅基础路径**并确认摘要及旧业务只读。激活恢复原成员状态和套餐期限；套餐缺少旧权限组映射时拒绝。准备本机同步器配置并启动。
5. 配置并核对支付渠道、运营开关、在售套餐和指南。EPay 使用宿主凭据库中的 `external-api` 凭据，内容为 `{"key":"<商户密钥>"}`。已有交易的渠道不可改变商户、网关或凭据引用；需要更换时新建渠道，保留旧渠道和原密钥供旧回调核验。不要直接轮换仍有待支付/待对账交易的凭据。
6. 核对同步、原订阅内容和节点拉取/上报，再让旧网页地址跳转到 apsp 成员入口。旧管理员地址可跳转成员运营页。不要对整域无条件重定向；保留旧订阅路径及查询参数、节点协议和必要回调。浏览器跳转使用暂时重定向，便于核对和恢复。

同步器配置示例（0600 文件，仅在受信本机使用）：

```json
{
  "legacy_database": "/private/nexus.sqlite",
  "legacy_container": "legacy-backend",
  "pg_container": "apsp-postgres-1",
  "pg_user": "apsp",
  "pg_database": "apsp",
  "import_id": "00000000-0000-4000-8000-000000000001",
  "interval": 10
}
```

```bash
python3 tools/nexus_compatibility.py --config /private/bridge.json --once
python3 tools/nexus_compatibility.py --config /private/bridge.json
```

同步器使用固定参数的本机 Docker CLI，不把密码放在命令行。PostgreSQL 产生带确认代次的成员资格批次，SQLite 事务原子更新允许字段，成功后确认心跳；失败重试不重复扣款。UUID/令牌不匹配时整批回滚。保留旧计量，旧后端初始化新成员缺失的计费日，但不重置已有流量。兼容期间拒绝重置原订阅令牌，防止原链接失效。成员资格变更后刷新旧 WebSocket 节点用户列表，每分钟补发一次完整列表，不改节点配置；失败时保留待刷新状态并重试。原节点仍由兼容后端提供协议服务，新增原生套餐须有旧套餐/权限组映射；原节点迁入 Agent 是后续独立操作。

超过 120 秒未确认同步时，新的购买、充值订单和预付交付暂缓；已下发配置保持。排查时先恢复同步，不轮换订阅令牌或覆盖余额。旧订阅及节点后端不能随着网页跳转停止。

## 回退与验收

服务器及代理运行时向 Agent 接管的条件、资产准备工具与当前差异见 [Nexus Agent 迁移](nexus-agent-migration.md)。服务器资产迁入不代表已接管代理进程。

开放新写入之前可恢复备份和旧网页路由；一旦 apsp 产生新订单、付款或邀请，不能直接恢复旧数据库而丢弃新流水，须冻结新写入、保留现库并对账。回退不得改变客户端原链接、UUID 或流量。

隔离验收使用 `cargo test -p apsp-panel --test member_commerce --test expense_subscriptions`、费用插件单元测试、`python3 -m unittest discover -s tools -p test_migration.py`、Bun 单元测试及 `web/tests/member-commerce.mjs`。EPay 用例须显式提供测试密钥环并以 `--ignored` 运行，仅读取本机夹具，不请求真实网关、不发送通知。完整范围与实际结果记在 [验收记录](acceptance/nexus-migration.md)。

旧后端的财务触发器和钱包账本保持原样；兼容器不回写余额，新建的旧协议身份余额为零。实际余额、充值、购买与退款只由 apsp 账本处理。旧协议仅使用套餐、期限、配额及禁用状态；停用、待资助和原生归档在兼容身份上表现为停用，不伪造旧归档审计记录。原本已归档的旧身份保持归档，不在兼容阶段重新启用。
