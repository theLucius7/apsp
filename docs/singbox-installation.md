# sing-box 安装与控制流程

Apsp 面板管理代理业务；服务器上的 Agent 和 sing-box 适配器将配置应用到本机独立的运行时服务。服务器只需要接入一个 Apsp Agent。代理用户、节点、链路、订阅和套餐都在「网络服务」工作区管理；系统管理员和服务器监控仍在原有系统/服务器页面。

```mermaid
flowchart LR
  A[管理员] --> P["面板网络服务<br/>节点、代理用户、链路、授权与订阅"]
  P --> C[目标配置与版本]
  C --> G[服务器 Agent]
  R[已验签制品库] --> G
  G --> S[设备 sing-box 适配器]
  S --> B[独立 sing-box 运行时]
  B --> G
  G -->|应用确认、健康与业务流量| P
```

## 操作顺序

1. 在“服务器”创建并接入设备，确认 Agent 在线且支持 sing-box。Agent 的安装命令只用于接入设备。
2. 在服务器详情的「网络服务」分页点击“安装 sing-box”；「代理节点 › 运行时」视图列出各服务器的安装状态并链接到该分页。面板安排配置，Agent 下载并校验面板已导入的对应平台签名制品，安装固定版本运行时。无节点时不会开放用户代理端口。
3. 在「网络服务 › 代理节点」创建直连节点；链路在「链路」视图用“创建链路”建立，模板为两跳（入口 → 落地）、入口 → 中转 → 落地或含外部节点的多跳。公开地址必须是客户端实际可访问的入口。
4. 创建代理用户。把普通节点、链路和外部节点放进策略组，再把策略组分配给代理用户。需要流量、重置周期和到期限制时另分配套餐。
5. 在服务器详情的「网络服务」分页确认目标配置已应用且健康，再使用代理用户的订阅。链路还需各段的服务器都应用成功。保存资源与实际代理可用分别显示。

设备支持 sing-box 不等于已安装，点击安装也不等于安装完成。服务器详情的「网络服务」分页和「代理节点 › 运行时」视图展示等待设备、等待应用、失败或已确认运行；在线状态与安装状态分别显示，历史成功不作为当前运行就绪。使用精确核对的 Agent 回报应用成功后，在核对确认实际配置与进程前显示为等待应用而不是失败；业务待完整预检确认期间，空运行时版本会一直停在这一状态，直到业务发布后核对。

## 安装失败的处理

缺少签名制品时，按[发布与导入说明](release.md)导入可信发布的 sing-box 1.14.2 对应平台制品，再等待 Agent 自动重试。「系统 › 制品与版本」只展示已验证的版本、平台与摘要，不在面板本机安装运行时。平台信息未知、libc 不受支持或签名校验失败时，页面保留具体原因；不能通过导入无签名脚本跳过。设备未声明支持时检查 Agent 的版本和运行模式；纯监控模式不会启动业务适配器。运行时配置或健康检查失败时，查看服务器详情的部署错误和已有版本。

修改节点或授权后，面板合并发布配置，设备离线期间保留待办，重连后继续。新配置失败时保留已有恢复机制；安装页不宣称所有长连接更新无中断。当前“安装 sing-box”不是卸载接口，删掉能力声明或移除清单也不能替代服务停止确认。

已有用户 ID、节点密钥、授权、旧 `/sub/{token}` 和历史流量继续可用。配额周期与计数器重置分开；详见[策略与套餐](singbox-groups.md)。签名导入及 Agent 接入见[部署说明](deploy.md)。

独立验收记录见[双端插件安装与恢复](acceptance/singbox-plugin-installation.md)，区分源码测试、专用节点实际安装和仍未验证的公网/生产范围。
