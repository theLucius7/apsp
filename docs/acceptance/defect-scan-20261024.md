# 2026-10-24 主线缺陷扫描与修复

用户在全部分支合入 `main` 后要求“扫描，进行下一步”。扫描起点是 main `b99eb03`（含 PR #160 运维平台、分支整合、apsp 改名、七个产品区与 shadcn/ui 界面重建、Nexus 导入与费用插件）。路线图的 M0 依赖尚未决定的 D6–D8，因此“下一步”按此前约定理解为：扫描主线，并修复核实的缺陷。

远端 CI 继续暂停，未触发、重跑或恢复。没有访问真实设备、云资源、DNS、支付或通知渠道。

## 扫描方法

| 手段 | 范围 | 结果 |
| --- | --- | --- |
| 自动检查 | `cargo fmt --check`、分层检查、全工作区严格 Clippy | 全部通过；整合方 2026-10-04 的全量本地测试见[整合记录](branch-main-integration-20261004.md)，本轮未重复全量测试 |
| 人工审查（六路并行，只读） | 管理员权限与全部路由；设备群、终端与 Agent；运维、备份、恢复与费用插件；网络配置、网络工作台、DNS 与阿里云；sing-box 插件与整合接缝（含会员与 Nexus 导入）；重建后的界面 | 见下表；高危项和多数中危项已逐条对照源码复核 |

系统性原因：全局守卫只从路径中的 `servers/{n}` 推导服务器范围，网络工作台、网络配置、运维和 DNS 四类前缀交给处理函数自查；处理函数检查了服务器编号，却普遍没有约束三类对象：凭据库引用、全局共享设置、不绑定服务器的对象。

## 第 1 步修复记录（权限与密钥）

统一规则：在凭据中心选择或改指凭据须所有者会话（限权 API 令牌不行）；修改全部服务器共享的设置和未关联服务器的对象须全局授权，这类对象的读取按既有规则对有读取权限者共享（费用记录除外，读写都须全局授权）。保持原引用不变的编辑不受影响。

| 编号 | 修复 |
| --- | --- |
| E1 | 面板自身执行的 HTTP/TCP 探测在解析后、每次重定向后都检查目标地址，回环、内网、链路本地和保留地址直接拒绝并提示改由服务器执行；拒绝发生在建立连接之前。 |
| E2 | IP 信息提供方的保存仅限所有者会话；非所有者读取列表时隐藏 `credential_ref`。 |
| E3 | DDNS 规则直接引用凭据时须所有者会话；同一规则保留原凭据、提供方、区域和名称的编辑不受影响。受限管理员仍可通过已授权的 DNS 账号创建规则。 |
| E4 | DNS 账号的创建，以及凭据、提供方变更或区域扩大须所有者会话；ACME 计划新设或更换凭据须所有者会话；会员邮件设置在选择凭据或更改主机、端口、加密方式时须所有者会话。 |
| E5 | 部署预览手工指定私钥引用须所有者会话；lego 签发版本自动关联其签发任务的私钥，不受影响。 |
| E6 | 没有关联服务器的网络配置文档，以及证书引用的无服务器域名台账，写入须全局授权；读取仍对有读取权限者共享，与全局搜索的既有规则一致。更新同时校验原文档与新文档，受限管理员不能给共享文档加入自己的服务器。 |
| E15 | Webhook、订阅来源与 sing-box 来源更换到其他协议、主机或端口时，若已保存认证请求头而本次既未重新填写也未清除，返回错误，不把旧请求头发往新地址。 |
