# 2026-10-24 界面第三轮：内容可见性修复与手机布局

用户要求继续优化界面。本轮先用现有浏览器夹具的截图功能，在桌面和手机宽度拍下代理网络核心页面（代理节点、链路、订阅来源、服务器、看板、统计等），再依据截图找问题、修问题。路线图 0.2“界面体现分级”仍等待决定 D6，本轮不做。没有新增依赖。

工作在分支 `claude/dreamy-heisenberg-w2g0rn` 上进行，从主线 `56a0d84`（已合并 PR #170、#172）重新开始。全部修改完成并冻结后集中验证。远端 CI 继续暂停，未触发、重跑或恢复。没有发布、部署，也没有访问真实设备或生产面板。

## 截图发现的问题

- **内容区空白（严重）：** 节点库等夹具的截图只有侧栏和顶栏，内容区完全空白，但夹具本身都通过了，因为 Playwright 把透明元素也算作可见。复现结果：
  - 正常浏览器：`<main>` 不透明度为 1。
  - 暂停页面时钟：为 0。
  - 拦截 Motion 特性包：为 0。

  原因是页面与登录表单的进入动画从透明开始，而动画特性包异步加载。只要特性包加载失败（网络中断、扩展拦截、升级后旧标签页请求已删除的分包）或动画帧不推进，整个后台和登录页都一直空白；网速慢时，特性包下载完成前首屏内容区也是空白。
- 手机宽度下，服务器列表需要横向滚动约 9 列表格。
- 选中的订阅来源卡片整块填充强调色，名称按钮保持灰底，看起来像徽标。
- 手机顶栏挤着被截断的账号名（如 “TEST_ONL…”）。

## 修改内容

- **动画与可见性：**
  - Motion 的 `domMax` 特性包改为随首屏同步加载，放在单独缓存的 `motion` 分包，删除异步加载的 `lib/motion-features.ts`。
  - 页面、登录表单、看板卡片和错误提示的进入动画改为只做位移，不再从透明、零高度或隐藏开始。淡入只保留给按需打开的浮层。规则写入 ADR 0088 的修订。
- **服务器列表：** 手机宽度改为逐台卡片，包括全选、选择、状态与最后联络、处理器/内存用量条、成本、流量、版本和操作；桌面仍用表格。行内各部分抽成共用函数，两种布局不重复写逻辑。成本、流量的辅助行补上了辅助文字样式。
- **订阅来源卡片：** 选中状态改为浅色描边加极淡底色；名称按钮展开时改为强调色文字，不再保持灰底。
- **手机顶栏：** 只显示退出图标按钮，无障碍名称和悬停提示包含账号名；账号名改在菜单面板底部显示。退出按钮仍始终可见。
- **测试：**
  - 新增 `motion-resilience.mjs`：暂停页面时钟后，检查登录表单、后台内容和错误提示的累计不透明度为 1、高度大于 0。旧构建在后台内容和错误提示两项上会失败。
  - 新增 `motion.test.ts`：内容进入预设不得包含透明度、高度或显示属性。
  - `server-list-selection.mjs` 在手机宽度改用服务器卡片，并检查卡片列表不横向溢出。
  - `subscription-sources.mjs` 的截图模式原先要求弹窗背景计算值等于 `rgb(255, 255, 255)`，在设计变量改为 oklch 后失效，现在先绘制成像素再比较。这条断言只在设置截图目录时执行，普通运行不受影响。

## 统一验证

环境：Bun 1.4.2（与仓库固定版本一致），Chromium 1243（Playwright 预装）。

- **构建：** `tsc -b` 与 Vite 生产构建通过，无 500 KB 警告。主入口约 202 KB（gzip 71 KB），`motion` 分包约 129 KB（gzip 43 KB）随首屏加载，样式约 108 KB（gzip 18 KB）。
- **前端单元测试：** Bun 36 个文件、193 项通过，2478 次断言。
- **浏览器回归：** 共 54 组（53 套夹具 + 主题对比审计）。
  - 首轮 53 组通过，合计约 1205 秒（4 路并行）。
  - `theme-contrast.mjs` 失败：它在手机宽度从表格行里找“删除”按钮，而手机上现在是服务器卡片。已改为按宽度选择表格行或卡片，意图不变。
  - 单独复跑通过：16 个页面状态、1370 个可见文字节点全部达到 WCAG AA，无横向滚动、无页面错误。文字节点比上一轮多，是因为手机上改为卡片后显示的字段更多。
- **仓库检查：** `git diff --check` 通过。本轮没有修改 Rust 源码，未运行 cargo。
