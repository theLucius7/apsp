# 2026-10-23 界面完全重构（shadcn/ui Nova）

用户要求完全重构界面：组件统一为 shadcn/ui Nova（Radix UI），样式使用 Tailwind CSS v4 与 CSS 变量，图标使用 Lucide，动画使用 Motion，可调分栏使用 react-resizable-panels，拖拽使用 dnd-kit，跨组件状态使用 Zustand。设计决定与新增依赖说明见 [ADR 0086](../adr/0086-ui-component-system.md)，实施中的选择记录在[待决问题](../open-questions.md)的 2026-10-23 条目。

工作在分支 `claude/dreamy-heisenberg-w2g0rn` 上进行，起点是主线 `1263b2d`。按仓库节奏，全部修改先完成并冻结，再集中验证；验证发现的问题修复后只补验受影响的范围，最后对冻结后的最终构建全量重跑浏览器回归。远端 CI 继续暂停，未触发、重跑或恢复。没有发布、部署，也没有访问真实设备或生产面板。

## 修改内容

- **基础设施：** 新增 Tailwind CSS v4（Vite 插件）、`components.json`、`@/` 路径别名；`src/index.css` 集中定义浅色/暗色设计变量（oklch、青绿主色、固定语义色、圆角、密度），删除其余 21 个 CSS 文件和 `app/page-styles.ts`。
- **组件：** `src/components/ui/` 为按 Nova 注册表源码生成的 Radix 组件（对话框、确认框、按钮、徽标、表格、输入、原生下拉、复选框、开关、提示、可调分栏等 21 个文件）；未被使用的生成组件已删除。`components.tsx` 及 `components/` 的页头、面板、通知、空状态、统计、弹窗、确认框、复制、分段导航、主从分栏和拖拽列表改用这些组件。
- **页面：** 管理端全部页面、插件页、公开看板与代理用户门户改用统一组件和 Tailwind 类；图标统一为 Lucide。看板保留独立浅/深色切换，用户门户跟随系统主题。
- **交互库：** Motion 以 `LazyMotion` 按需加载并跟随系统“减少动态效果”；后台侧栏与主从页面使用可调分栏；节点库自定义排序支持 dnd-kit 拖拽（含键盘与中文播报），保留上移/下移按钮；语言、外观、外框、会话和看板货币移入 Zustand store。
- **验证中修复的问题：**
  - 暗色危险按钮与浅色主按钮悬停态的文字对比度不足：调整危险色、主按钮悬停改为向前景色混合；静态对比测试增加 20% 底色并覆盖弹窗表面。
  - 运维页“再次验证管理员身份”的错误显示在模态弹窗背后，对辅助技术不可见：改为显示在弹窗内。
  - 看板筛选后旧卡片因退出动画短暂残留、已恢复的错误提示短暂残留：改为过期内容立即移除，新内容保留进入动画。
  - 重新进入看板时汇率为空会闪现“汇率缺失”：保留上次的全局参考汇率直到首次读取完成，读取失败或无权限时仍清除。
  - 外框状态在每次开关手机菜单时写入浏览器存储：改为只在侧栏折叠偏好实际变化时写入。
  - 安装命令预览恢复单行显示（`CopyField` 增加 `singleLine`），服务器详情第二组信息补回 `data-slot`，Webhook 模板预览使用独立钩子。
- **测试：** 浏览器夹具的类名选择器改为 `data-slot`/`data-dialog`；确认框按 `alertdialog`、授权开关按 `switch` 定位；在模态弹窗打开时故意操作背景元素的场景使用 `includeHidden`；Radix 复选框通过其表单镜像输入定位；一处原本可能先匹配到弹窗内批次预览的等待改为先等弹窗关闭。断言的原有意图不变。`theme-contrast.mjs` 和 `contrast.test.ts` 按新设计变量重写。

## 统一验证

环境：Bun 1.4.2（与仓库固定版本一致，另用本机 1.4.4 交叉构建），Chromium 1243（Playwright 预装），Rust 1.97.0，PostgreSQL 16（执行环境预装实例，经回环地址访问，只为本轮临时启动并建立测试角色与测试库）。

- **构建：** `tsc -b` 与 Vite 生产构建通过，无 500 KB 警告。主入口约 230 KB（gzip 81 KB），React 222 KB、Radix 87 KB、Motion 特性包 86 KB（按需加载）、样式 116 KB（gzip 18 KB）。Bun 1.4.2 与 1.4.4 构建出的 68 个 `web/dist` 文件逐字节一致，已提交的产物即该构建。
- **前端单元测试：** Bun 34 个文件、190 项通过，2420 次断言（1.4.2 与 1.4.4 均通过）。
- **浏览器回归：** 共 51 组（50 套夹具 + 主题对比审计）；`passkeys.mjs` 需由 Rust 用例拉起，见下条。
  - 首轮 51 套中 25 套通过；主题对比审计发现 3 处对比度不足。失败原因集中在：确认框角色变为 `alertdialog`、模态弹窗隐藏背景、Radix 复选框/开关、漏改的旧类名选择器，以及上文列出的应用问题。
  - 修复后补验失败范围：第二轮 27 组中 18 组通过，第三轮 8 组中 7 组通过（剩余一处背景按钮定位随后修正）。
  - 冻结输入后对最终构建全量重跑：51 组全部通过，合计约 1485 秒（4 路并行）。主题对比审计覆盖登录、服务器列表、确认框和公开看板 × 浅色/暗色 × 1440/390 宽度共 16 个页面状态、1354 个可见文字节点，全部达到 WCAG AA，且无横向滚动、无页面错误。
- **Rust 嵌入与 Passkey：** 使用最终 `web/dist` 编译 `apsp-panel`，运行 `frontend` 与 `passkeys` 两个测试目标（含被忽略的浏览器用例）：7 项全部通过。其中 `compiled_embedded_frontend_matches_every_dist_file_for_get_and_head` 确认 68 个构建文件均按原内容与缓存头嵌入；`virtual_authenticator_browser_roundtrip` 通过 Rust 拉起面板与隔离测试数据库，用 Chromium 虚拟认证器完成 `passkeys.mjs` 的管理员与代理用户 Passkey 往返。首次运行因测试角色没有在默认库建模式的权限而在 sqlx 准备阶段失败，改为该角色自有的测试库后重跑通过，与代码无关。
- **仓库检查：** `cargo fmt --check`、`tools/check-core-boundary.py`、`git diff --check`、`bun install --frozen-lockfile` 通过。本次没有修改 Rust 源码，未重跑全工作区 Clippy 与 `cargo test`。
