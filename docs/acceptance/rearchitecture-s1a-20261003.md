# 2026-10-03 阶段三 S1a：补齐有序来源的能力

2026-10-04 整合注：本文保留原分支对应提交与当时验收结果；原迁移 0049–0054 在主线依次顺延为 0059–0064，原 ADR 0077–0079 顺延为 0083–0085。正文的旧迁移号与性能、测试数字属于历史输入，不能认证当前整合源码；当前映射与集中验证见[本次整合记录](branch-main-integration-20261004.md)。

这是阶段三迁移方案中 S1 代码准备的第一步。用户已确认来源以 B（有序来源）为准、并开始 S1。起点是提交 `3e5600b`。

所有修改先集中完成并冻结，然后统一验证。远端 CI 继续暂停。本步不迁移任何数据，也不改变 A（数字编号来源）的行为。没有访问真实订阅服务、设备或生产面板。

## 修改内容

- **迁移 `0051_ordered_source_parity.sql`（只追加）：**
  - 有序来源新增 `user_agent`、`auto_refresh`、`traffic`、`changes` 四列；刷新周期检查放宽为 300–2592000 秒。
  - 现有来源保持原行为：不发送 User-Agent，自动刷新开启。
  - 节点新增采用标记 `adopted`；现有节点为未采用，不会因升级进入节点库。
  - 节点和版本新增数字别名 `public_id`，分别取自 A 的节点、版本编号序列，以后从 A 导入的编号不会与之冲突。
  - 版本新增 `legacy_config`，只给从 A 导入的版本使用；本步不写入。
  - 新增预览暂存表 `singbox_ordered_source_previews`。
- **解析器：**
  - 读取 sing-box JSON 和 Mihomo 节点上的 `provider_id`，规则与 A 相同（非空、不超过 256 字节、无控制字符）。
  - 有提供方编号的节点按 `provider:` 键识别；编号无效时只有该节点不受支持。
  - 解析结果因此变化，解析器版本由 `sinan-subscription-v1` 升为 `sinan-subscription-v2`。升级后旧的条件缓存不再使用，下次刷新整篇重新解析。
- **抓取与任务：**
  - 有序来源按设置发送 User-Agent。
  - 记录提供方的 `subscription-userinfo` 流量信息；解析函数移入共享抓取器，两套来源共用。
  - 关闭自动刷新后，不再自动排程。
- **快照：**
  - 修订写入逻辑抽成 `persist`，后台任务和预览保存共用。
  - 每次成功都记录相对上次成功的变更摘要：新增、更新、缺失、不受支持。304 时归零，不受支持的数量保留。
- **新接口：**
  - 来源预览：创建、放弃、保存。保存时只采用所选节点，`request_id` 幂等。
  - 节点采用开关：校验当前版本；采用只影响节点库可见性，不影响链路选点。
  - 来源创建和修改接受 `user_agent`、`auto_refresh`。
- **文档：**
  - `docs/api.md` 的来源一节原本写成 `/subscription-sources`，实际是有序来源接口；已改正路径并补上新字段和新接口。
  - `docs/chain-subscription-sources.md` 和迁移方案同步更新，方案中记录了已确认的决定和 S1 拆分。
- **界面：** 没有改动，界面合并放在 S1b。

## 统一验证

环境：本机 Rust 1.97.0，PostgreSQL 16（专用临时实例，回环 55432 端口）。

- `cargo fmt --check`、分层检查、`git diff --check` 通过。
- 全工作区全 targets Clippy（warnings 视为错误）：首轮报一处元组类型过于复杂，改为命名的行结构后通过。
- Rust 与 PostgreSQL（sing-box 插件与组装 crate）：一次运行全部通过，共 393 项，0 失败，7 项条件忽略。
  - 插件单元测试 76 项，比上一轮多 2 项，覆盖提供方编号的读取和无效编号的处理。
  - 组装 crate 集成测试 317 项，比上一轮多新增的 `ordered_source_parity` 6 项：
    - 设置往返，以及自动刷新的排程开关。
    - 变更摘要的四项计数。
    - 预览保存只采用所选节点；保存请求可以重放；预览用后失效；每位管理员最多 8 份预览。
    - 采用开关的版本校验。
    - 数字别名与 A 共用序列。
    - 从 0050 升级到 0051 时，已有数据的取值保持不变，版本表仍不可修改。
  - 迁移数量断言更新为 51。
- 宿主、DDNS、阿里云、云 API 和前端都没有改动，没有重跑。
