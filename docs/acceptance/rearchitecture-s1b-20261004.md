所有修改先集中完成并冻结，然后统一验证。远端 CI 继续暂停。本步只提供显式执行的命令，合入本身不迁移任何数据；没有访问真实订阅服务、设备或生产面板。

## 修改内容

- **迁移 `0052_source_migration.sql`（只追加，不搬数据）：**
  - 迁移状态表 `singbox_source_migration` 与判断函数 `singbox_sources_migrated()`；来源编号和修订编号对照表。
  - 导入版本保存原配置摘要 `legacy_config_sha256`。
  - 节点库元数据和外部授权指向 A 表的外键改为触发器检查：所引用的节点和版本须存在于 A 或 B 中。
  - 两个视图 `singbox_external_node_states`、`singbox_external_version_configs`：迁移前取 A，迁移后取 B，编号都是公开数字编号。
  - 迁移后 A 的六张表由触发器拒绝一切写入。
- **命令 `sinan-panel source-migration`：** `precheck`、`apply`、`rollback`、`snapshot [--at]`、`compare`，结果以 JSON 输出，详见方案第 11 节。
- **使用方切换：**
  - 节点库、外部授权和用户订阅改读上述视图，B 的类型化版本经编译器转换后才进入用户订阅。
  - 导入版本用原配置渲染，并按 A 的解析器版本判断是否可新授权。
  - 节点库移除节点时，采用状态写到当前为准的那张表。
- **A 的只读兼容：** 迁移后 A 的写接口返回 409，后台刷新停止；来源详情新增 `migrated_to`。迁移后不能新建带订阅跳的 mixed 链路。
- **B 的采用接口：** 增加 `metadata_revision`，与节点库共用修订号；取消采用前检查链路和授权引用，与节点库移除一致。
- **文档：** 迁移方案第 11 节、ADR 0085 状态、`docs/api.md`、节点库与来源说明。

## 统一验证

环境：本机 Rust 1.97.0，PostgreSQL 16（专用临时实例，回环 55432 端口）。

- `cargo fmt --check`、分层检查、`git diff --check` 通过。
- 全工作区全 targets Clippy（warnings 视为错误）：首轮报三处，均已修正后通过：
  - 一处模块路径写错；
  - 一处多余的解引用；
  - 测试中的元组类型过于复杂，已改为命名的行结构。
- Rust 与 PostgreSQL（sing-box 插件与组装 crate）一次运行：394 项通过，2 项失败，7 项条件忽略。两项失败如下：
  - **解析器交叉检查（真实缺陷）：** B 的解析器在节点缺少某些选项时填入默认值（Hysteria2 的 `server_ports: []`、`bbr_profile: "standard"`、`disable_chrome_parrot: false`，TUIC 的 `udp_relay_mode: ""`），A 的客户端校验不认这些字段。不修正的话，迁移后首次刷新会让所有 Hysteria2 和 TUIC 节点从用户订阅中消失。
    - 修正：`ExternalOutbound::from_normalized` 去掉这些默认值后再校验。
    - 非默认值（例如真正的端口跳跃）仍不能进入用户订阅，与 A 原来拒绝导入一致。
    - 测试改为断言：只有带端口跳跃的 Hysteria2 被拒绝，不带这些选项的 Hysteria2 和 TUIC 可以转换。
  - **迁移集成测试（测试夹具）：** mixed 链路要求面板配置可达的 HTTPS 地址。测试改为用占位公网地址启动，并从本地测试服务读取用户订阅。
- 修正后按规则只补验受影响范围，全部通过：
  - fmt、全工作区 Clippy；
  - 编译器 crate：49 项通过，7 项条件忽略；
  - sing-box 插件单元测试：77 项通过；
  - 迁移集成测试：2 项通过。
- 新增 `source_migration` 两项集成测试：
  - **数字编号来源经轮换后迁移：** 该来源有两个已采用节点，一个固定版本授权，一个跟随授权，还有一条以其节点为订阅跳的 mixed 链路。断言：
    - 预检计数正确，不改变数据。
    - 迁移前后在同一时刻的比对记录完全相同：配置包摘要、用户两种订阅格式、外部授权条目、节点库条目。
    - A 的写接口返回 409；直接写 A 表被触发器拒绝；不能新建带订阅跳的 mixed 链路。
    - 有序来源中的节点沿用原编号和采用状态；重复迁移被拒绝。
    - 导入节点仍可新授权；新的有序来源节点可以采用并授权，进入用户订阅。
    - 存在这种授权时回滚被拒绝；撤销后回滚成功，比对记录与迁移前完全相同，A 恢复可写，可再次预检。
  - **设置、错误和删除状态迁移：** 网址来源的地址与认证头、周期、下次刷新时间、错误代码、请求标识和创建时间原样迁移；已删除来源不带秘密；排队任务被取消；回滚后有序来源清空；未迁移时回滚被拒绝。
- 其余改动：迁移数量断言更新为 52；S1a 的采用测试补上 `metadata_revision`，并验证旧修订号被拒绝。
- 宿主、DDNS、阿里云、云 API 和前端都没有改动，没有重跑。
