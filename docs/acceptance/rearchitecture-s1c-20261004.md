## 修改内容

- **代码修正（第 5.1 节三项）：**
  - 有序发布对 legacy 代只在入口有有效授权时编译中继，与旧两跳路径一致。
  - `qualified` 对 legacy 代沿用两跳订阅规则。
  - 已应用阶段不再对 legacy 代发起探测。
  - 摘要算法差异经核实不影响生命周期；接管预检比较解码后的节点参数，不比较摘要。
- **迁移 `0053_legacy_takeovers.sql`（只追加）：** 新增 `singbox_legacy_takeovers`，保存接管时清空的出口与 relay UUID，供回滚恢复。
- **命令 `sinan-panel legacy-takeover precheck|apply|rollback [--chain <id>]...`：**
  - 每条链路一个事务，跳过的链路给出原因代码。
  - 同一事务内比较两台服务器的配置包摘要，以及相关用户两种格式的订阅摘要；有差异就回滚该链路。
  - 发布侧新增事务内的配置包摘要计算，编译时的写入都在保存点内回滚。
- **文档：** 迁移方案第 12 节（含接管后的行为差异）、ADR 0085 状态。

## 统一验证

环境：本机 Rust 1.97.0，PostgreSQL 16（专用临时实例，回环 55432 端口）。

- `cargo fmt --check`、分层检查、`git diff --check` 通过。
- 全工作区全 targets Clippy（warnings 视为错误）：首轮报测试中一处可省略的显式生命周期，修正后通过。
- Rust 与 PostgreSQL（sing-box 插件与组装 crate）一次运行：398 项通过，0 失败，7 项条件忽略。新增 `legacy_takeover` 两项：
  - **接管与回滚的字节一致：** 一条有授权的旧两跳和一条没有授权的旧两跳共用出口，用 0044 同样的 SQL 回填生成第 1 代。断言：
    - 预检全部就绪且不改数据。
    - 接管后，同一时刻的配置包、用户订阅和外部授权比对记录与接管前相同（只有节点库展示变化），用户订阅逐字节相同。
    - 运行有序生命周期后，链路仍是第 1 代、已应用。
    - 重新发布不产生新的设备修订。
    - 回滚后恢复旧两跳的出口与 relay UUID，比对记录再次相同；对未接管的链路回滚被拒绝。
    - 没有授权的那条链路覆盖第 1 项修正：修正前它的中继会出现在出口服务器上，配置包摘要随之改变。有授权用户的订阅覆盖第 2 项修正。
  - **不能保持字节一致的链路被跳过：** 入口有直接授权、入口有节点策略授权、出口已停用、入口参数改变、链路已删除、链路不存在，各自给出对应原因代码，链路保持旧两跳，没有写入接管记录。接管后链路一旦开始新代，回滚被拒绝。
  - 迁移数量断言更新为 53。
- 前端、宿主、DDNS、阿里云和云 API 都没有改动，没有重跑。
