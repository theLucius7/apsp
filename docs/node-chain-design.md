# 代理节点、混合链路与订阅来源设计

> 本设计的源码与本地隔离验证已完成；当前可用入口、保守的端点编辑限制及运行验证方式见[实施说明](agent-runtime-and-chains.md)与 [ADR 0045](adr/0045-mixed-path-execution.md)。下文保留设计背景与目标验收清单，不能据此认定实机签收完成。

状态：源码实现与本地隔离验证，正式签收另记。日期：2026-10-01。原设计核对基线：`042409039cdfb0379cc0192a5105d00455697b7c`。

用户要求“创建的多条链路，应该在代理节点里面创建”，并进一步明确中间链路可以使用来自机场等服务的订阅配置。本方案将直连节点和链路统一放到 **sing-box 插件 → 代理节点** 创建、查看和管理。每条链路有受管公开入口和按顺序连接的代理节点；中间段及最终出口均可选择自有受管节点或订阅中的具体节点。多条链路可以共用入口服务器，各自拥有独立监听端口、授权资源和订阅项。

用户已确认采用“统一代理节点页面，直连节点和链路并列管理”，据此确定页面结构。

这里的“代理节点”指用户可以连接的业务资源；服务器是承载资源的设备。新授权将原两跳范围扩展为有序混合链路，见 [ADR 0040](adr/0040-mixed-chains-and-subscriptions.md)。分层、授权并集和不可变账本继续遵循 [ADR 0035](adr/0035-singbox-policy-package-groups.md)。订阅来源的导入、格式和更新规则见 [订阅来源设计](chain-subscription-sources.md)。本文件描述目标行为，现有页面和接口的实际使用见 [策略与套餐说明](singbox-groups.md)。

```text
客户端 → 自有入口 A → 机场订阅节点 X → 自有出口 B → 互联网
客户端 → 自有入口 A → 自有中间节点 M → 机场节点 X → 自有出口 B → 互联网
客户端 → 自有入口 A → 机场节点 X → 机场出口 Y → 互联网
```

机场节点无需安装 Agent。订阅 URL 是节点集合的来源，导入后要选择其中一个明确节点作为某一跳，URL 本身不充当代理节点。用户订阅始终只提供公开入口及用户自己的凭据。

sing-box 插件
├─ 代理节点
│  ├─ 节点库：直连节点与链路并列，按类型、协议、标签、状态、服务器、来源筛选
│  ├─ 链路：两跳与有序链路的创建、路径与引用、版本、替代链路
│  ├─ 订阅来源：添加地址或配置、解析节点、更新记录、依赖链路
│  ├─ 创建节点：直连节点 / 链路

├─ 策略与套餐
│  ├─ 策略组：选择已创建的直连节点、完整链路

2026-10-03 界面重排后，三个分区由 `view=catalog|chains|sources` 选择；旧的 `kind=chains` 链接打开链路分区，见 [ADR 0084](adr/0084-admin-layout-and-node-sections.md)。代理节点列表按类型和服务器筛选。服务器筛选可选择“作为入口”“作为中间段”“作为出口”“任一段”；直连节点按所在服务器匹配。链路详情使用 `/#/nodes/chain/{id}`，直连详情使用 `/#/nodes/direct/{id}`，导航均归属“代理节点”。节点 ID 与链路 ID 可以相同，列表、深链接和操作必须携带类型。订阅来源在本页的区域或抽屉管理，不新增主导航，也不作为可单独授权给用户的公开入口。

链路入口从直连资源列表和单独授权选择器中排除。被引用的受管中间/出口节点可继续作为直连资源出现，并标注“被 N 条链路引用”。统计分别显示直连资源数和链路数；来源节点数、物理监听数、服务器数另行统计，避免把一条链路的内部节点重复计为用户资源。

策略组资源选择器将直连与链路并列展示，保存时仍映射到既有 `node_ids`、`chain_ids`。没有链路时显示“前往代理节点创建链路”，并保留当前策略表单草稿。“策略与套餐”移除链路 CRUD 页签；旧入口引导至代理节点的链路筛选。现有旧链路页签没有独立 URL，无需新增假重定向。

## 在代理节点内创建一条或多条链路

默认流程如下：

1. 点击“创建节点”，选择“链路”。
2. 选择入口服务器，填写客户端连接的公开地址、Reality 参数；端口可留空自动分配。
3. 按路径顺序添加中间段；每段可选择“自有节点”或“订阅节点”，支持移动顺序。选点时可添加订阅 URL、粘贴内容或上传配置，解析后选择具体节点。
4. 选择最终出口，同样支持自有节点或订阅节点。多选出口展开多行预览，共用已选择的中间段；每行可分别编辑，不自动生成中间段与出口的笛卡尔积。
5. 确认每行“客户端 → 入口服务器:端口 → 中间段 → 出口 → 互联网”、节点来源和更新方式，一次提交。
6. 返回创建结果，资源显示“未授权”。点击“加入策略组”只是进入明确的授权操作，不在创建时自动给既有用户授予权限。

示例使用同一台入口服务器：

| 代理资源 | 独立入口 | 中间段 | 最终出口 | 用户订阅 |
| --- | --- | --- | --- | --- |
| A → 机场 X → B | A:20001 | 订阅节点 X | 自有 B | 独立的一项 |
| A → 机场 X → C | A:20002 | 订阅节点 X | 自有 C | 独立的一项 |
| A → 自有 M → 机场 Y | A:20003 | 自有 M | 订阅节点 Y | 独立的一项 |

每行产生一个入口节点和一条有序链路。入口服务器可共用，中间段和出口节点也可共用；入口节点和监听端口必须独立。用户获得几条链路由策略组明确决定，客户端选择哪一项就使用其明确顺序的路径。路径是一条线性序列，不增加自动出口池、随机选点或任意有环拓扑。

兼容已有未授权入口时，在单行创建中提供“使用已有入口节点”。该节点必须为 Reality、没有任何用户授权或普通策略组引用、没有任何现有链路的入口、中间段或出口引用。提交前明确提示“此入口将作为该链路的专用入口管理”；批量新建默认生成独立入口，不复用同一个旧监听。

端口留空时，预览显示“提交时自动分配”；预览不预占端口。最终端口在事务锁内分配，创建结果显示实际地址，避免并发创建导致预览与真实监听不一致。

所有受管段必须来自未退役且已启用插件的服务器，内部段沿用受控 Reality 端点；外部段使用固定运行时支持的代理出站，不受服务器节点枚举限制。受管设备离线可以保存合法配置，但显示“等待设备上线应用”。没有合适节点时，在本页创建节点或添加来源并保留草稿；草稿不预占端口、不创建入口、不发布配置。未解析来源不能提交成有效链路。链路提交失败时不遗留新入口，前端过滤不能代替后端并发校验。

## 有序混合链路模型与编译

`entry_node_id` 仍代表独立公开入口；`hops` 按从入口到最终出口的顺序保存，每项为受管节点引用或外部节点版本引用，最后一项是出口。路径至少一个、最多八个入口后的代理跳，单批最多 32 条链路。创建时拒绝重复资源/端点、绕回入口、引用其他链路入口、协议或传输不兼容以及缺失依赖。受管内部跳不得位于入口服务器，也不在一条路径中重复同一受管服务器。

面板在入口 A 编译全部嵌套出站；后一个出站的 `detour` 指向前一个出站，入口路由指向最后一个。`A → 订阅 X → 自有 B` 的方向如下：

```text
X outbound：使用导入的 X 代理参数，无 detour
B outbound：使用 B 的专属内部凭据，detour = X 的内部 tag
A 的入口路由：目标 = B 的内部 tag
```

更长路径 `A → 自有 M → 订阅 X → 自有 B` 对应 `X.detour=M`、`B.detour=X`。各受管内部节点只接收自己的内部 relay 身份并直接转发，机场保持自身代理服务；面板不要求在机场部署服务。依据固定 [v1.14.2 的拨号定义](https://github.com/SagerNet/sing-box/blob/v1.14.2/docs/configuration/shared/dial.md) 和 [DetourDialer 源码](https://github.com/SagerNet/sing-box/blob/v1.14.2/common/dialer/detour.go) 推导，真实路径仍需验收。

导入内容的原 tag、detour、DNS、路由和监听不进入运行配置。编译器从资源 ID、路径代数、跳序号生成内部 tag，自己校验引用及依赖图。节点服务地址域名使用明确的入口 bootstrap DNS 政策，每个需要本地解析的出站显式指定 `domain_resolver`，保留原 TLS SNI；DNS 依赖不能循环，也不能借源配置改为另一条路径。目的域名是否远端解析按最终协议能力单独判断。

协议校验区分“代理提供的用户 TCP/UDP”与“连接该代理所需的下层承载”，从最终用户流量需求逐跳倒推。不能直接取所有跳的 TCP/UDP 交集。例如 HTTP 中间节点可以承载后续无额外 transport 的 Reality 出口所需的 TCP/TLS，而该 Reality 出口可用 XUDP 转发用户 UDP；HTTP 作为最终出口则只有 TCP。HTTP 中间节点不能直接承载后续 Hysteria2 所需的 UDP/QUIC。判断必须包含 transport、network、UoT/mux、目标平台和签名运行时构建特性，不能只按协议名称判断。参见固定 [VLESS](https://github.com/SagerNet/sing-box/blob/v1.14.2/protocol/vless/outbound.go) 与 [HTTP](https://github.com/SagerNet/sing-box/blob/v1.14.2/protocol/http/outbound.go) 实现。

原设计阶段用固定上游源码版本的 ARM64 1.14.2 运行时仅执行了九个配置 `check`：订阅 HTTP 中间段到 Reality 出口、混合四段等结构被接受，重复 tag 和未知字段被拒绝；环、缺失 detour 及 HTTP 到 Hysteria2 也返回成功。这证明 `check` 不能代替自己的图和承载校验，见上游 [check 命令](https://github.com/SagerNet/sing-box/blob/v1.14.2/cmd/sing-box/cmd_check.go)。该历史记录未启动服务；本轮新增的原生路径和探测结果独立记录于[本地夹具](acceptance/mixed-path-local-fixtures.md)。

## 后端资源模型与接口

保留 `nodes`、`singbox_chains` ID 和现有授权表，以插件内统一资源投影连接页面。链路新增不可变代数、按序跳记录及部署依赖，外部段引用已解析的节点版本；受管段引用不可变端点版本并记录自己的内部 relay 身份。端点版本冻结服务器/节点身份、地址、端口、SNI、公钥、short ID、协议/传输及运行时能力，恢复旧代不得重读当前可变节点参数。旧单一出口/relay 列仅保留旧两跳兼容投影，新路径不能伪造一个出口 ID 来塞入旧模型。资格视图、策略校验、发布与订阅统一按完整路径读取。

资源键使用 `direct:<node_id>` 或 `chain:<chain_id>`。直连行保留节点名称，链路行保留 `chain.name`，各段名称单独展示；旧订阅中的入口名称不因页面迁移隐式重写。版本表和跳表见 [ADR 0040](adr/0040-mixed-chains-and-subscriptions.md)。

所有新增接口位于 `/api/plugins/sing-box`，沿用管理员会话及请求安全校验。以下接口已实现；链路编辑本轮只开放名称，端点变化采用替代资源，实际参数与限制见[实施说明](agent-runtime-and-chains.md)：

| 接口 | 目标用途 |
| --- | --- |
| `GET /proxy-resources` | 同一数据库快照读取直连/链路投影、有序公开拓扑、引用和状态；保留破损链路供清理 |
| `GET /proxy-resources/{kind}/{id}` | 资源详情；`kind` 为 `direct` 或 `chain` |
| `POST /chains/batch` | 单条或多条原子创建，包含专用入口、按序 `hops` 和幂等键 |
| `PATCH /proxy-resources/{kind}/{id}` | 直连复用原节点校验；链路编辑管理名和明确指定的订阅名，拓扑与端点绑定保持不可变 |
| `DELETE /proxy-resources/{kind}/{id}` | 按资源语义检查引用并删除；链路和专用入口一起退役 |

资源投影只含公开字段、资源标识、脱敏来源和状态；不返回私钥、用户 UUID、内部 relay UUID、机场密码、订阅 URL 或完整部署配置。用户订阅仍经过资格检查。已有 `/nodes`、策略请求和旧受管两跳创建请求保持兼容；旧 `/chains` 结构只覆盖旧两跳资源，复杂链路的读取/修改使用新资源接口。旧 `DELETE /chains/{id}` 的解除关系行为与“删除代理资源”区分，对混合路径明确拒绝旧操作，防止遗漏中间段清理。

直连创建继续调用既有 `POST /nodes`；链路创建调用新批量接口，单条也是一行请求。读取、编辑和删除使用统一资源接口，避免为直连重复新增一套创建逻辑。统一编辑接口内部复用现有节点校验，不跳过协议、证书和同服务器配置约束。

批量请求示例：

```json
{
  "request_id": "<本次提交的 UUID>",
  "items": [
    {
      "name": "入口 A → 机场 X → 自有 B",
      "entry": {
        "mode": "new",
        "server_id": 1,
        "public_host": "entry.example.com",
        "sni": "www.example.com",
        "port": null
      },
      "hops": [
        {
          "kind": "subscription",
          "source_id": 1,
          "external_node_id": 10,
          "node_version_id": 20,
          "update_mode": "follow_node"
        },
        { "kind": "managed", "node_id": 2 }
      ]
    }
  ]
}
```

新建入口的名称默认取本行链路名称，协议固定为 Reality，使用既有的密钥和 short ID 生成、端口及配置校验。复用入口使用 `entry: {"mode":"existing","node_id":1}`，与新建字段互斥。外部引用必须属于对应来源并具有可选的已校验版本，不能提交任意 URL/JSON 绕过解析。更大链路集合分为用户明确提交的多批，每批分别给出完整结果。

原子提交遵循既有插件锁边界：

1. 认证并验证请求结构，对名称等字段进行与写入一致的规范化。
2. 开启事务，取得插件拓扑 advisory lock，检查同一 `request_id` 的已保存提交收据。
3. 按 ID 排序锁定外部来源/版本与全部受管服务器记录，重验启用、存活、版本、独立入口、完整路径及承载兼容性；HTTP 下载和解析在事务外完成，锁内不等待网络。
4. 校验整批端口，自动分配时将本批已分配端口也视为占用；任一非法项返回具体行号及原因。
5. 在同一事务写入全部入口、链路及跳记录、路径代数、受管内部凭据和幂等收据，标记全部受影响服务器待发布；整批候选配置通过业务图、承载和原生配置校验。
6. 提交后返回收据 `request_id`、`chain_ids`、`entry_node_ids`，前端重新读取资源状态。写入任一步失败均回滚整批，前端不循环 POST 组合批量创建。

新增插件表 `singbox_chain_creation_requests` 保存 `request_id`、规范化请求摘要、结果 ID 收据和创建时间，不保存私钥。收据不随链路或入口删除级联清除。相同键、相同请求返回原收据；相同键、不同请求返回 409。删除资源后重放只返回原创建收据，资源查询显示已删除，不重新创建。前端网络超时保留提交键和原请求，用户修改草稿后生成新键，不能用新键自动重试原提交。该幂等实现使用现有 SHA-256 和 JSON 能力，无需另增依赖。

## 授权、订阅与计量

授权对象是直连资源或链路资源。链路入口不能被单独授权，也不能通过普通 `node_ids` 绕过链路；这个限制同时保留在 API、数据库模型与编译器。多个策略组和原单独授权取并集，移除一个重叠来源不更换凭据，最后一个来源消失才撤销。

客户端只取得入口的用户凭据。机场凭据只进入入口所需的出站配置，受管内部节点只取得自己的 relay 身份，不收到整套机场订阅。每条链路仅在公开入口计量用户流量，各内部跳不重复扣量；受管中间/出口上的直连用户仍正常计量。一个用户全部直连和链路入口共同使用自己的套餐额度，历史账本与 epoch 保持。机场自己的流量和到期信息仅作来源参考，不代替本地套餐或参与重复扣量。

新路径的订阅资格要求全部受管依赖已经健康应用相应路径代数，并具有该代指定路径的成功探测证据；外部节点没有 Agent 应用状态。历史旧两跳按原资格逻辑接管，不补造探测记录。资源详情分别展示：

| 维度 | 展示规则 |
| --- | --- |
| 资源 | 完整 / 受管段缺失 / 外部版本无效 / 协议或承载不匹配；破损链路仍可查看和清理 |
| 授权 | 未授权，或引用策略组及受影响用户数量；创建本身不授予权限 |
| 受管设备 | 分段显示在线、离线、目标/已应用配置及观测时间 |
| 订阅来源 | 来源版本、最后成功刷新、跟随或固定、本次节点缺失/更新失败；不显示伪造的 Agent 在线 |
| 配置 | 未发布 / 等待受管依赖 / 等待入口 / 应用失败 / 受管配置已就绪 |
| 路径验证 | 尚未验证 / 按指定目标验证成功或失败及时间；不与解析或应用状态合并 |

“受管配置已就绪”不等于机场账户有效或路径连通。不能以解析、`check`、本地入口健康代替端到端验证。路径中的网络失败不能自动跳过某段、改入口直连或另选机场节点；显式授权撤销及受管资源退役同样作用于订阅和运行时配置。

订阅刷新生成不可变源/节点版本；默认“跟随所选节点更新”只采用同一明确节点的有效新版本，也可选择“固定当前版本”。名称和列表顺序不作为身份。下载/解析失败、本次所选节点缺失或身份不唯一都不换节点，保留已应用快照并明确展示使用旧版；这些是更新失败，不等于管理员撤销链路。新的创建不能引用本次缺失节点。来源归档只停止刷新和新引用；明确删除链路或撤销授权才执行本地停止流程。详细规则见 [订阅来源设计](chain-subscription-sources.md)。

每条链路最多一个正在应用的候选；新版本发布先准备受管内部跳的新 relay 代数，同时保留可恢复旧代数。依赖应用后，在入口通过受认证回环路径验证明确候选版本；探测成功才切用户入口，再验证切换后的路径。依赖和探测证明必须匹配签名配置实际包含的链路代数、revision/hash 及请求 ID，不能仅比较 revision 大小。初建没有旧代时也先验证候选，不提前开放用户路由。入口成功后持久确认最低可恢复代数；当前已应用配置和未完成 intent 均不再使用旧代，才允许清理旧身份，超时不撤旧。迟到刷新或 ApplyResult 不得推进新代。切换/探测失败且尚未固定恢复边界时可恢复原已应用代数；固定边界后保持边界以上版本并报告故障，不能自动回到已撤旧代。历史证据不原地改写。外部凭据可能由供应方立即撤销，旧快照保留不证明旧网络仍可用。外部认证和端到端失败与配置应用失败分别报告；精确确认和恢复屏障保持 [ADR 0020](adr/0020-chained-transit.md) 的要求，具体出站验证由 [ADR 0073](adr/0073-ordered-path-publication-and-native-probe.md) 覆盖原临时 SOCKS 方案，不新增公开探测入口。成功记录只证明指定时刻及目标，不保证第三方持续健康。

## 编辑与删除

直连资源继续使用既有协议和证书能力。链路本轮只允许修改管理名称及明确指定的入口订阅名称；入口公开地址、端口、SNI、协议、密钥、short ID 与路径保持不变。已被混合路径引用的受管节点只允许改名称和启用状态。原设计中的在线端点编辑需要同时维护可恢复的旧监听，本轮采用拒绝在线修改并创建替代节点/链路的方案，不能先覆盖共享端点使旧代失效。旧入口名称与链路显示名称分开保存，改变订阅名称需明确操作，不隐式改写用户正在使用的订阅投影。

已创建的入口、节点身份和路径顺序保持不可变；同一外部节点的版本更新推进路径代数，保留入口 ID、端口、用户 UUID 和授权。改变拓扑或换另一个节点采用“创建替代链路 → 明确调整策略组引用 → 等待新链路应用 → 清理旧链路”。替代链路有新入口和凭据，不承诺无损切换或自动继承旧授权。

删除链路资源前显示策略组引用和全部受管依赖影响。仍有策略组引用时返回 409 和清单。资源删除在一个事务内退役链路与专用入口、清理授权、撤销该路径代数并安排各受管内部身份清理；历史路径、恢复证据、计量与幂等收据保留，不能把不可变跳版本物理删掉。复用入口创建时明确其成为专用入口，删除规则相同。共享来源、中间/出口节点及其他链路、直连用户保持。

删除被任何路径引用的受管节点或来源前检查当前、待应用及恢复中的依赖，返回 409 和清单；归档来源可停止刷新但保留快照。core 服务器退役触发相关链路资格撤销和全部存活受管段清理，不级联删除其他服务器或绕链降级。旧兼容接口解除旧两跳关系后若保留入口，不自动授权任何用户；这种操作不等同于新的资源删除。

统一删除接口与旧 `DELETE /nodes/{id}` 必须共用完整路径引用检查。作为链路入口的节点通过资源删除，作为中间或出口的节点先处理引用，均返回 409 和清单。旧路由及请求形式保留，core 退役走前述失效与清理流程。

破损链路的清理不能依赖“入口服务器仍存活”的创建校验。资源删除在插件锁之后按 ID 锁定关联服务器记录，允许其已经退役，再清理链路和入口，对全部仍存活的受管依赖安排发布；不能直接调用会排除退役服务器的 `lock_server` 使清理永远返回 404。资源已删除时返回明确的已删除结果，不重复退役其他节点。

本轮规划没有增加独立“停用链路”按钮。停用需要持久的启用状态与订阅、入口用户和全部受管内部 relay 的共同资格检查；如果之后实现，应单独验证，不能用只隐藏页面或订阅来模拟停用。

## 迁移与实施顺序

旧链路以单个受管 hop 转入版本化投影，保留节点/链路 ID、出口关联、原 `relay_uuid`、用户凭据、`stat_name`、策略组、订阅 token / URL / 原名称、历史 `source_json` 及流量流水。首次接管版本标记为 legacy，保留原 tag、relay UUID 及原生配置字节；之后的新代才采用逐位置、逐代的新 tag/内部身份规则，不因迁移自动重编译旧配置。已有入口从直连视图隐藏，破损链路保留。仅页面归属不需要搬迁，新增混合路径模型需要插件迁移与统一 publisher，禁止混跑新旧发布器。

实施拆成四个可独立审查的阶段，最终交付以全部通过为准：

1. **统一资源读取与入口归位**：插件资源投影、节点列表/详情、策略选择器、服务器入口/出口角色展示。涉及 `plugins/singbox/panel/chains.rs`、`nodes.rs`、`mod.rs` 和 `web/src/plugins/singbox/{Nodes,Groups,ProxyUsers,ServerBusiness,UserEntitlements}.tsx`、`groupTypes.ts`、`web/src/types.ts`、`App.tsx`。
2. **订阅来源与版本化路径**：本地格式解析、受限下载、节点身份/版本、更新方式、混合路径与部署依赖迁移；扩展编译器、资格视图及统一 publisher，不把外部协议配置塞进服务器节点枚举。
3. **创建与生命周期**：事务内单条/批量创建、幂等、候选及恢复代数、公开参数编辑、全部路径引用保护与清理；更新中文创建/来源交互。
4. **验收与说明**：PostgreSQL/编译器/真实浏览器和隔离代理路径验收，构建并提交 dist，更新实际 API 和使用说明；发布及生产迁移继续使用独立授权和既有流程。

业务实现位于 sing-box 插件和编译器，不向 `agent-core` 添加代理资源模型；设备继续通过签名整包应用配置。新路径所需的候选探测和持久恢复确认按通用 SDK/协议及 core 边界实现，不让 core 理解机场订阅；缺少这些能力的 Agent 不能启用新路径或完成新代切换，保留已有配置。复用 JSON、Base64、HTTP 和摘要能力，新增 YAML 事件解析依赖的必要性及替代方案记录在 ADR 0040。保持单运行时实例与有界线性路径，新增迁移为 0025–0027。

## 必须通过的验收

| 场景 | 权威证据与通过标准 |
| --- | --- |
| 页面归属 | 桌面、手机和键盘浏览器操作：在代理节点创建、列出、查看、编辑及删除链路；策略页只有资源引用，无链路 CRUD |
| 多条链路 | PostgreSQL 和浏览器：同入口服务器创建三个出口对应三条链路、三个不同监听；资源列表和订阅各显示三项，无重复直连入口 |
| 订阅中间段 | 浏览器创建 A→订阅X→受管B 与 A→受管M→订阅X→受管B，保存/刷新/编译均保持顺序；X 无 Agent 依赖 |
| 订阅格式 | URI、Base64 URI、sing-box JSON、Clash/Mihomo 节点 YAML 转为等价节点；不支持的协议或参数具体报告，不导入全局规则 |
| 承载校验 | 验证 HTTP 中间→Reality 最终的 TCP/UDP 与 HTTP 最终仅 TCP；HTTP→Hysteria2/QUIC 等不兼容路径在业务校验拒绝，不能依赖 check |
| 来源更新 | 跟随同一明确节点更新凭据，固定模式不变；同名、重排、消失、歧义、下载/解析/应用失败不换节点，状态与旧版本运行事实对应 |
| 代数发布 | 所有受管依赖就绪后才切入口；并发刷新、乱序应用、入口失败与回滚使用同一代数，旧历史证明不被覆盖 |
| 导入边界 | SSRF、DNS 重绑定、认证重定向、超大正文/解压/别名/深度等拒绝；错误、预览、草稿和用户订阅不泄露源 URL 或节点秘密 |
| 原子失败 | 第二/第三项端口冲突、出口非法、编译失败及写入失败后，入口、链路、收据和 dirty 状态都无半批写入 |
| 并发与重试 | 两个请求争同端口、同一幂等键并发、超时重试、同键改内容、删除后重放；唯一创建且不复活已删除资源 |
| 拓扑边界 | API 与编译器拒绝不支持的配置、重复资源/端点、入口回环、既有授权入口、链路入口嵌套及缺失依赖；UI 给出跳序号和原因 |
| 共享出口 | 两条链路和出口直连用户共存；删除一条只撤其专用入口/relay，另一条与直连用户继续使用；新旧节点删除接口都拒绝绕过依赖检查 |
| 授权并集 | 同链路被两个策略组授予；撤一个来源保持 UUID，撤最后来源移除资格与运行配置；单独入口授权无法绕过 |
| 应用与资格 | 创建后受管依赖未全应用不提供链路；更新沿用有据可恢复代数；资源退役或授权撤销同时影响运行配置和订阅，不出现旁路 |
| 凭据与计量 | 列表、详情、代理用户 API、links/JSON 订阅不泄露内部凭据；入口计量一次，出口直连用户正常计量；套餐到期/耗尽同样作用于订阅和发布 |
| 旧数据兼容 | 升级前后逐项比较 ID、凭据、策略、订阅、名称、历史部署和流水；任一受管段节点删除或服务器退役后的破损链路可见可清理，全部存活受管依赖收到撤销；原直接节点协议/证书流程保持 |
| 发布与恢复 | 专用受控三/四段代理确认流量经过外部中间段、最终由指定出口出网；停止中间段连接失败，无旁路；持续流量、TCP/UDP、恢复与清理独立验收 |

本轮源码、PostgreSQL 状态机、浏览器和原生三/四段回环路径已有隔离证据，分别见[面板验证](acceptance/mixed-path-panel.md)与[本地网络夹具](acceptance/mixed-path-local-fixtures.md)。真实机场、完整 Agent 分布式发布/故障恢复、跨平台服务与入口实际计量仍未签收；上表是目标验收清单，不是全部已通过的声明。
