# 术语表

代码标识符与文档统一使用下表术语。

| 中文 | 代码中 | 含义 |
| --- | --- | --- |
| 模型 | `model` | 管理员在面板上编辑的对象，包括服务器、节点、用户与授权。 |
| 编译 | `compile` | 把模型变成每台服务器的配置包；相同输入产生相同字节。 |
| 配置包 | `bundle` | 某个运行时、某个版本的完整配置文件集合。 |
| 主机清单 | `manifest` | 一台服务器上所有模块的期望状态，包含配置版本和制品信息。 |
| 对账 | `reconcile` | Agent 比对期望状态与实际状态，并推动实际状态与期望一致。 |
| 计划 | `plan` | 适配器判断本次变更需要的动作：`noop`、`reload`、`restart`。 |
| 应用 | `apply` | 适配器把配置包落到运行时上。 |
| 意图 | `intent` | 应用前持久化的记录，用于崩溃后恢复。 |
| 周期 | `epoch` | 一段连续的计数周期，以 UUID 标识；运行时重载或重启后开启新周期。 |
| 适配器 | `adapter` | 把 core 的统一操作翻译成外部程序原生接口的一层，不保存持久状态，也不连接面板。 |
| 外插 | `plugin` | 原样安装、不做修改的外部程序，例如 sing-box。 |

## 状态与计量约定

- `rev`：单调递增的期望状态版本。`manifest.rev` 标识主机清单版本，模块的 `config_rev` 标识该模块配置版本；不能把版本号当作配置内容的哈希。
- `target_rev` / `applied_rev`：面板期望版本 / Agent 已成功应用版本。是否在线、是否应用成功、是否健康是不同状态。
- `stat_name`：按用户与节点生成的统计用户名，格式为 `u{user_id}_n{node_id}`；同一用户在不同节点有不同统计用户名。
- `seq`：某个 `epoch` 内递增的流量批次序号；面板以 `(server_id, epoch, seq)` 识别批次，记录以该三元组加 `stat_name` 唯一。
- `baseline`：上次已持久化的累计计数，用于计算本次差值；更新基准值与写入待发送批次必须处于同一事务。
- `outbox`：已持久化但尚未确认的流量批次队列；重连或 Agent 重启后可再次发送。
- `ack`：面板确认已持久化流量批次；重复确认必须是幂等操作。
- `noop`：配置内容与内核版本均无需改变；`reload`：配置改变而内核版本不变；`restart`：内核版本改变。

## 边界

面板持有期望状态；Agent 持有设备身份、已应用状态、意图日志和流量账本；适配器提供协议翻译与运行时操作。外插是被管理的独立程序，适配器是 Agent 内的代码，两者不能混称。

## 界面用语

面向管理员的界面名称（服务器与节点、管理员与代理用户、告警事件与故障事件、网络检测与网络配置、策略组与套餐等）及七个功能区的划分见[功能地图](product-map.md#界面用语)。代码标识符继续使用上表术语。
