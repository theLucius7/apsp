# CDT 脚本守护与迁移

在「服务器 → 阿里云 CDT → 配置自动启停」选择「CDT 脚本守护」，入口路径为 `/#/plugins/alicloud`。该模式复用阿里云插件与现有启停任务，不需要在面板或 Agent 中执行 Python 脚本。

## 行为

- 每个 ECS 独立配置停机线、突增阈值和低用量自动开机；按字节保存、按 GiB 展示，1 GiB = 1024³ 字节。两个旧配置的 150 GiB 停机线与 20 GiB 突增阈值原样导入，文件名中的 `200` 不作为停机线。
- 每分钟查询 `ListCdtInternetTraffic`，不带 `BusinessRegionId` 过滤。以账号为边界，汇总目标所属中国内地或海外额度池的全部 BGP 地域和产品，包括 IPv4、IPv6。分页未完成、重复地域/线路、非法字节数、产品和地域合计不符、同池有非 BGP 非零流量均拒绝决策。
- 零用量必须通过 `ListSwitchedCdtProducts` 确认目标地域存在已启用的公网 CDT 计费产品，不能把未开通、缺字段或请求失败当作零。
- 按北京时间自然月保存最高观测用量和最大单次增量。同月用量回退不降低累计值。最大单次增量达到突增阈值后，将其叠加为预估未上报流量，直到下次有效月度重置。
- 到达停机线请求 `ForceStop=false`、`StoppedMode=StopCharging`；低于停机线可启动仍存在的已停止普通或抢占式实例。过渡状态不改变。APSP 的手动停机暂停自动开机，需在界面恢复。
- 保留脚本使用的 `StartInstances` / `StopInstances` API（单个实例、`AllTogether`），无需把原有 RAM 权限改成单实例 API 权限。校验返回实例身份和逐实例结果，再读回实际状态；未知结果不重发。
- 新月必须观察到用量低于上月最高值；跨月查询、损坏状态、账号密钥或资源身份不符均保持实例原状。长时间停机后新月已超过上月用量需人工核对，不自动清空历史。
- 同一资源不能同时使用脚本守护、账单阈值、每日计划或抢占式保活。旧账单策略保持原有行为。CDT 用量守护独立于 BSS 账单是否可查询。
- 月度状态与待执行任务在同一数据库事务保存；通过现有账号锁、资源互斥、修订号、有效期和云端读回执行。未知启停结果只核对，不重发。过期超过 120 秒、跨月或查询失败的读数不能授权开机/停机。

CDT 兼容接口没有可信的用量账期时间戳。观察重置与突增缓冲只是保守保护，不构成实时硬限额、剩余免费额度或零费用保证。免费额度没有硬编码进策略。

## 导入

`tools/migrate-cdt-guards.py` 读取原目录中的 `config.env`、`config-hk-cdt-200.env` 和对应 `state/<实例>.json`。仅解析字面量赋值，不执行配置脚本；兼容 `TRAFFIC_THRESHOLD_GB` 的旧名称及缺少 `max_jump_bytes` 的旧状态。

先预览（不访问面板或云接口）：

```sh
python3 tools/migrate-cdt-guards.py --source /path/to/legacy-guard
```

导入前为面板配置现有凭据中心密钥环 `APSP_CREDENTIAL_KEYS` 与 `APSP_CREDENTIAL_CURRENT_KEY`，并独立备份。Docker Compose 已提供这两个变量的传递。密码文件和迁移记录保存在受保护目录，不放入仓库。

```sh
python3 tools/migrate-cdt-guards.py --source /path/to/legacy-guard \
  --apply --panel-url https://panel.example.com \
  --password-file /path/to/private/admin-password \
  --journal /path/to/private/cdt-migration.json
```

导入通过管理 API 将两套密钥分别写入加密凭据中心，并建立独立账号、ECS 资源和暂停的守护策略，保留本月最高值与最大突增。导入记录不含明文密钥，可用于断点续做。重复导入不能降低同月保护值；已运行的目标账号或策略会拒绝重导。历史导入不是新的云端观测，必须重新查询才能启停。

## 接管顺序

1. 在原 cron 运行时完成暂停导入；对每个资源调用 `POST /api/plugins/alicloud/resources/{id}/cdt-check`，只读核对真实用量与 ECS 状态，不写历史或启停实例。
2. 取得两个原脚本锁，备份原 crontab 与两份状态，持锁重读并重新导入最终状态。
3. 只删除这两个入口对应的 cron 行，核对其他任务未变化。通过 API 启用两个账号，再启用对应守护策略；账号自动降速保持关闭。
4. 观察至少两轮：更新时间持续推进、最高用量不回退、两账号互不混用、启停结果可核对；确认原 cron 已停用后结束切换。保留原脚本、配置和回滚材料。

如果切换失败，先暂停 APSP 策略并核对所有已发送的启停任务。将 APSP 的较新月度最高值和最大突增写回旧状态（同月取较大值），再恢复原两条 cron，避免两个控制器并行或丢失保护历史。不能仅凭暂停开关假定已发出的云请求被撤销。

## 验证

新增测试使用本地云 API 替身及隔离 PostgreSQL，覆盖普通 ECS 自动开机、缓冲停机、零用量、月界与用量回退、失效读数、手动暂停、持久化任务恢复及状态导入。前端覆盖策略选择、参数和保护显示；迁移工具测试覆盖字面量解析、二进制单位、加密引用、重复导入与暂停约束。真实切换的账号数量、状态核对和未验证项另记在交付记录中。
