# 服务器看板

> 2026-10-01 访问边界更新：默认仍需登录，可在「看板与通知」开启公开展示。看板使用 `/api/dashboard/…` 专用只读接口，隐藏节点在详情与历史接口中也不可见；匿名数据采用白名单脱敏。后台管理接口权限不变，见 [服务器运营说明](server-assets.md) 和 [ADR 0038](adr/0038-server-operations-and-public-dashboard.md)。服务器列表刷新旁的重复跳转按钮已删除，使用侧栏「服务器看板」进入。

登录后的默认首页为 `/#/dashboard`，点击卡片或表格中的服务器名称进入 `/#/dashboard/<服务器 ID>`。后台侧栏的“服务器看板”可跳转过去；看板右上角“进入后台”返回原管理页面。详情页返回看板，或直接进入该服务器的管理详情。旧 `/#/overview`、`/#/overview/<服务器 ID>` 书签继续可用。默认需要登录，管理员可在「看板与通知」开放匿名查看。

这是 Apsp 内独立的全宽监控页面，与管理后台分开展示，不需要再安装 Komari 或 Nezha，也没有将两者嵌入 iframe。沿用现有 NodeFlare 来源的主题、资源卡片和曲线，并保留许可说明。首页采用紧凑总览、搜索分组和节点卡片；状态筛选、地区、排序及表格收进“筛选与视图”。公开开关仅影响专用看板只读接口，不开放管理操作。

## 展示内容

- 总览：在线数量、管理员资产与剩余价值、网卡累计计数、实时上下行。搜索支持名称、系统、架构、主机名、地区、分组及标签；分组按钮常驻，其他筛选按需展开。
- 卡片：处理器、内存、磁盘、本期流量、网卡速率与累计计数；运行时间、价格、剩余价值和到期信息紧凑排列，地区显示在标题旁。延迟与丢包/连接失败率采用两列，每列按实际配置目标展示近期 20 格色条，最多三个目标，其余在详情切换；缺采样保持灰色。交换内存和连接数保留在详情。
- 详情：硬件、系统、设备版本、心跳/采样时间，处理器/内存/磁盘/网络历史曲线，已配置的拨测结果，以及逐网卡、磁盘读写、GPU 信息。
- 资产：卡片呈现手动填写的地区、成本、到期及周期流量；名称悬停可读分组与标签，搜索仍包含这些字段。详情显示完整资产、账单周期、统计网卡与观测范围。设置“在展示页隐藏”后，看板列表、详情与历史接口都不可见，后台仍可管理。
- 深浅主题只保存在当前浏览器；样式限定在展示页，不覆盖后台。界面使用中文，不增加字体、图标 CDN 或运行时依赖。
- 表格：适合横向比较较多设备，展示资源用量、实时上下行、一个拨测目标的当前结果和运行/采样时间。更多拨测在详情中查看；手机可在表格内横向滚动，不撑宽整个页面。卡片和表格使用同一组筛选结果，不额外逐台请求接口。
- 排序：默认编号顺序、名称、需关注的优先、处理器、内存或网络速率。只有有效的在线指标参与数值排序，未知值排在后面，真实零值保留。需关注的顺序为离线、指标待更新、待接入或任一资源占用达到 90%，这只是浏览顺序，不是新增告警系统。
- 视图和排序只保存在当前浏览器，禁用存储时仍能使用；不把搜索与筛选保存成后台业务配置。

新版服务器状态每 3 秒读取轻量接口，资产与静态信息每 30 秒读取；旧接口兼容模式仍为每 5 秒。页面隐藏时暂停轮询。资源曲线增加跨日历史窗口，按窗口使用有界聚合点，显示实际样本数、均值与极值；旧两小时原始接口继续保留。拨测卡片使用一次经过看板访问校验的汇总请求，每 15 秒读取各目标最近 20 条记录；详情配置每 30 秒刷新，结果每 15 秒刷新，可切换目标查看 1/6/24 小时的延迟和丢包双曲线。按目标读取最多 8641 条，覆盖最小 10 秒间隔的一整天；未指定目标的旧接口继续保留 4096 条限制。目标读取使用 0015 数据库索引。页面只读取已有任务，不会自动创建公网目标或启动诊断。

鼠标悬停或使用左右方向键可查看曲线读数，首尾键跳至首末采样，点击图例切换显示。缺失值、超长采样间隔保持断线，真实零值保留。曲线按时间桶保留首末值和极值，限制绘制开销。

## 刷新与快照

首页正常刷新时不显示技术说明；异常时显示简短状态与重试按钮。详情可查设备采样、面板接收和最新已持久化样本时间。轻量状态每 3 秒读取，资产每 30 秒、拨测汇总每 15 秒读取，各类只允许一个请求在途，单次读取最多 12 秒。切换到后台标签或离开看板会取消请求；回到前台立即刷新。每次轻量读取重新校验公开开关、登录和隐藏状态，旧请求不能恢复已不可见的设备。依照真实 API 成败判断是否可连接，不用浏览器的 `navigator.onLine` 推断局域网或回环面板是否可达。

手动刷新按钮立即读取服务器和拨测。全屏看板与手动暂停入口已删除，隐藏页面仍自动暂停。首次读取被取消时显示等待数据，不会声称没有服务器。同一访问身份下的迟到旧样本不能覆盖较新的真实样本；权限与隐藏变化仍以最新响应为准。服务器快照超过 15 秒未更新或读取失败时，也不能将旧速率、在线状态当作当前值。

顶部汇总始终覆盖所有未隐藏设备，不随搜索筛选改变。离线、待接入、在线但指标缺失/过期分别计数；没有设备、所有设备均被隐藏、无筛选匹配和接口失败是四种不同状态。看板只读，汇率、监控保存和通知等管理操作留在后台。

## 上报周期与历史保存

新建服务器或后台详情可分别设置采样、实时上报和历史批量写入：默认 1 秒、3 秒、60 秒。采样与实时上报为 1–60 秒，上报不能快于采样；历史写入为 15–3600 秒。新 Agent 先把采样保存至原有 SQLite outbox，实时请求不删除缓存，历史请求收到持久化确认后才删除对应样本。断线补传仍受原离线缓存上限约束，不能保证无限离线后恢复所有历史。

新版面板将实时样本放在有界内存缓存中，重启后等待新上报；历史批量写入、流量计数和重放收据在同一事务中确认。旧 Agent 沿用原上传频率，新 Agent 连接旧面板时回退旧模式。面板设置保存成功不代表旧设备已具备新能力。

「看板与通知 → 监控历史保存」设置 1–3650 天，默认 30 天。近两小时保留原始采样，七天内按分钟汇总，七至三十天按五分钟汇总，更早按小时汇总。每个指标分别统计有效样本数、加权均值、最小与最大值；未知值不补零，累计网卡计数保留最新精确值而不求平均。查询边缘不完整桶会标记，旧分钟末值只作为已知历史观测，不能当作整分钟均值。

后台分批汇总、清理，不要求设备在线。缩短保留期限会清除更早历史，之后调长无法恢复；不清理服务器网卡流量账本或代理业务用量。消息去重身份独立保留到整个七天重放窗口之后，历史压缩不会重复计算流量。拨测结果仍沿用原逐目标历史接口和现有保留规则，本次系统指标聚合不会把 TCP 失败率与 ICMP 丢包混合。

## 每日汇率与成本

管理员在“看板与通知 → 币种与汇率”设置当前浏览器的展示币种；保存后返回看板生效，不改服务器原币价格。看板仅呈现金额，来源、报价日期、抓取时间、报价表和手动更新全部移入后台。剩余价值按剩余天数除以周期天数折算，预付多个周期不再截断为一个周期；一次性费用有明确未到期日期时保留录入值，但不计入每 30 天成本。未填写价格、到期日期或缺少所需汇率时显示未知，不默认为零。匿名看板继续不包含价格、成本和到期财务信息。

面板使用 [Frankfurter](https://frankfurter.dev/) 的公开参考汇率，以 CNY 为基准，每 24 小时更新，在后台展示数据日期、抓取时间与来源。工作日数据可能早于抓取日期。更新失败时保留最后成功值并提示过期，一小时后重试；无缓存或缺少币种时不进行跨币种换算，同币种原价不受影响。管理员可手动刷新，连续操作有 30 秒冷却。普通看板读取只使用缓存，不按访问者数量请求上游。

## 数据语义

在线由面板判定，与指标新鲜度分别显示。离线、过期、无采样时间或读取失败时，不把旧速率加入实时汇总；保留最后信息并提示其状态。没有数据时显示“—”，不会补成零。接口失败不冒充空列表；登录失效仍回到原登录页。

“网卡累计”是各接口最近上报计数的合计，可能因重启重置、包含虚拟接口，不能作为计费总量或代理用户用量。总览累计仅汇总上下行计数完整的设备，完整设备数量可在总览悬停查看。卡片第四项使用周期网卡流量，无额度时显示“∞”；首次观测前保持“—”。

成本、到期、地区、分组和标签来自后台填写，不根据 IP 推测。“周期流量”使用面板收到的带时间戳网卡计数增量，按 UTC 账单日汇总；首次样本只建立基线，未观测到的历史不补算。显示所选网卡、统计方式和观测缺口，不作为供应商账单凭据；达到额度仅提示，不停止服务。自动顺延到期记录不代表实际续费或扣款。配置方法、单位和周期规则见 [服务器资产与流量额度](server-assets.md)。

## 持续拨测

后台侧栏“延迟检测”支持批量分配目标、新服务器默认分配及统一暂停，见[配置说明](monitoring.md)。也可在后台服务器详情的“持续网络拨测”中添加名称、目标地址、TCP 端口或 ICMP 类型、10–3600 秒间隔及线路备注，例如“电信”“联通”“移动”。展示页按实际备注呈现，不根据地址猜测运营商。未配置时显示配置提示；目标方向是**服务器到指定地址**，不代表浏览器到服务器的延迟。域名使用系统解析返回的首个单播地址；需要固定 IPv4/IPv6 时分别配置相应字面地址。

类型、目标地址和端口创建后固定；改变方向时新建目标，避免将旧历史或离线设备迟到的结果标为新方向。名称、线路备注、间隔和启用状态仍可编辑。接口更改固定字段返回 409，原配置与历史保持。

Agent 每轮执行四次 TCP 连接或 ICMP 回显。延迟取成功响应的平均值，四次都没有响应时延迟为空、失败率为 100%；TCP 连接失败率不等同于 IP 丢包率。Unix 使用系统 ping 汇总中的收发数和平均延迟，重复响应不降低丢包率，BSD 未逐行打印的迟到响应也按工具汇总计入。Windows 使用 PowerShell 调用 .NET Ping 并输出结构化 JSON，避免本地化文本及编码影响。

工具缺失、权限不足、DNS 失败、输出不完整/被截断或执行超时属于“检测不可用”，曲线保留空缺。兼容旧协议时 `loss_percent` 的数字占位字段保持不变，**只要 `error` 非空值（包括空字符串），该条延迟和失败率都不能作为实测值使用**；新的展示页与后台都遵循此规则。暂停、离线、读取失败和超过 `max(60 秒, 3 × 配置间隔)` 的旧样本不作为当前读数。

完整 Unix ping 汇总仍不能掩盖 stderr 工具诊断；发送权限失败也可能被工具计为已发送，因此这类结果记为不可用。命令保留发送错误输出，真实无响应且无工具诊断时仍可记录 100% 丢包。

Unix 需要系统 `env` 和 `ping`，macOS IPv6 使用 `ping6`；精简 Debian/Ubuntu 镜像可由管理员安装 `iputils-ping`，Alpine 可使用带完整 ping 功能的 BusyBox。Windows 需要系统 Windows PowerShell 与 .NET Ping。Agent 不静默安装软件或提高权限，检测不可用时可在后台查看实际错误。

最多配置 32 个目标，同时运行不超过 4 个，单次 DNS 最多 2 秒、命令最多 8 秒、整轮最多 12 秒。过期轮次跳过，不补跑积压轮次；慢目标不会阻塞其他结果落盘和上传，暂停或修改配置会取消已有测量。配置每 30 秒同步，离线最多沿用 24 小时；结果持久化后每 3 秒尝试上传，确认后删除，离线缓存最多 2 小时/4096 条。缓存清理与采样时间使用相同的面板时钟偏移，避免时差导致新数据立即被删。

平台参数依据 [iputils ping](https://www.man7.org/linux/man-pages/man8/ping.8.html)、[BusyBox ping](https://busybox.net/downloads/BusyBox.html#ping)、[FreeBSD ping](https://man.freebsd.org/cgi/man.cgi?query=ping&sektion=8)、[Apple ping6 实现](https://github.com/apple-oss-distributions/network_cmds/blob/main/ping6.tproj/ping6.c) 和 [Microsoft Ping.Send](https://learn.microsoft.com/en-us/dotnet/api/system.net.networkinformation.ping.send?view=netframework-4.8.1)。macOS IPv6 使用 `-X` 总时限，避免误用 IPv4 的 `-t`/`-W`。

```sh
cd web

```

`web/tests/server-display.mjs` 使用提交的真实构建产物、本机静态服务及拦截 API 夹具，检查三种宽度、两种主题、数据状态、曲线交互、搜索、后台返回和权限错误；通过 `APSP_PLAYWRIGHT_MODULE`、`APSP_CHROME_PATH` 指定本机浏览器工具，可用 `APSP_UI_SCREENSHOT_DIR` 保存截图。夹具测试不代表生产 Agent 或公网实机验收。CI 按当前安排保持暂停。
