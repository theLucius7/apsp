# 六工作区方案：全局页面、对象详情与系统设置的分工

- 状态：已接受（[ADR 0126](../adr/0126-workspaces-language-and-addresses.md)，2026-11-08）。[功能地图](../product-map.md)已按本文改写目标结构；界面按[执行计划](09-execution.md)步骤 4 实施，实施前现有界面不变。
- 依据：[设计依据](01-principles.md) R1、R2、R7、R8、R9、R10；对象定义见[对象词典](03-objects.md)，现有功能的去向见[功能盘点](02-inventory.md)。
- 与 [ADR 0125](../adr/0125-feature-modules.md) 的关系：ADR 0125 规定代码与数据按功能模块划分，界面分组交给功能地图。本方案只调整界面分组与入口，**不改变任何模块的归属**；每个入口仍由一个功能模块提供（§2.3）。

## 1. 三层分工

控制台的每个页面属于下面三层之一。判断一个功能放在哪里，先判断它属于哪一层。

| 层 | 回答的问题 | 放什么 | 不放什么 |
| --- | --- | --- | --- |
| **工作区页面** | 这一类事整体怎样？ | 某类对象的列表、筛选、汇总与批量操作；这类对象**唯一的新建入口**；属于本领域的设置分页 | 单个对象的完整配置；其他领域对象的编辑表单 |
| **对象详情** | 这一个怎样？ | 一个对象的全部状态（[状态设计](06-states.md)）、配置、关联对象（筛选视图）、本对象的操作与历史 | 别的对象的编辑逻辑（只链接到它的家） |
| **系统设置** | 面板本身怎样运行？ | 影响整个面板的设置：管理员与权限、令牌、凭据、审计、备份恢复、制品与版本、功能显示、迁移与兼容 | 某个领域的规则（告警阈值放监测与诊断，门户设置放网络服务） |

三条推论：

1. **一个对象只有一个家**（R1）。家是它的规范详情；其他位置出现的同一对象是筛选视图，点开进入家，编辑只在家里发生。
2. **服务器详情是筛选视图**（R8）。服务器详情里的节点、链路段、解析规则、告警、费用记录都是“按这台服务器筛选”的列表，复用各自领域的组件，不复制表单。
3. **设置跟着领域走**（R7）。只有跨领域、关于面板本身的设置进系统；领域内的设置是该工作区的一个分页。

## 2. 六个工作区

一级导航只用一种组织方案：按工作领域。每个工作区回答一个问题，顺序与使用频率一致。

| 工作区 | 回答的问题 | 包含 | 首页显示 | 频率 |
| --- | --- | --- | --- | --- |
| **概览** | 现在需要我处理什么？ | 只读汇总，不承载编辑 | 需要处理的事项（离线服务器、下发失败或长时间未应用、未恢复的告警、快到期或将超额的用户、30 天内的续费）、关键数字、开始使用步骤、网络示意图 | 每天 |
| **服务器** | 我有哪些机器，它们是否正常？ | 服务器、接入（单台与批量）、地址与域名（解析规则、DNS 账户）、云资源（阿里云 CDT）；实验：自动化与维护、改变服务器网络的配置 | 服务器列表（列表或看板两种视图），离线与异常排在前面 | 每天到每月 |
| **网络服务** | 我提供哪些服务，给谁用？ | 节点、链路、外部来源、代理用户（含门户与邀请）、策略与套餐、配置发布汇总 | 各服务器的配置是否已应用最新版本、需要关注的用户（快到期、将超额、已耗尽）、最近的变更 | 每周 |
| **监测与诊断** | 哪里出了问题，为什么？ | 告警（事件、规则、通知渠道）、线路质量（延迟、中国可达性、基础探测、IP 质量与解锁）、趋势与报表；实验：故障事件、吞吐测试与测试方案 | 未恢复的告警与最近恢复的告警；线路质量异常 | 按需，告警驱动 |
| **费用与续费** | 花多少钱，什么时候续？ | 续费项目、即将续费、支出、付费服务看板、设置（币种、预算、分类、提醒、Wallos 导入） | 本月费用、下一笔续费、即将到期 | 每月 |
| **系统** | 面板怎样运行？ | 面板设置、管理员与权限、API 令牌、凭据、审计、系统自检、备份与恢复、制品与版本、迁移与兼容 | 系统自检结果、待处理的版本升级 | 每季度 |

不属于控制台工作区、面向其他角色的入口保持独立：公开看板（访客）、用户门户、邮箱登录与接受邀请（代理用户）。

### 2.1 为什么是这六个

- **概览单独成区。** 它跨所有领域，只汇总不编辑。现在的「总览」把概览、统计报表、服务器看板、订阅看板放在一起，混合了四个领域；新方案中统计报表归监测与诊断，服务器看板是服务器列表的另一种视图，订阅看板归费用与续费。
- **服务器与网络服务分开。** 服务器上下文管机器、Agent、地址与资源；网络服务上下文管节点、链路、用户与授权，对应 ADR 0023 的核心与 sing-box 插件分层。代理用户属于 sing-box 业务域，留在网络服务。
- **地址与域名、云资源归服务器。** 解析规则把域名指向服务器的公网地址，CDT 调整服务器的带宽与启停，作用对象都是服务器（功能地图归类规则 3）。节点选择公开地址时引用解析规则中的域名，但不编辑它。
- **监测与诊断合并“告警”“线路检测”与“线路诊断”。** 它们回答同一个问题“哪里出了问题”。路线图 4.1 的“线路质量中心”与 4.3 的“事件统一”在这里落地。
- **费用与续费独立成区。** 它有自己的对象（续费项目、付款记录）和月度节奏；服务器的成本、机场订阅的到期只读引用自其他领域。
- **系统只放面板本身。** 插件中心改称「制品与版本」，因为它管理的是 Agent 与运行时的签名制品，而“插件”一词在界面与代码中有三种含义（[对象词典 §5](03-objects.md#5-多义词的处理)）；改名已于 2026-11-09 实施（ADR 0131）。迁移与兼容在这里集中显示，退出日常流程（R13）。

### 2.2 名称

- 工作区名是领域名，入口名是对象名，两者不重复（功能地图归类规则 6）。
- 「网络服务」是控制台内的工作区名。对外文案仍只写“服务器管理与配置”（2026-11-06 用户要求）；工作区内的入口继续使用“节点”“链路”“用户”“订阅”等功能名称。
- 「代理节点」「代理用户」在网络服务内简称「节点」「用户」；需要区分管理员时，界面写“代理用户”，见[对象词典](03-objects.md#36-用户)。
- 入口名不与工作区同名（功能地图归类规则 6；architecture.md §9 指出的“服务器 › 服务器”就违反了这条）：服务器工作区的第一个入口仍叫「服务器列表」。概览只有一个页面，侧栏中是一个独立入口，不设分组标题。

### 2.3 工作区与功能模块

工作区是界面分组，功能模块是代码与数据的边界（ADR 0125）。一个工作区由几个模块的入口组成；入口的所属模块写在该模块的前端清单（`index.ts`）里，工作区只是清单中的分组属性，调整分组不搬目录（R2）。

| 工作区 | 提供入口的功能模块 |
| --- | --- |
| 概览 | `overview` |
| 服务器 | 内核·设备（服务器列表、接入、服务器详情的概况与资产）、`dns`、`cloud`、`overview`（看板视图）；实验入口来自 `lab` |
| 网络服务 | `proxy` |
| 监测与诊断 | `alerts`、`lines`、`overview`（趋势与报表）；故障事件来自 `lab`，计划并入 `alerts` |
| 费用与续费 | `costs` |
| 系统 | 内核·身份、内核·平台服务、内核·设备（制品与版本）；迁移与兼容的只读页面来自 `proxy-legacy` 等兼容模块 |

服务器看板与统计报表的代码按 ADR 0125 属于 `overview`；本方案只把它们显示在服务器与监测与诊断两个工作区里。

## 4. 订阅一词的三个对象

现在的“订阅”指三件不同的东西，工作区方案按对象把它们分开（R3）：

| 对象 | 新名称 | 家 | 说明 |
| --- | --- | --- | --- |
| 代理用户拿到的配置链接 | **客户端订阅** | 网络服务 › 用户详情 | 订阅链接、格式（sing-box、Clash Meta、分享链接）、专属地址 |
| 作为节点来源的机场或外部订阅 | **外部来源** | 网络服务 › 外部来源 | 抓取、解析、版本；其中的节点可作为链路段 |
| 管理员自己付费的服务 | **付费服务**（续费项目的一种） | 费用与续费 | 原「订阅看板」只是它的卡片视图；概览只引用“即将到期”“本月费用”的摘要 |

外部来源报告的到期时间在费用与续费中只读显示，仅供参考（ADR 0097 现有行为）。

## 5. 实验与冻结功能的位置

现在的「实验功能」是按维护级别组成的一级分组，与按领域的方案混用（[设计依据](01-principles.md#45-信息架构)）。新方案：

- **不设“实验功能”工作区。** 实验功能放在它所属的工作区，默认隐藏；「系统 › 面板设置 › 功能显示」开启后在原位置出现，入口与页面标“实验”。冻结功能同理，标“冻结”。
- **维护级别只是元数据**（R6）。级别变化不改变位置，不搬代码；转正只去掉标记。
- **核心旅程不依赖实验页面**（ADR 0098 决定 6 保留）。

| 功能 | 级别 | 所属工作区 |
| --- | --- | --- |
| 批量任务、定时计划、维护窗口、有界自动处置 | 实验 | 服务器 › 自动化与维护 |
| 模板与批量接入 | 实验 | 服务器 › 服务器列表（批量接入） |
| 终端、服务日志与文件、资源与能力、资产与生命周期 | 实验 | 服务器详情 › 运维 |
| 远程命令 | 实验 | 服务器详情 › Agent |
| 域名台账、证书版本、端点台账、采集配置迁移 | 实验 | 服务器 › 网络配置 |
| 端口转发 | 实验，计划重做为中转规则（路线图 4.2） | 服务器 › 网络配置；重做后进入网络服务 |
| 系统网络参数调优、反向隧道、私有组网、受管防火墙 | 冻结 | 服务器 › 网络配置 |
| 故障事件 | 实验，计划并入告警（路线图 4.3） | 监测与诊断 |
| 吞吐测试、测试方案与综合报告 | 实验 | 监测与诊断 › 线路质量 |
| 硬件测试、Speedtest、NodeQuality 完整验机 | 冻结（完整验机门禁未解除） | 监测与诊断 › 线路质量 |
| 云资源与费用对照（Hetzner 等） | 冻结 | 费用与续费 |
| NodeQuality 日常检查 | 实验 | 服务器详情 › 诊断 |

## 6. 地址

现在有三条互相矛盾的规则：功能地图归类规则 8 与 ADR 0120 要求旧地址永久可用，ADR 0122 则清理了地址改写并拒绝改名前的地址（`web/src/app/paths.ts` 已删除，见[执行计划](09-execution.md#3-当前规范冲突清单)）。本方案按地址的读者区分：

| 地址 | 读者 | 规则 |
| --- | --- | --- |
| 已发给代理用户的链接：订阅、门户、邮箱登录、邀请、开通链接、专属地址 | 外部客户端与代理用户 | **外部契约，永不失效。** 改名必须保留旧地址并改写到新地址 |
| 控制台页面地址 | 管理员的书签与全局搜索记录 | **尽量稳定。** 工作区调整只改分组，不改已有地址；只有对象换了家时才改地址，旧地址改写到新地址并保留至少一个发布版本 |
| 接口地址 `/api/...` | 程序 | 按接口契约管理，不随界面变化 |

据此，第 3 节的调整中只有两处需要新地址：外部来源与链路升为入口（`/#/sources`、`/#/chains`，旧的 `?kind=`、`?view=` 查询改写过去），付费服务搬入费用与续费（`/#/expenses/services`，`/#/subscriptions` 改写过去）。其余地址不变。

这条规则也回答了功能划分文档原先列为待决定的“旧地址改写是否恢复”（2026-11-08 已由用户确认，见 [ADR 0126](../adr/0126-workspaces-language-and-addresses.md)）：ADR 0122 删除的改写里，已发给代理用户的门户、邮箱登录与邀请旧地址（`/#/plugins/sing-box/account`、`/member`、`/join` 一类，原先分别改写到 `/#/account`、`/#/member`、`/#/join`）属于外部契约，应当恢复改写；控制台的旧地址已过改写期，不恢复。需要用户确认。

## 7. 网络服务内的结构

网络服务是主线所在，对象最多，单独说明。

| 入口 | 列表显示 | 详情显示 | 新建入口 |
| --- | --- | --- | --- |
| 节点 | 受管节点：所在服务器、协议、公开地址、应用状态、所属策略组 | 配置、证书、应用与验证状态、被哪些链路使用、所属策略组、本期流量 | 「新建节点」：先选服务器 |
| 链路 | 入口、各段、落地、路径验证状态、所属策略组 | 各段（受管节点或外部来源节点版本）、验证记录、被哪些策略组包含、入口计量 | 「新建链路」：唯一入口，模板为两跳、入口 → 中转 → 落地、含外部来源节点（ADR 0098 决定 10） |
| 外部来源 | 来源、刷新状态、节点数、上次成功 | 节点及其版本、刷新历史、被哪些链路段与策略组引用、报告的到期 | 「添加外部来源」：先预览再采用（ADR 0076） |
| 用户 | 状态、套餐、本期用量、到期、最近订阅拉取 | 客户端订阅、登录地址、策略组与套餐、用量与历史、邀请、诊断 | 「新建用户」；邀请码由用户在门户中使用 |
| 策略与套餐 | 策略组：包含的节点、链路与外部节点，成员数；套餐：额度、有效期、重置周期，用户数 | 成员、包含对象、变更历史 | 「新建策略组」「新建套餐」 |

“配置发布”不是独立入口：每个对象详情显示自己的发布状态，网络服务首页汇总全部服务器的状态（[状态设计](06-states.md#4-配置下发的汇总视图)）。

## 8. 服务器详情

服务器详情的分页按“这台服务器的什么”组织。除概况外，每个分页都是筛选视图或这台服务器自身的设置。

| 分页 | 内容 | 来源领域 |
| --- | --- | --- |
| 概况 | 监控面板（与看板单机视图同一组件，ADR 0111） | 服务器 |
| 网络服务 | 运行时（安装、版本、健康、运维操作）、配置下发状态、这台服务器上的节点与经过它的链路段、部署历史 | 网络服务，按服务器筛选 |
| 地址与资源 | 公网地址、指向它的解析规则、云资源（CDT） | 服务器 |
| 资产与流量 | 到期与续费（链接到费用项目）、网卡流量额度与矫正 | 服务器；费用只读 |
| 诊断 | IP 信息、TCP 诊断、节点验机（实验） | 监测与诊断，按服务器筛选 |
| Agent | 版本与升级、采集与上报设置、周期拨测、远程命令（实验） | 服务器 |
| 运维（实验） | 终端、日志与文件、资源与能力、资产与生命周期 | 服务器 |

“带此服务器打开”保留，进入线路质量与实验的网络配置、自动化与维护，并预先选中这台服务器。
