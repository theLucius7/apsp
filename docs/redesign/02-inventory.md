# 功能盘点与新归属

- 状态：已接受（[ADR 0126](../adr/0126-workspaces-language-and-addresses.md)，2026-11-08）。归属变化在界面上按[执行计划](09-execution.md)步骤 4 实施。
- 依据：[设计依据](01-principles.md) R1、R2、R6、R7、R8、R17；对象定义见[对象词典](03-objects.md)，工作区与入口见[六工作区方案](04-workspaces.md)。
- 范围：main `a32ec49b` 上的全部页面与分页、服务器详情分页、代理用户与公开入口、面板命令行、后台任务与 Agent 能力。级别沿用[功能地图](../product-map.md)的五级：核心、支撑、可选、实验（降级）、冻结。

## 1. 盘点结论

1. **功能本身大多有清楚的对象，混乱主要来自位置。** 同一领域分散在多处（线路质量在 4 处，DNS 在 3 处，IP 质量在 4 个入口），一个入口里又混着几个领域（「总览」含四个领域，统计报表把网卡流量与代理流量两本账放在一页）。
2. **没有一项功能需要删除才能完成重新归类。** 归属变化只改导航、名称与组件复用；删除功能或数据仍需用户单独授权。
3. **按 crate 看归属基本正确，按表与 SQL 看越界很多。** ADR 0125 的边界检查在 2026-11-07 记录了 226 处已知的跨功能访问（跨功能 SQL 166 处、前端跨功能引用 57 处、跨 crate `#[path]` 3 处，[architecture.md §7](../architecture.md#7-自动守护)）。本次盘点从界面一侧补充几处与用户直接相关的：专属地址自带的 DNS 客户端、备份后端位于实验的 `operations` 模块、两份 Globalping 客户端、两个页面直接调用 sing-box 插件接口（§7）。
4. **文档与代码的描述不一致。** 侧栏实际是 5 组 22 个导航项（日常 11 个侧栏入口加 2 个实验入口），而文档分别写四组、六组；`web/src/app/paths.ts` 已删除，多份文档仍承诺旧地址可用（[执行计划 C1、C2](09-execution.md#3-当前规范冲突清单)）。

## 2. 归属判断规则

新增或调整功能时按顺序回答，第一个“是”决定工作区：

| 顺序 | 问题 | 是 → |
| --- | --- | --- |
| 1 | 它是否服务主线（节点、链路、用户与订阅，或运营这张网络所需的服务器、线路与费用感知）？ | 否则进入路线图候选池，不实现（功能地图归类规则 1） |
| 2 | 它只汇总、不编辑任何对象？ | 概览（只引用，不另建数据） |
| 3 | 它管理的是面板本身（管理员、凭据、审计、备份、制品、迁移与兼容、全局显示）？ | 系统 |
| 4 | 它写入的对象属于哪个上下文（[对象词典 §2](03-objects.md#2-五个界限上下文)）？ | 该上下文的工作区 |
| 5 | 它只读取、回答“哪里出了问题”？ | 监测与诊断 |

再按三条规则落位：作用于一台服务器的视图放服务器详情，并复用对象所在领域的组件（R8）；设置放在它所属领域的设置分页，跨领域的才进系统（R7）；实验、冻结功能放在所属工作区内并标记，不单独成组（R6）。

**所有者看写入，家看用户的问题。** 代码与数据的所有者按 [ADR 0125](../adr/0125-feature-modules.md) 的功能模块确定（下表“功能模块”一列，与 `tools/feature-boundaries.toml` 一致）；界面位置按本节规则确定。二者不必相同：同一个工作区可以显示几个模块的入口，调整工作区不改变所有者（[六工作区方案 §2.3](04-workspaces.md#23-工作区与功能模块)）。

| 6 | IP 质量有四个入口：IP 信息、网络检测的 IP 检查与 IP 资料来源、NodeQuality 日常检查、门户线路 | 家在线路质量；服务器详情 › 诊断按服务器筛选；资料来源（第三方密钥）是线路质量的设置分页；日常检查调用同一刷新接口 |

| 8 | 两套证书：节点 TLS 由运行时内置 ACME 签发，网络配置 › 证书版本由面板签发 | 保持两套，但名称区分：节点证书属于节点（网络服务），面板签发的证书属于网络配置（实验） |
| 9 | 六处事件存储各有投递队列（服务器告警、故障事件、可达性事件、阿里云事件、费用事件、成员邮件），只有服务器告警进告警事件页 | 路线图 4.3 事件统一：告警页汇总所有领域的事件，共用投递与状态用语（[状态设计](06-states.md)）；发件箱按 ADR 0125 §5.3 合并为内核的一个，各功能只登记事件类型 |
| 10 | 续费提醒分三处：服务器到期经告警设置，续费项目有自己的提醒，取消提醒在运维模块却在费用页编辑 | 提醒规则的家在费用与续费；服务器到期以续费项目的形式只读引用服务器资产 |
| 11 | 三处保存期限设置：面板设置 › 监控历史保存、每台服务器的数据上报与保存、系统自检 › 分类保留期限 | 全局默认在系统 › 面板设置；每台服务器的覆盖值在服务器详情 › Agent；系统自检只读显示 |
| 12 | 服务器资产在四处：资产与流量显示、编辑弹窗修改、运维 › 资产与生命周期、费用与续费的只读行 | 家在服务器详情 › 资产与流量；运维区的采购配置并入（路线图 4.4）；费用与续费只读 |
| 13 | sing-box 部署、预检与运行时操作在服务器详情 › 插件与节点部署弹窗两处打开；安装运行时从插件中心、服务器详情、概览三处开始 | 运行时的家在服务器详情 › 网络服务；网络服务首页的汇总与节点详情链接过去，复用同一组件 |
| 14 | DDNS 有五个入口 | 家在服务器 › 地址与域名；服务器详情 › 地址与资源按服务器筛选；其余入口改为链接 |
| 15 | 迁移分散在六处：运维区迁移采集配置、网络配置服务器替换、DDNS 批量修改、Wallos 导入、两个命令行、Nexus 导入与接管工具 | 一次性迁移（来源迁移、旧链路接管、Nexus）集中显示在系统 › 迁移与兼容；业务操作（DDNS 批量修改、Wallos 导入、服务器替换）留在各自领域 |

## 8. 只有后端的能力

这些能力没有界面入口，保留为接口或工具，并在能力清单中登记执行位置与授权要求：

- Nexus 节点导入、追加与运行时接管（`tools/nexus_node_inventory.py`、`tools/nexus_runtime_takeover.py`）：兼容流程，在系统 › 迁移与兼容中只读显示状态。
- 制品导入与目标列表（`/api/artifacts/import-release`、`/api/artifacts/targets`、`/api/bootstrap/versions`）：系统 › 制品与版本应显示导入状态，因为运行时升级依赖它（[收敛方案 §5](07-convergence.md#5-候选版本身份与发布门禁)）。
- 独立观察者上报（`/api/control-center/observers`，由 `scripts/observe-panel.py` 写入）与服务器导出：系统自检只读显示。
- 未找到网页调用方的接口：`/api/plugins/sing-box/operations/privacy`、`/chains/batch`、`/users/{id}/accesses`、`/api/network-workbench/exit-history/{server}`、`/api/network-workbench/ip-history/{address}`、`/api/fleet/health`。逐个确认是否有工具在用；没有调用方且属于旧模型的，随[收敛方案](07-convergence.md#2-新建只有一条路径)退出（删除接口需授权）。

## 9. 上游参考与自维护

用户要求每项功能自己维护（R17）。代码、许可与构建方式的归属以 [architecture.md §6](../architecture.md#6-上游代码每个功能自己维护一套) 为准：功能依赖的上游代码由该功能在自己的 `upstream/` 中保留可离线构建的副本、许可与 `UPSTREAM.md`，构建不下载未固定的文件。本节只补充产品层面：参考了上游的功能，哪些模型由 apsp 自己维护。

| 功能 | 参考的上游（归属功能） | apsp 自己维护的模型 |
| --- | --- | --- |
| 服务器看板、监控刷新与历史、汇率、通知 | NodeFlare（`overview`；ADR 0036、0039、0047、0123） | 遥测、历史聚合、告警规则与通知渠道的模型和状态 |
| 云资源（CDT、启停、EIP） | CDT-Monitor（ADR 0057、0058、0121）、用户原有的 CDT 与换 IP 脚本（ADR 0093）（`cloud`） | 云资源、阈值、启停计划与操作记录；只经阿里云官方接口读回确认 |
| 解析规则 | IPFlare、ddns-go（`dns`） | 解析规则、DNS 账户、记录历史与提供方适配 |
| 节点管理与外部节点 | 妙妙屋（ADR 0076）、3X-UI 与 S-UI（ADR 0042、0075）、Sub-Store 与 mihomo 的格式（ADR 0045）（`proxy`） | 节点、外部来源、不可变版本与采用流程 |
| 用户、邀请、权限组 | Nexus 的 Xboard 与 xboard-node（`proxy-legacy`，ADR 0089、0091、0113、0115）；Xboard 一类面板的导入（计划） | 用户聚合、策略组、套餐快照、门户；兼容桥退出后不再出现 Nexus 用语 |
| 续费与付费服务 | Wallos（`costs`，ADR 0090、0096、0117） | 续费项目、付款记录、提醒 |
| 服务器验机、IP 质量 | NodeQuality 一族与 IPQuality（`lines`） | 诊断任务与报告模型（ADR 0028）；上游报告在插件内解析 |
| TCP 诊断 | TcpQuality（`lines`，ADR 0029） | 全部，Rust 自行实现 |
| 运行时 | sing-box（`proxy-runtime`，ADR 0104、0119、0124） | 补丁、构建、签名与能力声明 |

自维护的落地要求：

1. **上游只出现在边界。** 导入工具、解析器、外部程序封装是唯一出现上游概念的地方（[对象词典 §2.1](03-objects.md#21-外部上下文与防腐层)）；界面、接口与数据库使用 apsp 的对象。
2. **不跟随上游的结构。** 上游的页面组织、字段名与状态值不直接搬用；需要兼容的格式在边界翻译。
3. **来源说明可查。** 按 architecture.md §6 在各功能的 `upstream/UPSTREAM.md` 写明拿了什么、改了什么、怎么跟进；现有的 `plugins/nodequality/UPSTREAM.txt`、`plugins/ipquality/SOURCE.md` 并入这一格式。
4. **测试按 apsp 的对象写。** 上游的样例数据只作为边界翻译的测试夹具。
